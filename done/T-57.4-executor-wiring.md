# T-57.4 — Executor Wiring

## Context

The pipeline executor (`executor.rs`) currently calls `AcpxDriver::prompt()` once per pipeline node. This is a passive "fire and wait" that expects the agent to self-orchestrate workflow steps. The new workflow runner (`run_workflow()` from T-57.1) drives steps actively.

## Requirements

Modify `executor.rs` to replace the raw `AcpxDriver::prompt()` call with `runner::run_workflow()`:

### In the dispatch loop (per spawned task):

**Before** (current):
```rust
let driver = build_driver(context, &node);
let response = driver.prompt(&workflow_session_id, &prompt).await;
```

**After**:
```rust
let result = runner::run_workflow(context, &node.workflow_id, &agent_name, &prompt).await;
```

### Changes needed:

1. **Replace `build_driver()` + `prompt()` with `run_workflow()`**: The runner creates its own `AcpxDriver` internally and manages the session lifecycle.

2. **Update `classify_response()`**: Currently classifies `AcpxResponse`. Now classifies `WorkflowResult`:
   - `WorkflowRunStatus::Completed` → node completed, use `result.conclusion`
   - `WorkflowRunStatus::Failed` → node abandoned
   - `WorkflowRunStatus::Cancelled` → node abandoned

3. **Remove `build_driver()`**: No longer needed — the runner handles driver construction.

4. **Pass `context` into spawned tasks**: The runner needs `ToolContext` for calling workflow handlers. Verify `ToolContext` is `Send + Sync` (already confirmed).

5. **Agent name resolution**: Use `node.acp_client` (required — no default). If `acp_client` is `None`, mark the node as abandoned immediately (matches bash behavior where missing `acpClient` → `pipeline_mark_abandoned`).

## Test Strategy

1. Pipeline with 2 nodes: both complete via workflow runner
2. Node with no `acp_client`: abandoned immediately
3. Cancellation: verify `run_workflow` respects CancellationToken (may need to pass cancel token through)
