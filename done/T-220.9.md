# T-220.9 - Require Explicit Active ONNX Model

## Problem

Vector discovery silently falls back to the largest top-level ONNX file when no active model is pinned.

## Evidence

- `crates/maenifold-core/src/vector/discovery.rs:88-115`, `128-149` scans candidate directories and chooses the largest flat `.onnx`.
- `crates/maenifold-core/src/tools/embedding_models_scan.rs:46-56`, `74-83` mirrors the behavior for UI status.
- Source: `docs/codebase-audit-2026-04-25.md#p1-8`.
- Parent sequential thinking session: `session-1777125506368-62098`.

## Acceptance Criteria

- [ ] Runtime vector discovery requires explicit `settings.vector.active_model`.
- [ ] The "largest file wins" runtime fallback is removed.
- [ ] Any migration or recovery path is explicit, user-triggered, and catalog/hash verified.
- [ ] UI status distinguishes no active model from invalid or unavailable model.
- [ ] `cargo build --release -p maenifold-cli` succeeds.
