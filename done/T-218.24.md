# T-218.24 — ACP Resume State-Machine Hardening

## Problem

Session resume correctness depends on subtle one-shot state: take `resume_session_id`, attempt `session/load`, clear on success, restore on failure. Prior work waived concurrency and error observability gaps.

## Acceptance Criteria

- [ ] Concurrent prompt attempts against one `AgentSession` are serialized or rejected with a clear internal error
- [ ] On successful resume, `resume_session_id` is cleared exactly once
- [ ] On failed resume, `resume_session_id` is restored exactly once
- [ ] Error `AcpPromptResult.meta` includes `requestedResume`, `resumed:false`, and sanitized `resumeFailureKind`
- [ ] Tests cover concurrent prompts, loadSession unsupported, loadSession not found, and successful resume
- [ ] No silent `.lock().ok()` swallowing for resume-critical state
