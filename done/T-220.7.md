# T-220.7 - Verify Vec0 Native Extension Integrity

## Problem

The Electron vec0 installer downloads and loads a native extension from GitHub latest-release assets without pinned artifact integrity.

## Evidence

- `apps/desktop/electron/vec0.ts:44-50` uses GitHub `releases/latest`.
- `apps/desktop/electron/vec0.ts:119-145` selects an asset by wildcard and validates only protocol/host.
- `apps/desktop/electron/vec0.ts:230-239` extracts and load-checks the native extension before rename.
- `apps/desktop/electron/preload.ts:18-23` exposes `vec0Download()` to the renderer.
- Source: `docs/codebase-audit-2026-04-25.md#p1-6`.
- Parent sequential thinking session: `session-1777125506368-62098`.

## Acceptance Criteria

- [ ] Vec0 download uses an explicit expected version instead of `latest`.
- [ ] Downloaded artifacts are verified by SHA-256 or signature before any load attempt.
- [ ] Renderer-triggered install/update requires explicit user confirmation and reports integrity failures.
- [ ] The app refuses to load unverified native vec0 artifacts.
- [ ] `cd apps/desktop && npx vue-tsc --noEmit` succeeds.
