# T-43.7: Prompt Capabilities Declaration

**Requirement**: FR-42 audit findings — Initialization + Content  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/components/ChatView.vue`

## Acceptance Criteria

1. In the `initialize` call's `clientCapabilities`, declare prompt capabilities once the content block refactor (T-43.1) is complete:
   ```ts
   clientCapabilities: {
     fs: { readTextFile: true, writeTextFile: true },
     terminal: true, // after T-43.6
     prompt: {
       image: true,
       audio: true,
       embeddedContext: true,
     },
   },
   ```

2. Gate UI attachment features behind `agentPromptCapabilities`:
   - Only show image attachment button if `agentPromptCapabilities.value.image === true`
   - Only show audio attachment button if `agentPromptCapabilities.value.audio === true`
   - Only allow @-mention file embedding if `agentPromptCapabilities.value.embeddedContext === true`

3. When `agentPromptCapabilities` is empty or missing capability flags, disable the corresponding UI controls with appropriate tooltip explaining the agent doesn't support that content type.

## SWE Remediation

### What I changed
- `vendor/acp-ui/src/lib/types.ts`
  - Added a shared `PromptCapabilities` type so the store and chat UI use the same prompt-capability shape.
- `vendor/acp-ui/src/stores/session.ts`
  - Declared `clientCapabilities.prompt` during ACP initialization with `image`, `audio`, and `embeddedContext` all advertised as supported by the client.
  - Switched `agentPromptCapabilities` to the shared type and preserved the negotiated agent prompt capabilities from `initialize`.
  - Used a typed intermediate `clientCapabilities` object so the ACP SDK's older TypeScript surface can still carry the new prompt capability field without changing runtime behavior.
- `vendor/acp-ui/src/components/ChatView.vue`
  - Added prompt-capability-aware UI controls for image attachments, audio attachments, and `@` file embedding guidance.
  - Disabled unsupported controls with explicit tooltips when the agent omits or disables a capability flag.
  - Added pending attachment chips for locally selected image/audio blocks.
  - Implemented `@path` / `@"path with spaces"` file embedding into ACP `resource` content blocks only when `embeddedContext` is supported.
  - Updated send flow so attachments are bundled with the prompt and the composer is only cleared after a successful send.

### Notes
- The current ACP SDK typings in this workspace do not yet declare `clientCapabilities.prompt`, so the initialization payload uses a typed compatibility shim while still sending the required runtime field.
- `@` file embedding intentionally only treats path-like mentions (for example `@README.md`, `@src/main.rs`, or `@"notes/file name.md"`) as embedded-context requests to avoid accidentally treating ordinary `@word` text as a file reference.

**Verdict: PASS**

All acceptance criteria verified:

- **AC1 — `clientCapabilities.prompt` declared in `initialize`**: ✅ verified at `session.ts:350–368`
  The typed compatibility shim correctly intersects `InitializeRequest['clientCapabilities']` with `{ prompt: PromptCapabilities }` to carry the runtime field without SDK type conflicts. The three required flags (`image: true`, `audio: true`, `embeddedContext: true`) are all present. `fs` and `terminal` are also present as specified.

- **AC2 — UI features gated on `agentPromptCapabilities`**: ✅ verified at `ChatView.vue:54–56` and `ChatView.vue:930–952`
  Three computed booleans drive the gating:
  - `supportsImageAttachments = agentPromptCapabilities.value.image === true` (strict equality, correct)
  - `supportsAudioAttachments = agentPromptCapabilities.value.audio === true`
  - `supportsEmbeddedContext = agentPromptCapabilities.value.embeddedContext === true`
  
  Buttons are rendered with `:disabled="!supportsXxx || isLoading"` rather than `v-if`. AC2 says "only show" while AC3 says "disable" — the implementation resolves this tension in favour of AC3 (show-disabled with tooltip), which gives better UX (users see why the feature is unavailable). The practical outcome matches the intent of AC2: the controls cannot be used when the agent does not advertise support. Additionally, `buildEmbeddedContextAttachments` (line 283–305) hard-gates the actual file-embedding side-effect with an early return when `!supportsEmbeddedContext.value`, so even bypassing the UI disabled state (e.g. via keyboard) produces no attachments.

- **AC3 — Disabled controls with explanatory tooltips**: ✅ verified at `ChatView.vue:57–65`

  - Audio: `'This agent does not support audio attachments.'` when `!audio`
  - Embedded context: `'This agent does not support embedded file context.'` when `!embeddedContext`
  All three tooltips are wired to the button `:title` attributes in the template.

- **Capability reading from ACP response**: ✅ `session.ts:397` — `initResponse.agentCapabilities?.promptCapabilities ?? {}` with nullish fallback to empty object (no capabilities assumed by default).

- **Store export**: ✅ `agentPromptCapabilities` ref is exported from the store (`session.ts:1421`) and consumed by ChatView.vue via `sessionStore.agentPromptCapabilities` (`ChatView.vue:53`).
