# T-219.3 — Gate Done Tab Subsequent Row Clicks Don't Update Detail

## Problem

In the Gate view Done tab, clicking the FIRST row correctly loads the task detail (breadcrumb updates, spec content renders, history loads). However, clicking a SECOND different row does NOT update the detail panel — it remains stuck on the first selected task.

This is a regression or incomplete fix from T-219.1, which addressed the initial "Done tab click doesn't work at all" bug. The first click now works, but subsequent clicks are silently ignored.

## Evidence

CDP verification on packaged Electron app (2026-04-25, commit 43e21828f + T-219.1 fix):
1. Navigate to Gate tab → Done tab (485 tasks)
2. Click T-01.0 → breadcrumb updates to "Gate T-01.0", detail shows T-01.0 spec ✓
3. Click T-01.2 → breadcrumb STILL shows "Gate T-01.0", detail STILL shows T-01.0 spec ✗
4. Click T-05.1 → same, stuck on T-01.0 ✗

Screenshot: `outputs/screenshots/sprint-219/done-tab-second-click-stuck.png`

## Root Cause Hypothesis

The `isCurrentRequest()` guard in `useGateTaskDetail.ts` (line 153-155) checks both `requestId === detailRequestToken` and `selectedTaskKey.value === taskSelectionKey`. The resource subscription callback from the first task fires between the second click's `selectTask()` setting `selectedTaskKey` and `loadTaskDetail()` completing, which increments `detailRequestToken` and invalidates the new request.

The T-219.1 fix added staleness checks to subscription callbacks, but the race window between `selectTask` line 224 (setting the new key) and `loadTaskDetail` line 157 (stopping old subscriptions) still allows the old callback to fire and corrupt the token counter.
