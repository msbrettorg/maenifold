# T-68.11 — MCP Protocol Trace View

**Sprint**: 68
**Requirement**: PRD §4.3 — Observability
**Depends**: T-68.9 (shares board infrastructure)

## Problem

When debugging agent-gate interactions there is no visibility into the raw MCP protocol traffic. Developers and PMs must infer what happened from tool outputs alone, with no way to see the actual requests and responses flowing through the server.

## Solution

A lightweight standalone HTML page served at `/trace` that displays the last 20 MCP messages (requests + responses) in real-time. Designed to be kept open alongside the kanban board or an IDE — supports resize, scroll, and a close button.

## Architecture

### Ring Buffer (Rust)

- `crates/maenifold-gate/src/trace.rs` — shared ring buffer behind `Arc<Mutex<VecDeque<TraceEntry>>>`
  - `TraceEntry { timestamp: String, direction: Direction, method: String, id: Option<Value>, body: String, session_id: Option<String> }`
  - `Direction` enum: `Incoming` / `Outgoing`
  - Capacity: 20 entries (oldest evicted on overflow)
  - `push()` and `snapshot() -> Vec<TraceEntry>` methods
  - Feature-gated behind `app`

### Capture Point

- In `crates/maenifold-gate/src/mcp/http.rs`:
  - Wrap the root and mcp `StreamableHttpService` with an axum middleware layer
  - The middleware intercepts POST request bodies (clone bytes before forwarding), extracts `method` and `id` from JSON, pushes `Incoming` entry
  - On response, captures response body, pushes `Outgoing` entry
  - Only captures when the trace buffer `Arc` is present (app feature)

### Trace Endpoint

- `GET /trace` — serves embedded `trace.html` (same `rust-embed` asset folder as the board)
- `GET /trace/data` — returns `JSON` snapshot of the ring buffer for polling

### HTML Page (`crates/maenifold-gate/src/board/trace.html`)

Single self-contained HTML file, inline CSS + JS. No frameworks.

**Layout:**
- Title bar: "MCP Trace — Gate" + close button (navigates to `/`)
- Scrollable message list, newest at top
- Each message card shows:
  - Timestamp (HH:MM:SS.mmm)
  - Direction arrow: `→` incoming (blue), `←` outgoing (green)
  - Method name (bold, monospace)
  - Session ID (truncated, muted)
  - Expandable JSON body (collapsed by default, click to expand)
- Auto-scroll toggle (default: on — scroll to show newest)
- Clear button (client-side only, just hides entries)
- Entry count badge: "17 / 20"

**Behavior:**
- Polls `GET /trace/data` every 2 seconds
- Diff-based update: only add new entries, don't re-render everything
- Resizable browser window — page is fluid, fills viewport
- Scrollbar always visible when content overflows

**Styling (pipeline-ui tokens):**
- Background: `#252525`
- Cards: `#1e2028` with `1px solid #404040` border
- Incoming arrow: `#3b82f6` (blue)
- Outgoing arrow: `#22c55e` (green)
- Error responses: `#ef4444` (red) highlight
- Text: `#e0e0e0`, muted: `#6b7280`
- Font: `'SF Mono', 'Fira Code', monospace`
- Border radius: `4px`
- JSON body: `pre` block, `font-size: 12px`, max-height `300px` with overflow scroll

6. Close button navigates to `/`
7. Page is scrollable and resizable (fluid layout)
8. Pipeline-ui color tokens used throughout

10. All Rust files under 300 LOC
11. All existing tests pass
12. No new dependencies beyond what T-68.9 already added
