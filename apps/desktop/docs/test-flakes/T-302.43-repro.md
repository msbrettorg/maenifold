## Suspected root cause

The test mounts the overlay and waits for a single `flushPromises()` before reading
`document.body.textContent` (`SemanticZoomOverlay.test.ts:133-140`). The component renders
footer controls through child components and post-flush reactive work: `SemanticZoomOverlay.vue`
has a `watch(..., { flush: 'post' })` at lines 105-113, resets overlay state in another watcher at
lines 221-227, and passes `viewNode.status` into `SemanticZoomOverlayControls` at line 267.
The footer gates the visible action labels from that prop (`SemanticZoomOverlayControls.vue:34-63`).

The likely mechanism is a scheduling race: in the full parallel Vitest pool, one `flushPromises()`
can be insufficient for the overlay/dialog/child footer render chain to settle before the test reads
global `document.body.textContent`. That would make the completed-node footer assertions at
`SemanticZoomOverlay.test.ts:137-140` occasionally observe the body before the footer controls have
settled, even though the same test passes in isolation.
