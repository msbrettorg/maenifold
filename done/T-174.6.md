# T-174.6 — Add `backon` retry with explicit per-node policy

## Why
The resilience research note documents zero automatic retry today — every transient failure (MCP rate limit, network blip, agent process hiccup) requires manual `/restart`. `backon` 1.6.0 (Apache-2.0, native tokio, 36M downloads) is the recommended crate. Policy must be **explicit** per the constitution: no silent retry default.

## Scope
**Crate:** `maenifold-core`. **Files:** `Cargo.toml`, `executor_run.rs` / `executor_nodes.rs`, `types.rs` (new node fields), plus tests.

## Design
New optional fields on the node frontmatter / `NodeState` config (NOT silently defaulted):
```rust
pub struct RetryPolicy {
    pub max_attempts: u32,        // 0 = no retry (the default — opt-in)
    pub backoff_min_ms: u64,
    pub backoff_max_ms: u64,
    pub jitter: bool,
}
```

Failure classifier:
- **Transient → retry:** `tokio::time::error::Elapsed` (timeout), `std::io::Error` kinds `Interrupted`/`TimedOut`/`ConnectionReset`/`BrokenPipe`, MCP error codes the resilience research lists as retryable.
- **Terminal → no retry:** Empty AgentResponse, explicit Abandon, `Cancelled`, schema validation errors, programmer errors (panics).

## Acceptance
- AC-1: `backon = "1.6"` added to `Cargo.toml` (workspace `[workspace.dependencies]` if applicable).
- AC-2: `RetryPolicy` structure (camelCase wire fields: `retryMaxAttempts`, `retryBackoffMinMs`, `retryBackoffMaxMs`, `retryJitter`) wired through node config to executor.
- AC-3: Default behavior is **no retry**. A node without retry config behaves identically to today.
- AC-4: When `retry_max_attempts > 0`, the node execution future is wrapped in `backon::ExponentialBuilder` with the configured min/max + jitter; `.when()` predicate uses the failure classifier.
- AC-5: `NodeState.attempts` increments on every retry; `failure_reason` reflects the **final** failure when retries are exhausted (e.g. `"abandoned after 3 transient retries: timeout after 5s"`).
- AC-6: Two new tests in `executor_retry_tests.rs` (real engine):
  - Transient failure recovers within retry budget → node Completes.
  - Persistent failure exhausts retries → node Abandoned with the expected `failure_reason`.
- AC-7: `cargo build --release -p maenifold-cli`.
- AC-8: All existing pipeline tests still pass.
- AC-9: Telemetry: each retry attempt logs at `info` with attempt number and classified error kind (uses existing `tracing` infrastructure — no `eprintln!`).

## Forbidden
- Silent default retry policy. `max_attempts = 0` is the only acceptable default.
- Retrying terminal errors. The classifier is explicit.
- Touching cancellation (T-174.5) or timeout enforcement (T-174.4) — those are dependencies, not this scope.
