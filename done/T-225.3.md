# T-225.3 — Remove Hand-Rolled Gate Resource Handlers

## Problem

`crates/maenifold-core/src/mcp/resources/` contains hand-rolled gate resource handlers that duplicate what the gate MCP server already provides:

- `gate_status.rs` — parses markdown `## headings` as stages instead of using pipeline definitions
- `gate_task.rs` — reads task file directly instead of using gate tool
- `gate_history.rs` — hand-parses stage records from markdown instead of using gate tool
- `gate.rs` — helper functions (`parse_frontmatter`, `parse_stage_headings`, `slug_stage`, `task_id_from_path`, `find_task_path`) that support the hand-rolled handlers

After T-225.2, no frontend consumer reads these resources. They should be deleted.

## Fix

Remove the `gate://` resource family from the maenifold MCP server entirely. The gate MCP server (`gate --http --port 8081`) is the authoritative source for gate data.

## Key Files

- `crates/maenifold-core/src/mcp/resources/gate_status.rs` — delete
- `crates/maenifold-core/src/mcp/resources/gate_task.rs` — delete
- `crates/maenifold-core/src/mcp/resources/gate_history.rs` — delete
- `crates/maenifold-core/src/mcp/resources/gate.rs` — delete or reduce to just `is_gate_uri` stub returning error
- `crates/maenifold-core/src/mcp/resources/mod.rs` — remove gate module registration

## Acceptance Criteria

- [ ] No hand-rolled gate resource handlers remain in maenifold-core
- [ ] `gate://` URIs are no longer advertised by the maenifold MCP server
- [ ] `cargo build --release -p maenifold-core` succeeds
