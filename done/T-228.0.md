## Goal

Agents return structured UI, not just text. When a user asks "show me gate status," the response is a live, interactive card with approve/reject buttons — not a markdown table. A2UI is the declarative spec (originated by Google, co-launched with CopilotKit) that makes this safe and cross-platform.

## Why

Sprint 224 proved the AG-UI transport works — ACP → bridge → SSE → CopilotKit renders streaming text and tool calls. But every response is still a wall of text. A2UI closes the gap between "agent that talks" and "agent that shows."

This is what "AI is the new UI" actually looks like:
- Gate task card with status badge, pass/fail buttons, history timeline
- Memory search results as a browsable card list with excerpts and WikiLinks
- Pipeline view as an interactive node graph
- Knowledge graph community as a visual cluster
- Settings form pre-filled by the agent, confirmed by the user
- Wallpaper preview (T-227.1) rendered inline in chat

All declarative JSON. No code injection. Rendered by the host's own component catalog. The agent says *what* to show; the host decides *how* to render it.

## Architecture

```
Agent (ACP) → maenifold daemon → A2UI JSONL in tool responses
                                        ↓
              CopilotKit bridge (AG-UI SSE) → A2UI render events
                                        ↓
              CopilotKit React app → renders components from catalog
```

The desktop Electron app gets the same A2UI support via its own Vue renderer — same JSON, different component library (shadcn-vue vs CopilotKit React).

## Key A2UI concepts

- **Surface** — a UI container the agent creates (`createSurface`)
- **Component catalog** — pre-approved component set the host exposes (no arbitrary code)
- **Components** — declarative JSON: `{ type: "Card", props: { title: "T-221.12", ... }, children: [...] }`
- **Data model** — agent can update application state (`updateDataModel`)
- **Streaming** — JSONL format, components appear incrementally as the LLM generates
