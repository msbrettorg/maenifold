# T-238.18 - Gate fail on pending tasks returns an unhelpful illegal-transition error

## Problem

During duo-review bookkeeping for T-232.6/T-232.10/T-232.11, the PM attempted to record spec-review failures with `gate fail` while the tasks were still in `pending`.

Gate returned:

```text
illegal transition: state 'pending' does not allow outcome 'fail'
```

The error is technically correct but not actionable. Pending tasks do not have a fail transition, so duo-review findings on pending specs must be handled by editing the task specs and re-reviewing, not by gate failure records.

## Evidence

- Active thinking session: `session-1777236650835-22077`
- Attempted operation: record duo review failures for pending tasks.
- Command failed during `gate fail T-232.6 ... --root .`
- Exact error: `illegal transition: state 'pending' does not allow outcome 'fail'`

## Expected behavior

When an operator runs `gate fail` on a state that cannot fail, gate should explain the available actions for that state, for example:

- advance the task to its next stage with `gate pass` before stage verdicts are recorded, or
- edit the pending task spec directly when the task has not entered the pipeline yet.

## Acceptance criteria

- [ ] Illegal transition errors include the current state, attempted outcome, and valid outcomes/actions.
- [ ] Pending-state `fail` specifically explains that pending specs should be edited directly or advanced first.
- [ ] Existing transition validation remains strict; the command must not silently record an invalid fail.

## Verification

- Run `gate fail <pending-task-id> --root .` against a pending task in a temporary gate root.
- Verify the error message is actionable and still exits non-zero.
