# T-218.40 — Gate Progress Column Design-Token Contrast

## Problem

The Gate task table Progress column renders section badges with terrible [[contrast]] in the dark theme. In the screenshot, badges such as "Description", "Acceptance criteria", and similar markers appear as dark blue text on a dark blue background, making them difficult to read.

This should not be fixed with ad-hoc color literals. The badges must use the [[maenifold-desktop]] design system tokens from `apps/desktop/DESIGN.md`, [[shadcn-vue]] primitives, and [[Tailwind CSS]] token utilities backed by `apps/desktop/src/assets/tailwind.css`.

## Evidence

Screenshot: `Screenshot 2026-04-24 at 9.35.47 PM.png`

Visible issue: Progress-column section badges are low-contrast blue-on-dark and do not match the rest of the Gate UI token system.

## Acceptance Criteria

- [ ] Progress-column badges use design-system semantic tokens, not raw hex colors, hardcoded Tailwind palette classes, or one-off Tailwind arbitrary color values.
- [ ] Badge foreground/background contrast meets WCAG 2.1 AA in the default dark theme: 4.5:1 for normal text and 3:1 for large text or non-text chip boundaries.
- [ ] Badge contrast is measured from packaged Electron rendered DOM computed styles, not inferred from token values or screenshots alone.
- [ ] Badge/chip token changes are expressed through `apps/desktop/src/assets/tailwind.css` `@theme` utilities, with no component-level `var()`, `color-mix()`, `<style>` blocks, companion CSS, or `audit-ok`.
- [ ] Badge styling matches existing [[shadcn-vue]] / token conventions for neutral metadata and semantic status without using decorative color.
- [ ] Hover, focus, selected-row, and active states preserve readable contrast.
- [ ] The fix applies to all progress chips in the Gate table, including problem/solution/description/acceptance-criteria/stage markers.
- [ ] Any shared badge/chip helper touched by this fix remains reusable by T-218.41 without duplicating class recipes per view.
- [ ] `npm run lint:design` passes for the desktop app
- [ ] `npm run audit:components` passes for the desktop app
- [ ] Verified in packaged Electron via `agent-browser` CDP with the Gate tab showing multiple progress badge types in default, hover/focus, and selected-row states.
- [ ] CDP evidence screenshots are saved under `outputs/screenshots/sprint-218/T-218.40/`.
