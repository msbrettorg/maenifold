# T-221.0 - ACP-backed Intent Gateway Epic

## Problem

The current MCP surface still exposes more than 100 tools in tools-only clients. Live Copilot CLI testing showed that tools are the reliable contract, while resources, prompts, dynamic discovery, and sampling are client-dependent. Client-side MCP sampling is therefore not a safe dependency for intent routing.

## Decision

Replace the large flat tool surface with a tiny tools-only gateway. Use an internally configured ACP/Jockey resolver for natural-language intent when configured, and expose the deterministic Unifi-style gateway tools side by side as the portable baseline.

Default model for our resolver configuration is `gpt-5.4-mini`. Reasoning level is configurable and must be empirically tested across `none`, `low`, `medium`, `high`, and `xhigh` before a default reasoning level is selected.

## Target Public MCP Tools

The Maenifold MCP server should advertise five baseline public tools, plus one conditional intent tool when a valid resolver is configured:

- `GatewayIndex` - inspect domains, commands, schemas, examples, and safety policy
- `GatewayExecute` - exact deterministic execution of a selected domain command
- `GatewayBatch` - deterministic batch submit/status operations for exact commands
- `ReadMcpResource` - tool-mediated resource read for clients that do not expose native resources
- `GetHelp` - separately exposed human/agent help and usage guidance
- `GatewayIntent` - conditional; resolves natural-language intent into candidates or a safe execution plan only when enabled and backed by a valid configured ACP/Jockey resolver agent

Gate, Maenifold memory/graph/workflows, and upstream gateway servers become indexed domains behind this surface rather than always-advertised flat tools.

## Safety Rules

- Client MCP sampling is not used.
- The ACP resolver may classify and rank commands, but it must not directly execute mutating commands.
- `GatewayIntent` returns candidates for ambiguous requests.
- Mutating or high-trust actions require explicit `GatewayExecute` with validated parameters.
- Resolver execution uses ACP/Jockey with permissions disabled for automatic tool grants.
- If the configured resolver is unavailable, invalid, or returns malformed output, the gateway returns a clear error plus deterministic index/execute instructions.
- No hidden model fallback: if `gpt-5.4-mini` or a configured override cannot be applied, surface the failure and available options.
- If intent is disabled by configuration or no valid ACP resolver agent is configured, `GatewayIntent` is disabled and not advertised in `tools/list`; `GetHelp` and `GatewayIndex` explain how to use the deterministic gateway path and how to enable intent.

## Acceptance Criteria

- [ ] Maenifold MCP tools/list advertises no more than 5 baseline public tools when intent is disabled and no more than 6 public tools when `GatewayIntent` is enabled.
- [ ] `GetHelp` remains separately exposed outside the routed gateway catalog.
- [ ] Gate and Maenifold capabilities are discoverable through `GatewayIndex`, not as 100+ flat tools.
- [ ] Exact execution through `GatewayExecute` covers all routed domains with validated schemas.
- [ ] Exact batch execution and status inspection through `GatewayBatch` covers deterministic, non-intent command batches.
- [ ] `GatewayIntent` uses the configured ACP/Jockey resolver when available and is disabled when intent is off or no valid resolver agent is configured.
- [ ] Resolver default model is `gpt-5.4-mini` and model override is configurable.
- [ ] Reasoning-level experiment covers `none`, `low`, `medium`, `high`, and `xhigh`.
- [ ] No client MCP sampling dependency remains in intent routing.
- [ ] Deterministic index/execute works when the resolver is disabled or unavailable.
- [ ] Mutating commands require explicit exact execution and are never auto-executed from `GatewayIntent`.
- [ ] Gateway catalog, schema validation, resource routing, batch state, and compatibility harnesses reuse existing in-repo registries/components and add no new runtime dependency unless a task-specific PM-approved spec justifies it.
- [ ] `cargo build --release -p maenifold-cli` succeeds.
