# T-238.29 — ACP WebSocket endpoint has zero authentication

## Problem

`/mcp` requires bearer tokens for authentication. `/api/acp/session` (the ACP WebSocket endpoint) has no auth middleware at all. This is the most sensitive transport — it provides full agent execution capabilities — and it's wide open.

## Evidence

Red-team finding from sprint 238 wave audit. Code inspection of HTTP routes shows no auth middleware on the ACP WebSocket upgrade handler.

## Acceptance criteria

- [ ] ACP WebSocket endpoint requires authentication (bearer token or equivalent).
- [ ] Unauthenticated WebSocket upgrade requests are rejected with 401.
- [ ] Authenticated ACP sessions continue to function.

## Verification

- `curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/acp/session` without auth → 401
- ACP session with valid auth → functional
