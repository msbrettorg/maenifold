# T-57.1 — Workflow Runner

## Context

The bash script `maenifold-acp` drives workflow sessions step-by-step: start a workflow session via the Workflow MCP tool, create an acpx session for conversation continuity, then loop — get current step, send to agent, advance workflow — until terminal (`✅` or `❌`).

The Rust pipeline executor (`executor.rs`) calls `AcpxDriver::prompt()` once per pipeline node with no step loop. This must be replaced with an active workflow runner that drives steps like the bash script does.

## Requirements

Create `crates/maenifold-core/src/workflow/runner.rs` with:

### `pub async fn run_workflow(context, workflow_id, agent, prompt) -> Result<WorkflowResult>`

1. **Start workflow session**: Call the existing `workflow::workflow()` handler with `{workflowId: workflow_id}`. Parse the response to extract the `session_id` (format: `workflow-{timestamp}`) and the first step text.

2. **Create acpx session**: Call `AcpxDriver::create_session(&session_id)` for conversation continuity across steps.

3. **Step loop**: Repeat until the step text starts with `✅` or `❌`:
   a. Call `AcpxDriver::prompt(&session_id, &format!("{prompt}\n{step_text}"))` to get the agent's response.
   b. Parse step numbers (current/total) from the step text (`Step N/M` pattern).
   c. If on last step (`cur == total`): advance with `status: completed` + `conclusion: response.text`.
   d. Otherwise: advance with `response: response.text`.
   e. Parse the next step text from the advance response.

4. **Return** `WorkflowResult { session_id, conclusion, steps_completed, status }`.

5. **Error handling**: If `AcpxDriver::prompt()` fails, return the error. Do NOT silently continue. The caller (executor or CLI) decides whether to abandon.

### `pub struct WorkflowResult`

```rust
pub struct WorkflowResult {
    pub session_id: String,
    pub conclusion: Option<String>,
    pub steps_completed: u32,
    pub status: WorkflowRunStatus, // Completed, Failed, Cancelled
}
```

### Integration points

- Call `workflow::workflow(context, payload)` directly — same function the MCP Workflow tool uses.
- Call `AcpxDriver::create_session()`, `prompt()`, `cancel()` — already implemented.
- Register module in `crates/maenifold-core/src/workflow/mod.rs`.

### What this does NOT include

- SequentialThinking submachine support (T-57.3)
- Pipeline executor wiring (T-57.4)
- CLI subcommands (T-57.5)

## Test Strategy

Integration tests using `AcpxDriver::new_for_tests()` and a mock workflow session. Tests:
1. Happy path: 3-step workflow completes with conclusion
2. Agent error on step 2: returns error, doesn't silently continue
3. Terminal step detection: `✅` prefix stops the loop
4. Session lifecycle: `create_session` called before first prompt, session name matches workflow session ID

## Acceptance Criteria

- [ ] `run_workflow()` drives a workflow step-by-step like the bash `run_workflow()` function
- [ ] acpx session created before first prompt for conversation continuity
- [ ] Step text parsed correctly to extract current/total step numbers
- [ ] Workflow advanced after each agent response via the Workflow tool handler
- [ ] Terminal condition (`✅`/`❌`) detected and loop exits
- [ ] All tests pass, no warnings
- [ ] Module registered in `workflow/mod.rs`
- [ ] Under 200 LOC
