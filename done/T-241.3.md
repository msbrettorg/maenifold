# T-241.3 — Teams monitor does not respond to @maenifold messages in self-chat

**Pipeline**: sdd

## Problem

User sends `@maenifold hi` in Teams self-chat (48:notes) and gets no response. The Teams monitor has been extensively refactored this iteration (~3,500 LOC of new code across 15 modules), but the end-to-end flow has not been verified with a live Teams connection.

## Possible Causes

1. **Trouter WebSocket not connecting** — token may be expired/invalid, trouter gateway URL wrong, or auth flow broken
2. **Message handler not matching** — keyword matching config may not include "maenifold" or the keyword format changed
3. **Dispatch not wiring through** — the new dispatch_store, prompt_queue, or session_registry modules may have broken the supervisor's dispatch path
4. **Reply not sending** — reply.rs may fail silently against chatsvc, or the region probe may not find the right endpoint
5. **Monitor not enabled** — TeamsMonitorConfig may not be enabled in the user's maenifold.json
6. **New code dead_code annotations** — several new modules have `#![allow(dead_code)]` because they're not wired into the live path yet (commands.rs, command_exec.rs, prompt_queue.rs, session_registry.rs)

## Investigation Steps

1. Check Teams monitor status via MCP: `teams://status` resource or TeamsMonitor tool with `status` action
2. Check if trouter is connected (connectionState should be "connected")
3. Check logs for incoming message events
4. Check if keyword matching fires
5. Check if dispatch is attempted
6. Check if reply is sent

## Acceptance Criteria

- [ ] `@maenifold hi` in Teams self-chat gets a response
- [ ] Teams monitor status shows connected
- [ ] End-to-end flow verified: message received → keyword match → dispatch → reply sent
