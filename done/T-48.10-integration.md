# T-48.10 — Integration: Mount WorkflowTreeView in UI

**Requirement:** FR-48
**Component:** `vendor/acp-ui/src/`

## Summary

Wire the WorkflowTreeView into the existing UI so users can view workflow execution trees.

## Acceptance Criteria

1. Add a "Workflow" button/link in the sidebar or session list that opens a workflow tree view
2. WorkflowTreeView renders in the main content area (replacing or alongside ChatView)
3. The golden test case URI is hardcoded as a default/demo: `memory://thinking/workflow/2026/03/17/workflow-1773720937011`
4. Later: workflow sessions from RecentActivity should be browsable (but not required for this spec)
5. The existing chat functionality is not broken
6. Build passes: `bun run build`

## Integration Options (SWE chooses)

- Option A: New "Workflows" tab/section in sidebar that lists recent workflow sessions
- Option B: Render WorkflowTreeView when a workflow URI is passed as a prop to the main content area
- Option C: Dedicated route if vue-router exists

## Scoped Tests

- `cd vendor/acp-ui && npx vue-tsc --noEmit`
- `cd vendor/acp-ui && bun run build`

## Files

- `vendor/acp-ui/src/App.vue` or `vendor/acp-ui/src/components/ChatView.vue`
- Possibly `vendor/acp-ui/src/stores/session.ts`

## SWE Remediation

### Changes Made

**`vendor/acp-ui/src/App.vue`** — sole file modified.

1. **Import**: Added `import WorkflowTreeView from './components/WorkflowTreeView.vue'` alongside other component imports.

2. **Constant**: Added `const GOLDEN_WORKFLOW_URI = 'memory://thinking/workflow/2026/03/17/workflow-1773720937011'` near the top of the script setup block.

3. **State**: Added `const showWorkflows = ref(false)` to track toggle state.

4. **Sidebar button** (Option A): Added a new `<div class="section">` below the SessionList section containing a `🌳 Workflows` toggle button with `.active` class when workflows are shown.

5. **Main content routing**: Updated the `v-if`/`v-else-if`/`v-else` chain in the main content area:
   - `ChatView`: shown only when `isConnected && !showWorkflows` (chat functionality preserved)
   - `WorkflowTreeView`: shown in a `.workflow-panel` wrapper (with header + close button) when `showWorkflows` is true — hardcoded with `GOLDEN_WORKFLOW_URI`
   - Welcome screen: shown otherwise (no connection, no workflow panel)

6. **CSS**: Added scoped styles for `.workflows-btn`, `.workflows-btn.active`, `.workflow-panel`, `.workflow-panel-header`, `.workflow-panel-body`, `.workflow-close-btn`.

### Decisions

- **Option A** was chosen (sidebar toggle button) as the simplest approach with no routing changes and minimal surface area.
- The close button in the workflow panel header (×) also dismisses the view, providing two ways to toggle.
- Chat is preserved: the `!showWorkflows` guard on `ChatView` ensures that opening workflows does not break an active session — switching back restores the chat.
- No store changes were needed; `showWorkflows` is purely local UI state in `App.vue`.
