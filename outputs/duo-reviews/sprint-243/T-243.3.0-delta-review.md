# T-243.3.0 — Pipelines tab delta review

Architect duo review of `T-243.3` (Pipelines UAT). Goal: surface the **delta** between (a) what UAT exercises, (b) what is actually built in `apps/desktop/src/components/Pipeline*.vue` + `stores/pipeline*.ts`, and (c) what a reasonable user expects from a DAG editor (n8n / Zapier / Airflow / GitHub Actions / Temporal).

Inputs read: `T-243.3-pipelines-tab-uat.md`, `outputs/uat/cdp-tab-enumeration.md` (lines 113–176, 588–595, 664), screenshot filenames in `outputs/screenshots/uat-tabs/03-pipelines-*.png`, source under `apps/desktop/src/components/Pipeline*.vue` and `apps/desktop/src/stores/pipeline*.ts`. Note: `outputs/uat/tab-inventory.md` referenced by the prompt does **not exist** on disk; only `cdp-tab-enumeration.md` and `mcp-ui-capabilities.md` are present in `outputs/uat/`. Flagging as a separate gap below.

---

## TL;DR

The most consequential delta is a **discoverability gap, not a capability gap**. The composer already implements add-node, delete-node, connect/disconnect edges, duplicate, edit, palette, right-click context menu, drag, marquee — gated behind a `designMode` flag (`pipeline-design.ts`, `PipelineComposer.vue`). The CDP enumeration completely missed it ("No visible pipeline editing interface"). Either the toggle into design mode is hidden or only fires on the Create flow. UAT will read this as "no editor exists" unless the tester knows to flip the mode.

The next-most-consequential delta is **persistence / save semantics**: no explicit save button, no dirty indicator, no "saving…/saved" affordance, no unsaved-changes prompt on navigation. Auto-save (if it happens) is invisible. The user has no way to know their edit landed.

Then come three smaller-but-real gaps: **resume-from-failed-node is not implemented** (the current `resumePipeline` only resumes polling / paused state, not re-executing from a failed step), **no per-run history view**, and **no cross-tab lineage** to Gate or Knowledge despite both being designed-in mental models elsewhere in the app.

The UAT checklist itself is solid — sections D, E, F, H are the high-leverage walks. Sections C (templates) and G (inspector / semantic zoom) are slightly underspecified.

## What a reasonable user expects that's not on the UAT

These are missing from `T-243.3` but a tester comparing to n8n / Airflow / GHA will ask for them:

1. **Per-node dry-run / "test this step in isolation"** — table-stakes in n8n/Zapier. Not in UAT, not in code.
2. **Pipeline duplication / "save as"** — `duplicateNode` exists for nodes; nothing for whole pipelines.
3. **Pipeline export / import (JSON)** — sharing with a teammate. Not built.
4. **Pipeline scheduling cross-link** — Schedules tab exists; no "schedule this pipeline" affordance from the editor.
5. **Pipeline versioning / diff view** — every comparable tool has at least version history.
6. **Run logs viewer per node** — Airflow-style log pane. Not clearly present.
7. **Variables / env / secrets** — pipelines presumably need parameters; no parameter editor surfaces in UAT.
8. **Branching by condition** — UAT mentions edges (`success`, `always`, `conditional`) per the gateway docs but the editor surface for choosing edge type isn't called out.
9. **Permissions / who-can-run** — unaddressed.
10. **Search across pipelines AND across runs** — flyout searches names only.
