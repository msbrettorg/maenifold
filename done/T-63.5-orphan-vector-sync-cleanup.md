# T-63.5 — Orphan Vector Cleanup in Sync Path

## Problem
`cleanup_orphan_vec_memory_files()` only runs during search queries (in `search_memories()` and `semantic_hybrid_search()`). Users who sync frequently but search rarely accumulate stale vector records for deleted files.

## Requirements
1. Add orphan vector cleanup call in `process_incremental_batch()` in `watchers.rs` after the file sync loop
2. Add orphan vector cleanup call in the full `Sync` tool handler (in `sync/mod.rs`)
3. Orphan detection: after syncing a batch, identify paths that no longer exist on disk
4. Call `cleanup_orphan_vec_memory_files()` with the orphan set
5. The cleanup is a simple `DELETE FROM vec_memory_files WHERE file_path IN (...)` — cheap and safe to call

## Implementation Notes
- `cleanup_orphan_vec_memory_files()` is defined in `search/vector.rs` (line 173)
- It takes `&Connection` and `&BTreeSet<String>` of orphan paths
- The watcher already processes deleted file events — need to collect deleted paths
- In full sync, detect orphans by comparing `vec_memory_files` paths against files on disk
- Consider: in the watcher batch, deleted files show up as `notify::EventKind::Remove` events — capture those

## Files
- `crates/maenifold-core/src/sync/watchers.rs` — add cleanup after batch sync
- `crates/maenifold-core/src/sync/mod.rs` (470 LOC) — add cleanup in full sync handler
- `crates/maenifold-core/src/search/vector.rs` — may need to make `cleanup_orphan_vec_memory_files` `pub` (currently `pub(crate)`)
