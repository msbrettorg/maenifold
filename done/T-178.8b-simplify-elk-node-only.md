# T-178.8b — Simplify ELK: node positioning only, delete edge routing

**Pipeline**: sdd
**Pipeline Digest**: tbd

## Objective

Strip ELK down to node positioning only. Let Vue Flow handle all edge rendering natively. Delete ~200 LOC of hand-rolled edge plumbing that has caused 3 rounds of bug fixes in one sprint.

## Grounding

Duo audit: `memory://reviews/sprint-178-duo-audit-handrolled-ui-design-system-violations`
Decision: ELK for node layout, Vue Flow smoothstep for edges. No `@vue-flow/layout` exists — our ELK integration is necessary for node positioning but edge routing through ELK is the source of repeated failures.

## Changes

### Delete from `useLayout.ts`
- Remove ALL port declarations from ELK nodes (no more `ports[]`, `FIXED_POS`, port coordinates)
- Remove `ACTIVE_PORTS` constant
- Edges: use `sources: [nodeId]`, `targets: [nodeId]` — no port references
- Stop harvesting `edge.sections` / `bendPoints` — don't return `edgePaths` map
- Simplify return type to just `{ nodes: Node[] }` (no edgePaths)

### Delete from `useComposerCanvas.ts`
- Delete `applyElkEdgePaths()` (~10 LOC)
- Delete `annotateEdgeSiblings()` (~17 LOC)
- Delete `clearElkEdgePathsForNode()` (~8 LOC)
- Delete `mergeExistingElkPaths()` (~13 LOC)
- Remove elkPoints references from `syncCanvas()`
- Remove sibling data annotation from edge pipeline

### Delete from `pipeline-composer-edge-utils.ts`
- Delete `elkPointsToSvgPath()` (~42 LOC)
- Delete `elkPointsMidpoint()` (~8 LOC)
- Delete `siblingLaneOffset()` (~27 LOC)
- Simplify `edgePath()` — remove elkPoints branch, use Vue Flow's `getSmoothStepPath()` directly
- Simplify `edgeLabelTransform()` and `edgeIndicatorTransform()` — no more elkPoints midpoint calculation

### Simplify `PipelineNodeCardPorts.vue`
- Keep 4 handles (in-top, out-bottom, in-left, out-right) for Vue Flow edge anchoring
- Remove any ELK-specific port metadata
- Handles are positioned by Vue Flow's own DOM layout — no manual coordinate math

### Edge rendering
- Edges use Vue Flow's built-in `smoothstep` type with `pathOptions: { offset: 20, borderRadius: 12 }`
- Vue Flow computes paths from handle positions automatically
- Direction (LR/TB) still works because handles are shown/hidden per direction

## Acceptance Criteria

1. ELK still positions nodes in DAG layers (LR and TB)
2. Edges render via Vue Flow smoothstep — no custom SVG path code
3. Edges visually connect to node handles (Vue Flow guarantees this)
4. No `elkPoints`, `elkPointsToSvgPath`, `annotateEdgeSiblings`, `siblingLaneOffset` remain
5. `useLayout.ts` return type is `{ nodes: Node[] }` (or equivalent without edgePaths)
6. `npx vue-tsc --noEmit` passes
7. `npm run build` succeeds
8. Net LOC deleted: ~200+
