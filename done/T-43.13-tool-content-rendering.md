# T-43.13: Tool call content rendering (content, diff, terminal)

**Requirement**: Tool-calls + terminals audit gap  
**Priority**: P1  
**Files**: `vendor/acp-ui/src/components/ChatView.vue` (or `ToolCallCard.vue`), `vendor/acp-ui/src/lib/types.ts`

## Acceptance Criteria

1. Tool calls with `content` field must be rendered in the UI. Currently content is stored but never displayed.

2. Render by content type:
   - `{ type: "content", content: { type: "text", text } }` → render as inline markdown
   - `{ type: "diff", path, oldText, newText }` → render as a unified diff view (use a diff library or simple pre-formatted diff)
   - `{ type: "terminal", terminalId }` → render terminal output inline (once terminal subsystem T-43.6 is implemented); show placeholder until then

3. Content should be rendered inside the tool call card/chip, expandable on click.

4. After `terminal/release`, terminal output should continue to be displayed in the tool call card.

## SWE Remediation

### What I changed
- `vendor/acp-ui/src/components/ChatView.vue`
  - Added expandable tool call cards/chips so tool call content renders inline inside each tool entry.
  - Rendered `content` blocks as markdown for `{ type: "content", content: { type: "text", text } }`.
  - Rendered `{ type: "diff" }` blocks as a simple unified diff view with colored add/remove/header lines.
  - Rendered `{ type: "terminal", terminalId }` blocks inline with a placeholder message for the not-yet-implemented terminal subsystem, while preserving any future inline output/status fields on the content block.
  - Re-ran Mermaid rendering when expanding thought/tool content so embedded markdown diagrams still render after expansion.
- `vendor/acp-ui/src/lib/types.ts`
  - Added typed tool-call content block unions for inline content, diff content, terminal content, and unknown fallback blocks.
  - Updated `ToolCallInfo.content` to use the new typed union instead of an untyped array.

### Test results
- **FAIL (pre-existing)**: `cd vendor/acp-ui && bun install && bun run build`
  - Fails in `src/stores/session.ts` with `TS6133: 'mergeSessionsFromAgent' is declared but its value is never read.`
  - This is outside the scope of T-43.13.
- **PASS**: `cd vendor/acp-ui && npx vite build`
  - Verified the updated UI component bundles successfully after the tool-content rendering changes.

### Notes / decisions
- I used a simple built-in unified diff renderer instead of adding a new dependency, which satisfies the spec's “diff library or simple pre-formatted diff” requirement.
- Terminal rendering currently shows a placeholder until T-43.6 lands, but the content is rendered from the stored tool-call content block so it remains visible even if the tool call later transitions through `terminal/release`.

## Red-team Audit

**Verdict: PASS**

All four acceptance criteria verified.

- **Criterion 1 — Tool call `content` field is rendered in the UI**: ✅  
  `ChatView.vue:485–530` — `v-if="hasToolCallContent(tc) && isToolCallExpanded(tc.toolCallId)"` renders a `tool-call-details` div iterating over `tc.content`. `hasToolCallContent` (`ChatView.vue:242–244`) returns true when `toolCall.content?.length > 0`.

- **Criterion 2 — Render by content type (content/diff/terminal)**: ✅  
  - `{ type: "content", content: { type: "text", text } }` → `v-if="isInlineTextContentBlock(block)"` → `v-html="renderMarkdown(block.content.text)"` (`ChatView.vue:494–498`).  
  - `{ type: "diff", path, oldText, newText }` → `v-else-if="isDiffContentBlock(block)"` → unified diff view with per-line `diff-add`/`diff-remove`/`diff-header` spans via `getUnifiedDiffLines()` (`ChatView.vue:499–515`; diff builder `ChatView.vue:347–357`).  
  - `{ type: "terminal", terminalId }` → `v-else-if="isTerminalContentBlock(block)"` → `<TerminalOutputBlock :terminal-id="block.terminalId" />` with terminal label and status (`ChatView.vue:517–527`).  
  - Unknown types → `<pre>{{ formatUnknownToolContent(block) }}</pre>` fallback (`ChatView.vue:529`).

- **Criterion 3 — Content rendered inside tool call card, expandable on click**: ✅  
  `ChatView.vue:468–480` — `<button class="tool-call-summary" :class="{ 'tool-call-expandable': hasToolCallContent(tc) }" @click="hasToolCallContent(tc) && toggleToolCall(tc.toolCallId)">` with chevron ▲/▼. Expansion state tracked in `expandedToolCalls` (`ChatView.vue:31`).

- **Criterion 4 — Terminal output persists after `terminal/release`**: ✅  
  `TerminalOutputBlock.vue` reads `sessionStore.terminalSnapshots[props.terminalId]`. The snapshot carries a `released: boolean` field; the component shows a "released" pill but continues to render `terminal.value?.output` from the persisted snapshot. The SDK-mirrored `terminalSnapshots` ref (`session.ts:218`, `session.ts:698–700`) is never cleared on release — it is only reset on full session disconnect — so output remains visible post-release.
