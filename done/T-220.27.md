# T-220.27 - Remove or Constrain Serde Yaml

## Problem

The workspace still depends on deprecated `serde_yaml`, which pulls `unsafe-libyaml`.

## Evidence

- `Cargo.toml:39`.
- `crates/maenifold-core/Cargo.toml:33`.
- `crates/maenifold-gate/Cargo.toml:26`.
- `crates/maenifold-pipeline-driver/Cargo.toml:13`.
- `Cargo.lock:5738-5749` resolves `serde_yaml 0.9.34+deprecated`.
- Source: `docs/codebase-audit-2026-04-25.md#p2-13`.
- Parent sequential thinking session: `session-1777125506368-62098`.

## Plan

**Approach:** Replace `serde_yaml` with `serde_yml` — a maintained pure-Rust fork using `yaml-rust2` (no unsafe-libyaml, no C FFI). The API is ~95% compatible: same `Value`, `Mapping`, `Number`, `Error` types. Migration is primarily import-path changes.

**Usage census:** 52 source files across 3 crates (maenifold-core: 50, maenifold-pipeline-driver: 1, maenifold-gate: 1). Dominant usage: YAML frontmatter manipulation for markdown session files.

**Implementation (decomposed due to >12 file limit per task):**

Phase 1 — Foundation:
- Add `serde_yml` to workspace Cargo.toml
- Create centralized `yaml.rs` re-export module in maenifold-core (re-exports `serde_yml::{Value, Mapping, Number, from_str, from_value, to_value, to_string, Error}` as `pub use`)
- Update maenifold-gate and maenifold-pipeline-driver Cargo.toml (2 files)
- Migrate the 2 non-core files (gate + pipeline-driver)

Phase 2 — Core migration (2-3 subtasks of ≤12 files each):
- Migrate maenifold-core workflow/pipeline files (25 files) → split into 2 batches
- Migrate remaining maenifold-core files (25 files) → split into 2 batches

Phase 3 — Cleanup:
- Remove `serde_yaml` from all Cargo.toml files
- Run `cargo update` to purge unsafe-libyaml from lockfile
- Verify `cargo build --release -p maenifold-cli` and `cargo build --release -p maenifold-gate`

**Risk:** Low. Only standard `Value`/`Mapping`/`Number`/`from_*`/`to_*` patterns used — no exotic serde_yaml features.

## Acceptance Criteria

- [ ] YAML support uses `serde_yml` (maintained fork, pure-Rust)
- [ ] `unsafe-libyaml` removed from Cargo.lock
- [ ] Centralized re-export module exists for future-proofing
- [ ] All YAML parsing/serialization behaves identically
- [ ] `cargo build --release -p maenifold-cli` succeeds
- [ ] `cargo build --release -p maenifold-gate` succeeds
