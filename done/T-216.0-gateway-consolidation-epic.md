# T-216.0 — Intent-Based Gateway Consolidation Epic

**Pipeline**: sdd
**Priority**: P1

## Problem

maenifold's MCP gateway exposes 174+ flat tools in `tools/list`, burning ~35K tokens of context window before the LLM reads a single user message. Most sessions use <10% of those tools. This makes maenifold expensive and slow as a gateway for external clients.

## Solution

Auto-generate one **hierarchical facade tool per upstream server** at `StdioPool` startup. Each facade accepts `intent` (natural language routing), `command` (exact tool dispatch), `learn` (progressive discovery), and `parameters` (forwarded args). Three-tier progressive disclosure keeps schema loading lazy.

## Prior Art

- **Azure MCP Server**: `consolidated-tools.json` maps 264 tools → 112 intent facades. Hierarchical command router with `intent` + `command` + `learn` + `parameters`. Source: https://github.com/microsoft/mcp
- **Anthropic Code Execution Mode**: Progressive disclosure + data bypass. 98.7% token savings. Source: https://www.anthropic.com/engineering/code-execution-with-mcp
- **Cloudflare Code Mode**: Same pattern validated independently. Source: https://blog.cloudflare.com/code-mode/

## Architecture

```
tools/list returns:
  ~32 native maenifold tools (unchanged)
  ~10 consolidated server facade tools (NEW — one per gateway server)
  Total: ~42 tools (down from 174)

Each facade tool schema:
  intent: string    — "what do you want to do?" (natural language routing)
  command: string   — exact tool name (direct dispatch)
  learn: boolean    — discovery mode (returns tool catalog)
  parameters: object — forwarded to upstream tool
```

## Three-Tier Disclosure

| Tier | Input | Output | Token cost |
|------|-------|--------|------------|
| 0 | `tools/list` | ~10 facades with summaries | ~3K (vs 35K) |
| 1 | `{ learn: true }` | Tool names + descriptions for one server | ~500/server |
| 2 | `{ learn: true, command: "X" }` | Full JSON schema for tool X | ~200/tool |

## Heuristics

- Servers with ≤3 tools: expose flat (no facade)
- Servers already hierarchical (accept command/learn): pass through as-is
- `intent` matching: substring/keyword against tool name + description
- Multiple matches: return candidates, LLM picks
- Zero matches: error + suggest learn=true

## Acceptance Criteria

- [ ] `tools/list` returns ≤50 tools (down from 174+)
- [ ] Any upstream tool callable via `{ command: "tool_name", parameters: {...} }`
- [ ] `learn=true` returns tool catalog for a server
- [ ] `learn=true, command="X"` returns full schema for tool X
- [ ] `intent` routing matches correct tool for unambiguous queries
- [ ] Ambiguous intents return candidate list
- [ ] Native maenifold tools unchanged
- [ ] `cargo build --release -p maenifold-cli` succeeds
