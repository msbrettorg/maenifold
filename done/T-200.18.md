# T-200.18 — MCP dispatch argument parsing tests

## Intent

Add unit tests for the MCP argument parsing utility functions in `mcp/dispatch.rs`. These pure functions are the boundary between MCP JSON arguments and typed Rust structs — type mismatches, missing fields, and null handling must be robust.

## Current Coverage

1 test (`context_from_value_rejects_nonexistent_root`). The `optional_string`, `optional_bool`, `required_string`, and `optional_path` functions are completely untested.

## New Tests

1. `optional_string_returns_some_for_string` — `{"key": "value"}` → `Some("value")`
2. `optional_string_returns_none_for_null` — `{"key": null}` → `None`
3. `optional_string_returns_none_for_missing` — `{}` → `None`
4. `optional_string_rejects_non_string` — `{"key": 42}` → `Err`
5. `optional_bool_returns_some_for_bool` — `{"key": true}` → `Some(true)`
6. `optional_bool_returns_none_for_missing` — `{}` → `None`
7. `optional_bool_rejects_non_bool` — `{"key": "true"}` → `Err`
8. `required_string_returns_value` — `{"key": "value"}` → `Ok("value")`
9. `required_string_rejects_missing` — `{}` → `Err`
10. `call_gate_tool_rejects_unknown_tool` — `call_gate_tool("nonexistent", ...)` → `Err`

## Files

- `crates/maenifold-gate/src/mcp/dispatch.rs` (append to existing #[cfg(test)] mod)

## Acceptance Criteria

1. All new tests pass: `cargo test -p maenifold-gate`
2. No existing tests broken
3. No production code changes — tests only
