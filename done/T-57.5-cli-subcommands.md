# T-57.5 — CLI Subcommands

## Context

The bash script `maenifold-acp` exposes `workflow`, `think`, and `pipeline` subcommands. The `pipeline` subcommand is already handled by the Pipeline MCP tool + supervisor + executor in Rust. The `workflow` and `think` standalone commands have no Rust CLI equivalent.

Users need to be able to run:
```bash
maenifold workflow <workflow-id> <agent> <prompt>
maenifold think <agent> <topic>
```

These replace the bash script's standalone use (not pipeline mode).

## Requirements

Add two CLI subcommands to `crates/maenifold-cli/`:

### `maenifold workflow <workflow-id> <agent> <prompt>`

1. Parse args: `workflow_id` (required), `agent` (required), `prompt` (required).
2. Construct a `ToolContext` from the CLI environment (maenifold root, etc.).
3. Call `runner::run_workflow(context, workflow_id, agent, prompt).await`.
4. Print conclusion to stdout on success.
5. Exit 0 on success, 1 on failure.

### `maenifold think <agent> <topic>`

1. Parse args: `agent` (required), `topic` (required).
2. Construct a `ToolContext`.
3. Call `runner::run_think(context, agent, topic, ThinkOptions::default()).await`.
4. Print conclusion to stdout on success.
5. Exit 0 on success, 1 on failure.

### CLI shape matches bash script

The interface mirrors `maenifold-acp`:
- `maenifold-acp workflow <id> <agent> <prompt>` → `maenifold workflow <id> <agent> <prompt>`
- `maenifold-acp think <agent> <topic>` → `maenifold think <agent> <topic>`

### Integration with existing CLI

Check `crates/maenifold-cli/src/main.rs` for the current clap structure. Add `workflow` and `think` as new subcommands alongside existing ones (`--tool`, `--mcp`, `--http`, `--app`, etc.).
