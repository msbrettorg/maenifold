# T-53.2 — `db.rs` — SQLite Cache Layer

**Requirement**: FR-41 (File-Authoritative Pipeline Gate Cache)
**Component**: `crates/maenifold-gate/src/db.rs`

## Context

The gate CLI treats `gate.db` as a rebuildable performance cache. This module provides all SQLite operations: schema creation, task upsert, work_log insertion, and queries for cross-checking. The `rusqlite` crate is already declared as a dependency.

## Schema

The cache must use the **exact same schema** as the existing `gate.db` (tables: `requirements`, `traceability`, `tasks`, `work_log`). The gate only writes to `tasks` and `work_log` — it does not manage `requirements` or `traceability`.

## Acceptance Criteria

1. Implement `GateDb::open(path: &Path) -> Result<GateDb>` that:
   - Opens (or creates) the SQLite database at `path`
   - Enables WAL mode for concurrent read safety
   - Runs `ensure_schema()` to create tables if they don't exist

2. Implement `GateDb::ensure_schema(&self) -> Result<()>` that:
   - Creates `tasks` and `work_log` tables with `CREATE TABLE IF NOT EXISTS`
   - Creates the same indexes as the existing schema (`idx_tasks_status`, `idx_tasks_requirement`, `idx_work_log_file`)
   - Does NOT drop or alter existing tables — additive only

3. Implement `GateDb::upsert_task(&self, file: &str, title: Option<&str>, requirement: &str, status: &str, location: &str, attempts: i32) -> Result<()>` that:
   - Inserts or replaces the task row (keyed on `file`)
   - Sets `updated_at` to current datetime

4. Implement `GateDb::insert_work_log(&self, file: &str, stage: &str, agent_model: Option<&str>, verdict: Option<&str>, duration_secs: Option<i64>, notes: Option<&str>) -> Result<()>` that:
   - Appends a new work_log entry

5. Implement `GateDb::get_task(&self, file: &str) -> Result<Option<TaskRow>>` that:
   - Returns the task row if it exists, None otherwise
   - `TaskRow` struct with: `file, title, requirement, status, location, attempts`

6. Implement `GateDb::get_all_tasks(&self) -> Result<Vec<TaskRow>>` that:
   - Returns all task rows ordered by file name

7. Implement `GateDb::delete_all_tasks(&self) -> Result<usize>` that:
   - Deletes all rows from `tasks` and `work_log`
   - Returns total rows deleted
   - Used by `sync --rebuild` for clean reconstruction

8. All functions use `anyhow::Result` with descriptive context.

9. Module must be under 200 LOC.

### Notes
**`created_at` reset on upsert**: `INSERT OR REPLACE` is a DELETE + INSERT under the hood. Because `created_at` is not included in the column list of `upsert_task`, SQLite will assign `datetime('now')` as its default on each replace, effectively losing the original creation timestamp. The spec only requires `updated_at` to be set and says nothing about preserving `created_at`, so this is not a spec violation. However, callers should be aware that the `created_at` column reflects the last upsert time, not the original insertion time. If preserving `created_at` becomes a requirement, the fix is to `INSERT … ON CONFLICT(file) DO UPDATE SET … updated_at = datetime('now')` (upsert syntax) rather than `INSERT OR REPLACE`.

**`idx_traceability_requirement` not created**: The live `gate.db` has this index on the `traceability` table. The gate does not manage `traceability`, so the omission is correct per spec.
