## Problem

AppTabBar uses `fixed inset-x-0 top-0 z-20` which forces every sibling to manually clear it with `pt-14`. The sidebar never got that clearance, causing header occlusion. The `fixed` positioning is unjustified — nothing scrolls behind the bar.

## Duo consensus (goldeneye + opus-4.7)

Both agents agree: restructure to column-first flex layout.

## Acceptance Criteria

1. App.vue uses column flex: tab bar at top (normal flow), then row container (sidebar + main)
2. AppTabBar.vue: remove `fixed inset-x-0 top-0 z-20`, add `shrink-0`
3. App.vue: remove `pt-14` from `<main>`
4. All tabs still render correctly below the tab bar
5. `npx vue-tsc --noEmit` passes

## Files

- `apps/desktop/src/App.vue`
- `apps/desktop/src/components/AppTabBar.vue`

## Spec

### App.vue template
```html
<div class="relative box-border flex h-screen flex-col overflow-hidden">
  <AppTabBar v-model="activeTab" />
  <div class="flex min-h-0 flex-1 overflow-hidden">
    <AppSidebar v-if="activeTab === 'agents'" ... />
    <div class="flex min-h-0 min-w-0 flex-1 flex-col overflow-hidden">
      <main class="flex min-h-0 flex-1 flex-col overflow-hidden bg-bg-app">
        ...
      </main>
      <div v-if="showTrafficMonitor" class="shrink-0">...</div>
    </div>
  </div>
  <!-- dialogs at end -->
</div>
```

### AppTabBar.vue nav element
Replace: `fixed inset-x-0 top-0 z-20 flex h-14 items-center border-b border-border-subtle bg-bg-app px-4`
With: `flex h-14 shrink-0 items-center border-b border-border-subtle bg-bg-app px-4`
