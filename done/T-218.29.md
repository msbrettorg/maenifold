# T-218.29 — Schedule MCP Consistency Matrix

## Problem

Schedule tools and resources were implemented separately. The tool layer uses `task_value()` (field: `description`) while resources serialize raw `ScheduledTask` (field: `name`). No test matrix proves these surfaces agree after mutations.

## Scope

Test-focused: add a consistency matrix test suite. If the matrix reveals semantic mismatches between tool and resource responses, document them but do NOT change production schemas in this task (file a follow-up instead).

## Acceptance Criteria

- [ ] Consistency matrix test exercises: create, update fields, update `enabled=true/false`, run_now, delete
- [ ] After each mutation, compare semantic task identity across: Schedule tool response, Schedule tool get/list, `schedule://job/{id}`, `schedule://jobs`
- [ ] Comparison explicitly normalizes known schema differences (tool `description` vs resource `name`) and documents which fields diverge
- [ ] `schedule://job/{missing_id}` and `schedule://logs/{missing_id}` return MCP `resource_not_found` without filesystem paths
- [ ] Logs matrix compares Schedule `logs` tool with `schedule://logs/{id}` and verifies both stay within documented bounds (64 KiB per file, 256 KiB total)
- [ ] Tests use only `enabled: false` tasks to avoid OS scheduler side effects, or use `ScheduleStore` directly where OS sync would trigger
- [ ] `cargo build --release -p maenifold-core` succeeds
- [ ] `cargo test -p maenifold-core -- schedule` succeeds

## Files Likely Touched

- New: `crates/maenifold-core/src/mcp/resources/schedule_consistency_tests.rs` — main test matrix
- `crates/maenifold-core/src/mcp/resources/mod.rs` — add test module if needed
- Possibly minor fixes if missing-ID errors leak filesystem paths
