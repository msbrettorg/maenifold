## Problem

During a requested gate sync inside a Copilot ACP session, the PM attempted the documented CLI fallback command:

```bash
gate sync --root . --rebuild
```

The command failed with:

```text
bash: gate: command not found
```

This was not a missing gate install or a repo setup problem. Inspection of the ACP terminal environment showed:

```text
SHELL=/bin/zsh
PATH=/usr/bin:/bin:/usr/sbin:/sbin
```

while the operator-level gate command exists:

```text
/usr/local/bin/gate -> /Users/brett/src/ma-collective/maenifold-rs/target/release/gate
```

The failure is therefore in Copilot's ACP terminal/session environment inheritance: the terminal session exposed to the agent is not inheriting the operator PATH that includes `/usr/local/bin`.

ACP grounding:

- `references/terminals.md` says terminal methods "allow Agents to execute shell commands within the Client's environment."
- `references/session-setup.md` says the session `cwd` "MUST be used for the session regardless of where the Agent subprocess was spawned."
- `references/initialization.md` says clients advertise terminal capability through `clientCapabilities.terminal`.

If the ACP client advertises terminal support but spawns terminal commands with a stripped system PATH, PM operations observe a materially different environment than the operator shell.

## Scope Notes

- Investigate how Copilot's ACP session creates terminal subprocesses and whether it intentionally sanitizes PATH.
- Ensure ACP terminal sessions inherit, reconstruct, or explicitly document the operator command environment needed for developer tools installed under `/usr/local/bin` and equivalent platform paths.
- Do not treat this as a gate install issue; `/usr/local/bin/gate` already exists.
- Do not change gate task lifecycle semantics.
- Do not weaken the MCP-first dogfooding requirement; this task only covers the CLI fallback availability path once fallback is explicitly tracked.

## Acceptance Criteria

- [ ] In a Copilot ACP session, `command -v gate` resolves the same operator-installed gate binary visible at `/usr/local/bin/gate`.
- [ ] `gate sync --root . --rebuild` succeeds in the ACP terminal without requiring a repo-local `./target/release/gate` fallback.
- [ ] If PATH sanitization is intentional, the ACP/Copilot docs explicitly state the restricted terminal PATH and the supported mechanism for adding operator tool paths.
- [ ] Diagnostics distinguish ACP terminal environment inheritance failures from missing gate installation or gate runtime failures.
- [ ] The documented fallback path remains subordinate to gateway-domain MCP access.
