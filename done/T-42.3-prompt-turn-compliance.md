# T-42.3: Prompt Turn Compliance

**Requirement**: FR-42.3  
**Priority**: P0  
**Files**: `vendor/acp-ui/src/stores/session.ts`

## Acceptance Criteria

1. In `cancelOperation()` (~L708), BEFORE sending the cancel notification:
   - Call `cancelPermission()` if `pendingPermission.value` is truthy (or if the bridge has a pending permission promise). This is a MUST per spec — without it, agents deadlock.
   - Iterate `toolCalls.value` map and set `status = 'cancelled'` for any entry with status `'pending'` or `'in_progress'`. Also propagate into matching entries in `messages.value[].toolCalls[]`.

2. After `sendPrompt` returns, branch on `response.stopReason`:
   - `'refusal'` → set a visible error/warning in the UI (e.g., `error.value = 'Agent refused the request'`)
   - `'max_tokens'` → show a truncation notice
   - `'max_turn_requests'` → show a notice about turn limit reached
   - `'end_turn'` and `'cancelled'` → no additional action

## Spec References

- https://agentclientprotocol.com/protocol/prompt-turn
- Audit findings: REQ-13 (MUST cancel pending permissions), REQ-12 (SHOULD cancel tool calls), REQ-10 (stopReason)

## SWE Remediation

- What you changed
  - `vendor/acp-ui/src/stores/session.ts`: added a `pushSystemMessage()` helper for visible system notices, added `cancelPendingToolCalls()` to mark in-flight tool calls as `cancelled` in both the global `toolCalls` map and mirrored `messages[].toolCalls`, updated `sendPrompt()` to react to `stopReason` values (`refusal`, `max_tokens`, `max_turn_requests`), and updated `cancelOperation()` to cancel pending permissions before notifying the ACP session cancellation.

- Test results
  - `cd vendor/acp-ui && npx vue-tsc --noEmit` → **fail**
    - Pre-existing typecheck errors outside this spec remain in `src/App.vue` (`sessionStore.setError` missing), `src/lib/acp-bridge.ts` (location/nullability mismatches), and an existing `initResponse.agentInfo` typing mismatch in `src/stores/session.ts`.

- Notes
  - `cancelOperation()` now checks both the store-level `pendingPermission.value` and `acpClient.pendingPermissionRequest.value` before calling `cancelPermission()` so the pending permission promise is released even if store sync lags behind the bridge.
  - No frontend build or full test suite was run, per instruction.
