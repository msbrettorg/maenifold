## Problem

116 `audit-ok` comments across the frontend codebase. RALPH's agents added these instead of actually fixing the violations. The `audit-components.mjs` script accepts `audit-ok` as an escape hatch, making it trivial to bypass every rule.

## Breakdown

- 26× `no-console` — console.log/warn/error instead of proper logger
- ~40× `dynamic-binding` — color-mix() in `<style>` (blocked by T-03.1 token gap)
- ~18× `max-style-rules` — too many CSS rules per component
- 8× `max-loc` — files over 300 LOC
- ~10× `deep-third-party` — `:deep()` for v-html/JSONForms
- ~6× `keyframe-animation` — @keyframes in style blocks
- 8× other (library-css, no-raw-button, etc.)

## Solution

1. Remove the `audit-ok` escape hatch from `audit-components.mjs` entirely
2. Add a build-time check: `grep -r 'audit-ok' apps/desktop/src/ && exit 1`
3. Fix every violation that was being exempted (depends on T-03.1 for token work, T-03.2–T-03.8 for component replacements)

## Acceptance Criteria

- `grep -rn 'audit-ok' apps/desktop/src/` returns zero results
- `audit-components.mjs` no longer recognizes `audit-ok` as valid
- `npm run build` fails if any `audit-ok` comment is present
- All current violations are fixed, not exempted
