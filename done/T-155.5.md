# T-155.5 — Sessions list broken

## Problem

1. The sessions list in the sidebar (bottom left, under "SESSIONS") shows "No saved sessions yet" even after creating sessions via New Session
2. Close/delete session actions are missing — no way to remove sessions from the list

## Likely cause

The session persistence layer (`useSessionPersistence` composable) was wired to the old Electron daemon on port 19760 which spawned its own maenifold process. Now that the Electron app connects to the launchd service on port 8080, the persistence API endpoints may not exist on that service, or the `daemon:restart` IPC handler removal may have broken the session save/load flow.

Also possible: the `savedSessions` store was backed by Jockey's session DB which was deleted in the T-155.2 diet. Need to check if `useSessionPersistence` calls any of the deleted Jockey DB endpoints.

## What to investigate

1. `apps/desktop/src/composables/useSessionPersistence.ts` — how does it save/load sessions?
2. `apps/desktop/src/stores/session.ts` — `savedSessions`, `resumableSessions`, `deleteSession`
3. Does the persistence layer use localStorage, the daemon API, or Jockey's DB?
4. Is the close/delete UI still present in `SessionList.vue` but the actions broken, or was the UI removed?

## Acceptance Criteria

1. Created sessions appear in the sessions list after creation
2. Sessions persist across app restart
3. Close/delete session buttons visible and functional
4. Session list updates when switching between sessions
