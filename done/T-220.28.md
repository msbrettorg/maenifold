# T-220.28 - Align Reqwest Dependency Stack

## Problem

The Rust dependency graph contains both `reqwest 0.12.28` and `reqwest 0.13.2`, increasing HTTP/TLS audit surface.

## Evidence

- `Cargo.toml:30`, `68`.
- `Cargo.lock:5127-5185` contains both `reqwest 0.12.28` and `0.13.2`.
- Source: `docs/codebase-audit-2026-04-25.md#p2-14`.
- Parent sequential thinking session: `session-1777125506368-62098`.

## Plan

**Approach:** Feature-gate `hf-hub` behind a `model-download` cargo feature. Default builds get a single reqwest (0.13 only). Model download is infrequent (run once per model install) — gating is low-impact.

**Implementation:**

1. In `crates/maenifold-core/Cargo.toml`:
   - Change `hf-hub` from direct dep to `hf-hub = { version = "0.5", features = ["tokio"], optional = true }`
   - Add feature: `model-download = ["dep:hf-hub"]`

2. In `crates/maenifold-core/src/tools/embedding_download.rs`:
   - Wrap the entire module contents in `#[cfg(feature = "model-download")]`
   - Add a `#[cfg(not(feature = "model-download"))]` fallback that returns a clear error: "Model download requires the `model-download` feature. Rebuild with `--features model-download`."

3. In `crates/maenifold-core/src/tools/embedding_models.rs` (or wherever `handle_download` is called):
   - Gate the download action handler with `#[cfg(feature = "model-download")]`
   - Add fallback for the non-feature build

4. In workspace `Cargo.toml`:
   - Add `model-download` feature forwarding to maenifold-core
   - Enable `model-download` by default in `maenifold-cli` so existing builds don't regress

5. Verify:
   - `cargo build --release -p maenifold-cli` (with feature, default)
   - `cargo build --release -p maenifold-core --no-default-features` (without feature, single reqwest)
   - `cargo tree -d | grep reqwest` shows single version without feature

## Acceptance Criteria

- [ ] `hf-hub` is optional, gated behind `model-download` feature
- [ ] Default `maenifold-cli` build still includes model download (no regression)
- [ ] `cargo build --release -p maenifold-core --no-default-features` succeeds without hf-hub
- [ ] `cargo tree -d` shows no avoidable duplicate reqwest versions without the feature
- [ ] Clear error message when download requested without feature enabled
- [ ] `cargo build --release -p maenifold-cli` succeeds
