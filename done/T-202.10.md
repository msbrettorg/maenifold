# T-202.10 — Bug: onboarding model download button calls nonexistent 'download' action

## Problem

The onboarding wizard Model step (`OnboardingStepModel.vue` line 83) calls:

    callTool('EmbeddingModels', { action: 'download', modelId: selectedModel.value.id })

But the `EmbeddingModels` MCP tool only supports two actions: `status` and `list`.

Error: `Unknown EmbeddingModels action 'download'. Available: status, list`

This is another Sprint 201 hallucination — the SWE wrote UI code calling an action that was never implemented in the backend.

## Verified ground truth

- `crates/maenifold-core/src/tools/embedding_models.rs` line 79+ — `embedding_models()` function
- `crates/maenifold-core/src/mcp/schema/embedding_models_params.rs` — `EmbeddingModelsAction` enum has only `Status` and `List`
- No `download` action exists anywhere in the backend

## Impact

Users who reach the Model step (after daemon + agent steps work) cannot download an embedding model. The "Download →" button always fails. The "Download later →" skip button works, but the primary action is broken.

## Fix options

1. **Implement download in the backend** — add a `download` action to `EmbeddingModels` that fetches the ONNX model from HuggingFace. This is real work (HTTP download, progress reporting, file management).

2. **Remove the download button and just show installed models** — if models are managed outside the app (e.g., manually placed in the models directory), the wizard step just shows what's available.

3. **Show a link to the model on HuggingFace** — let the user download manually and place in the models directory. Simple but not SLC.

## Acceptance criteria

1. The Model step does not call a nonexistent action
2. The Model step either successfully downloads a model OR clearly communicates how to get one
3. No error toasts from the download button
4. `npx vue-tsc --noEmit` passes
