## Problem

After T-231.5 lands, we can run multiple UI instances on different CDP ports for parallel UAT. The process needs to be tested live, documented, and reflected in AGENTS.md and ralph/uat.md.

## Approach

1. **Live test first** — PM must actually launch 3+ instances on different ports, connect separate agent-browser sessions, and confirm they work independently without interfering with each other
2. **Document the parallel launch sequence** — update `ralph/uat.md` with the multi-instance launch pattern, port allocation scheme, and any gotchas discovered during live testing
3. **Update AGENTS.md** — reflect the new parallel UAT capability in the constitution's CDP Testing and UI Verification sections
4. **Update uat.sh** — if the script needs changes to support launching/managing multiple instances

## Port Allocation Scheme

Two agent pools share the same machine. They MUST NOT collide on CDP ports:

- **Ralph (dev/test):** CDP ports `9222`+ (9222, 9223, 9224...)
- **UAT:** CDP ports `9330`+ (9330, 9331, 9332...)

This split must be documented in both `ralph/prompt.md` (or equivalent) and `ralph/uat.md` so each agent pool knows its lane. `AGENTS.md` must reflect this as the canonical port allocation.

## Contention Rules to Document

The PM must live-test and then document rules for these contention points between Ralph and UAT running in parallel:

1. **`todo/` writes** — both create gate task files. Different filenames, but `gate sync` rebuilding SQLite could race. Document retry/backoff behavior.
2. **Build outputs** — `apps/desktop/out/` is shared. Who packages, when? Does UAT use a pre-built binary or build its own?
3. **Git staging** — UAT writes `USAGE.md` and `ralph/uat-learnings.md` to the main tree. Ralph's `git add -A` from merge commits could stage UAT's partial writes. Document isolation strategy.
4. **`.gate/gate.db`** — SQLite WAL handles concurrent readers but only one writer. Rapid concurrent `gate sync` calls from both pools could cause busy errors. Document expected behavior.
