# T-202.7 — Add cancel/deprecate command to gate

## Intent

Gate has no way to archive a task that shouldn't be worked on. The only path from `todo/` to `done/` is passing through every stage to terminal. Tasks that are superseded, abandoned, or failed need a clean exit.

## Use case

T-179.34 shipped broken sub-tasks. We want to archive it with an honest record of why it's done — not pass it through red-team and blue-team pretending it succeeded.

## Design

### New command: `gate cancel`

```bash
gate cancel T-179.34 --root . --agent pm --notes "Superseded by T-202.2-T-202.4. Sprint 201 sub-tasks shipped hallucinated UI."
```

Behavior:
1. Appends a canonical `## Cancelled` section to the task file with agent, timestamp, and notes
2. Moves the file from `todo/` to `done/` (same as a terminal pass)
3. Sets a `cancelled: true` field in the task's derived state so `gate status --include-done` can distinguish cancelled vs completed

### MCP tool

Add `cancel` to the MCP surface alongside status/append/pass/fail/sync.

### Task file format example

The cancelled record in the task markdown would look like:

    ## Cancelled
    - Record Kind: cancel
    - Agent: pm
    - Recorded At: 2026-04-20T07:35:00Z
    - Notes: Superseded by T-202.2-T-202.4.

`cancel` is NOT a state transition. It bypasses the state machine entirely — it's an administrative action that says "this task is done, but not because it passed." Any task in any non-terminal state can be cancelled.

### Status display

`gate status` (default) already hides done tasks. `gate status --include-done` should show cancelled tasks with a `cancelled` indicator distinct from `done`.

## Acceptance criteria

1. `gate cancel <task-id> --root . --agent <name> --notes <text>` moves task to `done/`
2. Cancelled section appears in the task markdown
3. `gate sync --rebuild` correctly derives cancelled state
4. `gate status` hides cancelled tasks (same as done)
5. `gate status --include-done` shows cancelled tasks distinctly
6. MCP `cancel` tool works
7. `cargo build --release -p maenifold-gate` succeeds
8. `cargo test -p maenifold-gate` passes
