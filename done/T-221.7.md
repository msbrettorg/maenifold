# T-221.7 - Reasoning-level Experiment Harness

## Problem

The default model should be `gpt-5.4-mini`, but the optimal reasoning level is unknown. We need reproducible evidence across `none`, `low`, `medium`, `high`, and `xhigh`.

## Scope

Build a deterministic experiment harness for the ACP intent resolver:

- Fixture catalog containing Gate, Maenifold, and upstream gateway commands.
- Fixture intents covering clear read, clear mutate, ambiguous, broad, malformed parameters, and adversarial prompt-injection language.
- Run matrix for `none`, `low`, `medium`, `high`, and `xhigh`.
- Record accuracy, ambiguity handling, mutation safety, malformed-output rate, latency, and token/cost proxy if available.
- Write JSON reports to `outputs/intent-resolver/sprint-221/`.
- Commit the selected default reasoning level into `MaenifoldSettings` only after the experiment report identifies a winner.

`none` means omit thought-level config. `xhigh` must be attempted and reported even if the configured runtime rejects it.

## Dependency Policy

The harness must use existing project infrastructure:

- `serde` and `serde_json` for fixtures and reports
- existing Jockey execution path for live resolver runs
- normal Rust test/harness patterns
- existing fixture files or inline fixtures

The harness must not add tokenizer, reporting, benchmarking, statistics, or cost-estimation dependencies unless a later PM-approved spec explicitly justifies the addition. If ACP usage metadata is unavailable, record character counts, prompt size, and latency as proxy fields. Live-model execution must remain separate from deterministic unit tests.

## Acceptance Criteria

- [ ] Harness runs the resolver with `gpt-5.4-mini` for all reasoning levels: `none`, `low`, `medium`, `high`, `xhigh`.
- [ ] Harness records unsupported-level failures as data, not as silent fallback.
- [ ] Fixture set includes at least 30 intents across read, write, ambiguous, broad, and adversarial categories.
- [ ] Mutation safety is scored separately from route accuracy.
- [ ] Adversarial fixtures produce zero mutating execution recommendations across all reasoning levels; any failure blocks default selection.
- [ ] Harness produces a machine-readable JSON report at `outputs/intent-resolver/sprint-221/`.
- [ ] Report recommends a default reasoning level for Maenifold's local configuration.
- [ ] Recommended reasoning level is committed as the default in `MaenifoldSettings`, and defaulting tests are updated.
- [ ] Blue-team can rerun the harness with a single documented command.
- [ ] Harness uses existing `serde`/`serde_json` and Jockey execution infrastructure.
- [ ] Harness does not add tokenizer, reporting, benchmarking, statistics, or cost-estimation dependencies unless separately PM-approved.
- [ ] Live-model experiment execution is separated from deterministic unit tests.
- [ ] `cargo build --release -p maenifold-cli` succeeds.

### Phase 1: Fixtures

**New:** `mcp/gateway_experiment_fixtures.rs`
- 32 intents across 6 categories:
  - 8 clear read (route accuracy + safety=read)
  - 6 clear mutate/write (route accuracy + safety≠read + requiresExactExecute)
  - 6 ambiguous (multiple plausible candidates)
  - 4 broad (underdetermined → low confidence expected)
  - 3 malformed params (routes correctly but flags missing parameters)
  - 5 adversarial (zero mutating candidates required)
- Each fixture: intent string, expected domain, expected command, expected safety class, category label
- Fixtures use actual domains from domain_mapping.rs (maenifold.memory, maenifold.graph, gate, etc.)

### Phase 2: Runner

**New:** `mcp/gateway_experiment.rs`
- `pub(crate) async fn run_experiment(catalog: &GatewayCatalog, settings: &IntentResolverSettings, root: &Path, levels: &[&str]) -> ExperimentReport`
- For each level in [none, low, medium, high, xhigh]:
  - Clone settings, override thought_level
  - Run all 32 fixtures through `resolve_intent()`
  - Record per-intent: route accuracy, safety correctness, confidence, latency (Instant), char counts
  - Record unsupported-level failures as data (ResolverError::AcpError), NOT as silent fallback
- Mutation safety scored separately: adversarial fixtures must produce zero mutating candidates
- Any adversarial failure blocks default level selection
- Output: `ExperimentReport` with per-level metrics and recommended default

### Phase 3: Report Writer

**Part of** `mcp/gateway_experiment.rs`
- Write JSON report to `outputs/intent-resolver/sprint-221/experiment-{timestamp}.json`
- Report includes: per-level accuracy, mutation safety score, latency stats, recommended level
- Use `serde_json` for serialization, `std::fs::create_dir_all` for output dir

### Phase 4: Tests

**New:** `mcp/gateway_experiment_tests.rs`
- Deterministic tests (CI-safe, no live model):
  - Fixture count validation (≥30)
  - Report structure validation with canned outputs
  - Scoring logic: accuracy, safety separation
- Live experiment tests (`#[ignore]`):
  - Full run with configured agent
  - Requires MAENIFOLD_ROOT + configured resolver agent
  - Blue-team rerun: `cargo test -p maenifold-core gateway_experiment -- --ignored --nocapture`

### Phase 5: Apply Default

- After experiment report identifies a winner:
  - Commit recommended level as default in `IntentResolverSettings` thought_level default
  - Update defaulting tests in `gateway_settings_tests.rs`
