# T-221.1 - Tools-only Gateway Surface Contract

## Problem

The current tool surface is still too large for tools-only MCP clients. Before changing implementation, capture a measured baseline and lock the new public contract so later tasks cannot accidentally preserve passthrough or flat first-party exposure.

## Scope

Define the new tools-only public contract:

- `GatewayIndex`
- `GatewayExecute`
- `GatewayBatch`
- `ReadMcpResource`
- `GetHelp`
- `GatewayIntent` only when intent is enabled and backed by a valid configured ACP/Jockey resolver agent

`GetHelp` is the existing in-repo help tool preserved as-is for human/agent guidance. It is not routed under `maenifold.system`, not included in the hard-cut flat-tool removal set, and not reimplemented as a gateway shim.

Inventory current tools/list output by category:

- Native Maenifold tools
- Gate tools
- Gateway upstream tools
- Gateway facade tools
- Passthrough tools
- Resource-mediated tools

For each category, the baseline must record the existing source of truth that owns the capability:

- Native Maenifold: `ToolRegistry` and `crates/maenifold-core/src/mcp/schema/*`
- Gate: `crates/maenifold-gate/src/mcp/*`
- Upstream MCP: `ToolRoutingRegistry`, `StdioPool`, and existing discovery paths
- Resources: `crates/maenifold-core/src/mcp/resources/*` plus T-218.20 ownership/collision rules

## Acceptance Criteria

- [ ] Baseline report records current Maenifold-owned tools/list count and category breakdown.
- [ ] Target public contract is documented in a repo source file or task-linked design note.
- [ ] Target public contract caps `tools/list` at 5 baseline tools when intent is disabled and 6 tools when `GatewayIntent` is enabled.
- [ ] Existing `GetHelp` is preserved as a separately advertised tool outside routed domains and outside the hard-cut flat-tool removal set.
- [ ] Gateway contract identifies the canonical source of truth for each routed domain.
- [ ] Gateway contract forbids duplicated command metadata or schema tables unless they are generated from existing registries.
- [ ] Contract states that first-party Gate and Maenifold operations are routed domains, not permanent flat exceptions.
- [ ] Contract states that resources/prompts/sampling/dynamic discovery are optional client features and cannot be required for core operation.
- [ ] Contract states deterministic `GatewayIndex` + `GatewayExecute` is the portable baseline.
- [ ] Contract states `GatewayBatch` covers deterministic exact-command submit and status operations, not intent-routing paths.
- [ ] Contract states `GatewayIntent` is ACP-backed, optional by configuration, and omitted from `tools/list` when disabled or missing a valid resolver agent.
- [ ] Contract includes explicit handling for mutating commands and ambiguous intents.
- [ ] `cargo build --release -p maenifold-cli` succeeds if runnable code changes.
