# T-224.3 — Wire Bridge to Daemon + E2E Validation

## Problem

With the bridge and React app scaffolded, we need to prove the end-to-end path works: user types in CopilotKit → bridge translates to ACP → daemon processes → response streams back through AG-UI → CopilotKit renders.

## Scope

1. **Start the maenifold daemon** (it should already be running)
2. **Start the bridge** (`npx tsx index.ts`)
3. **Start the React app** (`npm run dev`)
4. **Validate these interactions**:
   - Simple chat: "What is maenifold?" → streaming text response
   - Memory search: "Search for AG-UI in the knowledge graph" → tool call visible, results render
   - Gate status: "What's the current gate status?" → tool call, structured result
   - Multi-turn: Follow-up questions maintain context
   - Error handling: What happens if the daemon is down?

## Acceptance Criteria

- [ ] User types a prompt, response streams token-by-token in CopilotKit UI
- [ ] Tool calls are visible in the chat (tool name, arguments, results)
- [ ] Multi-turn conversation maintains context
- [ ] Responses include content from maenifold's knowledge graph (proving MCP tools work)
- [ ] Bridge logs show ACP events being translated to AG-UI events
- [ ] Screenshot/recording of the working POC captured for comparison
- [ ] README updated with the full launch sequence (daemon → bridge → app)

## Validation Method

Manual testing with screenshots. This is a POC — no automated tests needed. Focus on:
- Latency: How long from submit to first token?
- Quality: Does CopilotKit's rendering look good?
- Fidelity: Are tool results legible?
- Comparison: How does this feel vs the existing Agents tab?
