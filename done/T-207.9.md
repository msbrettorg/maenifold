# T-207.9 — Migrate discovery endpoint to StdioPool

## Problem

`GET /api/discovery/mcp-tools` currently spawns a fresh stdio process for each configured server, runs `initialize` + `tools/list`, then kills the process. This takes up to 60s for slow servers and is the main bottleneck for the pipeline designer UI's tool palette loading.

## Solution

For gateway-enabled servers, the `StdioPool` already has tools cached from eager initialization. The discovery endpoint should read from the pool cache instead of re-spawning.

## Change

### 1. Add `Option<Arc<StdioPool>>` to `ApiState`

`ApiState` (in `crates/maenifold-core/src/api/routes.rs`) needs a reference to the gateway pool. Add:

```rust
pub struct ApiState {
    config: Arc<RwLock<Config>>,
    pub(super) config_manager: ConfigManager,
    pub(super) config_watch: ConfigWatchState,
    pub(crate) gateway_pool: Option<Arc<StdioPool>>,
}
```

Update `ApiState::new()` to accept `Option<Arc<StdioPool>>`, and update the call site in `http.rs` `serve_http_listener_with_shutdown()` to pass the pool through.

### 2. Use pool cache in discovery handler

In `discover_mcp_tools_handler`:

1. For servers with `gateway: true`: read tools from `state.gateway_pool.as_ref().map(|p| p.all_gateway_tools())`. No spawn needed.
2. For servers with `gateway: false` (or HTTP servers): continue with existing spawn-discover-kill pattern in `mcp_discovery::discover_all_mcp_tools()`.
3. Merge both sets into the response.

### 3. Thread pool from http.rs

In `serve_http_listener_with_shutdown()`, the gateway pool is already constructed. Pass the `Arc<StdioPool>` (or None) to `ApiState::new()`.

## Effect

- Gateway-enabled servers return tools instantly (cache read)
- Non-gateway servers use the existing discovery path (no change)
- Pipeline designer UI palette loads in <1s instead of 10-60s for gateway servers

## Key Files

- Modify: `crates/maenifold-core/src/api/routes.rs` (ApiState + discover_mcp_tools_handler)
- Modify: `crates/maenifold-core/src/mcp/http.rs` (pass pool to ApiState::new)
- Modify: `crates/maenifold-core/src/api/mcp_discovery.rs` (accept pre-discovered results)
- Uses: `StdioPool` from T-207.2
