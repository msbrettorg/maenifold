## Problem

The audit performed in sprint 242 (which surfaced T-242.16, T-242.17, T-242.18, T-242.19) was an ad-hoc one-time pass driven by user direction (`User input: "And do we have a gate item to UAT the MCP and CLI tools to update the docs/skills like we are doing?"`, 2026-04-28). There is no recurring task that locks in the cadence, so the same drift will happen again the next time tools are added, removed, or refactored.

The skill files at `assets/integrations/skills/maenifold/SKILL.md` and `assets/integrations/skills/gate/SKILL.md` were rewritten on 2026-04-28 against the **then-live** Gateway catalog. Once a single tool is added, renamed, or moved between domains, those skill files start lying to every agent that loads them. The maenifold skill is the primary onboarding surface for every downstream LLM; stale tool tables there waste tokens and produce wrong invocations.

## Required UAT

Every sprint that touches the gateway, MCP handler, CLI tool registry, or any tool definition must run the following pass before the sprint closes. This task standardizes the procedure so the next sprint can copy it verbatim.

### A. Surface enumeration

1. **Top-level MCP tools**: `tools/list` against `http://127.0.0.1:8080/mcp`. Expect exactly the published seven (`GetHelp`, `ReadMcpResource`, `DiscoverMcpTools`, `GatewayIndex`, `GatewayExecute`, `GatewayBatch`, `GatewayIntent`). Any drift = either a doc update or a P0 escalation.
2. **Gateway domains**: `GatewayIndex` (no args). Expect every native `maenifold.*` domain plus every downstream proxy declared in `maenifold.json`.
3. **CLI tool registry**: `maenifold tool` (no args). Cross-check against the MCP `tools/list` and the Gateway domain commands. **CLI parity is mandatory.** Every domain command exposed via MCP MUST have a matching `maenifold tool <Name>` entry. Gaps = P1 gate items (see T-242.16, T-242.17 for templates).

### B. Per-tool round-trip

For every tool in the registry, exercise both surfaces:

```bash
# CLI
maenifold tool <Name> '{"learn": true}'   # MUST return help text, never a missing-param error
maenifold tool <Name> '<minimal valid payload>'

# MCP
curl -s -X POST http://127.0.0.1:8080/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"<Name>","arguments":{"learn":true}}}'
```

Behavior MUST be byte-identical between the two paths (modulo transport framing).

### C. Downstream proxy + discovery

1. `DiscoverMcpTools` MUST enumerate every server in `maenifold.json` with `status=ok` and a non-empty `tools` array.
2. For each proxied server, run `GatewayIndex parameters={"domain":"<server>"}` and verify the command list matches what `DiscoverMcpTools` reported.
3. Pick one read-safe tool per proxy and run a real round-trip via `GatewayExecute` to verify the proxy connection works end-to-end (e.g. `fetch.fetch` against `https://example.com`).
4. Run `GatewayBatch` with `continueOnError=true` and at least two items spanning two different domains. Confirm both items report `ok`.

### D. Schema drift

For each Gateway domain, run `GatewayIndex parameters={"domain":"<domain>","includeSchemas":true}` and diff the returned schemas against what is documented in the corresponding skill table. Any mismatch is a documentation bug — fix the skill, not the schema.

### E. Skill resync

If A–D surface any drift, update both skill files in the same sprint:

- `assets/integrations/skills/maenifold/SKILL.md` — Domains and Commands tables, Invocation Cheat Sheet, top-level tool list.
- `assets/integrations/skills/gate/SKILL.md` — The Seven Commands table, worked examples.

Use `GatewayIndex … includeSchemas=true` as the source of truth — never infer parameter names from prior skill text.

## Acceptance Criteria

- [ ] Procedure A–E above is recorded in `docs/` (e.g. `docs/parity-uat.md`) so future sprints can run it without re-deriving.
- [ ] `make audit` (or equivalent) runs procedure A and B for every tool, fails the build if any tool is reachable on one surface but missing on the other, and fails if `learn=true` returns a required-param error on any tool.
- [ ] Skill files at `assets/integrations/skills/{maenifold,gate}/SKILL.md` carry a footer noting the date and commit hash they were verified against, so drift is visible in `git blame`.
- [ ] After this task lands, the next sprint that touches any tool/domain/registry must run the UAT and either (a) confirm no drift in gate notes, or (b) update the skill files in the same PR.
