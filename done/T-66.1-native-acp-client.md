# T-66.1: Native Rust ACP Client — Replace acpx Subprocess

## Requirement

FR-ACP: Replace the acpx Node.js subprocess with a native Rust ACP client using the `agent-client-protocol` crate (v0.10). Rip and replace — no migration path, no feature flags, no fallback.

## Background

Current: `AcpxDriver` spawns `acpx` CLI per-action, waits for exit, parses NDJSON stdout. 3 production call sites, ~377 LOC of shell wrapper + parser.

Target: Native `ClientSideConnection` with persistent connections, typed API, capability-aware config, streaming events.

Research: `memory://research/acp-rust-client-implementation-research-replacing-acpx-202607`

## Design

### Architecture — One New File

```
crates/maenifold-core/src/acp/
├── mod.rs          — update: add `pub mod native;`, remove `pub mod driver;`
├── config.rs       — KEEP (agents.json loader)
├── relay.rs        — KEEP (WebSocket relay for UI)

DELETE:
  acp/driver.rs

```

No trait. No pool file. No bridge file. No legacy wrapper. No feature flag.

### New Pipeline Node Parameters

```json
{
  "id": "deep-analysis",
  "type": "sequentialThinking",
  "agent": "OpenCode",
  "model": "claude-sonnet-4.6",
  "thoughtLevel": "high",
  "allowedTools": ["ReadMemory", "SearchMemories"],
  "maxTurns": 20
}
```

Applied via real ACP API methods (not a generic `set_config` shim):
- `model` → `conn.set_session_model(SetSessionModelRequest { session_id, model })`
- `thoughtLevel` → `conn.set_session_config_option(SetSessionConfigOptionRequest { session_id, config_id: "thought_level", value })`
- `allowedTools` / `maxTurns` → same pattern via config options
- Unsupported options logged and skipped (graceful degradation)
