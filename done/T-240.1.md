# T-240.1 - GatewayExecute schema omits required command parameters

**Pipeline**: sdd

## Problem

The live `maenifold` MCP server advertises `GatewayExecute` as the deterministic command execution path, but the registered tool schema exposed to the client does not include the command-specific `parameters` object that `GetHelp(GatewayExecute)` documents as required.

This prevents clients from executing parameterized gateway commands such as `maenifold.gate/gate_Status`, `maenifold.thinking/SequentialThinking`, `maenifold.memory/SearchMemories`, `maenifold.graph/BuildContext`, and upstream MCP commands through the gateway.

## Evidence

- `GatewayIndex` works and lists `maenifold.gate`, `maenifold.thinking`, `maenifold.memory`, and `maenifold.graph` commands with command-specific schemas.
- `GetHelp(GatewayExecute)` documents required parameters: `domain`, `command`, and `parameters`.
- The registered `maenifold-GatewayExecute` tool schema exposed to the client accepts only `domain`, `command`, and optional `idempotencyKey`.
- `GatewayIntent` returned `status=fallback` with `error="gateway intent resolver agent is not configured"`, instructing callers to use `GatewayExecute` explicitly; that explicit path is blocked by the missing schema field.
- Parent sequential thinking session: unavailable because the same `GatewayExecute` schema mismatch blocks `maenifold.thinking/SequentialThinking` invocation through the gateway.

## Expected behavior

- The MCP tool schema for `GatewayExecute` includes the documented `parameters` object.
- `GatewayBatch` supports per-item command parameters if batch execution is intended to invoke parameterized commands.
- The intent resolver either works for safe read-only commands or documentation clearly states it is unavailable and directs users to a working exact execution path.
- Clients can execute `gate_Status`, `SequentialThinking`, `SearchMemories`, `BuildContext`, and `FindSimilarConcepts` through MCP without CLI or filesystem fallback.

## Acceptance criteria

- [ ] `maenifold-GatewayExecute` accepts a command-specific `parameters` object from MCP clients.
- [ ] At least one parameterized read command succeeds through MCP, such as `maenifold.gate/gate_Status`.
- [ ] At least one parameterized orchestration command succeeds through MCP, such as `maenifold.thinking/SequentialThinking`.
- [ ] Gateway docs and client-facing schemas agree on the exact `GatewayExecute` and `GatewayBatch` request shapes.
- [ ] `cargo build --release -p maenifold-cli` succeeds.
