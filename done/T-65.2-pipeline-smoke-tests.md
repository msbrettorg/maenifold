# T-65.2: Pipeline Smoke Test Suite

## Requirement
Verify all pipeline node types (workflow, prompt, sequentialThinking, tool) function correctly end-to-end via the Pipeline MCP tool. This is a manual smoke test document — not integration test code.

## Smoke Tests

### 1. Pipeline CRUD — Create

**Call:** `Pipeline` tool with `definition`

```json
{
  "definition": {
    "nodes": [
      { "id": "fetch", "workflowId": "research" },
      { "id": "analyze", "type": "sequentialThinking", "topic": "Evaluate findings", "agent": "Copilot", "totalThoughts": 3 },
      { "id": "summarize", "type": "prompt", "prompt": "Summarize the analysis", "agent": "Copilot" },
      { "id": "store", "type": "tool", "toolName": "WriteMemory", "toolArgs": { "title": "smoke-test-result", "content": "[[smoke-test]] result" } }
    ],
    "edges": [
      { "source": "fetch", "target": "analyze", "type": "success" },
      { "source": "analyze", "target": "summarize", "type": "success" },
      { "source": "summarize", "target": "store", "type": "success" }
    ]
  }
}
```

**Verify:**
- Response contains `pipelineId` matching `pipeline-{timestamp}` format
- Response contains 4 nodes, each with `nodeId`, `sessionId`
- Each `sessionId` matches `workflow-{timestamp}-{nodeId}` format
- Node IDs in response match input: `fetch`, `analyze`, `summarize`, `store`
- Status is `pending` for all nodes

**Verify files created in memory:**
- `memory://thinking/workflow/{date}/workflow-{ts}-fetch` exists
- `memory://thinking/workflow/{date}/workflow-{ts}-analyze` exists
- `memory://thinking/workflow/{date}/workflow-{ts}-summarize` exists
- `memory://thinking/workflow/{date}/workflow-{ts}-store` exists
- Each file has correct frontmatter: `pipelineId`, `nodeId`, `workflowId`
- `workflowId` for workflow node = `research`
- `workflowId` for prompt node = `__prompt__`
- `workflowId` for sequentialThinking node = `__sequentialThinking__`
- `workflowId` for tool node = `__tool__`

### 2. Pipeline CRUD — View

**Call:** `Pipeline` tool with `sessionId`, `view: true`

**Verify:**
- Returns full pipeline state with all 4 nodes
- Edges match definition
- Mermaid diagram is valid
- `ready` list contains root node(s) with no upstream dependencies
- `status` is correct for each node

### 3. Pipeline CRUD — Dispatch

**Call:** `Pipeline` tool with `sessionId`, `dispatch: true`

**Verify:**
- Root node(s) move to `active` status
- `ready` list is updated
- Response shows which nodes were dispatched

### 4. Pipeline CRUD — Node Completion

**Call:** `Pipeline` tool with `sessionId`, `nodeId`, `status: "completed"`, `conclusion`

**Verify:**
- Node status transitions to `completed`
- Downstream nodes become `ready`
- Output/conclusion is stored in node state

### 5. Pipeline CRUD — Rewind

**Call:** `Pipeline` tool with `sessionId`, `rewind: { "nodeIds": ["analyze"] }`

**Verify:**
- Target node resets to `pending`
- All downstream nodes also reset
- New session IDs allocated for rewound nodes
- Old session files preserved (not deleted)

### 6. Pipeline CRUD — Graft

**Call:** `Pipeline` tool with `sessionId`, `graft` adding a new node

```json
{
  "graft": {
    "nodes": [
      { "id": "review", "type": "prompt", "prompt": "Review the summary", "agent": "Copilot" }
    ],
    "edges": [
      { "source": "summarize", "target": "review", "type": "success" }
    ]
  }
}
```

**Verify:**
- New node appears in pipeline state
- New edge connects to existing node
- New node has allocated session file in memory
- Pipeline view shows updated graph

### 7. Pipeline CRUD — Cancel

**Call:** `Pipeline` tool with `sessionId`, `cancel: true`

**Verify:**
- Pipeline status transitions to `cancelled`
- Active nodes are abandoned
- No new nodes can be dispatched

### 8. Pipeline CRUD — Delete

**Call:** `Pipeline` tool with `sessionId`, `delete: true`

**Verify:**
- Pipeline session file removed from memory
- All node workflow session files removed
- Pipeline no longer appears in `list`

### 9. Pipeline CRUD — List

**Call:** `Pipeline` tool with `list: true`

**Verify:**
- Returns all pipeline sessions with status summaries
- Shows node counts and completion percentages

### 10. SequentialThinking Node — Thought Adjustment

Create a pipeline with a sequentialThinking node set to `totalThoughts: 3`.

**Verify during execution:**
- Agent can set `needsMoreThoughts: true` to extend beyond the initial 3
- Agent can revise earlier thoughts with `isRevision: true`
- Each thought is persisted to the sequential session file under `memory://thinking/sequential/{date}/session-{ts}-{suffix}`
- The sequential session file contains all thoughts as H2 sections

### 11. SequentialThinking Node — Confession

**Verify on completion:**
- Final thought includes a `conclusion` (confession report)
- Confession is stored as the node's `output` in pipeline state
- Sequential session file is finalized with correct status
- Pipeline can read the thinking trace via the node's actual sequential session ID (not the wrapper workflow session ID)

### 12. SequentialThinking Node — Session Linkage

**Verify:**
- The pipeline node state contains a reference to the actual `session-{ts}-{suffix}` sequential session
- The sequential session file's frontmatter links back to the pipeline via `parentWorkflowId` or `pipelineId`
- `pipeline view` can retrieve and display the thinking trace

### 13. Prompt Node — Execution

**Verify:**
- Prompt is assembled with predecessor context from upstream nodes
- Agent response is stored as node `output`
- Assembled prompt (with injected context) is visible in pipeline view

### 14. Tool Node — Execution

**Verify:**
- Tool is invoked with the specified `toolName` and `toolArgs`
- Tool result is stored as node `output`
- Edge mapping (if any) correctly passes upstream output into tool args

### 15. Naming Convention Audit

**Verify across all operations:**
- Pipeline IDs: `pipeline-{timestamp_millis}`
- Node IDs: caller-provided, semantic, stable (e.g. `fetch`, `analyze`, not `prompt-{uuid}`)
- Node session IDs: `workflow-{timestamp_millis}-{nodeId}`
- Sequential session IDs: `session-{timestamp_millis}-{suffix}`
- URIs: `memory://thinking/workflow/{YYYY}/{MM}/{DD}/{sessionId}`
- Sequential URIs: `memory://thinking/sequential/{YYYY}/{MM}/{DD}/{sessionId}`

## Acceptance Criteria

- All 15 smoke tests pass
- No orphaned session files after pipeline lifecycle
- Sequential thinking traces are accessible from pipeline view
- Thought adjustment (needsMoreThoughts) works during pipeline execution
- Every pipeline operation produces correctly-named files in the expected memory locations
