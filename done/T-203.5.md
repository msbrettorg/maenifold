# T-203.5 — Security hardening: CSP + permission consent

## Problem

MCP Apps run untrusted HTML from third-party servers in our Electron app. The security model requires:
- CSP enforcement per `_meta.ui.csp` — controls what external origins the app can load
- Permission gating per `_meta.ui.permissions` — camera, mic, clipboard, etc.
- Tool call scope restriction — app should only call tools on its own server, not all connected servers

## Fix

1. **CSP enforcement**: AppBridge applies CSP from `_meta.ui.csp`. Verify this works in Electron. If not, apply CSP via iframe `csp` attribute or `<meta>` injection.
2. **Permission consent UI**: When an app requests permissions (camera, mic), show a consent dialog before granting. Follow the same pattern as existing `PermissionEntry.vue` for ACP permissions.
3. **Tool call scope**: When proxying `tools/call` from app → host, restrict to tools registered by the same MCP server that served the app. Prevent cross-server tool calls.
4. **Default deny**: If `_meta.ui.csp` is absent, apply a restrictive default (no external loads). If `_meta.ui.permissions` is absent, grant none.

## Files

- `apps/desktop/src/components/McpAppFrame.vue` (CSP application)
- `apps/desktop/src/components/McpAppPermissionDialog.vue` (new, if needed)
- Electron main process CSP config (if Electron-level changes needed)

## Acceptance criteria

1. Apps cannot load external resources not in their CSP
2. Permission requests show user consent before granting
3. Apps cannot call tools on unrelated MCP servers
4. Default-deny when `_meta.ui` metadata is incomplete
5. No Electron security warnings in console
