# T-178.3a — graph:// URIs — corpus snapshot, communities, stats

## Intent

With subscription plumbing landed in [[T-178.2]], expose maenifold's coarse-grained graph state as canonical MCP resources. This slice covers the three "whole-corpus" reads that are read-mostly and updated on sync / cluster boundaries — the foundation for any dashboard backdrop. Concept-template reads land in [[T-178.3b]]; high-frequency activity stream lands in [[T-178.3c]].

Constitutional fit: "AI is the new UI — our UI uses MCP."

## Scope

1. Define and register three resources in `crates/maenifold-core/src/mcp/resources.rs`:

   | URI | Read returns | Updated when |
   |---|---|---|
   | `graph://corpus/snapshot` | `{ nodes: [{name, weight?}], edges: [{source, target, weight}], generated_at }` (full weighted graph) | `Sync` completion |
   | `graph://corpus/communities` | `{ communities: [{id, members:[name], size}], edges: [{source, target, weight}], generated_at }` (Louvain output). **Top-level key is `communities`, not `nodes`.** | Re-clustering completes |
   | `graph://stats` | `{ node_count, edge_count, community_count, signals_per_sec, last_sync_at, last_cluster_at }` | Sync, cluster, periodic tick (≤ 1Hz) |

2. **Frozen JSON shapes** — these payload schemas are part of this task's contract. Document them in `assets/help/resources/graph.md`. Downstream T-178.3b / T-178.3c / T-178.4 / T-178.5 consume them; do not change them mid-sprint without updating those tasks.

3. Reuse existing data sources — do not rebuild graph traversal logic:
   - `corpus/snapshot` → `api::graph::get_nodes` + `api::graph::get_edges`, lifted into the resource handler.
   - `corpus/communities` → existing endophasia / community module output.
   - `stats` → cached counters updated by sync / cluster / signal hooks.

4. Wire emitters at change points:
   - Sync completion → `notify_resource_updated("graph://corpus/snapshot"); notify_resource_updated("graph://stats")`
   - Cluster completion → `notify_resource_updated("graph://corpus/communities"); notify_resource_updated("graph://stats")`
   - Signal pipeline updates `signals_per_sec` ⇒ at most one `graph://stats` notification per second (use the throttling primitive from [[T-178.3c]] if landed; otherwise a local 1s coalescer here, refactor when 3c lands).

5. Cold-read paths: each `resources/read` returns the freshest available snapshot synchronously. `corpus/snapshot` and `corpus/communities` may be cached server-side and invalidated on the same hooks that fire notifications.

6. `resources/list` includes the three URIs with names, descriptions, and `mimeType: "application/json"`.

7. Tests:
   - `resources/read` on each URI returns the documented JSON shape against a small fixture corpus.
   - Sync hook fires → exactly one notification on `graph://corpus/snapshot` and one on `graph://stats`.
   - Cluster hook fires → exactly one notification on `graph://corpus/communities` and one on `graph://stats`.
   - `corpus/communities` payload's top-level key is verified to be `communities` (regression guard against future drift to `nodes`).

1. `cargo test -p maenifold-core` passes.
2. `resources/list` returns the three URIs with documented metadata.
3. Reading each URI returns the documented JSON shape.

6. Help doc `assets/help/resources/graph.md` documents the three URIs, their shapes, and update cadence.
