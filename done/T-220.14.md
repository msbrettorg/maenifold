# T-220.14 — Route Knowledge Graph UI Through MCP

## Problem

The knowledge graph UI fetches graph topology through direct daemon REST endpoints (`/api/graph/communities`, `/api/graph/communities/{id}/concepts`) instead of the shared MCP boundary. This violates the "AI is the new UI" tenet — agents can't access graph topology through MCP.

## Shape Mismatch (duo feedback)

The existing MCP resource `graph://corpus/communities` has the WRONG SHAPE for the UI:

**MCP resource returns** (`graph_corpus.rs`):
```json
{
  "communities": [{"id": 1, "members": ["concept-a", "concept-b"], "size": 2}],
  "edges": [{"source_name": "x", "target_name": "y", "weight": 5}]
}
```

**UI expects** (`graph-types.ts`):
```json
{
  "nodes": [{"id": 1, "anchor": "concept-a", "size": 2}],
  "edges": [{"source": 1, "target": 2, "weight": 5}]
}
```

And there is NO MCP equivalent for `/api/graph/communities/{id}/concepts`.

## Design

### New MCP resource: `graph://community/{id}`

Returns per-community concept graph matching the UI's `ConceptGraph` shape:
```json
{
  "communityId": 1,
  "anchor": "primary-concept",
  "nodes": [{"name": "concept-a", "occurrences": 5}],
  "edges": [{"source": "concept-a", "target": "concept-b", "weight": 3}]
}
```

Implementation: delegate to existing `api::graph::get_community_concepts(conn, id)` which already returns this shape.

### Reshape existing MCP resource: `graph://corpus/communities`

Update `graph_corpus.rs` to return `CommunityGraph`-compatible shape:
```json
{
  "nodes": [{"id": 1, "anchor": "primary-concept", "size": 5}],
  "edges": [{"source": 1, "target": 2, "weight": 3}],
  "generated_at": "..."
}
```

Implementation: delegate to existing `api::graph::get_communities(conn)` which already returns this shape. The current MCP resource builds its own query instead of reusing the existing API function — fix this to call `get_communities()`.

### UI migration

Replace `fetch(getDaemonUrl('/api/graph/...'))` calls with MCP resource reads:
- `loadGraphCommunities()`: read `graph://corpus/communities` via `mcpResources.readResource()`
- `loadGraphConcepts(id)`: read `graph://community/{id}` via `mcpResources.readResource()`

### REST route cleanup

Mark the direct graph REST routes as deprecated or remove them if no other consumer exists. Check:
- `GET /api/graph/communities` — used only by desktop UI
- `GET /api/graph/communities/{id}/concepts` — used only by desktop UI
