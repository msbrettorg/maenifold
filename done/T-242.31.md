# T-242.31 — Verify recovered Knowledge tab via CDP testing

**Pipeline**: tdd

## Background

T-242.13's Knowledge tab redesign was recovered in T-242.29a via cherry-pick of 8 commits from `recover/dev-pre-quiesce`. vue-tsc and `npm run build` pass on dev. But interactive CDP verification per the AGENTS.md UI rule was NOT done at recovery time.

## Required CDP testing

Per T-242.13 spec acceptance:

- [ ] Knowledge tab opens to a Memory/Graph subtab control (default: Memory).
- [ ] Memory subtab: vault tree + note viewer + collapsible related-concepts rail. NO graph element.
- [ ] Graph subtab: full-canvas force-directed graph, communities list left, inspector right/bottom. Drag-pan, scroll-zoom, click-detail, double-click-to-jump-to-note all functional.
- [ ] CDP smoke test: open Knowledge -> switch to Graph -> click a community -> click a node -> see inspector populate -> double-click -> land on the note in the Memory subtab. Screenshot evidence captured.
- [ ] Visual review against Obsidian's "Graph view" -- comparable readability and density at default zoom.

## Method

Use `agent-browser` per AGENTS.md UI verification protocol.

1. `cd apps/desktop && npm run build && npm run package` -- packaging required to pick up the recovered Knowledge components.
2. Stop any running maenifold instance via the explicit PID found by `ps aux | grep maenifold`.
3. Launch the packaged binary with `--remote-debugging-port=9222` via a detached process (NOT shell `&`).
4. `agent-browser connect 9222`.
5. Navigate to Knowledge tab and run the spec scenarios above.
6. Save screenshots to `outputs/screenshots/T-242.31/`.

## Acceptance Criteria

- [ ] Each spec criterion verified via interactive CDP click-through.
- [ ] Screenshot evidence for each scenario.
- [ ] Any UX issues filed as separate gate tasks.
