# T-238.57 — P1 Add persistent dispatch store for Teams crash recovery

**Pipeline**: sdd

## Problem

No persistent tracking of dispatched prompts. If the monitor crashes mid-dispatch, there is no record of what was in-flight or what needs retry.

## Reference

- agency-cowork: `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/dispatch_store.py` (244 LOC)
- Rust target: new file `crates/maenifold-core/src/teams/dispatch_store.rs`

## Required changes

1. Port `DispatchStore` — persistent JSON store at `monitor/dispatch-queue.json`
2. Track dispatch states: `pending`, `in_progress`, `done`, `failed`, `timeout`, `cancelled`
3. On startup, `mark_interrupted_as_pending()` — recover in-flight dispatches from prior crash
4. `cleanup_old(max_age_hours=72)` — prune stale entries
5. Wire into supervisor dispatch flow

## Acceptance Criteria

- [ ] Dispatches persisted to disk with state tracking
- [ ] Crash recovery re-queues interrupted dispatches
- [ ] Old entries cleaned up after 72 hours
- [ ] `cargo build --release -p maenifold-cli` passes
