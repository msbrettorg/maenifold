# T-65.17 — Design Token Adoption Sweep

**Requirement**: NFR-4
**Test Cases**: TC-115, TC-116
**Repo**: pipeline-ui
**Component**: src/components/*, src/composables/*

## Context

The design token system (T-63.0) defined 40+ CSS custom properties in App.vue :root, but 115 unique hardcoded hex colors remain across components. NFR-4 requires "a consistent type scale and spacing system derived from design tokens, replacing ad-hoc pixel values."

## Acceptance Criteria

1. Replace ALL hardcoded hex color values in Vue component `<style>` blocks and inline styles with the appropriate CSS custom property from the design token system defined in App.vue
2. Where no exact token match exists, map to the closest semantic token (e.g., `#444` → `var(--text-secondary)`, `#e0e0e0` → `var(--border-default)`)
3. Hardcoded hex values in App.vue `:root` and `@media (prefers-color-scheme: dark)` blocks are EXCLUDED — those ARE the token definitions
4. After the sweep, running `grep -roh '#[0-9a-fA-F]\{3,8\}' src/components/ src/composables/ --include='*.vue' --include='*.ts' --include='*.css' | wc -l` returns 0 (excluding App.vue)
5. `npx vue-tsc --noEmit` passes
6. No visual regressions in light mode — colors should map to equivalent values
7. Dark mode benefits automatically from token adoption
