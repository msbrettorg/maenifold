## Problem

`maenifold tool` (no args) prints a help banner that includes:

```
  Sync:   StartWatcher, StopWatcher
```

But invoking either tool fails:

```bash
$ maenifold tool StartWatcher '{}'
Unknown tool: StartWatcher
$ maenifold tool StopWatcher '{}'
Unknown tool: StopWatcher
```

Neither tool is registered in the runtime tool registry (verified by exhaustive enumeration across MCP `tools/list` and `GatewayIndex` over every domain — no match).

This is dead text in the CLI help banner. Either the tools were removed and the banner was not updated, or the banner is asserting tools that were never implemented. Either way, the help is lying to the user.

## Required Behavior

Either:
1. **Remove** the `Sync: StartWatcher, StopWatcher` line from the CLI help banner (preferred — the work that would have been those tools now lives in the autosync background watcher inside the daemon, which has no externally-invocable surface).
2. **Implement** both tools as a registered CLI tool wrapper around the existing watcher mechanisms.

Almost certainly option 1.

## Acceptance Criteria

- [ ] `maenifold tool` help no longer mentions StartWatcher / StopWatcher (option 1) **OR** both tools are registered and return a deterministic response (option 2).
- [ ] `maenifold tool StartWatcher '{}'` does not return `Unknown tool` while help still claims it exists.
- [ ] CLI help text and the runtime tool registry are in lockstep — this should be enforced by a unit test that fails if the help banner mentions a tool not in the registry.
