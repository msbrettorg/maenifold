# T-203.1 — Research: AppBridge API + Electron iframe compatibility

## Objective

Produce an architecture decision document covering:

1. **AppBridge API surface** — what it provides, what we wire up, what we customize.
2. **Electron compatibility** — do sandboxed iframes in Electron work with AppBridge's postMessage protocol? What `webPreferences` are required? Any CSP header conflicts?
3. **Vue integration pattern** — how to wrap AppBridge in a Vue 3 component (lifecycle, cleanup, reactivity boundaries).
4. **Security model** — what capabilities we expose/restrict by default. Which `_meta.ui.permissions` we support (camera? mic? clipboard?).
5. **npm dependency** — `@modelcontextprotocol/ext-apps` version, bundle size impact, tree-shaking.

## Method

- Read AppBridge source: https://github.com/modelcontextprotocol/ext-apps/tree/main/packages/sdk/src/app-bridge
- Read basic-host example: https://github.com/modelcontextprotocol/ext-apps/tree/main/examples/basic-host
- Read MCP-UI client for comparison: https://github.com/MCP-UI-Org/mcp-ui
- Test iframe sandbox behavior in Electron (our version in package.json)
- Review existing maenifold iframe usage (if any) for patterns

## Acceptance criteria

1. Architecture decision document written to memory (memory://)
2. Go/no-go on AppBridge vs custom implementation
3. Electron compatibility confirmed or blockers identified
4. Recommended `webPreferences` and CSP configuration documented
