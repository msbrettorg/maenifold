## Summary

Modify `HomeDashboard.vue` to display wallpaper images as a CSS background when enabled. Add crossfade transition between images and an opacity overlay to keep foreground content readable. Add a preload IPC bridge to safely read local images as data URLs from the sandboxed renderer.

## Implementation

### 1. Add image-reading preload IPC bridge

The Electron renderer has `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`. CSP allows `img-src 'self' data: https:` — NO `file://`. Local images must be served as `data:` URLs via IPC.

**Main process** (`apps/desktop/electron/main.ts`):
```typescript
ipcMain.handle('read-wallpaper-image', async (_event, filePath: string) => {
  const resolvedPath = path.resolve(filePath);
  const wallpaperDir = path.resolve(maenifoldRoot(), 'memory', '.cache', 'wallpaper');
  if (!resolvedPath.startsWith(`${wallpaperDir}${path.sep}`)) {
    throw new Error('Path outside wallpaper cache');
  }
  if (path.extname(resolvedPath).toLowerCase() !== '.png') {
    throw new Error('Only PNG wallpaper images allowed');
  }
  const data = await fs.promises.readFile(resolvedPath);
  return `data:image/png;base64,${data.toString('base64')}`;
});
```

**Preload** (`apps/desktop/electron/preload.ts`):
```typescript
readWallpaperImage: (filePath: string): Promise<string> =>
  ipcRenderer.invoke('read-wallpaper-image', filePath),
```

**Type declaration** (`apps/desktop/src/vite-env.d.ts`):
Add `readWallpaperImage(filePath: string): Promise<string>` to `ElectronApi` interface.

**Security constraint:** The IPC handler MUST validate that `filePath` resolves inside `{memoryPath}/.cache/wallpaper/` (where `memoryPath` = `{maenifoldRoot}/memory`) and has a `.png` extension. This prevents the renderer from reading arbitrary local files through the bridge.

### 2. Modify `apps/desktop/src/components/HomeDashboard.vue`

**Wallpaper display logic:**

- On mount, check if wallpaper is enabled via config store (`configStore.settings?.easterEggs?.wallpaper?.enabled`)
- If enabled, fetch image paths via `callTool('WallpaperStatus', {})` → `{ images: [path, ...], currentIndex: 0 }`
- Load each image path via `window.electronAPI.readWallpaperImage(path)` → `data:image/png;base64,...`
- Display using positioned background layers (see crossfade pattern below)
- On timer tick (`rotateMinutes`), advance to next image with crossfade
- Re-fetch on tab activation (no live config hot-reload needed)

**Crossfade pattern using positioned layers:**
- Root container gets `relative isolate overflow-hidden` (the `isolate` creates an explicit stacking context so negative z-indexes don't escape)
- Two absolutely-positioned `div`s (`absolute inset-0 -z-10 pointer-events-none`) with `:style="{ backgroundImage }"`, stacked below foreground content
- Foreground content wrapped with `relative z-10` to stay above wallpaper
- Alternate which layer is visible with `opacity` CSS transition (`transition-opacity duration-1000`)
- On rotation: set next image on the hidden div, then swap opacity classes
- Semi-transparent overlay between wallpaper and foreground (`absolute inset-0 -z-5 pointer-events-none bg-bg-surface/80`)
- All wallpaper/overlay layers have `pointer-events-none` so they don't interfere with tile/composer interaction

**z-index discipline:** The `isolate` on the root creates a new stacking context. All wallpaper z-indexes are negative (`-z-10`, `-z-5`) and scoped within this context. They do NOT conflict with global overlay layers (backdrop 9, inspector 10, flyout 11, context menu 60, dialogs 1000).

**Fallback:**
- If wallpaper disabled or no images available: render as current (no background layers)
- If WallpaperStatus returns empty images array: no-op
- If readWallpaperImage fails for a path: skip that image, cycle whatever is available

### 3. Keep under 300 LOC

HomeDashboard is currently 155 LOC. The wallpaper logic adds ~60-80 lines (state, timer, crossfade). If it approaches 250+, extract the wallpaper rendering into a `WallpaperBackground.vue` child component.
