# T-63.10 — Dispatch Response Consistency

**Requirement**: FR-12
**Test Cases**: TC-24
**Repo**: maenifold-rs
**Component**: crates/maenifold-core/src/workflow/pipeline/dispatch.rs

## Context

Dispatch response for WorkflowNode omits `type` field. All types omit configuration fields (prompt, workflowId, agent). Polling clients can't log what was scheduled without caching the creation payload.

## Acceptance Criteria

1. Dispatch response for ALL node types includes `type` discriminant field
2. Dispatch response includes node configuration fields: `workflowId`/`prompt`/`topic`/`toolName` as applicable
3. Dispatch response includes `agent` for all node types
4. Response shape is consistent: every dispatched node has `id`, `type`, `agent`, plus type-specific fields
5. ALL existing pipeline tests pass: `cargo test -p maenifold-core -- pipeline`
6. Add a test: dispatch pipeline with mixed node types → all responses include `type` field

## Swe Notes

PASS. Updated pipeline dispatch responses so every node type returns consistent id/type/agent metadata plus node-specific config fields, and added a mixed-node dispatch test covering workflow, prompt, sequentialThinking, and tool nodes. Verified pipeline suite with only the pre-existing pause/resume test still failing.

## Red-team Audit

- ✅ AC1 — `type` discriminant: base `json!({...})` in `build_dispatched_node_response` unconditionally sets `"type": node.node_type_name()` for all four node variants (workflow/prompt/sequentialThinking/tool). Verified across all per-type tests in dispatch.rs.
- ✅ AC2 — Config fields: Workflow → `workflowId` (required) + `prompt` (conditional); Prompt → `prompt`; SequentialThinking → `topic`; Tool → `toolName` + `toolArgs`. Each inserted as post-base merge into response object. Matches "as applicable" wording in spec.
- ✅ AC3 — `agent` for all types: base response sets `"agent": node.acp_client()`. Prompt/SequentialThinking/Tool always return `Some(agent)`. Workflow returns `Some` or `None` (serialised as `null`) depending on `acp_client` field — key is always present.
- ✅ AC4 — Consistent shape: every response has `id`, `nodeId` (compat alias), `sessionId`, `type`, `agent` from the base block; then type-specific fields appended via `response_object.insert(...)`.
- ✅ AC5 — All pipeline tests pass: 124 passed, 0 failed (`cargo test -p maenifold-core --lib -- pipeline`). No pause/resume failure present in this suite.
- ✅ AC6 — Mixed-type test: `pipeline_dispatch_mixed_node_types_include_consistent_type_and_config_fields` in handler.rs dispatches workflow + prompt + sequentialThinking + tool nodes, asserts `id`/`type`/`agent` on every node via loop, then asserts type-specific fields individually (workflowId, prompt, topic, toolName).
