# T-42.2: Session Setup Compliance

**Requirement**: FR-42.2  
**Priority**: P0  
**Files**: `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/App.vue`

## Acceptance Criteria

1. In `App.vue`, validate `selectedCwd` is an absolute path (starts with `/` on Unix, drive letter on Windows) before calling `createSession`. Remove the `'.'` fallback. If no cwd selected, show an error message requiring the user to pick a directory.

2. In `resumeSession()`, after calling `initialize`, check `initResponse.agentCapabilities?.loadSession`. If `false` or absent, disconnect and throw a clear error: `"Agent no longer supports session loading"`.

3. Add `connectionAborted = false` and `isConnecting.value = true` at the top of `resumeSession()`. Mirror the abort-check pattern from `createSession` at equivalent points (after initialize, before loadSession, etc).

## Spec References

- https://agentclientprotocol.com/protocol/session-setup
- Audit findings: cwd MUST be absolute, loadSession MUST be checked from live initialize response, resume abort guards missing

## SWE Remediation

- What changed
  - `vendor/acp-ui/src/App.vue`
    - Removed the `'.'` cwd fallback before `createSession`.
    - Added absolute-path validation for the selected working directory (Unix `/...` and Windows drive-letter paths).
    - Surface a clear UI error when no directory is selected or when the path is not absolute.
    - Updated the cwd picker placeholder text so the UI no longer implies `.` is acceptable.
  - `vendor/acp-ui/src/stores/session.ts`
    - Added a `setError()` store action so `App.vue` can show validation failures without starting a session.
    - Updated `resumeSession()` to set `connectionAborted = false` and `isConnecting.value = true` at the top.
    - Added abort guards in `resumeSession()` after spawn, after client setup, after initialize, before `loadSession`, after auth selection, after authenticate, and after `loadSession`.
    - Added a live `initResponse.agentCapabilities?.loadSession` check after initialize; when absent/false, the client disconnects and throws `Agent no longer supports session loading`.
    - Normalized `agentInfo` assignment to avoid null-valued optional fields in the store state.

      - `src/lib/acp-bridge.ts` type mismatch around `ToolCallInfo.locations`

- Notes

  - I kept the fix scoped to the requested files and did not remediate unrelated frontend issues that are currently breaking `vue-tsc`.

**Regression Finding (non-blocking, dead code):**

In `createSession()`, lines 487–490 and 492–495 contain two consecutive, identical `connectionAborted` checks with no `await` between them:

```ts
// session.ts:487–495
if (connectionAborted) {      // check A
  await acpClient.disconnect();
  throw new Error('Connection cancelled');
}

if (connectionAborted) {      // check B — DEAD CODE
  await acpClient.disconnect();
  throw new Error('Connection cancelled');
}
```

Because `connectionAborted` is a plain boolean and there is no `await` between the two checks, check B is unreachable dead code. This was introduced during the T-42.2 refactoring (most likely a copy-paste artefact when the SWE studied the existing abort-guard layout to inform the resumeSession mirrors). It does not affect correctness but does pollute the diff and will confuse future readers. The SWE should remove the duplicate on a follow-up pass.

Recommendation: Remove lines 492–495 from `createSession()` in a cleanup commit.
