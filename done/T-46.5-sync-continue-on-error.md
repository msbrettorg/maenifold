# T-46.5: Sync Continue-on-Error

**Requirement**: FR-46
**Priority**: P0
**Files**: `crates/maenifold-core/src/sync/mod.rs`

## Context

`run_sync` iterates all memory files and processes each one. If `read_markdown` or `upsert_processed_file` errors on any file, the `?` operator aborts the entire sync. This means one bad file kills the whole sync run.

## Acceptance Criteria

1. In `run_sync`, wrap the per-file processing loop body in a `match` or `if let Err(e)` block. On error:
   - Log the error with the file URI using `eprintln!` (or the existing diagnostic pattern)
   - Collect the error into a `Vec<(String, String)>` of `(file_uri, error_message)` pairs
   - Continue to the next file — do NOT abort the sync

2. After the sync completes, if there were file errors:
   - Include an `## Errors` section in the sync markdown output listing each failed file and its error
   - Set the status to `"partial"` instead of `"success"` when there are errors but some files succeeded

3. Add `file_errors: Vec<(String, String)>` to `SyncSummary` (in `sync_state.rs`).

4. Update `render_sync_markdown` to render the errors section when `file_errors` is non-empty.

5. Apply the same pattern to `sync_files` — collect errors per file, continue processing, report at end.

6. `sync_single_file` stays fail-fast — it's explicitly targeting one file, so errors should propagate.
