# T-63.1 — Watcher Health Counters

## Problem
`sync/watchers.rs` logs batch sync errors to stderr via `eprintln!` and continues silently. Users cannot query watcher health — they only know it's "running" or "not running" via `watcher_is_running()`. Failed file syncs accumulate invisibly.

## Requirements
1. Add `SYNC_FAILURES: AtomicU32` static — total failure count since watcher start
2. Add `CONSECUTIVE_FAILURES: AtomicU32` static — reset to 0 on any successful batch
3. Add `LAST_FAILURE_MSG: Mutex<Option<String>>` static — most recent error message
4. Increment `SYNC_FAILURES` and `CONSECUTIVE_FAILURES` in `flush_pending_paths()` error branch
5. Increment `SYNC_FAILURES` per-file in `process_incremental_batch()` error branch
6. Reset `CONSECUTIVE_FAILURES` to 0 on successful batch completion
7. Create `WatcherHealth` struct: `{ is_running: bool, total_failures: u32, consecutive_failures: u32, last_error: Option<String>, changes_processed: u32 }`
8. Expose `pub fn watcher_health() -> WatcherHealth`
9. Add `pub fn reset_health_counters()` for test isolation
10. Wire into `render_system_health()` in `benchmark/render.rs` — show watcher section in MemoryStatus output

## Files
- `crates/maenifold-core/src/sync/watchers.rs` — add statics, health struct, accessor
- `crates/maenifold-core/src/benchmark/render.rs` — add watcher health section

## Tests
- Unit test: call `reset_health_counters()`, simulate failure increment, assert `watcher_health()` reflects it
- Existing `cargo test -p maenifold-core` must pass

## Acceptance
- `watcher_health()` returns accurate failure counts
- `MemoryStatus` MCP tool output includes watcher health section
- No warnings, no panics
