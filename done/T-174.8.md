# T-174.8 — Static validation of `Conditional` edge `path`

## Why
Conditional edges resolve `path` at runtime against the upstream node's output JSON. A typo (`verdic` instead of `verdict`) makes the predicate silently false forever — the node sits Pending, the user thinks the pipeline is broken, debugging is brutal. Catch the typo at definition time.

## Scope
**Crate:** `maenifold-core`. Pipeline definition validation path (wherever `validation_test_support.rs` is exercised). Does not touch the executor.

## Acceptance
- AC-1: Each `PipelineNode` variant declares its **static output shape** as a list of supported top-level paths the executor is known to populate (e.g. `prompt` → `["response", "summary", "conclusion", "metadata"]`; `tool` → `["result", "error"]`; `workflow` → `["conclusion", "thoughts"]`; `sequentialThinking` → `["conclusion", "thoughts"]`). The list lives next to the executor code that produces those fields, not as a magic constant.
- AC-2: Definition validation: a `Conditional` edge whose `path` head segment is not in the source node type's static output paths is **rejected** at create / graft time with a clear error: `"conditional edge from <source> references unknown path '<path>' (supported: <list>)"`.
- AC-3: Nested paths (e.g. `metadata.exitCode`) only validate the **head** segment. Deep keys remain runtime-resolved (output JSON is open-ended below the top level).
- AC-4: Wildcard / dynamic node output (e.g. external MCP tool nodes whose schema is unknown) bypass validation with a single-line warning, never an error.
- AC-5: Tests in `validation_test_support.rs` (or a sibling `conditional_edge_validation_tests.rs`) covering: valid path on each node type, invalid head on each node type, deep nested path (allowed), tool-node bypass.
- AC-6: `cargo build --release -p maenifold-cli`.
- AC-7: No effect on pipelines without `Conditional` edges.

## Forbidden
- Validating runtime values — only structural paths are validated here.
- Hard-coding the output paths as string literals scattered across the codebase. Centralize via an associated function on the node-type enum.
