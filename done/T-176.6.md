# T-176.6 — Fix ELK layout — edge spaghetti, node overlap, and fit-to-view

## Intent

The pipeline canvas with 19 nodes looks like a rats nest. Edges cross through nodes, tiers have inconsistent spacing, nodes clip off-screen, and the overall layout fails to communicate the DAG structure. This is a configuration/measurement problem, not an ELK replacement problem.

## Evidence

Screenshot 2026-04-18: 19-node FinOps pipeline. Orthogonal edges spaghetti across the middle tier. 5 tool nodes crammed horizontally with edges routing through them. Right-side nodes truncated off viewport. Warning status indicators floating disconnected. Massive vertical gap between tiers 1-2, then cramped between 2-3.

## Root cause analysis (from `src/composables/useLayout.ts`)

1. **Fixed `NODE_HEIGHT = 220`** — all nodes get the same height regardless of content. Short nodes (1-line tool calls) waste space. Tall nodes (sequential thinking with topic/model/thought count) overflow. ELK routes edges based on these dimensions, so wrong heights = edges routing through visible content.

2. **No edge merging** — `elk.layered.mergeEdges` is not set. When a single source fans out to 5+ targets, each edge gets its own routing lane. This creates the horizontal bus of parallel lines visible in the screenshot.

3. **`semiInteractive` crossing minimization** — preserves source-handle ordering but doesn't aggressively reduce crossings. For a 19-node DAG with fan-outs, this produces the crossing mess.

4. **No fit-to-view after layout** — after ELK positions nodes, the canvas doesn't `fitView()`. Nodes placed beyond the viewport are invisible until the user manually pans.

5. **No `thoroughness` tuning** — ELK's default thoroughness is low. For complex graphs, increasing it produces significantly better layouts at negligible cost (it's a web worker).

## Scope



### Fix 1: Dynamic node measurement

Before calling ELK, measure actual rendered node dimensions from the Vue Flow node elements. If nodes aren't rendered yet (first layout), use estimates based on content:
- Base height: 80px (header + type badge)
- Per-field: +24px for each of: agent, model, topic, toolName, prompt preview
- Width: keep 280px fixed (card width is constant in the design)

After first render, re-layout with actual `getBoundingClientRect()` measurements.

### Fix 2: ELK option tuning

```typescript
// Merge parallel edges from the same source into shared routing channels
'elk.layered.mergeEdges': 'true',
// Increase layout quality — worth it for graphs under 100 nodes
'elk.layered.thoroughness': '20',
// Better crossing minimization for DAGs
'elk.layered.crossingMinimization.strategy': 'LAYER_SWEEP',
'elk.layered.crossingMinimization.semiInteractive': 'false',
// Increase node-to-node spacing in same layer for fan-outs
'elk.spacing.nodeNode': '120',
// Ensure edges don't route through node bodies
'elk.spacing.edgeNode': '64',
// Better port placement for multiple edges
'elk.layered.nodePlacement.strategy': 'NETWORK_SIMPLEX',
```

### Fix 3: Fit-to-view after layout

After `layout()` resolves and positions are applied to Vue Flow nodes, call `fitView({ padding: 0.15, duration: 300 })` to ensure all nodes are visible with 15% padding.

### Fix 4: Edge label clearance

Edge labels (if any) need `elk.spacing.labelNode` set so labels don't overlap nodes.

## Files touched

- `src/composables/useLayout.ts` (ELK options, dynamic height)
- `src/composables/useComposerCanvas.ts` (fitView after layout, node measurement)
- `src/components/PipelineComposer.vue` (trigger fitView after layout settles)

1. 19-node FinOps pipeline renders with zero edge-through-node crossings
2. Fan-out edges from single source merge into shared routing channels
3. All nodes visible after layout (fitView fires automatically)

5. Layout completes in < 500ms for 20-node graphs (web worker)
6. Both LR and TB directions produce clean results
7. Manual node drag clears ELK edge paths (existing behavior preserved)
