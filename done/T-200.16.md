# T-200.16 — Fix clippy violations in maenifold-gate

## Intent

Resolve all three clippy violations in maenifold-gate to achieve clean `cargo clippy -p maenifold-gate --no-deps -- -W clippy::all`.

## Violations

1. **tray_menu.rs:7** — `single_component_path_imports`: redundant `use libc;`
2. **cache_task_row.rs:199** — `too_many_arguments`: `error_status_row` has 6 params
3. **section_factory.rs:38** — `too_many_arguments`: `build` has 6 params

## Fix Strategy

### 1. tray_menu.rs
Delete `use libc;` on line 7. The `libc::getuid()` call on line 16 is already fully qualified.

### 2. cache_task_row.rs
Introduce `ErrorRowContext` struct:
```rust
pub(crate) struct ErrorRowContext<'a> {
    pub root: &'a Path,
    pub file: &'a str,
    pub task_id: &'a str,
    pub location: &'a str,
    pub linked: bool,
}
```
Refactor `error_status_row(ctx: &ErrorRowContext, issue: &str)` and `pipeline_mismatch_row(ctx: &ErrorRowContext, requested: &str, bound: Option<&str>)`. Remove the `#[allow(clippy::too_many_arguments)]` on `pipeline_mismatch_row`. Update the caller `into_status_value` to create the context struct.

### 3. section_factory.rs
Introduce a `SectionRecord` struct:
```rust
struct SectionRecord<'a> {
    stage: &'a str,
    record_kind: &'a str,
    outcome: Option<&'a str>,
    agent: &'a str,
    notes: &'a str,
    model: Option<&'a str>,
}
```
Add a `render(&self) -> String` method containing the current `build` logic. Replace both public methods to construct the struct and call `.render()`. Remove the `build` method.
