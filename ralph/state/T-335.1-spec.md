# T-335.1 spec — Copilot `/models` parity

## 1. Summary

Ship a daemon-side Copilot capability fetcher that reads the Copilot OAuth token from disk, resolves the real Copilot API endpoint the way Zed does, fetches `/models`, exposes the result through a new localhost MCP command, and overlays the live-session ACP `reasoning_effort` picker with per-model values in the desktop store. User-visible win: the live Reasoning Effort dropdown stops flattening every model to `none/low/medium/high` and shows `xhigh` where the Copilot `/models` API advertises it, including GPT-5-family models that expose `xhigh` and the distinct `claude-opus-4.7-xhigh` model id. Zed parity basis: `crates/copilot_chat/src/copilot_chat.rs:60-62`, `crates/copilot_chat/src/copilot_chat.rs:325-327`, `crates/copilot_chat/src/copilot_chat.rs:532-535`, `crates/copilot_chat/src/copilot_chat.rs:823-853`, `crates/copilot_chat/src/copilot_chat.rs:887-917`; live API delta and cache header: `ralph/state/T-335.1-discovery.md:103-110`, `ralph/state/T-335.1-discovery.md:148-154`, `ralph/state/T-335.1-discovery.md:255-287`.

## 3. Rust contract

### 3.1 Token store

- **Locked decision Q1 applies here verbatim:** Daemon reads `~/.config/github-copilot/apps.json` + `~/.config/github-copilot/hosts.json` directly via `tokio::fs`. NO `gh auth token` shell-out. NO IPC to Copilot CLI. Zed basis: `crates/copilot_chat/src/copilot_chat.rs:118-122`, `crates/copilot_chat/src/copilot_chat.rs:532-535`. Discovery justification: `ralph/state/T-335.1-discovery.md:137-171`.
- Module path: `crates/maenifold-jockey/src/copilot_models.rs` or `crates/maenifold-jockey/src/copilot_models/{mod.rs,token_store.rs,...}`.
- Paths read, in order:
  1. `~/.config/github-copilot/hosts.json`
  2. `~/.config/github-copilot/apps.json`
- Selection rule:
  - Parse each file as a top-level JSON object.
  - Iterate entries in file order.
  - Return the first entry whose key starts with the resolved `oauth_domain` and whose object contains a non-empty `oauth_token` string.
  - `hosts.json` wins over `apps.json` because Zed watches both paths in that order (`crates/copilot_chat/src/copilot_chat.rs:532-535`) and extracts the first domain-matching `oauth_token` (`crates/copilot_chat/src/copilot_chat.rs:920-935`).
- Signatures:

```rust
pub struct CopilotTokenStore {
    config_dir: PathBuf,
}

pub struct CopilotToken {
    pub oauth_domain: String,
    pub access_token: String,
    pub fingerprint: String,
}

impl CopilotTokenStore {
    pub fn new(config_dir: PathBuf) -> Self;

    pub async fn load_token(
        &self,
        oauth_domain: &str,
    ) -> Result<CopilotToken, CopilotTokenStoreError>;
}
```

- Error enum:

```rust
pub enum CopilotTokenStoreError {
    TokenMissing { oauth_domain: String },
    TokenExpired { oauth_domain: String },
    HostsJsonMissing { path: PathBuf },
    MalformedJson { path: PathBuf, source: serde_json::Error },
    Io { path: PathBuf, source: std::io::Error },
}
```

- Expiry rule:
  - If a parsed record carries an expiry field and it is in the past, return `TokenExpired`.
  - If no expiry field is present, treat the token as non-explicitly-expired and continue.
- File I/O is `tokio::fs::read_to_string`; no blocking std fs.

### 3.2 Endpoint discovery

- **Locked decision Q4 applies here verbatim:** Daemon process makes HTTPS GET directly to `api.githubcopilot.com/models` (or the enterprise endpoint resolved via GraphQL `viewer.copilotEndpoints.api`, with `https://api.githubcopilot.com` as the fallback). No APIM intermediary in this task.
- Struct:

```rust
pub struct CopilotEndpoint {
    pub api: String,
}
```

- Resolution order:
  1. Compute `oauth_domain` from configured enterprise URI using Zed-equivalent host stripping (`crates/copilot_chat/src/copilot_chat.rs:31-45`, `crates/copilot_chat/src/copilot_chat.rs:64-74`; discovery mapping: `ralph/state/T-335.1-discovery.md:241-253`).
  2. POST GraphQL query `query { viewer { copilotEndpoints { api } } }`.
  3. If GraphQL succeeds and returns a non-empty `api`, use it.
  4. Otherwise fall back to `https://api.githubcopilot.com`.
- Zed proof:
  - default endpoint constant: `crates/copilot_chat/src/copilot_chat.rs:22-24`
  - GraphQL query: `crates/copilot_chat/src/copilot_chat.rs:823-825`
  - GraphQL response extraction: `crates/copilot_chat/src/copilot_chat.rs:849-853`
  - fallback log path: `crates/copilot_chat/src/copilot_chat.rs:732-740`
- Implementation rule:
  - Reuse an existing GitHub GraphQL client if one already exists in the touched crate tree.
  - Current discovery found no existing GitHub GraphQL client in the relevant path; SWE shall implement a minimal `reqwest` POST for this query.

### 3.3 Models client

- **Locked decision Q2 applies here verbatim:** Per-model exact id parsing (for example `claude-opus-4.7-xhigh` is a distinct model id from `claude-opus-4.7`). NO family-level rollup.
- Request:
  - `GET <endpoint>/models`
  - `Authorization: Bearer <token>`
  - `X-Github-Api-Version: 2025-04-01`
- Zed parity for direct fetch and exact per-model reasoning-effort list:
  - models URL construction: `crates/copilot_chat/src/copilot_chat.rs:60-62`
  - request/parse flow: `crates/copilot_chat/src/copilot_chat.rs:887-917`
  - per-model exact list access: `crates/copilot_chat/src/copilot_chat.rs:325-327`
- Timeout contract:
  - `connect_timeout = 10s`
  - `timeout = 30s`
  - Justification: keep endpoint discovery + `/models` fetch bounded and align with existing 30s reqwest precedent in maenifold (`crates/maenifold-core/src/mcp/gateway_direct_inference_resolver.rs:18`, `crates/maenifold-core/src/mcp/gateway_direct_inference_resolver.rs:37-44`).
- Response structs:

- **LIVE API DELTA is mandatory:** keep `structured_outputs: Option<bool>` and `max_non_streaming_output_tokens: Option<u32>` optional, because discovery observed them live even though the cited Zed commit does not model them (`ralph/state/T-335.1-discovery.md:103-110`).
- Filtering rule:
  - Keep exact model ids from the service.
  - Filter to model-picker-enabled, chat-type, enabled-policy records before returning MCP data.
- Failure behavior:
  - Internal refresh path logs the live fetch error.
  - If a cached value exists, return cached models and `source = "cache"`.
  - If no cached value exists, surface the mapped `GetCopilotModelsError`.

### 3.4 Cache

- **Locked decision Q5 applies here verbatim:** 6 hours, derived from the live API's `Cache-Control: private, max-age=21600` response header observed during discovery. Use that header value as a refresh hint; refresh sooner on auth-token rotation.
- Storage:

```rust
pub struct CopilotModelsCache {
    pub entries: HashMap<String, CopilotModelsCacheEntry>,
}

pub struct CopilotModelsCacheEntry {
    pub endpoint: String,
    pub fingerprint: String,
    pub cached_at: DateTime<Utc>,
    pub expires_at: DateTime<Utc>,
    pub models: Vec<CopilotModel>,
}

pub type SharedCopilotModelsCache = Arc<RwLock<CopilotModelsCache>>;
```

- Key: endpoint string.
- Refresh policy:
  - cache miss -> refresh live
  - expired entry -> refresh live
  - `refresh=true` -> refresh live
  - auth fingerprint changed -> refresh live immediately
- Failure policy:
  - refresh failure + stale entry present -> serve stale and log
  - refresh failure + no entry -> return error

### 3.5 Public Rust API surface

```rust
pub async fn get_copilot_models(
    services: &CopilotModelsServices,
    refresh: bool,

```

```rust
pub struct GetCopilotModelsResult {
    pub models: Vec<CopilotModel>,
    pub cached_at: DateTime<Utc>,
    pub source: CopilotModelsSource,
}

pub enum CopilotModelsSource {
    Live,
    Cache,
}

pub enum GetCopilotModelsError {
    TokenMissing,
    EndpointUnreachable,
    ParseFailed,
    Forbidden,
    Other,
}
```

- Error mapping:
  - token-store `TokenMissing`/`HostsJsonMissing` with no usable `apps.json` token -> `TokenMissing`
  - HTTP 403 -> `Forbidden`
  - connect/timeout/network failure with no stale cache -> `EndpointUnreachable`
  - JSON decode failure with no stale cache -> `ParseFailed`
  - anything else with no stale cache -> `Other`

## 5. Frontend integration

- Live-session hook lives in the session store getter layer, not the raw ACP mutator path.
  - `apps/desktop/src/stores/session.ts:128` composes `createSessionGetters(...)`.
  - `apps/desktop/src/stores/session-getters.ts:56-58` currently exposes raw `activeSession.configOptions`.
  - ACP ingress is `apps/desktop/src/composables/useMessageHandler.ts:124-126`.
  - Raw ACP mutation is `apps/desktop/src/composables/session-state-helpers.ts:56-62`.
- Contract:
  1. When a live session opens for the Copilot agent, call `useMcpClient().callTool('GetCopilotModels', { refresh: false })` through the existing MCP wrapper exposed by `apps/desktop/src/composables/useMcpClient.ts:154-204` and `apps/desktop/src/composables/mcpClientOps.ts:204-236`.
  2. Store the result as `Map<modelId, reasoningEffortList>` in session-store state keyed by exact model id.
  3. In the live `ConfigOptionUpdate` overlay path for option id `reasoning_effort`:
     - read the currently selected exact model id from the ACP `model` config option
     - if the fetched map contains that exact model id, replace the ACP-advertised `reasoning_effort.options` array with the fetched per-model ordered list
     - if the fetched map does not contain that model id, fall through to the ACP-advertised option list unchanged
- **Locked decision Q3 applies here verbatim:** xhigh is exposed in the live ACP session config picker for models whose `/models` response includes `xhigh` in their per-model `reasoning_effort` list. Workflow YAML asset schemas are NOT widened in this task.
- Failure modes:
  - token missing -> keep ACP-advertised list; emit one dev-only warning
  - fetch fails -> keep ACP-advertised list; emit one dev-only warning
  - cached response present -> use cached list; no user-visible error
- Warning rule:
  - dev-only warning path is allowed because the frontend already gates warnings behind `import.meta.env.DEV` via `warnRawResourceErrorInDev()` (`apps/desktop/src/lib/error-sanitizer.ts:24-27`).
  - no unconditional production `console.*`.
