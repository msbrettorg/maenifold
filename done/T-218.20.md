# T-218.20 — Gateway Resource Routing Registry

## Problem

Gateway `resources/read` for upstream UI resources is broadcast-to-all for `ui://` only. This creates ambiguous ownership, hides resource collisions, is inefficient across many upstream servers, and does not prove parity with `resources/list`.

## Acceptance Criteria

- [ ] Build a resource routing registry from upstream tool `_meta.ui.resourceUri` and/or upstream `resources/list`
- [ ] Route `resources/read` to the owning server instead of broadcasting
- [ ] Duplicate `ui://` resource ownership fails gateway startup with a clear collision error
- [ ] `resources/read` returns resource-not-found only when the owning server reports not-found
- [ ] Operational upstream errors remain operational errors, not not-found
- [ ] `resources/list` includes gateway-owned UI resources, or unsupported listing is explicitly documented and tested
- [ ] Native resources remain unaffected
- [ ] Tests cover a server with tool `_meta.ui.resourceUri` but no `resources/list`
