## Problem

During MCP gateway diagnostics, the PM ran `gate --version` to verify the gate binary and received `error: unexpected argument '--version' found`.

Version checks are a standard diagnostic path. If gate intentionally lacks a version flag, the PM docs need to say so; otherwise the CLI should expose one.

## Scope Notes

- This is a repo-owned gate CLI fix. The current parser in `crates/maenifold-gate/src/cli_parser.rs` derives `clap::Parser` for `GateCli` but does not expose `--version` in the live help output.
- `gate --help` currently shows `--mcp`, `--http`, `--port`, `--root`, and `-h/--help`, but no version flag.
- Default expectation: support standard Clap version output through the existing parser path. Only fall back to docs-only clarification if implementation review finds a concrete blocker that makes normal Clap version support unsafe or impossible.
- Do not add an ad hoc custom branch in `cli.rs` if the existing Clap derive can provide the version surface cleanly.

## File / Surface Scope
