# T-178.5b — Workflow dashboard — desktop MCP resources migration

## Intent

Migrate the desktop Workflow surface inside `apps/desktop/src/` onto MCP `workflow://` resources delivered via the [[T-178.0]] resource client. Same pattern as [[T-178.5a]] — define resources server-side, wire emitters, swap the desktop data layer, keep writes on `tools/call`.

## Scope

### 1. Define + register `workflow://` resources in `crates/maenifold-core/src/mcp/resources.rs`

| URI | Read returns | Updated when |
|---|---|---|
| `workflow://sessions/active` | `{ sessions: [WorkflowSessionSummary], generated_at }` | Session created, step advanced, status changed |
| `workflow://session/{id}` (template) | `{ id, workflowId, currentStep, totalSteps, status, history: [...], thoughts: [...], ... }` | Step advance / status change / thought added on this session |
| `workflow://catalog` | `{ workflows: [{ id, name, description, steps }], generated_at }` | Asset reload (`UpdateAssets`) |

Apply the [[T-178.3c]] throttle wrapper to `workflow://sessions/active` (highest fan-out). Per-session URIs are unthrottled.

### 2. Wire emitters

- Workflow step advance → `workflow://session/{id}` + `workflow://sessions/active`.
- Workflow session create / cancel / complete → `workflow://session/{id}` + `workflow://sessions/active`.
- `UpdateAssets` completion → `workflow://catalog`.

### 3. Migrate desktop components

Identify and migrate the workflow UI surface in `apps/desktop/src/components/` (e.g. workflow listing, workflow detail / step viewer wherever it currently lives). If the desktop app does not yet have a dedicated Workflow view component, create:
- `apps/desktop/src/components/WorkflowView.vue`
- `apps/desktop/src/components/WorkflowSessionList.vue`
- `apps/desktop/src/components/WorkflowSessionDetail.vue`

Pinia: `apps/desktop/src/stores/workflow.ts` (extend or create). Slices: `activeSessions`, `selectedSession`, `catalog`. Subscribe-on-mount / unsubscribe-on-unmount contract per [[T-178.0]].

Writes (start workflow, respond, append, cancel) continue via `tools/call`.

### 4. Fluent 2 styling — HARD REQUIREMENT

Same rules as [[T-178.4]] / [[T-178.5a]]:
- All tokens from `apps/desktop/DESIGN.md`.
- shadcn-vue Card / Badge / ScrollArea / Collapsible / Button / Input / Tooltip / Progress.
- Status: `--success` (completed), `--warning` (in-progress), `--danger` (cancelled/failed), `--muted` (idle).
- Body font: Segoe UI Variable.
- ZERO hardcoded hex/RGB/HSL. ZERO `<style>` blocks.

### 5. Help docs

`assets/help/resources/workflow.md` (NEW) documents the URI scheme.

## Files in scope

- `crates/maenifold-core/src/mcp/resources.rs` (workflow URI registration + read dispatch)
- Workflow step-advance / session-lifecycle call sites (minimal `notify_resource_updated` additions)
- `apps/desktop/src/stores/workflow.ts` (extend or create)
- Existing workflow-related Vue components in `apps/desktop/src/components/` — enumerate during implementation
- `apps/desktop/src/components/WorkflowView.vue` and siblings (NEW if no equivalent exists today)
- `apps/desktop/src/components/__tests__/Workflow*.test.ts` (NEW or extend)
- `assets/help/resources/workflow.md` (NEW)

## Acceptance criteria

1. `cargo test -p maenifold-core` passes.
2. `pnpm --filter desktop build` and `pnpm --filter desktop test` pass; zero `vue-tsc` errors.
3. Workflow view performs ZERO `/api/workflow/*` HTTP calls.
4. Reads via `useMcpResources`; writes via `tools/call`.
5. Step-advance and session-lifecycle notifications drive UI updates without manual reload (Playwright assertion).
6. ZERO hardcoded hex/RGB/HSL and ZERO `<style>` blocks in files in scope (grep verification).
7. Playwright screenshot of Workflow view with at least one active session, attached to PR.
8. `assets/help/resources/workflow.md` documents the URIs and update conditions.

## Out of scope

- Gate / Pipeline / Agent dashboards.
- Workflow authoring UX changes.
