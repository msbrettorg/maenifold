# T-46.4: Session Store Decomposition

**Requirement**: FR-46
**Priority**: P1
**Files**: `vendor/acp-ui/src/stores/session.ts`, new composable files

## Context

After T-46.2, session.ts is a large monolith. Split into focused composables.

## Acceptance Criteria

1. Create `vendor/acp-ui/src/composables/useSessionLifecycle.ts`:
   - Move `performInitialization`, `createSession`, `resumeSession`, `disconnect`, `closeSession`, `setActiveSession`, `cancelConnection`
   - Accepts the sessions Map, bridges Map, activeSessionId ref, and savedSessions ref as parameters
   - Returns the functions

2. Create `vendor/acp-ui/src/composables/useMessageHandler.ts`:
   - Move `handleSessionUpdate`, `sendPrompt`, `cancelOperation`, `pushSystemMessage`, `cancelPendingToolCalls`
   - Accepts sessions Map, bridges Map, activeSessionId ref as parameters
   - Returns the functions

3. Create `vendor/acp-ui/src/composables/usePermissions.ts`:
   - Move `resolvePermission`, `cancelPermission`, `selectAuthMethod`, `cancelAuthSelection`
   - Accepts sessions Map, bridges Map, activeSessionId ref as parameters
   - Returns the functions

4. Create `vendor/acp-ui/src/composables/useSessionPersistence.ts`:
   - Move `savedSessions`, `initStore`, `saveSessionsToStore`, `deleteSession`, `resumableSessions`, `mergeSessionsFromAgent`
   - Returns the refs and functions

5. `stores/session.ts` becomes a thin orchestrator:
   - Imports and calls the composables
   - Owns the sessions Map, bridges Map, activeSessionId
   - Defines computed compatibility shims
   - Re-exports everything through the store's return object
   - The external API does NOT change — all existing consumers work unchanged

6. External API contract: every property and method currently exported from `useSessionStore()` must still be exported with the same name and type.
