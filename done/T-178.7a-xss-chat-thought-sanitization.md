# T-178.7a — XSS sink in ChatThoughtSection.vue

**Pipeline**: sdd
**Pipeline Digest**: tbd

## Severity: P1 — Security

## Finding

`ChatThoughtSection.vue:12,30` renders `marked.parse(props.thought, { async: false })` via `v-html` **without** `DOMPurify.sanitize()`. The thought content originates from assistant output. With `sandbox: false` in Electron (`electron/main.ts:65-70`) and privileged IPC in preload (`electron/preload.ts:4-9`), a malicious thought payload can become renderer-side HTML injection.

## Found By

Red-team (goldeneye) during T-178.6c Vite upgrade audit.

## Fix

Wrap `marked.parse()` output in `DOMPurify.sanitize()` before passing to `v-html`. The project already depends on `dompurify` (just upgraded to 3.4.0 in T-178.6b).

## Acceptance Criteria

1. Every `v-html` binding that receives `marked.parse()` output is wrapped in `DOMPurify.sanitize()`
2. Audit ALL other `v-html` bindings in the codebase for the same pattern
3. `npx vue-tsc --noEmit` passes
4. `npm run build` succeeds

## Out of Scope

- `vite.config.ts` `server.host: true` — separate concern, tracked separately
- v-html sinks #117–125 are already DOMPurify-wrapped per audit — confirm they remain sanitized but do not modify
- CSP meta tag in renderer HTML — defense-in-depth, separate task
