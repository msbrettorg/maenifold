# T-69.8 — Agent Capability Enumeration MCP Tool

**Requirement**: FR-52
**Component**: crates/maenifold-core/src/tools/, crates/maenifold-core/src/acp/

## Problem

There is no MCP tool or API to enumerate available ACP agents, their supported models, reasoning effort levels, and capabilities. Without this, the pipeline UI composer cannot populate dropdowns for agent/model/reasoning selection when building pipeline nodes. Users must know agent names and model IDs by heart.

## Acceptance Criteria

1. New MCP tool `ListAgents` (or add to existing tool) returns all configured agents from `agents.json`
2. For each agent, the response includes:
   - `name`: agent identifier (used in pipeline node `agent` field)
   - `command`: the agent command (for display, not execution)
   - `models`: array of `ModelInfo` (`model_id`, `name`, `description`) from ACP `InitializeResponse.models`
   - `capabilities`: from ACP `AgentCapabilities` (load_session, prompt_capabilities, session_capabilities)
   - `mcp_servers`: configured MCP servers for the agent
3. Agent capabilities are fetched lazily — if the agent has been initialized (pool has a handle), return cached capabilities. If not initialized, return the static config from `agents.json` without capabilities.
4. Response is JSON-serializable and usable by the pipeline UI
5. Tool is registered in the tool registry with alias `list_agents` / `ListAgents`
6. MCP schema advertises the tool with clear description

## Implementation Notes

- `agents.json` already has agent configs via `AgentsConfig::load()`
- The ACP pool (`AgentPool`) caches `InitTask` which contains `capabilities` and `agent_info`
- For initialized agents, capabilities and models can be read from the pool
- For non-initialized agents, return config-only response (agent name, command, mcp_servers)
- Consider whether to auto-initialize agents on listing — probably not, to avoid side effects
- The pipeline UI will call this tool to populate the node composer form
