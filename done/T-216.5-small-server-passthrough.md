# T-216.5 — Small-Server Passthrough

**Pipeline**: sdd
**Priority**: P2

## Scope

Ensure servers with ≤3 tools are exposed flat (no facade indirection) and that already-hierarchical servers pass through without double-wrapping.

## What to Build

### Small server detection

In `build_consolidated_tools()`, servers with `tool_count <= min_tools_for_consolidation` (default 3) return their tools in the passthrough list. These appear individually in `tools/list`, preserving zero-overhead access.

### Already-hierarchical detection

Some upstream servers (like azure-mcp-server) already expose hierarchical tools that accept `command`/`learn`/`intent` parameters. Detect this by checking if ANY tool in the server's catalog has `command`, `learn`, or `intent` in its inputSchema properties.

If detected: expose those tools individually (they're already consolidated). Don't wrap a hierarchy in another hierarchy.

### Validation

The combined count of `consolidated_facade_tools + passthrough_flat_tools + native_tools` should always be < 60. Log a warning if it exceeds 50.

## Acceptance Criteria

- [ ] Servers with ≤3 tools exposed flat
- [ ] Already-hierarchical tools not double-wrapped
- [ ] Total tool count logged at startup
- [ ] Warning if >50 tools
- [ ] `cargo build --release -p maenifold-cli` succeeds
