# T-174.3 — MCP schema for `Conditional` edges

## Why
The MCP `Pipeline` tool surface validates `definition` against a JSON Schema generated from `crates/maenifold-core/src/mcp/schema/pipeline_node_schema.rs`. After T-174.2 lands the new `EdgeType::Conditional` variant, the schema must allow callers (UI, agents) to describe it.

## Scope
**Crate:** `maenifold-core`. **Files:** `crates/maenifold-core/src/mcp/schema/pipeline_node_schema.rs`, plus any handler that re-validates incoming `PipelineEdge` JSON.

## Acceptance
- AC-1: `EdgeType` enum in the schema gains `"conditional"` alongside `"success"` and `"always"`.
- AC-2: When `type == "conditional"`, `path` (string, required) and `equals` (any JSON value, required) are surfaced as edge fields.
- AC-3: When `type` is `success` or `always`, `path` and `equals` are forbidden (additionalProperties / oneOf gate).
- AC-4: Schema validation rejects malformed payloads with a clear error message naming the offending field.
- AC-5: Tool surface (handler API, MCP method names, parameter names) is otherwise **unchanged**.
- AC-6: `cargo build --release -p maenifold-cli`.
- AC-7: A new schema unit test covering: valid conditional edge, missing path, missing equals, conditional fields present on a `success` edge.

## Forbidden
- Renaming or restructuring existing schema fields.
- Touching the engine, executor, or UI.

## Build
`CARGO_TARGET_DIR=target/agents/T-174.3 cargo build --release -p maenifold-cli`
`CARGO_TARGET_DIR=target/agents/T-174.3 cargo test -p maenifold-core mcp::schema`
