# T-174.2 — Add `EdgeType::Conditional { path, equals }`

## Why
Today `EdgeType` only has `Success | Always` (`types.rs:210`). Trio consensus (2026-04-15) ranks conditional edges #1 priority — they unlock smart routing (e.g. red-team verdict → swe vs done), subsume agent handoff as a pattern not a primitive, and preserve DAG acyclicity. Sprint 159 gap analysis flags this as 🔴 Critical Gap-1.

## Scope
**Crate:** `maenifold-core` only.
**Files (after T-174.0/1 splits land):** `types.rs`, `engine_ready.rs` (or wherever `is_edge_satisfied` lives), `engine_cascade.rs`, `executor_helpers.rs`, `update_context.rs`, `mapping_predecessor.rs`, `view_mermaid.rs`, `view_nodes.rs`, plus a new test file.

## Design
```rust
#[derive(Serialize, Deserialize, Clone, Debug, PartialEq, Eq)]
#[serde(rename_all = "lowercase")]
pub enum EdgeType {
    Success,
    Always,
    Conditional { path: String, equals: serde_json::Value },
}
```

Wire format (camelCase, matches existing `PipelineEdge` schema):
```json
{ "source": "redteam", "target": "swe", "type": "conditional", "path": "verdict", "equals": "FAIL" }
```

Path resolves against the upstream node's output JSON via the existing `resolve_dot_path` (now in `mapping_resolve.rs`). Equality is JSON value equality (string == string, number == number, bool == bool).

## Acceptance
- AC-1: New `Conditional` variant on `EdgeType`. `match` exhaustiveness errors guide every consumer to handle it.
- AC-2: **Readiness predicate:** `Conditional` is satisfied iff (a) upstream is `Completed`, (b) `resolve_dot_path(upstream.output_json, path)` returns a value equal to `equals`. Update both `executor_helpers.rs` and `update_context.rs` (and unify them — they're duplicates today).
- AC-3: **Cascade rule:** `Conditional` cascades abandonment like `Success` (an upstream that abandons cannot satisfy any predicate). Update `engine_cascade.rs`.
- AC-4: **Predecessor context filter** (`mapping_predecessor.rs`): include the upstream output only if the conditional predicate is satisfied.
- AC-5: **Mermaid:** `Conditional` renders as `-->|?path=value|`. Update `view_mermaid.rs` plus `edge_type_name` JSON serializer in `view_nodes.rs` / `view.rs`.
- AC-6: New file `crates/maenifold-core/src/workflow/pipeline/conditional_edge_tests.rs` covering the **real engine** (no mocks):
  - Fan-out where one Conditional edge fires and another does not.
  - Conditional-only target with no satisfied incoming edge → stays Pending, then cascades correctly when upstream Abandons.
  - Conditional + Always edges to the same target → target activates if Always satisfied even when Conditional is not.
  - Path that does not resolve (missing field) → predicate is false, treated like a non-match (NOT an error — keeps definitions resilient to optional output fields).
  - JSON value types: string equals, number equals, bool equals.
- AC-7: Existing tests in `retry_tests.rs`, `orphan_cascade_tests.rs`, etc. still pass.
- AC-8: `cargo build --release -p maenifold-cli`.
- AC-9: **No backwards-compat shim.** Existing pipelines with `type: "success"` or `type: "always"` continue working unchanged because the wire format is additive.

## Forbidden
- Expression languages, multi-arm conditionals, regex/inequality operators in v1. Equality on a single dot-path only.
- Touching MCP schema, pipeline-ui, validation — those are T-174.3/7/8.
- Editing `types.rs`, `engine.rs`, or `executor_mapping.rs` directly — those files must already be split (T-174.0/1) before this task starts.
