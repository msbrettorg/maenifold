## Summary

Add an "Easter Eggs" section to `SettingsView.vue` with a new `SettingsEasterEggs.vue` component. The UI exposes the wallpaper toggle, mode selector, prompt editor, Azure env var status, slideshow params, and continuity settings.

## Implementation

### 1. Create `apps/desktop/src/components/SettingsEasterEggs.vue`

New component following the pattern of `SettingsMaenifold.vue` and `SettingsPreferences.vue`:

**Controls:**

1. **Wallpaper toggle** — Switch for `enabled`. Label: "Wallpaper slideshow". Description: "Generate AI wallpaper from your knowledge graph."

2. **Mode selector** — `Select` component with 3 options:
   - **Endophasia** — "The inner monologue — renders recent activity as imagery"
   - **Zeitgeist** — "The spirit of the time — one image per concept community"
   - **Self-actualization** — "The self-portrait — maenifold reads its own knowledge graph"

3. **Prompt** — Textarea showing `prompt` value. "Reset to default" button.

4. **Azure configuration** — Three text inputs for env var names:
   - Endpoint env var (default: `AZURE_OPENAI_ENDPOINT`)
   - API key env var (default: `AZURE_OPENAI_API_KEY`)
   - Image model deployment (default: `gpt-image-2`)
   
   Each field shows a green/red dot indicating env var presence. **Never show the actual value.** Use a preload IPC bridge to check presence (see implementation section below).

5. **Slideshow** — Number input for `rotateMinutes` (range 1-60). Number input for `communityCount` (range 1-20, visible only in zeitgeist/self-actualization modes).

6. **Continuity** — Checkbox "Evolve from previous image". When checked, show fidelity selector (`Select` with low/medium/high options). "Reset wallpaper" button — disabled until T-232.8 ships the backend tool.

7. **Preview** — "Generate now" button — disabled until T-232.5 ships the WallpaperStatus backend tool. Shows tooltip "Available when wallpaper service is running."

**State management:**
- Follow the `SettingsMaenifold.vue` pattern (load-mutate-save):
  1. Load full config via `configStore.loadConfig()` (which calls MCP `GetConfig`)
  2. Mutate the `easterEggs.wallpaper` subtree
  3. Save via `mcp.callTool('UpdateSettings', { settings: fullSettingsObject })`
  4. Apply via `configStore.updateFromEvent(nextConfig)`
- Do NOT rely on deep-merge — send the full settings object per existing pattern.

### 2. Add env var presence check via preload IPC

**Electron preload bridge** (`apps/desktop/electron/preload.ts`):

Add a safe IPC method:
```typescript
checkEnvVarPresence: (names: string[]): Promise<Record<string, boolean>>
```

This returns `{ "AZURE_OPENAI_ENDPOINT": true, "AZURE_OPENAI_API_KEY": false }` — booleans only, never values.

**Main process handler** (`apps/desktop/electron/main.ts`):
```typescript
ipcMain.handle('check-env-vars', (_event, names: string[]) => {
  const result: Record<string, boolean> = {};
  for (const name of names) {
    result[name] = !!process.env[name];
  }
  return result;
});
```

Expose via `window.electronAPI.checkEnvVarPresence(names)`.


### 4. Use shadcn-vue components ONLY

Use existing UI primitives:
- `Switch` for toggles
- `Select` for mode selector AND fidelity selector (NOT RadioGroup — not available)
- `Textarea` for prompt
- `Input` for text fields
- `Button` for actions
- `Label` for field labels
- `Checkbox` for continuity toggle

Do NOT use raw HTML controls — the `audit:components` build check rejects them.

### 5. LOC management

If `SettingsEasterEggs.vue` approaches 250 LOC, extract child components:
- `SettingsEasterEggsAzure.vue` — Azure config section with env var indicators
- `SettingsEasterEggsPreview.vue` — Preview/generate controls

Each child must stay under 300 LOC. The audit script enforces this.
