## What this looks like in one sentence

We have an excellent **markdown / WikiLink / Mermaid** pipeline and a real **MCP-apps iframe** (genuinely impressive — that’s the hard one), but the **`resource` content block is wallpaper**: a `<pre>` that ignores mimeType. That single bug demolishes most of the spec’s row C *and* row K3 *and* the “fresh memory write preview” loop the user cares about.

## Architect (claude-opus-4.7) take

The shape is right — one funnel (`ChatContentBlocks`) for ACP/MCP content blocks, with `KnowledgeNoteRenderer` doing markdown/mermaid/wikilinks. The funnel just stops short. The fix is mechanical:

1. In `ChatContentBlocks.vue`’s `resource` branch, switch on `block.resource.mimeType` and `'text' in block.resource`, then dispatch to: KnowledgeNoteRenderer (markdown), Shiki via getMarkdownIt fenced as the language (code/json), `<img>` (image blob), `<audio>` (audio blob), or download chip (everything else). Reuse the existing image/audio/text branches — don’t fork the renderer.
2. Treat `memory://` as a first-class internal link: parse it to a Knowledge-tab route in `onResourceLinkClick`, intercept rather than letting the `<a>` open externally; and surface the title via `useMcpResources` lookup.
3. Add a `resources/read` fetch path for `resource_link` clicks that aren’t `memory://`/external — render the result through the same dispatcher from (1). This is the single biggest UX delta.

After (1)–(3), most of the spec collapses to “done”. Then layer in elicitation (wire `SchemaFormRenderer` to the MCP `elicitation/create` request) and sampling approval as separate sub-tickets.

## Skeptic (gpt-5.5) take

A few cautions before we file ten new tickets:

- **Spec drift on “mcp apps.”** The research doc tells us not to build it; the codebase already shipped `McpAppFrame` against `@modelcontextprotocol/ext-apps`. Decide which doc is canonical and update the other before more reviewers chase the wrong target.
- **The `resource` branch may be intentional placeholder.** Before filing as P0, verify there isn’t a feature flag or a deliberate “v1 = pre” decision recorded somewhere. The git blame on those 6 lines will tell us in 10 seconds.
- **Don’t scope-creep elicitation into this ticket.** Elicitation and sampling are their own surfaces (modal dialogs, request lifecycle, decline/cancel semantics). They deserve their own tickets — file them, link parent T-243.12, but don’t bundle. Otherwise this becomes a swamp.
- **Vega-Lite / Chart.js / Plotly are P2 at best.** Don’t build them on speculation. We have zero data on whether agents in this codebase ever emit those fences. File a P3 “measure first” ticket if anyone cares.
- **Annotations (`audience`/`priority`).** Tempting to skip, but `audience: ["assistant"]` content currently leaks into the user’s chat view. That’s a small **correctness** issue, not just a polish one. Worth a P2 with a clear acceptance test.
- **Pagination/virtualization is a footgun.** A 5 MB base64 image dumped into a `<pre>` will hang the renderer today. Even after we fix row C, set a defensive byte cap in the dispatcher.
