# T-241.6 — Azure configuration env var detection broken

**Pipeline**: sdd

## Problem

The Settings → Maenifold → Azure configuration section shows red dots for "API key env var" (AZURE_OPENAI_API_KEY) and "Image model deployment" (gpt-image-2) even when the env vars are set in the environment. The feature was shipped without interactive testing.

The "Recheck" button may also not work — needs verification.

## Evidence

- Screenshot: Settings → Maenifold shows:
  - ● green: Endpoint env var (AZURE_OPENAI_ENDPOINT) — detected
  - ● red: API key env var (AZURE_OPENAI_API_KEY) — NOT detected despite being set
  - ● red: Image model deployment (gpt-image-2) — NOT detected/working
- This feature was never CDP-tested

## Investigation Required

1. How does the frontend check for env var presence? Does it call an MCP tool or read config?
2. Does the Electron app inherit shell env vars? (Electron apps launched from Finder don't inherit shell env vars — only apps launched from terminal do)
3. Is the backend check looking for the right env var name?
4. Does the "Recheck" button trigger the right backend call?
5. Is the image model deployment check calling Azure to verify the deployment exists?

## Acceptance Criteria

- [ ] All three Azure config items show correct status (green when env var is set)
- [ ] "Recheck" button works and updates status
- [ ] Feature verified via CDP interactive testing
