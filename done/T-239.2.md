**Pipeline**: sdd

## Contract

`TeamsMonitorConfig` must store non-secret monitor settings:

- `enabled`
- `identity`
- `keyword`
- `listenScope`
- `monitoredConversations`
- `replyBehavior`
- `replyPrefix`
- `dispatchTimeoutMinutes`
- `dispatchAgent`
- connection defaults needed by Trouter, including `chatsvcRegion`

MCP must expose:

- `TeamsMonitor status` with connection state, auth state, expiry, detected identity, config, last auth error, and last connection error.
- `TeamsMonitor detect_identity` for explicit retry from UI/AI clients.
- `TeamsMonitor configure` for keyword, listen scope, reply behavior, reply prefix, timeout, dispatch agent, and backend-detected identity state.
- `TeamsMonitor enable` that acquires a signed-in Teams token, detects identity, persists non-secret identity/config, and starts the supervisor.
- `TeamsMonitor refresh` using the same provider.
- `TeamsMonitor sign_out` that clears token/cache state without deleting non-secret monitor config.
- `teams://status` and `teams://config` with the same non-secret state.

MCP must not expose the old app-registration flow as a current public surface:

- remove `authenticate`, `authenticate_start`, and `authenticate_complete` from the advertised action enum/schema/docs
- remove `clientId`, `tenantId`, and `scopes` from user-facing TeamsMonitor parameters
- delete or rewrite `tools/teams_monitor_auth.rs` so `authenticate_start`, `authenticate_complete`, `persist_auth_ids`, and pending device-code state are gone
- delete or quarantine `teams/auth.rs` device-code types (`TeamsAuth`, `DeviceCodeInfo`, `TokenInfo`) so the binary has no monitor enablement path that requires app-registration IDs
- T-239.1 owns `teams/mod.rs`; this task consumes its exported token/identity provider and must not edit `teams/mod.rs`

## Acceptance Criteria

- [ ] `TeamsMonitor enable` no longer returns “run authenticate_start first” for missing app-registration IDs.
- [ ] `clientId` and `tenantId` are not required operational inputs for new Teams Monitor enablement.
- [ ] `authenticate*`, `clientId`, `tenantId`, and `scopes` are not advertised in MCP schema, tool usage docs, or desktop-facing status/config responses.
- [ ] Invoking removed legacy auth actions returns an explicit unsupported-action error and does not start a device-code flow.
- [ ] The binary contains no Teams Monitor enablement code path that requires `clientId` or `tenantId`; deserializing legacy config fields is allowed only for migration and they are ignored.
- [ ] Existing configs deserialize safely while new config is agency-cowork-shaped.
- [ ] MCP status/config never expose bearer tokens.
- [ ] Auth and detection errors are structured and visible in MCP responses.
- [ ] Tool usage docs describe signed-in identity detection, not app-registration setup.
