## Problem

The Gate tab still uses a dedicated gate MCP path through `useGateMcp`, with `DEFAULT_GATE_MCP_BASE_URL = http://localhost:8081/mcp`. That conflicts with the new operating model: gate is no longer directly configured as a Copilot MCP server and should be reached through maenifold's gateway service.

Other tabs use the shared maenifold MCP client path (`useMcpClient` / `usePipelineMcp`) and route tool calls through `GatewayIndex` + `GatewayExecute`. The Gate tab needs to follow the same pattern so the UI and AI use one backend surface.

## Evidence

- `apps/desktop/src/components/GateView.vue` imports `useGateMcp`
- `apps/desktop/src/composables/useGateMcp.ts` creates a shared MCP client using `DEFAULT_GATE_MCP_BASE_URL`
- `apps/desktop/src/lib/constants.ts` defines `DEFAULT_GATE_MCP_BASE_URL = 'http://localhost:8081/mcp'`
- `apps/desktop/src/composables/usePipelineMcp.ts` uses the shared maenifold client path

## Scope Notes

- Gate must use the shared maenifold client/session path already used by other tabs.

- If packaged-app verification fails because maenifold auth/session is unavailable after restart, treat that as blocked by `T-235.9`, not as a reason to backdoor the Gate tab.
