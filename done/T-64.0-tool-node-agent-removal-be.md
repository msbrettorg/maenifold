# T-64.0 — Remove `agent` from ToolNode (BE)

**Requirement**: FR-13

## Acceptance Criteria

- `agent` field is optional (not required) on Tool variant in types.rs
- Tool node validation in mod.rs does NOT require agent for tool nodes
- Executor guard at executor.rs:111-125 does NOT abandon tool nodes when acp_client() is None
- Unused `agent` param removed from `run_tool_node` signature
- Wire format backward compat: old pipelines with agent on tool nodes still deserialize
- All existing pipeline tests pass
- `cargo test -p maenifold-core -- pipeline` green

## Context

Tool nodes execute via `ToolRegistry::global().try_invoke()` — direct MCP call, no agent involved. The `agent` field is validated and checked but never used for invocation. It causes silent abandonment when acp_client() returns None.

See: `memory://build/architecture/pipeline-t64-architectural-intent-analysis` Section 5.
