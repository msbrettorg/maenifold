## Problem

The gate MCP server was removed from the Copilot MCP config so gate must now be reached through the maenifold gateway service. The Copilot CLI maenifold MCP service is not available, even though the desktop UI appears to connect to the backend/gateway path.

This is suspicious because AI and UI are supposed to share the same MCP-backed backend surface. If the UI can connect but the agent cannot, either the agent config, transport endpoint, gateway exposure, or service startup path is inconsistent.

## Scope Notes

- Focus this task on the Copilot CLI / agent path to the maenifold HTTP MCP endpoint
- Preserve bearer-token auth; do not “fix” this by making `/mcp` unauthenticated
- Do not use this task to fix gateway-domain reload or Gate-tab direct-8081 issues; those belong to `T-235.12` and `T-235.14`
- Docs-only guidance is not sufficient by itself; this task requires a repo-owned remediation that makes authenticated Copilot access survive a maenifold restart

## File / Surface Scope

- `crates/maenifold-core/src/api/auth.rs`
- `crates/maenifold-core/src/mcp/http.rs`
- `assets/integrations/skills/maenifold/SKILL.md`

## Required fix class

The intended remediation for this task is:

1. Make the maenifold HTTP bearer token stable across normal `maenifold --http` restarts unless it is missing or invalid, so a Copilot/agent config does not break on every restart.
2. Document the authenticated Copilot configuration requirement for the maenifold MCP endpoint as a one-time setup, not a per-restart manual recovery step.

Do **not** satisfy this task with:

- unauthenticated `/mcp`
- a docs-only workaround with no repo-owned product fix
- a fix that still requires re-editing Copilot auth headers after every maenifold restart

## Observed Evidence

- A local process is listening: `/usr/local/bin/maenifold --http --port 8080`
- The packaged Electron UI process is running from `apps/desktop/out/maenifold-darwin-arm64/maenifold.app`
- Copilot CLI does not expose maenifold MCP tools in the current tool surface
- Unauthenticated `POST http://127.0.0.1:8080/mcp` returns `401 Unauthorized` with `missing or invalid bearer token`
- The same endpoint succeeds when called with the local bearer token from `~/maenifold/auth/localhost.token`
- `GatewayIndex` exposes maenifold gateway domains but not `gate`
- Direct `http://127.0.0.1:8081/mcp` gate HTTP is not listening
- `UpdateMcpServer` accepted `gate` as `stdio` with `gateway: true` and `ReloadConfig` returned success, but `GatewayIndex({ domain: "gate" })` still returned `Unknown gateway domain 'gate'`
