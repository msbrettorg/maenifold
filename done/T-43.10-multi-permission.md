# T-43.10: Multiple pending permission requests

**Requirement**: Prompt-turn audit gap  
**Priority**: P0  
**Files**: `vendor/acp-ui/src/lib/acp-bridge.ts`, `vendor/acp-ui/src/stores/session.ts`

## Acceptance Criteria

1. Replace the singleton `pendingPermissionRequest` / `permissionResolver` in `acp-bridge.ts` with a `Map<string, { request, resolver }>` keyed by request ID (or tool call ID).

2. `requestPermission()` should add to the map, not overwrite a single slot.

3. `resolvePermission(optionId)` should resolve the specific pending request, not just the one slot.

4. `cancelPermission()` must iterate ALL pending permission requests and resolve each with `{ outcome: 'cancelled' }`.

5. `cancelOperation()` in session.ts must call `cancelPermission()` which now cancels ALL pending requests per the spec's MUST.

6. The UI (`PermissionDialog`) may need to queue/stack multiple permission dialogs, or show them in sequence.

## SWE Remediation

- **What I changed**
  - `vendor/acp-ui/src/lib/acp-bridge.ts`: Replaced the singleton pending permission state with a `Map<string, { request, resolver }>` keyed by tool call ID, updated `requestPermission()` to enqueue requests, updated permission resolution to target a specific request, and made `cancelPermission()` resolve every pending request as cancelled.
  - `vendor/acp-ui/src/stores/session.ts`: Switched the store to track a queued `pendingPermissions` list plus the active `pendingPermission`, synchronized the list from the bridge, routed permission approval through the active tool call ID, and ensured `cancelOperation()` cancels all pending permissions.
  - `vendor/acp-ui/src/components/PermissionDialog.vue`: Added queue messaging so the dialog can present multiple permission requests sequentially.
  - `vendor/acp-ui/src/App.vue`: Passed the pending permission count into the dialog host.
  - `vendor/acp-ui/src/components/ChatView.vue`: Surfaced the number of queued permission requests while the session is waiting on review.

- **Test results**
  - PASS — `cd vendor/acp-ui && npx vue-tsc --noEmit`
  - PASS — `cd vendor/acp-ui && bun run build`

- **Notes**
  - I used `toolCall.toolCallId` as the stable permission key, which satisfies the spec's "request ID (or tool call ID)" requirement without introducing a new UI-facing identifier.
  - The UI now shows pending permission requests in sequence rather than stacking multiple modals at once.

## Red-team Audit

**Verdict: PASS**

All acceptance criteria verified:

- **AC1 — Singleton replaced with Map**: ✅ `acp-bridge.ts` declares `private pendingPermissionResolvers: Map<string, PendingPermissionEntry> = new Map()` (keyed by `toolCallId` via `getPermissionRequestKey()`). The old singleton fields are gone.

- **AC2 — `requestPermission()` enqueues, not overwrites**: ✅ `requestPermission()` calls `this.pendingPermissionResolvers.set(key, { request, resolver })` and then `syncPendingPermissionRequests()` — a new entry is added for each request. (Duplicate `toolCallId` keys would overwrite, but that case is semantically invalid in ACP and would indicate an agent bug.)

- **AC3 — `resolvePermission()` targets a specific request**: ✅ Signature changed to `resolvePermission(requestId: string, optionId: string)`. In `session.ts`, the store routes through the active request's `toolCallId`: `acpClient.resolvePermission(activePermission.toolCall.toolCallId, optionId)`. After resolution the entry is deleted and `syncPendingPermissionRequests()` advances the queue.

- **AC4 — `cancelPermission()` resolves ALL pending requests as cancelled**: ✅ In `acp-bridge.ts`, `cancelPermission()` snapshots the map, clears it, then iterates every entry resolving each with `{ _meta: null, outcome: { outcome: 'cancelled' } }`. All in-flight permission requests are cancelled atomically.

- **AC5 — `cancelOperation()` calls `cancelPermission()`**: ✅ `session.ts` line 1033: `cancelOperation()` checks `pendingPermissions.value.length > 0 || acpClient.pendingPermissionRequests.value.length > 0` and calls `cancelPermission()`. The double-check against both the store array and the bridge reactive ref guards against watch-sync races.

- **AC6 — UI shows multiple permission requests sequentially**: ✅ `PermissionDialog.vue` accepts a `totalPending?: number` prop and renders "Showing request 1 of N. The remaining requests will appear after you respond." when `totalPending > 1`. `App.vue` passes `:total-pending="pendingPermissionCount"` (derived from `sessionStore.pendingPermissions.length`). `ChatView.vue` surfaces "N permission requests awaiting review" inline during a session.
