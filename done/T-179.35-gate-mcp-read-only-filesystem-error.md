# T-179.35 — Gate MCP server: read-only file system error (os error 30)

**Pipeline**: tdd
**Priority**: P1

## Problem

When the gate MCP server is accessed via MCP, the following error occurs:

```
MCP server 'gate': io error: Read-only file system (os error 30)
```

This prevents all gate MCP operations from functioning.

## Root Cause Hypothesis

The gate process is likely attempting a filesystem write (`.gate/gate.db` creation or SQLite WAL/journal) relative to a path that is read-only. On macOS, this commonly occurs when:

1. The gate binary is launched from an app bundle or signed container where the CWD is inside a read-only volume
2. The `default_root` or `bound_root` resolves to a read-only path
3. SQLite tries to create journal/WAL files adjacent to `gate.db` in a protected location

## Prior Art

- **T-117** implemented per-session root binding (`bound_root: Mutex<Option<PathBuf>>` + `default_root: Option<PathBuf>`). Root resolution chain: explicit param → bound_root → default_root → error.
- Gate sync creates `.gate/` and writes `gate.db` inside it.

## Acceptance Criteria

1. Identify the exact write operation that triggers os error 30
2. Ensure the gate MCP server handles read-only filesystem gracefully — either by:
   - Requiring `--root` at startup and validating write access before accepting connections
   - Returning a clear MCP error response explaining the root is not writable, with the path that failed
   - Falling back to a writable temp location for the cache if the project root's `.gate/` is not writable
3. The fix must not regress per-session root isolation (T-117)
4. Error message must include the path that failed and suggest `--root <writable-path>`

## Files of Interest

- `crates/maenifold-gate/src/mcp/mod.rs` — handler, root resolution
- `crates/maenifold-gate/src/mcp/http.rs` — HTTP transport config
- `crates/maenifold-gate/src/db.rs` — SQLite operations (likely write site)
- `crates/maenifold-gate/src/sync.rs` — sync creates `.gate/` dir
