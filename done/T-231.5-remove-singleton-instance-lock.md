# T-231.5 — Remove Singleton Instance Lock for Parallel UAT

**Pipeline**: lightweight
**Pipeline Digest**: 5e87c1e63e7e75a984367a8bd7e97027a94e10eb16bd17b0e86e89b1f92b0e6c

## Problem

`apps/desktop/electron/main.ts:231` calls `app.requestSingleInstanceLock()` which prevents launching multiple copies of the app. A second launch silently exits with code 0 and focuses the existing window.

This blocks parallel UAT — we can't run multiple app instances on different CDP ports for concurrent agent testing.

## Why the lock exists

Standard Electron "bring existing window to front" UX pattern. Prevents users from accidentally running two copies. No shared state, file locks, or port conflicts to protect — the backend handles multiple clients fine.

## Fix

Remove the singleton lock entirely. The app has no technical reason to be single-instance. Each copy gets its own renderer, its own MCP connection, its own CDP port.

In `apps/desktop/electron/main.ts`, replace lines 231-250:
- Remove the `requestSingleInstanceLock()` check
- Remove the `second-instance` event handler
- Keep the `app.whenReady()` block and other event handlers at top level

- [ ] Each copy connects to the backend independently
