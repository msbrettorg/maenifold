# T-67.3: Handle Additional SessionUpdate Variants

## Requirement
FR-50 — Native ACP client must capture tool calls and agent thoughts, not just text.

## Problem
`HeadlessClient::session_notification` handles only `AgentMessageChunk(Text)` — 1 of 11 possible update types. The remaining 10 are silently dropped:
- `AgentThoughtChunk` — agent reasoning (useful for debugging/audit)
- `ToolCall` / `ToolCallUpdate` — tool execution (critical for pipeline visibility)
- `Plan` — structured task breakdown
- `AvailableCommandsUpdate` — slash commands
- `CurrentModeUpdate` / `ConfigOptionUpdate` / `SessionInfoUpdate` — session state changes
- `UserMessageChunk` — echo of user input
- Non-Text `AgentMessageChunk` blocks (Image, Resource, ResourceLink)

`AcpxResponse.tool_calls` is hardcoded to `Vec::new()` — the `ToolCallRecord` type exists but is dead code.

## Acceptance Criteria
1. `HeadlessClient` must accumulate `ToolCall` events into a `Vec<ToolCallRecord>`
2. `HeadlessClient` must accumulate `AgentThoughtChunk` text into a separate `thought_buf`
3. `AcpxResponse` must return populated `tool_calls` from accumulated data
4. `AcpxResponse` must include a new `thought: Option<String>` field with accumulated thinking
5. Non-Text `AgentMessageChunk` variants should be logged at debug level (not silently dropped)
6. `AvailableCommandsUpdate` should be logged at info level

## Files to modify
- `crates/maenifold-core/src/acp/native.rs` — `HeadlessClient` session_notification match arms
- `crates/maenifold-core/src/acp/native.rs` — `AgentResponse` / response accumulation
- `crates/maenifold-core/src/workflow/agent_session.rs` — pass through tool_calls and thought

## Reference
- `../pipeline-ui/src/composables/useMessageHandler.ts` → `handleSessionUpdate()` switch
- `agent-client-protocol-schema` `SessionUpdate` enum (11 variants)

## Tests

## SWE Remediation

- **What changed**
  - `crates/maenifold-core/src/acp/native.rs`
    - Added per-session `SessionAccumulator` state so prompt handling now collects assistant text, agent thought text, and tool call state together.
    - Extended `HeadlessClient::session_notification()` to:
      - accumulate `AgentThoughtChunk` text,
      - record `ToolCall` notifications,
      - apply `ToolCallUpdate` changes onto tracked tool calls,
      - log non-text `AgentMessageChunk` content at debug level,
      - log `AvailableCommandsUpdate` at info level,
      - log `Plan`, `CurrentModeUpdate`, `ConfigOptionUpdate`, `SessionInfoUpdate`, `UserMessageChunk`, and other/unhandled updates at debug level.
    - Extended `AgentResponse` / `AcpxResponse` with `tool_calls` passthrough and `thought: Option<String>`.
    - Mapped ACP `ToolCall` records into the existing `ToolCallRecord` response shape.
  - `crates/maenifold-core/src/workflow/agent_session.rs`
    - Passed through `tool_calls` and `thought` from the native ACP response instead of hardcoding empty tool call results.

- **Test results**
  - **PASS** — `cargo test -p maenifold-core --lib -- --nocapture 2>&1 | tail -10`
  - **PASS** — `cargo build -p maenifold-core 2>&1 | tail -10`

- **Notes / decisions**
  - Used a single session accumulator instead of parallel hash maps so all streamed prompt state stays synchronized and can be removed atomically when a prompt completes.
  - `ToolCallUpdate` notifications are applied to tracked tool calls when possible so returned tool call status/title/arguments stay current; the update is also logged at debug level per spec guidance.
  - `thought` is returned as `None` when only whitespace was accumulated to avoid emitting empty strings.
