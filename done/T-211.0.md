# T-211.0 — Scheduled Tasks

## Vision

Schedule recurring agent tasks that run autonomously. "Every morning at 9am, triage my inbox." "Every Monday, generate a sprint report." Uses OS-native scheduling (launchd on macOS, systemd on Linux). Tasks dispatch via ACP through the maenifold MCP server. Results render as normal sessions in the UI.

## Architecture

```
User creates schedule (UI or natural language)
    ↓
maenifold writes launchd plist / systemd timer
    ↓ OS fires at scheduled time
Supervisor script: maenifold tool AcpExec '{"agent":"...","prompt":"..."}'
    ↓ ACP session
Results stored as session, visible in UI
```

### Design principles (from opencode-scheduler, improved)

- **OS-native scheduling.** launchd on macOS, systemd --user on Linux. No custom poll loops. The OS handles missed runs, sleep/wake, boot persistence.
- **Supervised execution.** Lock files prevent overlap. Timeout with SIGTERM→SIGKILL. Non-interactive by default (auto-approve permissions).
- **Scoped by workspace.** Each maenifold root gets its own schedule namespace. No collision between projects.
- **MCP-native.** Everything exposed as MCP tools and resources. The UI is just a view.

### What already exists

- `AcpExec` MCP tool — dispatches agent sessions
- `maenifold tool` CLI — invokes any MCP tool from shell
- `maenifold --http` — HTTP MCP endpoint for scripted access
- Pipeline engine — for multi-step scheduled workflows
- Session persistence — results visible in UI after completion
- launchd experience — maenifold + gate already run as launchd services

### What we build

1. **Schedule manager** — Rust, in `maenifold-core`. CRUD for scheduled jobs. Writes/reads launchd plists and systemd timers. Stores job config in `~/maenifold/schedules/`.

2. **Supervisor script** — Shell script installed at `~/maenifold/bin/schedule-supervisor.sh`. Called by OS scheduler. Acquires lock, runs `maenifold tool AcpExec`, logs output, releases lock. Handles timeout.

3. **MCP tools:**
   - `Schedule { action: "create" | "update" | "delete" | "list" | "get" | "run_now" | "logs" }`
   - Natural language cron parsing: "every weekday at 9am" → `0 9 * * 1-5`

4. **MCP resources:**
   - `schedule://jobs` — list all scheduled jobs
   - `schedule://job/{id}` — job detail + last run status
   - `schedule://logs/{id}` — recent execution logs

5. **UI: Schedules section in Settings** — shadcn Table for job list, Dialog for create/edit, Badge for status (active/paused/failed), Switch for enable/disable. No custom components.

## Cron syntax

Standard 5-field, same as opencode-scheduler:
```
┌─ minute (0-59)
│ ┌─ hour (0-23)
│ │ ┌─ day of month (1-31)
│ │ │ ┌─ month (1-12)
│ │ │ │ ┌─ day of week (0-6, Sun=0)
* * * * *
```

Natural language mapping built into the MCP tool — agent says "every weekday at 9am", tool parses to `0 9 * * 1-5`.

## Storage

| What | Where |
|------|-------|
| Job configs | `~/maenifold/schedules/{id}.json` |
| Run logs | `~/maenifold/logs/schedules/{id}/*.log` |
| Lock files | `~/maenifold/schedules/locks/{id}.lock` |
| Supervisor | `~/maenifold/bin/schedule-supervisor.sh` |
| launchd plists | `~/Library/LaunchAgents/com.ma-collective.schedule.{id}.plist` |
| systemd units | `~/.config/systemd/user/maenifold-schedule-{id}.{service,timer}` |

- ❌ No custom UI components — shadcn Table/Dialog/Badge/Switch

- ❌ No embedded cron library — use the `cron` crate for parsing
