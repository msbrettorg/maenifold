# T-218.43 — Canonical Split-Pane Layout

## Problem

Column-heavy desktop pages have inconsistent, janky horizontal resizing. The Knowledge tab demonstrates the failure clearly: the visible resize handle moves, but the folder/tree pane does not visually resize with it because the sidebar content does not fill its resizable panel. Similar risks exist wherever pages wire low-level `ResizablePanelGroup`, `ResizablePanel`, and `ResizableHandle` directly.

The design system already has low-level resizable primitives under `components/ui/resizable/`, but it does not provide a canonical app-level split-pane layout that guarantees pane fill, min-width behavior, persisted widths, overflow containment, and consistent handle affordance.

## Evidence

- Screenshot: Knowledge tab resize handle is disconnected from the tree pane.
- `apps/desktop/src/components/KnowledgeExplorer.vue` uses `ResizablePanelGroup` directly.
- `apps/desktop/src/components/KnowledgeSidebar.vue` renders an `<aside>` with `h-full min-w-0` but no `w-full`, so the child can fail to fill the resized panel.
- Other direct resizable users include:
  - `apps/desktop/src/components/GateViewContent.vue`
  - `apps/desktop/src/components/WorkflowAuthoringPage.vue`

## Implementation Plan

Based on discovery findings: the root cause is missing `w-full` on inner wrapper divs, plus three inconsistent implementations with ~50 lines of copy-pasted manual localStorage persistence boilerplate. Reka UI's `autoSaveId` on `SplitterGroup` provides free built-in persistence — WorkflowAuthoring already uses it correctly with zero custom code.

### Step 1: Fix the Knowledge tab resize bug

Add `w-full` to inner wrapper `<div>` elements at lines ~204 and ~217 in `KnowledgeExplorer.vue` so panel content fills the allocated width. (Note: `KnowledgeSidebar.vue` already has `w-full flex-1` — no changes needed there.)

### Step 2: Migrate Knowledge and Gate to `autoSaveId`

Replace the manual localStorage persistence in both `KnowledgeExplorer.vue` and `GateViewContent.vue`:
- Delete: `clamp()` helper, `readStoredRatio()`/`writeStoredRatio()`, `ResizeObserver` setup for pixel→percentage min-size, `handleLayout()` event handler
- Add: `autoSaveId="knowledge-layout"` (or `"gate-layout"`) prop on `ResizablePanelGroup`
- Use static percentage `minSize` props on `ResizablePanel` instead of dynamic pixel→percentage calculation
- This deletes ~50 LOC per file (~100 total) and replaces with ~5 LOC each

### Step 3: Standardize handle styling

Knowledge and Gate already use the same long Tailwind handle class string. WorkflowAuthoring uses the default. Unify by promoting the class to the `ResizableHandle.vue` wrapper as a default slot/prop, or extract a shared handle class constant. All three pages should use the same pattern after this step.

### Migration note: localStorage key change

Switching from manual persistence to `autoSaveId` changes the storage key format (old: `knowledge-splitter-ratio`, new: `reka:<autoSaveId>`). Old keys will be silently ignored — users get a one-time reset to default ratios. This is acceptable. Do NOT add migration code for the old keys.

### MinSize values

Use static percentage `minSize` props: sidebar/left pane `minSize={15}`, content/right pane `minSize={30}`. These approximate the current pixel-based minimums at typical viewport widths.

### Step 4: Document in DESIGN.md

Add a "Split-Pane Layout" section to `apps/desktop/DESIGN.md` covering:
- Use `autoSaveId` for persistence (never manual localStorage)
- Inner content filling pattern: `h-full w-full min-w-0` on all panel children
- Handle styling convention
- Min-size conventions (use percentages, not pixels)
