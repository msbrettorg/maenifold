# T-235.1 — Frontend callTool Must Route Through GatewayExecute

**Pipeline**: sdd
**Pipeline Digest**: f1e9e87a3b94825e24ef1d1a1d3c03f21f6e20e0dbff56e5e4e43e6883fc5aa8

## Priority

**P0 — Blocks all UI tool calls**

## Problem

Every callTool() from the frontend sends bare tool names via MCP tools/call. The backend gateway intercepts ALL tool names except GetHelp and ReadMcpResource, returning -32602.

## Fix

Desktop MCP client must:

- build a toolName -> domain map from `GatewayIndex` when the connected server exposes the gateway surface
- route non-passthrough tool calls through `GatewayExecute`
- preserve direct passthrough behavior for `GetHelp`, `ReadMcpResource`, and gateway control-plane tools
- avoid assuming every MCP server exposes `GatewayIndex`

Current worktree evidence already includes desktop routing changes in
`apps/desktop/src/composables/mcpClientOps.ts` and
`apps/desktop/src/composables/mcpGatewayRouting.ts`, plus gateway-first doc
updates in `docs/gateway-surface-contract.md`.
