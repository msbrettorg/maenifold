# T-43.17: Clean stdio for ACP — remove login shell wrapper

**Requirement**: Transports audit gap  
**Priority**: P1  
**Files**: `crates/maenifold-app/src/agent.rs`

## Acceptance Criteria

1. The current agent launcher uses the user's login shell (`-l -c`) on Unix. This means shell startup files (`.bashrc`, `.zshrc`, `.profile`) can emit text to stdout before the agent speaks JSON-RPC, contaminating the ACP stdio channel.

2. Change the subprocess spawning to use a non-login shell (`-c` without `-l`), OR spawn the agent binary directly without a shell wrapper when possible.

3. If a shell wrapper is still needed (for PATH resolution), use `-c` only (not `-l -c`) to avoid loading login profiles.

4. Alternatively, add a startup-output filter in the stdout reader: discard lines until the first valid JSON-RPC message is received.

## SWE Remediation

- **What I changed**
  - `crates/maenifold-app/src/agent.rs`: updated the Unix agent launcher to keep shell-based PATH resolution but invoke the shell with `-c` only, removing the `-l` login-shell wrapper so shell profile output cannot contaminate the ACP stdio channel.

- **Test results**
  - PASS — `cargo build -p maenifold-app`
  - FAIL — `cargo build --release -p maenifold-cli --features web` (workspace currently reports that `maenifold-cli` does not define a `web` feature)

- **Notes**
  - I used the non-login shell approach from the spec rather than changing process launching to a direct binary spawn.
  - `crates/maenifold-app/src/agent.rs` already had additional in-progress modifications in the working tree outside this remediation; I limited my change to the login-shell removal in the launcher block.
