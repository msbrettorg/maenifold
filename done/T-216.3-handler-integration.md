# T-216.3 — MaenifoldHandler Integration

**Pipeline**: sdd
**Priority**: P1

## Scope

Modify `MaenifoldHandler` in `crates/maenifold-core/src/mcp/http.rs` and `mod.rs` to use consolidated gateway tools instead of flat exposure.

## What to Change

### `list_tools` (tools/list response)

Currently returns: `native_tools ++ gateway_tools` (all flat).

Change to: `native_tools ++ consolidated_facade_tools ++ passthrough_flat_tools`

Where:
- `consolidated_facade_tools` = one facade per server with 4+ tools
- `passthrough_flat_tools` = individual tools from servers with ≤3 tools

### `call_tool` (tools/call dispatch)

Currently: `ToolRoutingRegistry.lookup(name)` → if found, route to `StdioPool`.

Add: if `name` matches a consolidated server facade:
1. Parse args as `{ intent?, command?, learn?, parameters? }`
2. Delegate to `gateway_dispatch` logic from T-216.2
3. For direct command dispatch, call `StdioPool::call_tool(server, command, params)`

Existing native tool dispatch is unchanged.

### Startup wiring

In `gateway_startup.rs` `build_gateway()`:
- After `StdioPool::start()`, call `build_consolidated_tools(pool.all_gateway_tools())`
- Store both `ConsolidatedServerTool` list and `ToolRoutingRegistry` (for direct routing)
- Pass consolidated tools to `MaenifoldHandler`

## Acceptance Criteria

- [ ] `tools/list` returns ≤50 tools total
- [ ] Native tools still appear individually
- [ ] Each gateway server with 4+ tools appears as one facade
- [ ] Facade tool calls route correctly to upstream tools
- [ ] Learn mode returns catalog/schema
- [ ] Direct command dispatch works end-to-end
- [ ] `cargo build --release -p maenifold-cli` succeeds
