## Intent

Prevent regression after Sprint 176 by enforcing [[Fluent 2]] token compliance and visual stability in CI.

## Scope

1. Add design lint rule set using the existing repo lint engine (ESLint or Stylelint as present in `apps/desktop/package.json`):
   - Disallow hex color literals in `.vue`, `.ts`, `.tsx`, `.css`
   - Allowlist exceptions: `apps/desktop/src/assets/tailwind.css` (token source) and `apps/desktop/components.json`
   - Enforce token usage via CSS variables/Tailwind utilities.
2. Add lint rule rejecting component-local CSS border declarations:
   - Reject `border:`, `border-color:`, and `border-style:` in component-level styles
   - Enforce border usage through tokenized Tailwind utilities (`border-subtle`, `border-card`) instead.
3. Add `pnpm lint:design` script in `apps/desktop/package.json` to run both guardrails.
4. Add visual baseline test suite (Playwright is already present) for these surfaces:
   - Home dashboard
   - Gate view
   - Knowledge explorer
   - Chat surface
   - Pipeline canvas
   - Store baselines under `apps/desktop/tests/visual/baselines/`
   - CI fails when pixel diff exceeds 1%.
5. Wire `lint:design` and visual diff checks into existing PR CI workflow(s) under `.github/workflows/`.

## Acceptance Criteria

1. `pnpm lint:design` exits 0 on a clean repository.
2. Introducing `color: #4d8eff` in any `.vue` file fails lint.
3. Introducing `border: 1px solid red` in any `.vue` `<style>` block fails lint.
4. Visual baselines exist for home dashboard, gate view, knowledge explorer, chat surface, and pipeline canvas.
5. CI runs `lint:design` and visual diff checks on every PR.

## Files In Scope

- `apps/desktop/.eslintrc.*` or `apps/desktop/.stylelintrc.*`
- `apps/desktop/package.json`
- `apps/desktop/tests/visual/**`
- `.github/workflows/*.yml`

## Out Of Scope

- Fixing existing design violations (handled by T-176.11 and T-176.12).
- Refactoring feature components for visual updates beyond guardrail enablement.
