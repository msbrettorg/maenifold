# T-68.2 — Gate Registry and Auto-Register

**Requirement**: FR-68
**Status**: pending

## Summary

Add a system-wide registry so the gate HTTP daemon knows which project roots exist. `gate sync` auto-registers the project root. A new `gate_list_gates` MCP tool exposes the registry. The `directories` crate resolves platform-appropriate paths.

## Acceptance Criteria

1. Registry file at `~/Library/Application Support/com.ma-collective.gate/registry.json` (macOS via `directories::ProjectDirs`)
2. `gate sync <ROOT>` auto-registers the root in the registry after successful sync
3. Registration is idempotent — syncing the same root twice doesn't create duplicates
4. Registry format: `{"gates": [{"root": "/abs/path", "name": "dir-name", "registered_at": "ISO8601"}]}`
5. New MCP tool `gate_list_gates` returns the registry contents as JSON
6. `gate_list_gates` requires no session binding — works immediately
7. `directories` crate added as a non-optional dependency (registry is available in both CLI and app modes)
8. Tests guard against writing to production registry (use temp dirs or env override)
9. All existing 95 tests pass
10. Both feature configurations build clean

### RT-68.7-A — MEDIUM: No file locking on registry save

auto_register_at does load→mutate→save with no file lock. Two concurrent gate sync invocations on different roots will race: one read wins, the other's entry is silently dropped. Low probability in normal dev use but possible in parallel CI. Fix: atomic rename pattern (write to registry.json.tmp, fs::rename over target).

### RT-68.7-B — LOW: /var/folders is a macOS-only hardcode

is_temp_root() contains root.starts_with("/var/folders") which is macOS-specific. Harmless on Linux (never matches). The TMPDIR env branch already covers the macOS case when TMPDIR is set. This branch only fires when TMPDIR is unset, which is atypical. Guard with #[cfg(target_os = "macos")] or rely on TMPDIR + /tmp + std::env::temp_dir().

### RT-68.7-C — LOW: Hand-rolled Gregorian calendar

format_timestamp + civil_from_days implement ISO8601 without chrono/time. Algorithm is correct (Hinnant) but only one test case (epoch+90123 secs). No coverage of leap years, month rollover, pre-epoch timestamps. Either expand tests or use the time crate already in workspace.

### Informational
- auto_register_at updates registered_at on re-registration. Spec only says no duplicates — benign but undocumented.
- normalize_root fallback preserves raw path when canonicalize fails: could theoretically create two entries for the same real path if first registered before directory exists.
