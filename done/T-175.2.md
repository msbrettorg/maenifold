# T-175.2 — Pipelines: polish view shell (status, runner panel, empty state)

**Pipeline**: sdd
**State**: pending

## Context

The Pipelines tab works but reads utilitarian. Three rough edges:

1. **Runner panel toggle** is a single `▲ / ▼` glyph in the right corner — discoverability is poor; users don't realise the bottom panel collapses.
2. **Pipeline status** (`active | completed | stuck | abandoned`) is exposed only as small text in the runner header. The Vue Flow canvas has no top-of-canvas badge so a glance does not tell you whether a pipeline is mid-run, completed, or wedged.
3. **Empty state** when entering Pipelines with no current pipeline: `TemplateGallery` renders, but the entry surface has no clear "browse existing" affordance — flyout discovery requires clicking the rail icon.

Repo: `/Users/brett/src/ma-collective/maenifold-rs`

## Acceptance Criteria

- Runner panel toggle is a labelled control ("Runner" / chevron) with hover tooltip `Show runner` / `Hide runner`. Keyboard `Esc` while focused does not close the flyout (don't break the existing `handleWindowKeyDown`).
- A pipeline status badge renders top-left of the Vue Flow canvas (above the controls) with one of: `active` (blue), `completed` (sage), `stuck` (terracotta), `abandoned` (muted). Dot + label, matches Paper/Ink palette from `gate-pipeline.html`.
- Collapsed runner panel shows a one-line summary: `<status> — N/M completed — Active: <nodeId or 'none'>`. Currently the panel collapses to bare bar.
- Empty state (no pipeline loaded, design mode off) shows a `Browse existing pipelines` button next to / above `TemplateGallery` that calls `handleTogglePipelineFlyout()`.
- No regression on success banner, graft/join/promotion dialogs, mobile sidebar.
- Build passes: `cd apps/desktop && pnpm build`.
