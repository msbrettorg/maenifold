# T-48.2 — API: `/api/memory/search` Endpoint

**Requirement:** FR-48
**Component:** `crates/maenifold-core/src/api/`

## Summary

Add a REST endpoint that wraps maenifold's `SearchMemories` MCP tool, allowing the UI to search memory files.

## Acceptance Criteria

1. `GET /api/memory/search?query=workflow+dispatch&mode=Hybrid&pageSize=10` returns JSON search results
2. Response shape: `{ results: [{ uri, title, snippet, score }], totalCount, page, pageSize }`
3. Parameters: `query` (required), `mode` (optional, default "Hybrid"), `pageSize` (optional, default 10), `page` (optional, default 1), `folder` (optional)
4. Empty query returns 400 error
5. Handler reuses existing `SearchMemories` logic — no duplicate search implementation
6. Route registered in `api_routes()`

## Architecture Context

- Same pattern as T-48.1 — add to `crates/maenifold-core/src/api/routes.rs`
- Search logic lives in `crates/maenifold-core/src/memory/` or `crates/maenifold-core/src/search/`
- Follow existing `ApiState` + `ApiError` patterns

## SWE Remediation

### What Changed

**File: `crates/maenifold-core/src/api/routes.rs`**

- Added imports: `crate::search::search_memories`, `crate::tools::ToolContext`, `crate::util::json::OutputFormat`, `serde_json::{Value, json}`
- Added `SearchResultItem` struct (fields: `uri`, `title`, `snippet`, `score`) and `MemorySearchResponse` struct (fields: `results`, `total_count`, `page`, `page_size` with `camelCase` serde rename)
- Added `memory_search` async handler:
  - Validates `query` param is non-empty → returns 400 if missing/empty (AC 4)
  - Accepts `mode` (default "Hybrid"), `pageSize` (default 10), `page` (default 1), `folder` (optional) query params (AC 3)
  - Constructs a JSON payload and calls `search_memories` via a `ToolContext` with `OutputFormat::Json` — no duplicate implementation (AC 5)
  - Parses the `success`-wrapped JSON response from `search_memories`
  - Treats whitespace-only `query` values as invalid and rejects `page`/`pageSize` values of `0`
  - Converts non-JSON `ERROR:` responses from the shared search layer into 400 responses instead of surfacing a 500
  - Maps the score field based on mode: `fusedScore` (Hybrid), `semanticScore` (Semantic), `textScore` (FullText)
  - Maps `path` → `uri`, preserves `title`, `snippet`
  - Returns `{ results: [{uri, title, snippet, score}], totalCount, page, pageSize }` (AC 2)
- Registered route `/api/memory/search` → `GET memory_search` in `api_routes()` (AC 6)

### Caveats (not AC violations)

1. **Error misclassification (lines 305–311):** When `search_memories` returns an `ERROR:`-prefixed string, the handler calls `ApiError::bad_request(raw.clone())`. This means internal server-side errors (DB failures, config issues) from the search layer surface to the client as `400 Bad Request` rather than `500 Internal Server Error`. The error message content is also forwarded verbatim, which could leak internal path information. Low risk for a local tool API, but worth hardening.

2. **Mode not normalized before forwarding (lines 277–283 / 317–323):** The `mode` string is passed as-is to `search_memories` in the payload (`payload["mode"] = mode`). The score-key mapping uses `eq_ignore_ascii_case`, so `hybrid`→`fusedScore` works correctly in the response shaping. However, the underlying search function expects canonical casing (`"Hybrid"`, `"Semantic"`, `"FullText"`) and may return an `ERROR:` response for `mode=hybrid`. A `mode.to_string()` normalization step would make this robust.
