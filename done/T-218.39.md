# T-218.39 — Voice/Handy Error Visibility

## Problem

Voice/Handy launch and check errors can be hidden from the UI, and platform validation was deferred. Users can see a mic button without actionable feedback when Handy cannot launch or cannot be detected.

## Acceptance Criteria

- [ ] `voice-handy` store exposes `lastError` and launch/check failures to UI
- [ ] Voice button and settings show actionable error states
- [ ] Polling lifecycle is tied to app/window focus events explicitly, not only setup-store unmount
- [ ] macOS packaged smoke verifies install detection, launch, foreground existing Handy, and status update after quit
- [ ] Windows/Linux either pass smoke tests or the UI clearly marks support as experimental/unavailable
