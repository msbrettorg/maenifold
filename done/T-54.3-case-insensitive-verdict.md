# T-54.3 — Case-Insensitive CLI Verdict

**Requirement**: FR-41 (File-Authoritative Pipeline Gate Cache)
**Sprint**: 54
**Component**: `crates/maenifold-gate/src/lib.rs`

## Problem

`gate advance T-1.1.md --root . --stage red --verdict pass` fails with an error because the CLI only accepts uppercase verdicts (`PASS`, `REJECT`, `FAIL`). This is a usability friction — agents and humans naturally type lowercase or mixed case.

## Acceptance Criteria

### 1. Accept any case for --verdict

All of these MUST work identically:
- `--verdict PASS`, `--verdict pass`, `--verdict Pass`, `--verdict pAsS`
- `--verdict REJECT`, `--verdict reject`, `--verdict Reject`
- `--verdict FAIL`, `--verdict fail`, `--verdict Fail`

### 2. Normalize to uppercase internally

The verdict value MUST be normalized to uppercase before validation and storage. The canonical format written to files and the cache is always `PASS`, `REJECT`, or `FAIL`.

### 3. Error message unchanged for invalid verdicts

Invalid verdicts (e.g., `--verdict maybe`) MUST still produce the existing error message listing valid options.

## Test Cases

1. `--verdict pass` with `--stage red` → accepted, normalized to PASS
2. `--verdict REJECT` with `--stage red` → still works (regression test)
3. `--verdict Fail` with `--stage blue` → accepted, normalized to FAIL
4. `--verdict maybe` → error listing valid options
5. Verify the section written to the file uses uppercase `**Verdict**: PASS` regardless of input case

## Constraints

- Change ONLY the argument parsing in `lib.rs`
- Do NOT change `parser.rs`, `advance.rs`, or any other module
- Preserve all existing passing tests (25 tests)

## SWE Remediation

Normalized --verdict to uppercase at CLI boundary. 4 new tests.
