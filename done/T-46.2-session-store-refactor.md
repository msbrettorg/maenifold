# T-46.2: Session Store — Multi-Session Map

**Requirement**: FR-46
**Priority**: P0
**Files**: `vendor/acp-ui/src/stores/session.ts`

## Context

The session store is currently a singleton — one `acpClient`, one set of messages, one `isConnected`. When a user switches sessions in the sidebar, the existing connection is lost. We need multiple simultaneous connections.

## Acceptance Criteria

1. Replace all singleton per-session refs with:
   ```ts
   const sessions = ref<Map<string, SessionState>>(new Map());
   const activeSessionId = ref<string | null>(null);
   const bridges = new Map<string, AcpClientBridge>();
   ```

2. Add computed properties that read from the active session, preserving backward compatibility:
   - `activeSession` → `sessions.get(activeSessionId)`
   - `isConnected` → `activeSession?.isConnected ?? false`
   - `isConnecting` → `activeSession?.isConnecting ?? false`
   - `isLoading` → `activeSession?.isLoading ?? false`
   - `error` → `activeSession?.error ?? null`
   - `messageList` / `messages` → `activeSession?.messages ?? []`
   - `currentSession` → `activeSession?.session ?? null`
   - `agentInfo`, `agentPromptCapabilities`, `configOptions`, `hasConfigOptions`, etc. — same pattern
   - These computed shims mean App.vue and ChatView.vue DO NOT need changes in this task.

3. Refactor `createSession(agentName, cwd)`:
   - Generate a session ID via `generateSessionId()`
   - Create a new `SessionState` via `createEmptySessionState()`
   - Add to `sessions` Map
   - Set `activeSessionId` to the new session
   - Create the `AcpClientBridge`, store in `bridges` Map keyed by session ID
   - Wire `onSessionUpdate` scoped to that session ID
   - All state mutations write to `sessions.get(sessionId)`, not global refs

4. Refactor `resumeSession(savedSession)`:
   - Same pattern: new session slot, new bridge, set active

5. Refactor `disconnect(sessionId?: string)`:
   - If no sessionId, use activeSessionId
   - Disconnect the bridge for that session
   - Remove from `bridges` Map
   - Remove from `sessions` Map
   - If the closed session was active, set activeSessionId to next available (or null)

6. Add `setActiveSession(sessionId: string)`:
   - Guards with `sessions.has(sessionId)` before assignment
   - Sets `activeSessionId`

7. Add `closeSession(sessionId: string)`:
   - If connected, disconnect first
   - Remove from sessions Map
   - Adjust activeSessionId

8. `handleSessionUpdate` must be scoped per session via closure:
   ```ts
   bridge.onSessionUpdate = (update) => handleSessionUpdate(sessionId, update);
   ```

9. `sendPrompt`, `setMode`, `setModel`, `setConfigOption`, `resolvePermission`, `cancelPermission`, `cancelOperation` — all operate on the active session's state and bridge.

10. `savedSessions` stays global — it's the catalog, not live state.

11. Export `sessions`, `activeSessionId`, `setActiveSession`, `closeSession`.

## Constraints

- Backward compatibility: all existing computed properties (`isConnected`, `messages`, `currentSession`, etc.) must continue to work by reading from the active session.
- Do NOT modify App.vue, ChatView.vue, SessionList.vue, or any component in this task.
- `savedSessions` stays global.
