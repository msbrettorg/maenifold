# T-68.10 — Tray Restart Menu Item

**Requirement:** PRD §operational — daemon lifecycle management
**Priority:** Medium
**Depends:** T-68.1

## Problem

After rebuilding `maenifold` or `gate`, the running daemon serves a stale binary. Users must manually run `launchctl kickstart -k` to pick up changes. There is no in-app way to restart.

## Solution

Add a **"Restart"** menu item to both tray icons (maenifold and gate). On click, the daemon re-execs itself via `launchctl kickstart -k` on the daemon's own launchd service label.

## Acceptance Criteria

1. Both tray menus show a "Restart" item between existing items and "Quit"
2. Clicking "Restart" calls `launchctl kickstart -k gui/{uid}/{service_label}` where:
   - maenifold: `com.ma-collective.maenifold`
   - gate: `com.ma-collective.gate`
3. The UID is resolved at runtime via `unsafe { libc::getuid() }`
4. Restart is fire-and-forget — the current process will be killed by launchd and restarted
5. macOS only — guard with `#[cfg(target_os = "macos")]`; on other platforms the menu item is hidden
6. `crates/maenifold-core/src/tray.rs` must be refactored to stay under 300 LOC — extract helpers to a `tray_menu.rs` or similar
7. `crates/maenifold-gate/src/tray.rs` stays under 300 LOC
8. All existing tests pass
9. Both binaries build: `cargo build --release -p maenifold-cli` and `cargo build --release -p maenifold-gate --features app`

## Implementation Notes

- `std::process::Command::new("launchctl").args(["kickstart", "-k", &format!("gui/{uid}/{label}")])` then fire-and-forget (don't await exit — we'll be killed)
- maenifold-core tray.rs is currently 364 LOC and needs splitting regardless
- The restart command should be a shared helper if possible, parameterized by service label
- Do NOT add `libc` as a new dep — use `std::process::Command::new("id").arg("-u")` to get UID if libc isn't already available
