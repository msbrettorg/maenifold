## Problem

The T-239.2 dependency audit passed, but found duplicated auth-error mapping logic in two public Teams Monitor surfaces:

- `crates/maenifold-core/src/tools/teams_monitor_helpers.rs`
- `crates/maenifold-core/src/mcp/resources/teams.rs`

Both implementations parse stored auth error state into the MCP-visible `authError` shape and maintain a duplicated known-code/recoverability list. This can cause future drift between tool status and MCP resource status.

## Scope

- Extract a shared public auth-error DTO/helper for Teams Monitor status.
- Use it from both tool status and `teams://status`.
- Keep the existing public JSON shape stable: `{ code, message, recoverable }`.
- Do not add third-party dependencies.

## Acceptance Criteria

- Auth-error mapping exists in one shared implementation.
- `TeamsMonitor` status and `teams://status` use the same shared helper/DTO.
- Existing T-239.2 behavior remains intact: structured `authError` is visible and `tenantId` remains omitted from public identity.
- Focused tests cover both public surfaces or a shared helper plus one integration surface.
