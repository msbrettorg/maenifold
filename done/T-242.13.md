## SDD Justification

Per AGENTS.md (sprint 242): TDD is the default; SDD is the fallback that requires justification.

This task stays on SDD because the deliverable is a **UI redesign** whose acceptance contract is visual fidelity to an Obsidian-style reference, not a behavior that can be pinned by an automated test before work begins. The spec emerges through layout iteration + interactive CDP verification per the AGENTS.md UI verification rule. Component-render unit tests would only assert "the subtabs exist," which provides no signal about whether the redesign actually achieves the intended look-and-feel. Blue-team verification on this task is human + CDP, not headless test execution.

If the task body later defines a behavior with a clear pass/fail contract (e.g., "backlinks panel renders all incoming WikiLinks for the active note"), spin that contract out into a TDD child task.

## Problem

The current Knowledge tab (screenshot in gate notes) crams three independent surfaces — vault tree / search, note viewer, concept graph + community list + related concepts panel — into a single 3-column layout. None of them get enough room. The graph in particular is rendered in a ~400px right-rail box and looks like a pinhead spiderweb. This is one of the marquee tabs of the product and it looks unfinished.

## Target Design

Split Knowledge into **two subtabs** mounted under one top-level Knowledge entry:

- **Memory** — Obsidian-style vault browser
  - Left rail: vault tree (folder/file) + search input + "Tree | Search" toggle (keep current control set, give it room)
  - Center: full-width note viewer with markdown rendering, `[[WikiLink]]` chips, edit affordance
  - Right rail (collapsible): "Related concepts" surfaced by `findsimilarconcepts` + `buildcontext` for the open note's WikiLinks
  - No graph in this tab

- **Graph** — concept-as-protocol explorer (the second subtab)
  - Full-canvas force-directed concept graph (re-use the cytoscape/d3 instance currently squashed into the right rail)
  - Top toolbar: Filter concepts, Reset view, Reload, community-cluster picker
  - Left rail: communities list (current `Communities` panel) — clicking a community zooms / focuses the cluster
  - Bottom or right inspector panel: clicked-node details (concept name, file count, Louvain community, member files, neighbours, edge weights)
  - Honor Obsidian's interaction model: drag to pan, scroll to zoom, click node for details, hover for label, double-click to open the strongest-bond memory note in the Memory subtab

## Implementation notes

- Use the existing `app-shell` tab plumbing for the subtab pattern (or pinia-backed router state inside the Knowledge view if we don't have nested tabs yet — see `composables/useAppShell.ts`).
- Reference the existing components in `apps/desktop/src/components/Knowledge*.vue` and `Concept*.vue` — don't rewrite the data fetching, just rehome the rendering.
- DESIGN.md is the visual spec — maintain DESIGN.md tokens, no hex literals, no btn-* classnames, no component-local CSS files. Each `.vue` under 300 LOC.
- The current `KnowledgeView.vue` (or whatever file mounts the 3-pane layout) should split into `KnowledgeMemoryView.vue` and `KnowledgeGraphView.vue`, with a thin parent that switches between them based on subtab state.
- Sketch for "looks like Obsidian, but concepts": dark canvas, glowing nodes sized by file-count, edges with subtle alpha, communities differentiated by hue (use the existing community palette already in `community/` Rust module). Hover overlay = concept name + file count. Selected node halo. Smooth WebGL rendering if we have it; otherwise SVG with throttled render.

## Acceptance criteria

- [ ] Knowledge tab opens to a Memory/Graph subtab control (default: Memory)
- [ ] Memory subtab: vault tree + note viewer + collapsible related-concepts rail. NO graph element.
- [ ] Graph subtab: full-canvas force-directed graph, communities list left, inspector right/bottom. Drag-pan, scroll-zoom, click-detail, double-click-to-jump-to-note all functional.
- [ ] All Vue files under 300 LOC, no `<style>` blocks, no btn-* classes, no hex literals
- [ ] CDP smoke test: open Knowledge → switch to Graph → click a community → click a node → see inspector populate → double-click → land on the note in the Memory subtab. Screenshot evidence captured.
- [ ] Visual review against Obsidian's "Graph view" — comparable readability and density at default zoom
