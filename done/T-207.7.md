# T-207.7 — Integration test + demo

## Requirement

Two deliverables: a Rust integration test that verifies gateway correctness programmatically, and a dashboard HTML demo page for manual verification.

## Part A: Rust integration test

Location: `crates/maenifold-core/tests/gateway_integration.rs`

Test cases:
1. **tools/list includes gateway tools** — start HTTP server with a mock stdio server, call `tools/list`, verify gateway tools appear alongside native tools.
2. **tools/call delegates to gateway** — call a gateway tool, verify the result comes from the stdio server.
3. **Tool collision rejected** — configure two servers with same tool name, verify startup returns collision error.
4. **Upstream crash + restart** — kill the stdio process, call a tool, verify restart-on-connection-failure works.
5. **Mid-call EOF no retry** — have the stdio process die after receiving a request but before responding, verify error returned (not retry).
6. **Timeout** — have the stdio process hang, verify timeout error returned within configured timeout.
7. **Upstream JSON-RPC error preserved** — have stdio server return a JSON-RPC error, verify it propagates with correct code.
8. **Tool not found** — call a non-existent tool, verify `-32601` error.

Mock stdio server: a simple Rust binary in `tests/fixtures/` that implements MCP initialize + tools/list + tools/call with configurable behavior (hang, crash, error, succeed).

## Part B: Dashboard demo page

Location: `memory/Dashboards/gateway-test.html`

A minimal HTML page that:
1. Sends `initialize` (separate POST, not batched — per Lifecycle § Initialization)
2. Sends `notifications/initialized` (expects 202 Accepted)
3. Calls `tools/list` and renders all tools, marking gateway vs native
4. Has a button per gateway tool that calls `tools/call` and shows the result
5. Uses correct `Accept: application/json, text/event-stream` header (per Transports § Streamable HTTP)
6. Handles SSE vs JSON response format (per spec, client MUST support both)

This is a manual demo, not an automated test. It exists for visual verification during development.

## Protocol References

- Lifecycle § Initialization: initialize MUST NOT be batched
- Transports § Streamable HTTP: Accept header, 202 for notification-only, SSE vs JSON responses
