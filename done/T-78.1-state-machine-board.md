# T-78.1: State Machine Board — Replace Kanban with Table View over Standard MCP

## Context

The current gate board is a kanban with fixed columns (pending, swe, red, blue, done). This is a lie — tasks follow heterogeneous pipelines (SDD, TDD, GSD, lightweight) with different stages. A kanban with fixed columns cannot represent this truthfully.

Additionally, the board uses a hand-rolled `/board/api` endpoint that manually reimplements JSON-RPC dispatch (`callGateTool()` in index.html, lines 189-217). The server already exposes a proper Streamable HTTP MCP endpoint at `/mcp` via `rmcp::StreamableHttpService`. The board should use a standard MCP client SDK, not custom JSON-RPC.

## Requirements

### 1. Delete `/board/api` endpoint
- Remove `board_api()` handler from `mcp/http.rs`
- Remove the `.route("/board/api", post(board_api))` line
- Remove `board_trace()` helper (tracing is handled by rmcp's StreamableHttpService)
- The board frontend connects to `/mcp` using a standard MCP client

### 2. Standard MCP client in frontend
- Use the official `@modelcontextprotocol/sdk` TypeScript/JS client or equivalent browser-compatible MCP client library
- Connect to `/mcp` endpoint (Streamable HTTP transport)
- No hand-rolled JSON-RPC. No custom fetch wrappers for MCP.
- All tool calls go through `client.callTool(name, args)`

### 3. Replace kanban layout with state machine table
- **Table view**: Each row = one task file, each file = independent state machine
- **Columns**: ID (monospace) | Title | Pipeline (badge) | Progress (inline state machine) | Requirement | Modified
- **Progress column**: Horizontal chain of dots/circles connected by lines. Completed = filled, current = highlighted, future = hollow. Different pipelines render different stage counts.
- **Zebra-striped rows**: Alternating surface colors per design system
- **Filter bar**: All | Backlog | In-Flight | Done segmented toggle. Pipeline filter pills (SDD, TDD, GSD, Lightweight).
- **Detail drawer**: Right panel showing full task details, state machine with transition timestamps, agent notes, Pass/Reject actions

### 4. Port in header
- Top bar shows `gate :{port}` so user knows which instance they're viewing
- Port is injected server-side (template variable or meta tag)

### 5. Design system
- Use existing "Command Deck" design system tokens
- Surface hierarchy: #131313 base, #1c1b1b panels, #201f1f containers
- Typography: Space Grotesk headings, Inter body, JetBrains Mono for IDs/metadata
- 4px max rounding, no shadows, ghost borders, tonal layering
- Reference design: `.stitch/designs/state-machine-table.html`

## What to delete
- `board_api()` function in `mcp/http.rs`
- `board_trace()` function in `mcp/http.rs`
- `callGateTool()` in `board/index.html` (replaced by MCP client SDK)
- All hand-rolled JSON-RPC construction in the frontend
- Fixed kanban column layout

## Acceptance Criteria
- Board loads at `http://localhost:{port}/?gate={project}`
- All data fetched via standard MCP client → `/mcp` endpoint
- Zero custom JSON-RPC code in frontend or backend
- Table renders heterogeneous pipelines correctly (SDD rows show 5 stages, TDD rows show different stages, etc.)
- Detail drawer shows task state machine with transition history
- Pass/Reject actions work through MCP client
- Port visible in header
