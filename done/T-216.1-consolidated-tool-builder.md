## What to Build

`ConsolidatedServerTool` struct and `build_consolidated_tools()` function that transforms the flat per-server tool lists from `StdioPool::all_gateway_tools()` into facade tools.

### Struct

```rust
pub struct ConsolidatedServerTool {
    pub server_name: String,
    pub tool_catalog: Vec<Tool>,   // original tools from this server, sorted by name
    pub facade_tool: Tool,         // the MCP Tool exposed in tools/list
    // description is derived from facade_tool.description — no separate field
}
```

### Function

```rust
pub fn build_consolidated_tools(
    gateway_sources: Vec<(String, Vec<Tool>)>,
    min_tools_for_consolidation: usize, // must be >= 2, panic on 0/1
) -> (Vec<ConsolidatedServerTool>, Vec<Tool>)
//    consolidated facades,              passthrough flat tools
```

### Facade Tool Naming

- Name: `gateway_{sanitized_server_name}` where sanitized = lowercase, replace non-alphanumeric with `_`, truncate to 60 chars (leaves 4 chars headroom for MCP 64-char limit)
- The `gateway_` prefix prevents collisions with native tool names and passthrough tools
- If two servers produce the same sanitized name: return `Err` (fail fast, don't silently shadow)

### Facade InputSchema

```json
{
  "type": "object",
  "properties": {
    "intent": { "type": "string", "description": "Natural language description of what you want to do" },
    "command": { "type": "string", "description": "Exact tool name to invoke" },
    "learn": { "type": "boolean", "description": "Discovery mode — returns available commands" },
    "parameters": { "type": "object", "description": "Arguments forwarded to the selected tool" }
  },
  "additionalProperties": false
}
```

**Precedence rules (documented in facade description, enforced in T-216.2):**
1. `learn: true` + no `command` → Tier 1: return tool catalog
2. `learn: true` + `command` → Tier 2: return schema for that tool
3. `command` present → direct dispatch to named tool with `parameters`
4. `intent` present (no `command`) → intent matching against catalog
5. Empty object → error: "Specify intent, command, or learn=true"

**At least one of `intent`, `command`, or `learn` must be provided.** Schema does not enforce this (JSON Schema can't express mutual dependency cleanly) — dispatch logic (T-216.2) validates at runtime.

### Description Generation

- Sort tools by name for deterministic output
- Extract key nouns from tool names (split on `_`, `-`, camelCase boundaries)
- Deduplicate and take top 5 by frequency
- Format: "{server_name} — {capability summary}. Use learn=true to discover available commands."
- Cap at 200 characters (excluding learn hint)

### Edge Cases

- **Empty servers (0 tools):** filtered out — produce neither facade nor flat tools
- **min_tools_for_consolidation = 0 or 1:** panic — this is a programming error, not user input
- **Duplicate tool names within one server:** trust upstream, no dedup
- **Empty/whitespace server names:** return as error
- **Stable ordering:** tool_catalog sorted by name, facades sorted by server_name
