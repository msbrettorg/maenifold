# T-242.34 — Memory subtab related-concepts rail collapse missing

**Pipeline**: tdd

## Problem

Discovered during T-242.31 CDP verification. T-242.13's spec line:

> Right rail (collapsible): "Related concepts" surfaced by `findsimilarconcepts` + `buildcontext` for the open note's WikiLinks

The recovered Memory subtab (`KnowledgeMemoryView.vue` + `KnowledgeRelatedConcepts.vue`) shows the rail but no visible collapse toggle. The user has no affordance to hide the rail when they want full-width note view.

Evidence: `outputs/screenshots/T-242.31/scenario-2-memory-loaded.png`.

## Fix

Add a small chevron/icon button at the top of the related-concepts rail that toggles its visibility:
- When visible: rail at standard width.
- When collapsed: rail collapses to ~40px showing only the toggle button.
- Clicking the button restores the rail.

Use lucide `PanelRightClose` / `PanelRightOpen` icons. Match the existing toggle pattern from other panels in the desktop app (look at `KnowledgeWorkspace.vue` or `WorkflowsView.vue` for precedent).

## Acceptance Criteria

- [ ] Visible toggle button on the related-concepts rail.
- [ ] Clicking the toggle collapses/expands the rail.
- [ ] State persists across navigation within the Memory subtab (optional: persist across app restarts via localStorage).
- [ ] CDP verification with screenshot of both states.
