# T-61.8 — Validate New Node Types on Create/Graft

**Requirement**: FR-47
**Test Cases**: TC-204
**Component**: `crates/maenifold-core/src/workflow/pipeline/handler.rs` + `crates/maenifold-core/src/workflow/pipeline/mod.rs`
**Depends on**: T-61.4 (types.rs must be updated first)

## Context

`validate_definition()` in `mod.rs:21` validates pipeline definitions but only knows about flat `PipelineNode` structs. After T-61.4, nodes are a tagged enum and the validation needs to handle type-specific required fields.

`handler.rs` is the MCP tool entrypoint. The `create` handler deserializes `PipelineDefinition` from JSON. With the new wire-type adapter, serde handles most validation (missing required fields → TryFrom error). But we should still validate semantic constraints.

## Acceptance Criteria

### Validation (mod.rs)

1. `validate_definition()` MUST accept all three node types without error when they have valid fields.

2. The existing validation checks MUST continue to work:
   - Non-empty graph (at least 1 node)
   - Unique node IDs
   - Valid edge references (source/target exist)
   - No duplicate edges
   - No cycles (existing DAG check)

3. Add type-specific semantic validation:
   - Workflow nodes: `workflow_id` must not be empty
   - Prompt nodes: `prompt` must not be empty, `agent` must not be empty
   - SequentialThinking nodes: `topic` must not be empty, `agent` must not be empty, `total_thoughts` must be > 0 if specified

### Handler (handler.rs)

4. The `create` path MUST accept pipeline definitions with mixed node types. The serde wire-type adapter handles deserialization; the handler should pass the definition through `validate_definition()` as today.

5. The `graft` path MUST also accept new node types in the grafted nodes.

6. Error messages for validation failures MUST include the node ID and the specific field that failed.

7. All existing handler tests MUST continue to pass.

8. The code MUST compile: `cargo build -p maenifold-core`

## SWE Remediation

### What I changed

- `crates/maenifold-core/src/workflow/pipeline/mod.rs`
  - Added type-specific semantic validation for tagged `PipelineNode` variants.
  - Enforced non-empty `workflowId`, `prompt`, `agent`, and `topic` fields using trimmed string checks.
  - Enforced `totalThoughts > 0` for `SequentialThinking` nodes.
  - Preserved existing graph validation behavior for empty pipelines, duplicate node IDs, bad edge references, duplicate edges, and cycles.
  - Added validation tests covering mixed node types and type-specific failure cases.

- `crates/maenifold-core/src/workflow/pipeline/handler.rs`
  - Updated pipeline create/graft handling to accept mixed node types by only preloading workflow definitions and creating workflow session files for workflow nodes.
  - Updated graft merge validation to reuse `validate_pipeline()` so semantic validation runs for grafted nodes too, while preserving the detailed graft cycle error.
  - Updated handler code paths that were assuming every node had a `workflowId` when creating/restoring workflow session files.
  - Added handler tests for mixed-node create/graft flows and surfaced semantic validation errors.
