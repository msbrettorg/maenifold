# T-174.7 — `pipeline-ui`: render + edit Conditional edges

## Why
Trio consensus (Beta perspective): Conditional edges **must be visual in pipeline-ui, not expression syntax**. Backend support without UI plumbing is "not a feature" per the constitution.

## Scope
**Path:** `apps/desktop/` only (Vue + TS). Backend types are consumed via the MCP schema landed in T-174.3 — do not modify Rust.

## Acceptance
- AC-1: Pipeline canvas renders edges of type `conditional` with a label `?{path}={value}` (truncate at 20 chars with ellipsis on overflow). Visually distinguishable from `success` (solid) and `always` (dashed) — propose **dotted with diamond endpoint** to match the Mermaid `-->|?...|` semantics.
- AC-2: Edge inspector / edit panel:
  - Edge type selector includes `conditional` alongside `success` / `always`.
  - When `conditional` selected, two required inputs appear: `path` (string) and `equals` (JSON literal — string|number|bool — with type toggle).
  - Validation: empty `path` blocks save; `equals` parses to JSON or shows inline error.
  - Switching back to `success`/`always` clears `path`/`equals` (no orphaned data).
- AC-3: Conforms to `apps/desktop/DESIGN.md` strictly: 4px radius, sentence case, no ALL CAPS, status bead conventions, Inter/Space Grotesk/JetBrains Mono typography, ambient glow not drop shadows.
- AC-4: Visual verification via CDP: launch the packaged binary with `--remote-debugging-port=9222`, capture screenshot of a pipeline containing all three edge types, attach to the gate task notes.
- AC-5: `cd apps/desktop && npx vue-tsc --noEmit` passes.
- AC-6: `cd apps/desktop && npm run package` succeeds.
- AC-7: No new top-level dependencies. Reuse existing icons from `lucide-vue-next` and existing edge-rendering components.

## Forbidden
- Free-text expression input. Path + equality literal only.
- ALL CAPS labels, drop shadows, `1px solid` borders, pill badges, redundant display — all are constitutional gate failures.
- Touching backend Rust crates.
