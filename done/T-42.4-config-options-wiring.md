# T-42.4: Session Config Options Wiring

**Requirement**: FR-42.4  
**Priority**: P1  
**Files**: `vendor/acp-ui/src/components/ChatView.vue`, `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/lib/acp-bridge.ts`

## Context

SWE agents have already completed:
- `SessionConfigOption` types in `types.ts`
- `configOptions` reactive ref in session store
- `config_option_update` notification handler
- `configOptions` parsing from `session/new` and `session/load`
- `setConfigOption(configId, value)` store method
- `ConfigOptionPicker.vue` component

## Acceptance Criteria

1. **Wire ConfigOptionPicker into ChatView.vue**:
   ```vue
   import ConfigOptionPicker from './ConfigOptionPicker.vue';
   const configOptions = computed(() => sessionStore.configOptions);
   ```
   In template, render ConfigOptionPicker for each option:
   ```vue
   <ConfigOptionPicker
     v-for="option in configOptions"
     :key="option.id"
     :option="option"
     :disabled="isLoading"
     @change="handleConfigOptionChange"
   />
   ```
   Where `handleConfigOptionChange(configId, value)` calls `sessionStore.setConfigOption(configId, value)`.

2. **Suppress legacy pickers when configOptions present**: In `ChatView.vue`, show `ModelPicker` and `ModePicker` ONLY when `configOptions.length === 0`. When `configOptions` is populated, the ConfigOptionPicker components handle both mode and model selection.

3. **Suppress legacy store population**: In `session.ts`, when `sessionResponse.configOptions?.length > 0`, skip populating `availableModes`/`availableModels` from the legacy `modes`/`models` fields. This prevents double-rendering.

4. **Implement `unstable_setSessionConfigOption` on AcpClientBridge** (`acp-bridge.ts`): Add a method that calls `this.sendRequest('session/set_config_option', { sessionId, configId, value })`. The store's `setConfigOption` should call this bridge method.

5. **Filter unrecognized types**: In the store's configOptions parsing, filter out options where `type !== 'select'`.

## Spec References

- https://agentclientprotocol.com/protocol/session-config-options
- Audit findings: REQ-04 (ConfigOptionPicker dead code), REQ-11 (legacy not suppressed), REQ-05 (filter types)

## SWE Remediation

- **What I changed**
  - `vendor/acp-ui/src/components/ChatView.vue`: imported `ConfigOptionPicker`, added `configOptions` computed state, added `handleConfigOptionChange`, rendered config option pickers in the header, and gated legacy `ModelPicker`/`ModePicker` behind `configOptions.length === 0`.
  - `vendor/acp-ui/src/stores/session.ts`: filtered session config options to `type === 'select'` in update/new/load/set flows, suppressed legacy mode/model population when config options are present, and kept `setConfigOption` wired through the ACP bridge method.
  - `vendor/acp-ui/src/lib/acp-bridge.ts`: added `unstable_setSessionConfigOption({ sessionId, configId, value })` that sends `session/set_config_option`.

- **Test results**
  - `FAIL` — `cd vendor/acp-ui && npx vue-tsc --noEmit`
  - The typecheck failure is due to pre-existing TypeScript issues outside this task's acceptance criteria, including nullability/type mismatches in existing tool-call location handling, an existing `WriteTextFileResponse` return mismatch, an existing `agentInfo` assignment mismatch, and a missing `persistSessions` symbol.

- **Notes**
