## Problem

The MCP surface exposes five Gateway meta-tools that route to every domain (native and downstream-proxied):

- `GatewayIndex` — list domains and commands
- `GatewayExecute` — invoke one command
- `GatewayBatch` — sequentially invoke multiple commands
- `GatewayIntent` — natural-language → candidate commands
- `DiscoverMcpTools` — enumerate downstream MCP servers and their tools

**None of these are exposed in the CLI.**

```bash
$ maenifold tool GatewayIndex '{}'
Unknown tool: GatewayIndex
$ maenifold tool DiscoverMcpTools '{}'
Unknown tool: DiscoverMcpTools
```

Practical consequence: CLI users cannot reach **any** of the 10 downstream MCP servers configured in `~/maenifold/maenifold.json` (workiq, srectl, msx-mcp, fetch, azure-mcp-server, ai-infrastructure, shell-mcp, mcp-apps-demo, microsoft-learn, plus maenifold itself). The CLI is locked to whatever the hand-curated tool registry inside `crates/maenifold-cli` happens to enumerate.

## Required Behavior

```bash
# discover what is available
maenifold tool GatewayIndex '{}'
maenifold tool GatewayIndex '{"domain":"workiq"}'
maenifold tool GatewayIndex '{"domain":"workiq","includeSchemas":true}'

# invoke any domain (native or proxied)
maenifold tool GatewayExecute '{"domain":"workiq","command":"ask_work_iq","parameters":{"question":"…"}}'
maenifold tool GatewayExecute '{"domain":"fetch","command":"fetch","parameters":{"url":"https://example.com"}}'

# batch
maenifold tool GatewayBatch '{"operation":"submit","continueOnError":true,"items":[…]}'

# enumerate downstream proxies
maenifold tool DiscoverMcpTools '{}'
```

The CLI should construct the same in-process Gateway state the MCP daemon uses (catalog, stdio pool, intent settings) so behavior is identical.

## Acceptance Criteria

- [ ] All 5 Gateway meta-tools invokable via `maenifold tool <Name>` with the same JSON schema as the MCP equivalents.
- [ ] `maenifold tool DiscoverMcpTools '{}'` enumerates the same servers as the MCP call.
- [ ] `maenifold tool GatewayExecute …` round-trips to a downstream proxied server (test against `fetch` or `workiq`) and returns the same envelope MCP returns.
- [ ] `maenifold tool` help text adds a `Gateway:` section.
- [ ] `GatewayIntent` honors AGENTS.md P0 #6: any inference path it triggers MUST surface in the desktop Sessions inspector. (If that visibility does not yet exist, the CLI surface for `GatewayIntent` returns the same `status: disabled` envelope the MCP path will return — see related work for the inspector.)
