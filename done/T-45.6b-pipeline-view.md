# T-45.6b: Pipeline MCP Tool — View Operation

**Requirement**: FR-45.6
**RTM**: RTM-335, RTM-336
**Priority**: P0 — Observability for pipeline state

## Context

The `pipeline(sessionId=X, view=true)` operation returns the current state of a pipeline as structured JSON plus a pre-rendered Mermaid diagram string. This enables both the UI and AI agents to inspect pipeline progress.

## Scope

Add `view=true` handling to the Pipeline tool handler.

## Acceptance Criteria

1. **View response**: `pipeline(sessionId=X, view=true)` reads the pipeline session file and returns JSON matching this shape:
   ```json
   {
     "pipelineId": "pipeline-...",
     "status": "active",
     "nodes": [
       {"nodeId": "...", "workflowId": "...", "sessionId": "...", "status": "...", "attempts": N}
     ],
     "edges": [
       {"source": "...", "target": "...", "type": "success"}
     ],
     "ready": ["nodeId1"],
     "active": ["nodeId2"],
     "completed": ["nodeId3"],
     "mermaid": "graph LR\n  ..."
   }
   ```
2. **Status derivation**: Read `nodeStates` from pipeline session frontmatter. Compute `ready`, `active`, `completed` lists using `compute_ready_set` and filtering by status.
3. **Mermaid generation**: Generate a Mermaid `graph LR` diagram string with:
   - Node labels include status emoji: ⏳ pending, 🟡 ready, 🔄 active, ✅ completed, ❌ abandoned, 🚫 stuck
   - Edges rendered as `source --> target`
   - `always` edges rendered as `source -.-> target` (dashed)
4. **Pipeline status**: Include overall `status` field computed from `compute_pipeline_status`.
5. **Session ID validation**: Return error if `sessionId` doesn't exist or isn't a pipeline session (`type: pipeline`).

## Implementation Notes

- Read pipeline session via `read_markdown` with pipeline URI
- Parse `definition` and `nodeStates` from frontmatter
- Mermaid string is plain text — no rendering, just the source code for the diagram
- The view operation is read-only — no state mutations

### Observations (not spec violations)

- `compute_ready_set` silently skips nodes absent from `node_states`; `node_ids_with_status` returns a hard error for the same condition. The asymmetry is acceptable — `ready` is derived from the live graph algorithm while `active`/`completed` must match the persisted state exactly.
- `compute_pipeline_status` returns `"active"` for pipelines where all nodes are `Abandoned` (none are `Completed`, none are `Stuck`, none are `Active|Ready`). This is an engine-level edge case; the view operation faithfully reports whatever `compute_pipeline_status` returns, so it is not a view-layer defect.
- `view=true` without a `sessionId` falls through to the parameter-combination error at `handler.rs:63–71`, which includes the hint "view=true requires a sessionId". Not a spec requirement, but correctly handled.
