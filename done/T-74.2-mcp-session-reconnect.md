# T-74.2 — MCP sessions lost on server restart (P0)

## Priority: P0

## Problem
When the maenifold MCP server restarts, all pipeline sessions are lost. Subsequent calls with existing sessionIds return "Session not found". There is no:
- Session persistence to disk
- Client reconnection mechanism  
- Session recovery on server startup

This makes pipelines unreliable — any server restart (crash, upgrade, compaction) destroys all in-flight work.

## Acceptance Criteria
- [ ] Pipeline sessions persist to disk (SQLite or file)
- [ ] Server restart recovers previously active sessions
- [ ] Clients can reconnect to existing sessions after restart
- [ ] In-flight nodes marked `active` at crash time are detected and handled (restart or mark abandoned with reason)
- [ ] All existing pipeline tests pass

## SWE Notes

Fixed [[mcp-session]] restart handling in [[maenifold-core]]. Updated stale-session JSON to use clearer Re-initialize guidance, added 404 body inspection so only stale-session "not found"/"session" responses are rewritten, and introduced [[http-server]] listener injection for the restart test to remove the ephemeral-port race. Verified with cargo test -p maenifold-core --test http_session_restart_tests and cargo test -p maenifold-core --lib -- mcp::tests.
