## Goal

Remove stale docs/config references to the standalone [[gate-service]] and document the native maenifold [[MCP]] `maenifold.gate` surface.

## File Scope

Stay within 12 files and 600 LOC:

- `.mcp.json`
- `README.md` or `readme.md`
- `docs/gate-uml-spec.md`
- `docs/gateway-surface-contract.md`
- `crates/maenifold-gate/README.md`
- `crates/maenifold-gate-core/README.md`
- `docs/README.md`
- `assets/` packaged config files referencing standalone gate MCP
- `.github/` or repository config surfaces referencing standalone gate MCP, if present
- In-repo source for the gate skill, if present

## Acceptance Criteria

- No current docs/config instruct users to run `gate --mcp` or `gate --http`.
- No current docs/config require a separate gate MCP server.
- No current docs present standalone Gate CLI fallback as reliable current behavior.
- Docs list `gate_Status`, `gate_Pass`, `gate_Fail`, `gate_Append`, `gate_Sync`, `gate_History`, and `gate_TaskBody` under `maenifold.gate`.
- Docs preserve file-authoritative `todo/` / `done/` and `.gate/gate.db` recovery guidance.
- In-repo gate skill text is updated when present.

## Verification Commands

- `rg "gate --mcp|gate --http|separate gate|DEFAULT_GATE_MCP_BASE_URL|gate MCP :|gate MCP stdio"`
- Manual review of changed docs/config.

## Non-Goals

- Do not change source behavior.
- Do not add compatibility migration docs for continuing to run the old service.
