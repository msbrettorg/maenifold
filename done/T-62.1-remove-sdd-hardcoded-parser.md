# T-62.1 Remove SDD-hardcoded logic from parser.rs

## Acceptance Criteria

Remove all hardcoded `"swe"`/`"red"`/`"blue"` logic from `parser.rs` so the no-pipeline path uses generic stage handling instead of SDD-specific rules.

### Changes

1. **`normalize_stage_name()`** (lines 18–29): Remove the three SDD prefix shortcuts entirely. The function should only do `first_word = lower.split_whitespace().next()` normalization. No stage-specific fast paths.

2. **`parse_section_verdict()`** (lines 152–155): Remove the `stage == "swe"` guard. When `allowed_verdicts` is `None` (no-pipeline path), the function should NOT suppress verdicts for any specific stage name. Instead, if no pipeline is provided, accept all verdicts — the caller already handles validation.

3. **`validate_stage_verdict()`** (lines 209–217): Remove the SDD match arms (`"swe" => false`, `"red" => ...`, `"blue" => ...`). When `allowed_verdicts` is `None`, accept all verdict types (`_ => true` for everything). The comment already explains this is the no-pipeline fallback.

4. **`derive_status()`**: Audit for any remaining SDD-specific logic. The function should derive status purely from section order and verdicts, not from hardcoded stage names.
