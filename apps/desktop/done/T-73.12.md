## Description
Wire the Run button in WorkflowStepTimeline.vue to the `maenifold-Workflow` MCP tool using the current workflow ID. On success, navigate to the existing execution view (`WorkflowTreeView`) to show progress. If draft is dirty, prompt to save first, and keep Run disabled while unsaved draft changes exist. Reuse the existing execution components (`WorkflowTreeView`, `WorkflowNodeCard`, and `ThinkingSessionCard`) rather than building any new execution UI. Session lifecycle: start → running → completed/abandoned.

## Acceptance Criteria
- [ ] Run button calls `maenifold-Workflow` MCP tool with the current workflow ID
- [ ] On success, app navigates to the existing execution view (`WorkflowTreeView`) to show workflow progress
- [ ] Run button is disabled when no workflow is loaded
- [ ] Run button is disabled when the workflow has unsaved draft changes
- [ ] Dirty-state check: prompts to save before running if draft has changes
- [ ] Session creation confirmed with visual feedback
- [ ] Running state shown (button disabled or spinner)
- [ ] No new execution UI is introduced; existing `WorkflowTreeView` / `WorkflowNodeCard` / `ThinkingSessionCard` components are reused
- [ ] Session result viewable in the existing tree view
- [ ] Error handling for MCP failures
- [ ] vue-tsc --noEmit passes
- [ ] Tauri build produces .app bundle
