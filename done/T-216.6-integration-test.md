# T-216.6 — Gateway Consolidation Integration Test

**Pipeline**: sdd
**Priority**: P2

## Scope

End-to-end verification that the consolidated gateway works correctly via the live MCP endpoint.

## What to Test

### 1. Tool count reduction
- `tools/list` returns ≤50 tools (down from 174+)
- Native maenifold tools still present individually
- Each gateway server with 4+ tools appears as one facade

### 2. Learn mode — Tier 1
- Call facade with `{ learn: true }`
- Returns list of available commands with descriptions
- Does NOT return full schemas (token-efficient)

### 3. Learn mode — Tier 2
- Call facade with `{ learn: true, command: "specific_tool_name" }`
- Returns full JSON schema for that tool

### 4. Direct command dispatch
- Call facade with `{ command: "tool_name", parameters: {...} }`
- Tool executes and returns result from upstream server

### 5. Intent matching
- Call facade with `{ intent: "list subscriptions" }` (unambiguous)
- Correctly identifies and dispatches to `subscription_list`

### 6. Ambiguous intent
- Call facade with `{ intent: "list" }` (too broad)
- Returns candidates rather than executing

### 7. Unknown command
- Call facade with `{ command: "nonexistent_tool" }`
- Returns helpful error

## Acceptance Criteria

- [ ] All 7 test scenarios pass against live MCP endpoint
- [ ] Token savings verified: consolidated tools/list response < 15K tokens
- [ ] No regression in native tool access
- [ ] `cargo build --release -p maenifold-cli` succeeds
