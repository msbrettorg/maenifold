# T-223.2 — OpenCode sessions connect but never return assistant output

## Problem

On the Agents tab, an OpenCode session can appear connected, but prompt submission produces no assistant response. The failure mode is silent from the user's perspective.

## Hypotheses (from duo review)

1. **Silent default branch** — `useMessageHandler.ts:213-216` has an empty `if (import.meta.env.DEV) {}` block for unknown `sessionUpdate` variants. If OpenCode emits a variant the handler doesn't recognize, it's silently dropped.
2. **No TextDelta events** — Relay success only returns `stopReason: end_turn`. UI gets assistant content from streamed `agent_message_chunk` notifications. If OpenCode never emits `AcpEvent::TextDelta`, the UI legitimately shows nothing.
3. **Upstream agent failure** — `session/prompt` rejects but the rejection is swallowed in the sendPrompt catch path.
4. **Missing authentication** — OpenCode may require `authenticate` handshake that the desktop doesn't drive.
5. **Upstream opencode-ai regression** — fix may not live in this repo.

## Research Stage (GSD: research → plan → execute → verify)

Before any code changes, the researcher must:
1. Capture an ACP wire transcript of a failing OpenCode session (use `RUST_LOG=trace`)
2. Identify which `sessionUpdate` variants OpenCode emits
3. Determine if `agent_message_chunk` events are present in the stream
4. Check the `default:` branch in `useMessageHandler.ts` for dropped updates
5. Pin the `opencode-ai` version used in testing
