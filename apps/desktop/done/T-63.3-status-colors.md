# T-63.3 — Status Colors: Single Source of Truth

**Test Cases**: TC-7
**Repo**: pipeline-ui
**Component**: src/components/PipelineNodeCard.vue, src/components/PipelineInspector.vue, src/components/PipelineSidebar.vue

## Context

Status colors are defined as JS objects in 3 separate files with CONFLICTING values. `stuck` is orange in 2 files and red in 1. This is the #1 visual inconsistency.

## Acceptance Criteria

1. DELETE all `STATUS_COLORS` / `statusColor` JS/TS objects from PipelineNodeCard.vue, PipelineInspector.vue, and PipelineSidebar.vue
2. Replace with CSS classes defined in T-63.0's design tokens: `.status-dot--pending`, `.status-dot--active`, `.status-dot--completed`, `.status-dot--abandoned`, `.status-dot--stuck`, `.status-dot--ready`
3. Add `.status-text--{status}` classes for text coloring (same palette)
4. All 3 components use the CSS classes — zero JS color mapping for status
5. `stuck` renders consistently as `--color-status-stuck` (orange/amber) everywhere
6. Typecheck passes: `npx vue-tsc --noEmit`
