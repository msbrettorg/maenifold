# T-205.702 — Fix: Sidebar expand button does not restore sidebar

**Pipeline**: test
**Pipeline Digest**: 16842feaee5604e196f8d0c4ddc8a6566bd538a1ad2d739bc956a9e49f123128

## Bug

On the Agents tab, after clicking "Collapse sidebar" the sidebar collapses correctly. However, clicking "Expand sidebar" does NOT restore the sidebar. The button exists in the accessibility tree and is clickable, but clicking it has no visible effect — the sidebar remains collapsed showing only "No active session / Select an agent and start a new session" with no way to access the agent selector, session list, or any sidebar controls.

**Severity: P1** — The user is locked out of the Agents sidebar with no recovery path other than navigating away and back.

## Reproduction

1. Navigate to Agents tab
2. Click "Collapse sidebar"
3. Click "Expand sidebar" — **nothing happens**
4. Click it again — still nothing
5. Sidebar remains collapsed

## Found During

UAT T-205.19 interactive CDP testing. Multiple clicks on @e2 ("Expand sidebar") confirmed via accessibility tree snapshots.

## Evidence

Screenshots: T-205.18-sidebar-collapsed.png, T-205.19-expand-stuck.png

## Acceptance

- Clicking "Expand sidebar" restores the full sidebar with agent selector, sessions list, and all controls
- Round-trip: collapse → expand → collapse → expand works reliably

## Additional Findings

- **Real mouse click works** (user confirmed)
- **Keyboard activation (focus + Enter) works** via CDP
- **CDP `.click()` does NOT work** — the programmatic click event is eaten or ignored

This suggests the button handler may be on `mousedown`/`pointerdown` instead of `click`, or there's a transparent overlay intercepting pointer events that a real mouse bypasses but CDP dispatch does not.

**Revised severity: P2** — workaround exists (keyboard activation), but programmatic click failure is still a bug for automation and accessibility.
