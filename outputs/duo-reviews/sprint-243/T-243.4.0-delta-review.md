# T-243.4.0 — Gate tab delta review

Plain-English review of the **Gate tab**. Three lenses:

1. **What the UAT doc tests** (`T-243.4-gate-tab-uat.md`)
2. **What's actually built today** (per `outputs/uat/cdp-tab-enumeration.md` + screenshots `04-gate-*.png`)
3. **What a normal user expects from a task tracker** (Issues / Linear / Jira / Trello / Things)

Gate is our delivery process. If the UI can't drive it, it's a viewer, not a tool.

---

## Snapshot of "what is actually built"

From CDP enumeration of the Gate tab:

- Top counts: `0 todo / 824 done / 824 total`.
- Controls: repo selector, Browse…, Remove, Refresh, filter searchbox, **process filter**, **state filter**, one checkbox.
- Table columns: **Task ID | Task | Process | Progress**. Sortable. Rows clickable → detail.
- Detail view: shows task body + breadcrumb to on-disk file path.
- Explicitly **missing**: create-task button, inline edit, stage-action buttons (Append / Pass / Fail), pipeline diagram, dependency view, per-row progress bar, "Browse…" purpose unclear.

So today the Gate tab is a **read-only file browser** over `todo/` and `done/` with sort/filter. Nothing more.

## Lens 1 — UAT doc vs reality

| UAT section | What the doc asks for | What's built | Delta |
|---|---|---|---|
| A. Task list | ID/title/state/pipeline/timestamp; filter by state/pipeline/ready-blocked; include-done toggle; text search; sort by ID/recency/state | ID, title, process, progress columns; state + process filters; text filter; sort by columns; the checkbox is probably the include-done toggle | **Mostly there.** Missing: `last-updated` column, explicit `ready` / `blocked` filter, sort by recency. |

| C. Task CRUD | Create, edit title, edit body, delete/cancel, re-pipeline | None of these are in the UI | **Total gap. CDP's "no task creation in UI" is confirmed.** |
| D. Stage actions | Append note, Pass, Fail, Sync | None visible | **Total gap.** Gate's three mutating commands (`gate_Append` / `gate_Pass` / `gate_Fail`) plus `gate_Sync` are unreachable from the UI. The user must drop to MCP / curl. |
| E. Pipeline browser | List pipelines, view diagram, edit JSON | Nothing visible. (Process filter is a dropdown of names only.) | **Total gap.** `assets/gates/*.json` is invisible to the user. |

**Headline:** the UAT doc's checklist sections **A** and parts of **B** map to ~60% of what's built. Sections **C, D, E** map to ~0%. The doc is correctly scoped — it just exposes how much of Gate is missing from the UI.

## Lens 2 — Built vs user expectations (Issues / Linear / Jira / Trello / Things)

What a normal user reaches for and what we have:

| User expectation | Found in… | Have it? | Gap impact |
|---|---|---|---|
| **Quick-add a task without leaving the screen** ("+ New task" button, or just press `n`) | Every tracker | ❌ | High. Friction here is the difference between people using gate and people not using gate. |
| **Inline edit a title** (single click) | Linear, Things, GitHub | ❌ | Medium. Forces editor round-trip for typos. |
| **Inline edit body / markdown editor in the detail pane** | Linear, GitHub | ❌ | Medium-high. Today the detail pane is read-only; you have to open the .md file in another editor and refresh. |
| **Move a task through states from the UI** (drop-down, button, or kanban drag) | Linear, Trello, Jira | ❌ | **Critical.** This is what gate *is*. The UI exposes none of it. |
| **Kanban / swimlane view by state** | Trello, Jira, Linear | ❌ | Medium. We have the data (state column) but no board view. |
| **"Mine" / assignee filter** | Every tracker | ❌ (no assignee model in gate) | Low for solo, high once multi-agent. |
| **Workflow / state-machine diagram for the active pipeline** | Jira workflows, Linear cycles | ❌ | Medium. We literally render this on the Pipelines tab for DAGs — Gate is the obvious second home for a state-diagram view. |
| **Desktop notification when red-team finishes a task of mine** | Linear, Slack-integrations | ❌ | Medium. Also relevant to the orchestration loop. |
| **Full-text search across `done/`** (e.g. "what did I ship in sprint 220?") | GitHub Issues, Linear | Partial — there's a "Filter tasks" searchbox; unknown if it spans body or just titles, or if it includes `done/` when "include done" is off | Likely gap. Worth filing a sub-task to verify scope. |
| **Stage history timeline** (who passed/failed when, with notes) | GitHub PR timeline, Linear activity | ❌ | High. Gate's append-only stage records are the most useful audit artifact in the system and they aren't shown. |
| **Click an ID anywhere → jump to detail** | Every tracker | ❌ (likely) | Medium. |
| **Empty state with onboarding** ("Create your first task") | Linear, Things | Unknown — `0 todo` is shown but no CTA visible | Low-medium. |
| **Bulk select + bulk advance / reassign** | Jira, Linear | ❌ | Low (gate is one-task-at-a-time by design). |

The **must-haves** for credibility as a task tracker are: quick-add, inline edit, advance/fail buttons, stage history timeline, and the pipeline state diagram. Everything else is polish.

## What we'd file as sub-tasks

In priority order:

1. **T-243.4.1 — Stage actions in UI** (Append / Pass / Fail / Sync buttons in the detail view, with a notes textarea). Without this, Gate is a viewer.
2. **T-243.4.2 — Stage history timeline in detail view** (chronological list of stage records: agent, outcome, notes, timestamp). The data is already in `gate_History`.
3. **T-243.4.3 — Create-task form** (title, pipeline, priority, sprint, body). Writes to `todo/`. No more "drop to terminal" to file a task.
4. **T-243.4.4 — Inline edit of title and body**. Markdown editor in detail pane.
5. **T-243.4.5 — Pipeline state diagram in detail view**, current state highlighted. Re-use the rendering from the Pipelines tab.
6. **T-243.4.6 — Pipeline browser sub-tab** (list of installed pipelines, view JSON, view diagram). Edit-in-editor link is fine; inline JSON edit is a stretch goal.
7. **T-243.4.7 — `ready` / `blocked` filter and `last-updated` column + recency sort** (closes Section A gap).
8. **T-243.4.8 — Verify search scope** (titles only? body? does it span `done/` when hidden?). Likely a small fix once verified.
9. **T-243.4.9 — Cross-tab deep-linking** for task IDs (`gate://T-243.4` style or in-app router).
10. **T-243.4.10 — Error / recovery surfaces** (daemon down, corrupt YAML, sync failure). Likely a wider UX task.
11. **T-243.4.11 — Kanban / swimlane view by state** (stretch; only after 1-5 land).
12. **T-243.4.12 — Desktop notifications on stage transitions** (stretch; tie to the existing daemon).

`T-243.4.1` and `T-243.4.2` are the bare minimum to call this tab "the Gate tab" instead of "a markdown viewer with filters."
