# T-238.44 - Gate append terminal task follow-up error lacks recovery path

**Pipeline**: lightweight

## Goal

Make Gate follow-up error recording robust when a related task is already terminal. Operators need an MCP-visible way to record a new reproduction or successor task without losing the exact error context.

## Trigger

During T-239.3 red-team fail handling, the PM attempted to append a new SequentialThinking reproduction to T-238.41. Gate returned:

```text
code: -32602
message: task 'T-238.41' is already terminal; append is not allowed on completed tasks
```

## Expected behavior

Gate should provide one of:

- a supported successor/follow-up task creation flow through MCP;
- a clear error response that names the correct recovery command;
- or a terminal-safe append mechanism for post-completion reproductions.

The operator should not have to fall back to ad hoc file creation to preserve an MCP/tooling error.

## Acceptance Criteria

- [ ] Terminal-task append failures return actionable recovery guidance.
- [ ] The MCP/Gateway surface documents how to record a follow-up when the related task is done.
- [ ] The recovery path preserves the original attempted task id, failing operation, exact error, and expected behavior.
- [ ] No standalone Gate CLI dependency is required for this flow.

## Verification

- Focused Gate/Gateway test or real MCP exercise demonstrating a terminal task follow-up can be recorded through the documented path.
