# T-43.1: Content Block Refactor — Rich Content Support

**Requirement**: FR-42 audit findings — Content Blocks  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/lib/types.ts`, `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/components/ChatView.vue`

## Acceptance Criteria

1. Refactor `ChatMessage.content: string` to support rich content. Add a `blocks` field:
   ```ts
   export interface ContentBlock {
     type: 'text' | 'image' | 'audio' | 'resource' | 'resource_link';
     text?: string;
     data?: string; // base64 for image/audio
     mimeType?: string;
     uri?: string;
     name?: string;
     resource?: { uri: string; text?: string; blob?: string; mimeType?: string };
     annotations?: Record<string, unknown>;
   }
   
   export interface ChatMessage {
     id: string;
     role: 'user' | 'assistant' | 'system';
     content: string; // kept for backward compat — concatenated text
     blocks?: ContentBlock[];
     thought?: string;
     timestamp: number;
     toolCalls?: ToolCallInfo[];
   }
   ```

2. In all three `handleSessionUpdate` handlers (`user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`), when receiving non-text content blocks, store them in the `blocks` array instead of dropping them.

3. In `ChatView.vue`, render `blocks` when present:
   - `text` → `renderMarkdown(block.text)`
   - `image` → `<img :src="'data:' + block.mimeType + ';base64,' + block.data" />`
   - `resource_link` → clickable chip with `block.name` and `block.uri`
   - `resource` → code block with URI label
   - `audio` → `<audio controls :src="'data:' + block.mimeType + ';base64,' + block.data" />`

4. Refactor `sendPrompt(text: string)` to `sendPrompt(text: string, attachments?: ContentBlock[])`. When attachments are provided, include them in the prompt content array alongside the text block.

## Spec References
- https://agentclientprotocol.com/protocol/content
- Audit: R2–R5 (image/audio/resource/resource_link all unimplemented)

## SWE Remediation

### What I changed
- `vendor/acp-ui/src/lib/types.ts`
  - Added `ContentBlock` as an ACP-backed rich content type and extended `ChatMessage` with optional `blocks` for structured message content while keeping `content` as the legacy concatenated text field.
- `vendor/acp-ui/src/stores/session.ts`
  - Added structured content helpers for session updates.
  - Updated `user_message_chunk`, `agent_message_chunk`, and `agent_thought_chunk` handling so non-text ACP content blocks are preserved on `message.blocks` instead of being dropped.
  - Refactored `sendPrompt(text)` to `sendPrompt(text, attachments?)`, sending a text block plus attachments to ACP and storing attachments on the local user message for rendering.
- `vendor/acp-ui/src/components/ChatView.vue`
  - Added rich content rendering for message `blocks`.
  - Implemented rendering for `text`, `image`, `audio`, `resource_link`, and `resource` blocks.
  - Kept legacy `message.content` rendering as a fallback so pre-refactor/plain-text messages still display correctly without duplicating text when structured text blocks are present.

### Test results
- PASS — `cd vendor/acp-ui && npx vue-tsc --noEmit`
- PASS — `cd vendor/acp-ui && bun run build`

### Notes
- `ContentBlock` is sourced from the ACP SDK type export so the UI state stays aligned with protocol-defined block shapes.
- For thought updates, text chunks continue to accumulate in `message.thought`; any non-text thought chunks are preserved on the assistant message `blocks` collection so they are no longer lost.
