## Problem

During PM orchestration for `T-235.1`, background agents were launched with explicit
model overrides:

- `t2351-duo-opus` requested `claude-opus-4.7`
- `t2351-duo-gpt` requested `gpt-5.5`

When the PM later read those agents via `read_agent`, both results reported
`model: gpt-5.4`.

That is a tooling integrity failure. The PM relies on explicit architect-model
selection for duo review. If the runtime silently substitutes a different model
or reports the wrong model back, the review provenance becomes untrustworthy and
the PM cannot tell whether spec approval actually came from the intended agent.

## Scope Notes

- Do not assume this repository owns the underlying task runtime. The task must first classify whether the problem is:
  - **A. execution drift** — requested model differs from the effective execution model
  - **B. metadata drift** — requested model matches the effective execution model, but `read_agent` / `list_agents` report it incorrectly
  - **C. external/opaque** — the effective model cannot be verified from repo-owned surfaces
- Treat stylistic similarities or model self-reporting as non-evidence. Evidence must come from dispatch inputs, runtime/session acceptance signals, repo-owned reporting surfaces, or a provider/runtime effective-model signal if one exists.
- If the runtime is external/opaque, the repo-owned fix surface is mitigation/docs/policy, not a fabricated runtime patch.
