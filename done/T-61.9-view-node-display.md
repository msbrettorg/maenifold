# T-61.9 — Mermaid Display for New Node Types

**Requirement**: FR-47
**Test Cases**: TC-205
**Component**: `crates/maenifold-core/src/workflow/pipeline/view.rs`
**Depends on**: T-61.4 (types.rs must be updated first)

## Context

`view.rs:53` generates a Mermaid DAG diagram for pipeline visualization. Currently all nodes are rendered identically since they're all workflow nodes. After T-61.4, nodes have different types that should be visually distinguishable.

The view response also includes node metadata. It should include `type` and type-specific fields in the node data.

## Acceptance Criteria

### Mermaid Diagram

1. Workflow nodes: render as rectangles (current behavior, Mermaid default `[label]`)
2. Prompt nodes: render as rounded rectangles (Mermaid `(label)` syntax)
3. SequentialThinking nodes: render as hexagons (Mermaid `{{label}}` syntax)

4. Node labels MUST include the type prefix:
   - Workflow: `"wf: {workflow_id}"` (existing behavior but now prefixed)
   - Prompt: `"prompt: {first_40_chars_of_prompt}..."`
   - SequentialThinking: `"think: {topic}"`

5. Edge styling MUST remain unchanged (success = solid, always = dotted).

### View Response

6. In the JSON view response, each node object MUST include:
   - `type`: "workflow" | "prompt" | "sequentialThinking"
   - Type-specific fields: `workflowId` for workflow, `agent` for prompt/thinking, `topic` for thinking

7. Use `node.node_type_name()` accessor for the type string.

8. All existing view tests MUST continue to pass.

9. The code MUST compile: `cargo build -p maenifold-core`
