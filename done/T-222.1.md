# T-222.1 — Voice Companion Absolute Path Hardening

## Problem

The voice companion electron handler uses PATH-resolved system utilities (`tasklist`, `sh`, `pgrep`, `open`) which could theoretically execute unexpected binaries if the Electron process PATH is poisoned. Windows candidate paths also depend on mutable environment variables (`LOCALAPPDATA`, `PROGRAMFILES`).

## Evidence

- `apps/desktop/electron/voice.ts:42-46` — `spawnSync('tasklist', ...)`
- `apps/desktop/electron/voice.ts:52-56` — `spawnSync('sh', ['-c', 'pgrep ...'])`
- `apps/desktop/electron/voice.ts:89-91` — `spawnSync('open', ['-a', 'Handy'])`
- `apps/desktop/electron/voice.ts:20-24` — Windows paths from env vars
- Red-team finding from T-220.24 audit (pre-existing behavior, not part of T-220.24 delta)

## Acceptance Criteria

- [ ] Replace PATH-resolved `tasklist` with absolute path (`%SystemRoot%\System32\tasklist.exe`)
- [ ] Replace `sh -c 'pgrep'` with direct `/usr/bin/pgrep` absolute path
- [ ] Replace `open -a Handy` with `/usr/bin/open -a Handy`
- [ ] Windows candidate paths derive from trusted OS APIs or use fixed known roots
- [ ] `cd apps/desktop && npx vue-tsc --noEmit` succeeds
