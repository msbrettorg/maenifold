# T-221.11 — Config Validation Errors Must Not Be Swallowed

## Problem

`AgentsConfig::load_or_default()` in `loader.rs` catches all errors from `AgentsConfig::load()` and returns defaults. This silently swallows `MaenifoldError::AgentSetup` validation errors added by T-221.4 for the gateway intent resolver config.

If a user configures `gateway.intentResolver.enabled: true` with an invalid agent, the app starts with defaults (enabled=false) instead of surfacing the configuration error.

## Scope

Make `load_or_default()` propagate `AgentSetup` errors while still falling back to defaults for missing/unparseable config files.

## Acceptance Criteria

- [ ] `load_or_default()` propagates `MaenifoldError::AgentSetup` errors instead of swallowing them
- [ ] Missing config file still returns defaults (no regression)
- [ ] Malformed JSON/YAML config file still returns defaults (no regression — pre-existing behavior)
- [ ] Invalid intent resolver config (enabled=true, bad agent) surfaces a clear error
- [ ] `cargo build --release -p maenifold-cli` succeeds

### Phase 1: Change Return Type

**Modified:** `acp/config/loader.rs`
- Change `load_or_default(root: &Path) -> AgentsConfig` to `-> Result<AgentsConfig>`
- Match on error: `Err(MaenifoldError::AgentSetup(..))` → propagate
- All other `Err(..)` → warn + `Ok(Self::default())`

### Phase 2: Update Callers

**Modified:** `config.rs`
- `Config::current()` calls `load_or_default().settings.unwrap_or_default()`
- Change to `load_or_default(&maenifold_root)?.settings.unwrap_or_default()`
- This means `Config::current()` must return `Result<Config>`

**Modified:** `api/config_manager.rs`
- `ConfigManager::new()` wraps `load_or_default()` in Arc
- Handle the Result: propagate or warn + default

### Phase 3: Propagate Config::current() Result

All callers of `Config::current()` need to handle Result. Check with LSP `findReferences` for the full call chain and update each caller with `?` propagation.
