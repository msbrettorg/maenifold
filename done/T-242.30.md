# T-242.30 — Fix mcp-loopback.ts type errors blocking vue-tsc

**Pipeline**: tdd

## Problem

The T-242.15 merge introduced `apps/desktop/src/__tests__/helpers/mcp-loopback.ts` which fails `vue-tsc --noEmit` on dev:

```
src/__tests__/helpers/mcp-loopback.ts(1,73): error TS2591: Cannot find name 'node:http'. Do you need to install type definitions for node?
src/__tests__/helpers/mcp-loopback.ts(2,34): error TS2591: Cannot find name 'node:net'. Do you need to install type definitions for node?
src/__tests__/helpers/mcp-loopback.ts(51,21): error TS7006: Parameter 'chunk' implicitly has an 'any' type.
src/__tests__/helpers/mcp-loopback.ts(191,42): error TS7006: Parameter 'req' implicitly has an 'any' type.
src/__tests__/helpers/mcp-loopback.ts(191,47): error TS7006: Parameter 'res' implicitly has an 'any' type.
src/__tests__/helpers/mcp-loopback.ts(286,27): error TS7006: Parameter 'error' implicitly has an 'any' type.
```

The T-242.15 SWE reported `vue-tsc --noEmit` passed in their worktree, but the merged dev tree fails. Likely cause: the worktree had stale tsconfig type resolution, or @types/node was loaded transitively in their env.

## Root cause

`apps/desktop/tsconfig.json` does NOT include `"types": ["node"]` in compilerOptions, so `node:http` and `node:net` modules aren't resolved by vue-tsc even though `@types/node` is installed.

## Fix

Pick the smallest non-breaking fix:

**Option A (preferred):** Add `/// <reference types="node" />` at the top of `apps/desktop/src/__tests__/helpers/mcp-loopback.ts`. Localized — doesn't affect the rest of the project's type resolution.

**Option B:** Add explicit type annotations to the implicit-any callbacks (`chunk: Buffer`, `req: IncomingMessage`, `res: ServerResponse`, `error: Error`).

Both are needed:
1. Triple-slash reference for node types.
2. Explicit param annotations for the 4 implicit-any callbacks.
