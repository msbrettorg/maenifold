# T-63.2 — Regex Static Compilation

## Problem
`workflow/runner.rs` has 4 `.expect()` calls on `Regex::new()` at lines ~105, 162, 251, 258. The patterns are valid constants so they won't panic today, but:
- They recompile on every call (performance waste)
- A panic mid-workflow leaves sessions in zombie state
- The codebase uses `once_cell::sync::Lazy` in 60+ files — this should follow the same pattern

## Requirements
1. Add 3 `once_cell::sync::Lazy<Regex>` statics at module top:
   - `WIKILINKS_RE` — `r"\[\[.*?\]\]"`
   - `WORKFLOW_SESSION_RE` — `r"workflow-\d+"`
   - `STEP_PROGRESS_RE` — `r"Step (\d+)/(\d+)"`
2. Replace `.expect("wikilink regex")` at lines ~105 and ~162 with `&WIKILINKS_RE`
3. Replace `Regex::new(...).expect("workflow session regex")` at line ~251 with `&WORKFLOW_SESSION_RE`
4. Replace `Regex::new(...).expect("workflow step regex")` at line ~258 with `&STEP_PROGRESS_RE`
5. No `.expect()` calls on `Regex::new` remain in `runner.rs`

## Reference Pattern
```rust
// From config.rs
use once_cell::sync::Lazy;
static OVERRIDES: Lazy<RwLock<Overrides>> = Lazy::new(|| RwLock::new(Overrides::default()));
```

## Files
- `crates/maenifold-core/src/workflow/runner.rs` — replace 4 call sites with 3 statics

## Tests
- Existing `cargo test -p maenifold-core` must pass (behavior unchanged)
- `grep -n 'expect.*regex' runner.rs` returns empty

## Acceptance
- Zero `.expect()` on regex compilation in runner.rs
- Regexes compiled once at module load
- No warnings, no panics
