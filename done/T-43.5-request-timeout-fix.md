# T-43.5: Request Timeout Fix

**Requirement**: FR-42 audit findings — Transports  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/lib/acp-bridge.ts`

## Acceptance Criteria

1. The current `sendRequest` method in `acp-bridge.ts` applies a blanket 60-second timeout to ALL outgoing requests (~L221-228). This is incompatible with long-lived methods like `terminal/wait_for_exit` which may block for minutes.

2. Add per-method timeout support:
   ```ts
   private getTimeoutForMethod(method: string): number {
     switch (method) {
       case 'terminal/wait_for_exit':
         return 30 * 60 * 1000; // 30 minutes
       case 'terminal/create':
         return 5 * 60 * 1000; // 5 minutes
       case 'session/load':
         return 5 * 60 * 1000; // 5 minutes (large session replay)
       default:
         return 60 * 1000; // 60 seconds
     }
   }
   ```

3. Use `this.getTimeoutForMethod(method)` instead of the hardcoded `60000` in the `setTimeout` call.

The Pass 1 audit contained several **fabricated claims** that do not match the actual code and must be corrected for the record:

1. **Wrong line numbers throughout.** Pass 1 cited `getTimeoutForMethod` at lines `259–274` and `sendRequest` at line `276`. The actual locations are `getTimeoutForMethod` at lines `203–214` and `sendRequest` starting at line `216`.

2. **Non-existent `if (timeoutMs > 0)` guard.** Pass 1 claimed: *"`acp-bridge.ts:326–331` guards `setTimeout` behind `if (timeoutMs > 0)`."* No such guard exists anywhere in the file. The `setTimeout` fires unconditionally for every call to `sendRequest`. There is no mechanism to skip the timer for async mutation methods. Line 326 is beyond the end of the `sendRequest` method entirely.

3. **Non-existent switch cases.** Pass 1 claimed the implementation includes `session/prompt → 30 minutes` and `session/set_mode` / `session/set_config_option` / `session/set_model → 0`. None of these cases appear in `getTimeoutForMethod`. Those methods fall through to the `default → 60 seconds` branch.
