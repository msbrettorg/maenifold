# T-43.8: Validate cwd for session/load

**Requirement**: FR-42.2 audit gap  
**Priority**: P0  
**Files**: `vendor/acp-ui/src/stores/session.ts`

## Acceptance Criteria

1. In `resumeSession()`, validate `savedSession.cwd` is an absolute path before passing it to `session/load`. Use the same `isAbsolutePath()` check from App.vue, or inline it. If invalid, throw an error.

2. Fix the path validator to also handle Windows UNC paths (`\\server\share`): add `||  /^\\\\/.test(path)` to the regex.

3. Apply the same validation before both `loadSession` call sites in `resumeSession()` (there are two — normal path and post-auth retry path).

## SWE Remediation

- **What changed**
  - `vendor/acp-ui/src/stores/session.ts`: added an `isAbsolutePath()` helper matching the app-side validator, updated it to accept Windows UNC paths, and validated `savedSession.cwd` before both `acpClient.loadSession()` call sites in `resumeSession()`. Invalid saved cwd values now disconnect and throw a clear error before issuing `session/load`.
  - `vendor/acp-ui/src/App.vue`: updated the existing absolute-path validator to also accept Windows UNC paths (`\\server\share`).

- **Test results**

- **Notes**
