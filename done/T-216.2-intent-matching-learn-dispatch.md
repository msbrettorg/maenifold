# T-216.2 — Intent Matching and Learn Dispatch

**Pipeline**: sdd
**Priority**: P1

## Scope

Add intent-matching and learn-mode dispatch logic to `gateway_consolidation.rs` or a new `gateway_dispatch.rs` (~100 LOC).

## What to Build

### Learn Mode

When a consolidated facade tool is called with `learn: true`:

**Tier 1** — `{ learn: true }` (no command):
Return a text summary listing all available commands for this server with name + one-line description.

**Tier 2** — `{ learn: true, command: "X" }`:
Return the full JSON schema for tool X from the cached tool catalog.

### Intent Matching

When called with `intent` but no `command`:

1. Score each tool in the server's catalog against the intent string
2. Scoring: case-insensitive substring match on tool name + description. Prefer name matches over description-only matches.
3. If exactly 1 match: dispatch to that tool with `parameters`
4. If 2-5 matches: return candidates with descriptions, let LLM pick
5. If 0 matches: return error suggesting `learn=true`
6. If >5 matches: return error — intent too broad, suggest `learn=true` or more specific intent

### Direct Command

When called with `command`:
- Look up exact tool name in the server's catalog
- If found: dispatch via `StdioPool::call_tool(server_name, command, parameters)`
- If not found: return error with available commands hint

## Acceptance Criteria

- [ ] `learn=true` returns readable tool catalog
- [ ] `learn=true, command="X"` returns full schema
- [ ] Intent matching finds correct tool for clear intents
- [ ] Ambiguous intents return candidate list
- [ ] Direct command dispatch works
- [ ] Unknown command returns helpful error
- [ ] `cargo build --release -p maenifold-cli` succeeds
- [ ] File ≤300 LOC
