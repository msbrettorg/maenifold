# T-46.6: Session Map Reactivity Fix

**Requirement**: FR-46
**Priority**: P0
**Files**: `vendor/acp-ui/src/stores/session.ts`

## Context

`sessions` is a `ref<Map<string, SessionState>>`. Vue's reactivity tracks the Map reference, not deep mutations to objects inside it. When code does `sessionState.isConnected = true`, Vue doesn't know the computed shims need to re-evaluate. This causes:
- ChatView not rendering after connection succeeds
- Sidebar losing connected badge
- Folder button staying disabled

Prior sprint (T-44.10) identified this exact bug with `shallowRef(Map) + triggerRef()` and concluded it's a bug factory.

## Acceptance Criteria

1. Wrap each `SessionState` in `reactive()` when adding it to the Map. This makes deep property mutations automatically trigger Vue's reactivity.

2. In `createSession` and `resumeSession`, when creating the session state:
   ```ts
   const sessionState = reactive(createEmptySessionState(localId, agentName, cwd));
   sessions.value.set(localId, sessionState);
   ```

3. After `sessions.value.set(...)`, reassign the Map to trigger the ref:
   ```ts
   sessions.value = new Map(sessions.value);
   ```
   This ensures the computed `activeSession` re-evaluates when new entries are added or removed.

4. After `sessions.value.delete(...)`, same pattern:
   ```ts
   sessions.value = new Map(sessions.value);
   ```

5. All in-place mutations to session state properties (isConnected, isConnecting, messages, etc.) should now be reactive automatically via the `reactive()` wrapper — no `triggerRef` needed.

6. Fix the folder button: remove `:disabled="isConnecting"` from the cwd button in App.vue — it should never be disabled. Users need to pick folders for new sessions regardless of connection state.
