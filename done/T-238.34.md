# T-238.34 — Gate CLI pass/fail must require expectedState

## Problem

T-237.1a2 remediation added `expectedState` guard to the MCP gate tools but the CLI path sets it to `None`, bypassing replay protection. The core `OutcomeArgs.expected_state` is `Option<String>`.

## Fix

- Add `--expected-state` CLI flag to `gate pass` and `gate fail`
- Make it required (error if omitted)
- Change `OutcomeArgs.expected_state` from `Option<String>` to `String` for pass/fail
- Use a separate args type for cancel if it needs to omit expectedState

## Verification

- `gate pass T-xxx --root . --agent x --notes x` without `--expected-state` → error
- `gate pass T-xxx --root . --agent x --notes x --expected-state wrong` → state mismatch error
- `cargo test -p maenifold-gate`
