# T-200.12 — Split execute.rs (395 LOC → 2 files under 300)

## Intent

`crates/maenifold-jockey/src/acp/session/execute.rs` is 395 production LOC — 1.32x the 300 LOC hard limit. Extract the delta stream processing loop and support types into a separate module.

## Scope

Files to modify:
- `crates/maenifold-jockey/src/acp/session/execute.rs` — trim to ~170 LOC (setup + delegation + result building)
- `crates/maenifold-jockey/src/acp/session/execute_stream.rs` — new, ~225 LOC (stream loop, payload types, utility functions)
- `crates/maenifold-jockey/src/acp/session/mod.rs` — add `mod execute_stream;`

## Extraction Plan

### execute_stream.rs (new, ~225 LOC)

Move from execute.rs:
- `AcpDeltaPayload` struct (lines 18-25)
- `AcpStreamPayload` struct (lines 27-34)
- `error_code_from_raw()` function (lines 356-375)
- `mock_execute()` function (lines 377-395)
- New function `run_delta_loop()` containing the stream processing logic (lines 127-286)

The `run_delta_loop` function signature:
```rust
pub(super) async fn run_delta_loop(
    delta_rx: &mut mpsc::Receiver<AcpEvent>,
    result_rx: oneshot::Receiver<Result<(String, String), String>>,
    event_tx: &crate::EventSender,
    runtime_key: &str,
    role_name: &str,
    app_session_id: &str,
    prompt: &str,
) -> (Result<(String, String), String>, String, usize)
```

Returns `(result, full_output, delta_count)`. The `flush_delta_batch!` macro becomes inline code or a local closure within the new function.

### execute.rs (keep, ~170 LOC)

Retain:
- `execute_runtime()` function — setup (adapter resolution, worker message) + call to `run_delta_loop()` + result building
- No payload structs (moved)
- No utility functions (moved)

Add import: `use super::execute_stream::{run_delta_loop, error_code_from_raw, mock_execute, AcpDeltaPayload, AcpStreamPayload};`

Wait — `AcpDeltaPayload` and `AcpStreamPayload` are NOT used in execute.rs after moving `run_delta_loop`. So only import `run_delta_loop`, `error_code_from_raw`, `mock_execute`.

1. `cargo build --release -p maenifold-jockey` succeeds
2. `cargo test -p maenifold-jockey` passes (all existing tests)
3. Both files are under 300 production LOC
4. No behavioral changes — pure code move + function extraction
