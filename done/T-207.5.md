# T-207.5 — Gateway opt-in config

## Requirement

Add a `gateway` boolean field to `McpServerEntry::Stdio`. Default `false`. Only servers with `gateway: true` have their tools exposed through the HTTP endpoint.

## Change

In `crates/maenifold-core/src/acp/config.rs`:

```rust
#[serde(rename = "stdio")]
Stdio {
    name: String,
    command: String,
    #[serde(default)]
    args: Vec<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    timeout: Option<u64>,
    #[serde(default, skip_serializing_if = "HashMap::is_empty")]
    env: HashMap<String, String>,
    #[serde(default, skip_serializing_if = "crate::util::is_false")]
    gateway: bool,
},
```

Add helper:

```rust
impl McpServerEntry {
    pub fn is_gateway(&self) -> bool {
        match self {
            McpServerEntry::Stdio { gateway, .. } => *gateway,
            McpServerEntry::Http { .. } => false, // HTTP servers are already directly reachable
        }
    }
}
```

## Config Example

```json
{
  "mcpServers": [
    { "type": "stdio", "name": "msx", "command": "npx", "args": ["-y", "@anthropic/msx-mcp"], "gateway": true },
    { "type": "stdio", "name": "internal-tool", "command": "my-tool" }
  ]
}
```

Second entry has no `gateway` field — defaults to `false`, not exposed.

## Security Note

Enabling `gateway: true` exposes ALL tools from that server to any localhost HTTP client (any page served from localhost). This is the trust model for local development. For future hardening, a `gatewayTools` allowlist field could restrict which specific tools are exposed per server.
