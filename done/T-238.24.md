# T-238.24 - Replace Knowledge tab with Obsidian-style browser and graph workspace

## Problem

The Knowledge tab still ships a broken split-pane layout with unacceptable blank space/gutter behavior. The user explicitly rejected incremental fixes to the current tab and directed that the whole Knowledge tab be removed and replaced with an Obsidian-style knowledge browser plus graph combo.

This task is Knowledge-first. It establishes the UI pattern that the Workflow tab must later reuse.

## Direct user instruction

Remove the whole Knowledge tab implementation and replace it with an Obsidian-style workspace:

- left vault/file browser
- note/content tabs using an Obsidian-like leaf/tab interaction model
- graph pane integrated with the browser/content surface
- no dead split-pane gap
- no blank vertical gutter
- no empty content desert when a list exists
- real data through the existing Maenifold/MCP boundary

Do not copy proprietary Obsidian source code, assets, or copyrighted UI implementation. Implement the Obsidian interaction model in this app using the project's Vue, Pinia, Tailwind, shadcn-vue/Reka primitives, and existing Maenifold graph/memory tools.

## Scope

Replace the current Knowledge tab surface. Current candidate files include:

- `apps/desktop/src/components/KnowledgeExplorer.vue`
- `apps/desktop/src/components/KnowledgeSidebar.vue`
- `apps/desktop/src/components/KnowledgeSidebarNode.vue`
- `apps/desktop/src/components/KnowledgeContent.vue`
- `apps/desktop/src/components/KnowledgeGraphPanel.vue`
- `apps/desktop/src/components/KnowledgeNoteRenderer.vue`

SWE must trace the active render path with LSP before editing. Dead components are not valid targets.

## Requirements

1. The Knowledge tab presents an Obsidian-style workspace:
   - vault/browser column for memory notes/folders
   - tab strip for open notes/views
   - note/content pane
   - graph pane visible in the same workspace, not hidden behind dead space
2. Selecting a note opens it in a tab/leaf and renders the note content.
3. Selecting graph nodes can open the corresponding note/concept where supported by existing data.
4. The graph pane and browser/content panes fill the available viewport without unexplained blank columns or vertical gutters.
5. Empty states must be useful and local to the pane that is empty; a populated browser must not coexist with a giant unrelated blank area.
6. The UI uses real Maenifold data through existing frontend MCP/transport surfaces. No fake notes, mock graph, stub data, or renderer-only shortcuts.
7. Each touched Vue/TS file stays under 300 LOC.
8. Use project design system constraints: no raw HTML controls where shadcn-vue/Reka components exist, no local `<style>` blocks, no hex colors, no audit suppressions.
9. The replacement pattern is documented in the task notes so T-238.25 can apply it to Workflows.

## Verification

- `cd apps/desktop && npx vue-tsc --noEmit && npm run build`
- `cd apps/desktop && npm run package`
- Launch packaged Electron with `--remote-debugging-port=9222`.
- Use `agent-browser` with the Electron skill to:
  1. click the Knowledge tab,
  2. click a note/folder in the browser,
  3. verify a content tab opens,
  4. verify graph pane is visible and usable,
  5. capture evidence that no blank split-pane gutter remains at the reported viewport size.

Screenshots alone are not sufficient; the verification must include clicked interactions and observed results.

## Non-goals

- Do not change the Workflow tab in this task.
- Do not add programmatic UAT/checklist generation.
- Do not bypass MCP/transport with direct filesystem reads from the renderer.
