## Description

Create the SDD gate pipeline template at `ralph/pipeline-meta/templates/sdd-v1.json`. This is the primary template for feature work: SWE → red-team → blue-team → done, with conditional routing for remediation.

## Template structure

Nodes:
- `swe` — prompt node, Copilot agent, opus model, cwd=worktree
- `red_team` — prompt node, returns JSON `{ "verdict": "PASS"|"FAIL", ... }`
- `blue_team_primary` — prompt node, returns JSON verdict
- `remediate` — prompt node, addresses red-team findings
- `red_team_reaudit` — prompt node, re-audits after fix
- `blue_team_after_fix` — prompt node
- Gate tool nodes — `gate.pass` / `gate.fail` at each stage transition
- `cleanup_worktree` — tool node, always-edge from terminal nodes

Edges:
- `swe → red_team` (success)
- `red_team → blue_team_primary` (conditional: verdict==PASS)
- `red_team → remediate` (conditional: verdict==FAIL)
- `remediate → red_team_reaudit` (success)
- Bounded at 2 remediation cycles
- All terminal paths → cleanup_worktree (always)

## Constraints (verified against code)

- `cwd`, `agent`, `toolName` rendered by shell, not pipeline interpolation
- `prompt` and `toolArgs` use `{{inputs.*}}` interpolation
- Conditional edges use dot-path `verdict`
- Template uses `definition.inputs` for parameterization

## Acceptance Criteria

- Valid JSON, parseable by `serde_json::from_value::<PipelineDefinition>`
- Can be instantiated by substituting inputs and submitted via `Pipeline` MCP tool
- Conditional edges route correctly on PASS/FAIL verdicts
- All terminal paths reach cleanup_worktree
