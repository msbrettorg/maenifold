# T-45.5b: Define `always` + `stuck` Edge Semantics

**Requirement**: FR-45.5
**RTM**: RTM-330
**Priority**: P2 — spec gap, no current bug

## Context

Red-team audit of T-45.5 identified that the behavior of `always` edges when the upstream node is `stuck` is undefined in the spec. Currently, `is_edge_satisfied` for `Always` only accepts `Completed` or `Abandoned` — `Stuck` is not included. This means a downstream node connected via an `always` edge to a `stuck` upstream stays `Pending` forever (not blocked, not ready — limbo).

The pipeline eventually reports `"stuck"` overall, but the downstream node never gets a chance to run even though the edge type suggests it should.

## Acceptance Criteria

1. **`always` edges accept `stuck`**: An `Always` edge SHALL be satisfied when the upstream node is `Completed`, `Abandoned`, OR `Stuck`. This matches the semantic intent of "always run regardless of upstream outcome."
2. **Update `is_edge_satisfied`**: In `crates/maenifold-core/src/workflow/pipeline/engine.rs`, add `NodeStatus::Stuck` to the `Always` edge match arm.
3. **Add explicit test**: Add a test for `Always + Completed` upstream → ready (currently untested per red-team).
4. **Add explicit test**: Add a test for `Always + Stuck` upstream → ready.
5. **Update PRD**: Add a note to FR-45.5 and FR-45.7 that `always` edges are satisfied by `Completed`, `Abandoned`, or `Stuck`.

## Implementation Notes

- Target: `crates/maenifold-core/src/workflow/pipeline/engine.rs`, `is_edge_satisfied` function
- Currently: `Always => matches!(status, Completed | Abandoned)`
- Fix: `Always => matches!(status, Completed | Abandoned | Stuck)`
- Also in T-45.8 `swe-resume-restart` the SWE already updated engine.rs to let `always` edges pass `stuck` — verify this is actually in the code
