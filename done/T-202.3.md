# T-202.3 — Fix agent step: replace hardcoded presets with free-form command input

## Problem

The agent step has hardcoded runtime presets (`copilot-cli`, `claude`, `openai`) that don't match how agents work. Agents are configured in `maenifold.json` with a `command` field containing a full shell command (e.g., `npx @github/copilot-language-server@latest --acp`).

## Verified ground truth

- `AgentConfig` in `apps/desktop/src/lib/types.ts`: `{ command: string; env?; mcpServers? }`
- `SettingsConnectionAgents.vue:88` already has the correct placeholder: `npx @github/copilot-language-server@latest --acp`
- `configStore.addAgent(name, { command })` POSTs to `POST /api/config/agents` which exists at `routes.rs:669`
- `configStore.hasAgents` and `configStore.agentNames` already exist in the store

## File

`apps/desktop/src/components/OnboardingStepAgent.vue`

## Changes required

1. **Delete** the `RUNTIMES` array and radio card selector (lines 15-37, 138-178)
2. **Replace** with two text inputs: `name` (default "Copilot") and `command` (placeholder from `SettingsConnectionAgents.vue`)
3. **Add skip logic**: If `configStore.hasAgents` is true on mount, show existing agents with a "Continue" affordance instead of the creation form
4. **Keep** `configStore.addAgent(name, { command })` — it already uses the correct POST endpoint

## Acceptance criteria

1. Agent step shows name + command text inputs (not a preset dropdown)
2. Command placeholder shows a real ACP command
3. Submitting adds the agent via `POST /api/config/agents`
4. If agents already exist, step shows them and allows continuing
5. Duplicate name shows error
6. `npx vue-tsc --noEmit` passes
