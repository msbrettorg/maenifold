# T-240.4 - Ralph revert report does not restore repository baseline

**Pipeline**: sdd

## Problem

Ralph reported an immutable-file violation and printed:

```text
VIOLATION: immutable file ralph.sh was modified!
REVERTING iteration 1: immutable file modified
Ralph iteration 1 complete: duration=3309s revert=true
```

The post-run repository state does not match a full iteration rollback.

Evidence from 2026-04-27:

- `ralph.sh` was restored to the expected hash `5246cb8aefc1bd0c0584229839622e057f13426d956593c88aa2e8c961ad24cb`.
- `git diff --quiet && git diff --cached --quiet` returned clean.
- `HEAD` remained at `f9d9f645f`, merge commit `Merge branch 'task/T-238.45' into dev`.
- `git log -2` still included `d887f1be8 feat(gate): add gate_Create command to MCP Gateway surface`.
- `git diff --stat f0599c3fe..HEAD` showed 33 changed tracked files since the earlier reset point.
- `git ls-files --others --exclude-standard` reported 147 untracked files, including `done/T-238.45.md`, `crates/maenifold-core/src/acp/config/public.rs`, and `crates/maenifold-core/src/api/oauth_bridge.rs`.
- A follow-up `gate_Sync` failed because rollback residue produced duplicate canonical task id `T-238.45` in both tracked `todo/T-238.45-gate-create-command-missing.md` and untracked `done/T-238.45.md`.

This means `revert=true` restored at least the immutable file but did not prove the branch returned to the pre-iteration baseline or that untracked iteration artifacts were cleaned or quarantined.

## Required Behavior

When Ralph reports an iteration rollback:

- The harness records the pre-iteration `HEAD` and immutable-file hashes before dispatch.
- A rollback restores `HEAD`, index, and working tree to the recorded pre-iteration baseline.
- New untracked files created by the iteration are removed or moved to an explicit evidence/quarantine directory outside the repository worktree.
- The final summary distinguishes:
  - immutable files restored;
  - tracked commits rolled back;
  - tracked working tree clean;
  - untracked residue count and paths;
  - convergence marker state.
- A convergence marker must not survive a failed rollback unless the summary explicitly records why it is safe.

## Acceptance Criteria

- [ ] A reproduced immutable-file violation cannot leave Ralph-created commits on the active branch while reporting `revert=true`.
- [ ] Rollback validation compares current `HEAD` to the recorded pre-iteration `HEAD`.
- [ ] Rollback validation fails closed if untracked iteration residue remains in the repository.
- [ ] The final Ralph summary prints base commit, final commit, tracked diff status, staged diff status, untracked count, and immutable hash results.
- [ ] Existing non-iteration untracked files are handled explicitly rather than silently mixed with iteration residue.
- [ ] Rollback cannot leave duplicate canonical task IDs that block `gate_Sync`.
- [ ] `ralph/state/converged` is removed or rejected when rollback validation fails.
- [ ] `ralph.sh` immutable protection remains enforced.

## Verification

- Run Ralph in a disposable branch or worktree with an intentional immutable-file mutation.
- Confirm the rollback returns `HEAD` to the pre-run commit.
- Confirm the working tree and untracked residue checks match the final summary.
- Confirm no convergence marker remains after a failed rollback.
