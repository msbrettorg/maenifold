# T-178.5a — Gate dashboard — desktop MCP resources migration

## Intent

Migrate the desktop Gate view (`apps/desktop/src/components/GateView*.vue`) from its current data-fetch path onto MCP `gate://` resources delivered via the [[T-178.0]] resource client. Apply the pattern proved out in [[T-178.4]]: subscribe to a small set of resource URIs, read on notification, write through `tools/call`. This is one of four parallel dashboard migration tasks under Sprint 178 ([[T-178.5a]] / [[T-178.5b]] / [[T-178.5c]] / [[T-178.5d]]).

## Scope

### 1. Define + register `gate://` resources in `crates/maenifold-core/src/mcp/resources.rs`

| URI | Read returns | Updated when |
|---|---|---|
| `gate://tasks/active` | `{ tasks: [GateTaskSummary], generated_at }` | Stage transition (pass/fail/sync), task append |
| `gate://tasks/done` | `{ tasks: [GateTaskSummary], generated_at }` | Task moves to done |
| `gate://pipelines/list` | `{ pipelines: [{ id, name, taskCount }], generated_at }` | Pipeline created / removed / renamed |
| `gate://task/{id}` (template) | `{ id, title, stage, history: [...], notes: [...], ... }` (full task body) | Stage transition or note append on this task |

Reuse subscription + throttling primitives from [[T-178.2]] / [[T-178.3c]]. Apply the throttle wrapper to `gate://tasks/active` (the only high-fanout URI here). Per-task notifications are unthrottled (low frequency).

### 2. Wire emitters at gate stage-change call sites

- `gate-pass`, `gate-fail`, `gate-sync`, `gate-append` on a task → notify `gate://tasks/active` and `gate://task/{id}`.
- Task entering `done/` → notify `gate://tasks/done` (in addition to active list).
- Pipeline mutation → notify `gate://pipelines/list`.

Minimal touches at the existing call sites — single function call each.

### 3. Migrate desktop Vue components

- Replace existing data-fetch path in `GateView.vue` / `GateViewContent.vue` / `GateViewStatus.vue` / `GateTaskTable.vue` / `GateTaskDetail.vue` with `useMcpResources` calls.
- Pinia store (`apps/desktop/src/stores/gate.ts` if present, or new): hold `activeTasks`, `doneTasks`, `pipelines`, `selectedTask` slices with `data / loading / error / lastUpdated` shape.
- Subscribe on mount, unsubscribe on unmount; re-subscribe on reconnect (per the T-178.0 contract).
- Writes (`gate-pass`, `gate-fail`, `gate-append`, etc.) continue via `tools/call` — do not change the write surface.

### 4. Fluent 2 styling — HARD REQUIREMENT

All visuals come from `apps/desktop/DESIGN.md` tokens. Same forbidden list as [[T-178.4]]:
- No hardcoded hex / RGB / HSL color literals.
- No `<style>` blocks in any `.vue` file in scope.
- shadcn-vue primitives only (Card, Badge, ScrollArea, Button, Input, Tooltip, Table, etc.).
- Body font: Segoe UI Variable (per DESIGN.md).
- Status colors: `--success` (passed), `--warning` (pending/in-progress), `--danger` (failed), `--muted` (done) — never raw hex.

### 5. Help docs

Append a section to `assets/help/resources/gate.md` (NEW file) documenting the URI scheme, payload shapes, update cadence, and throttling.

## Acceptance criteria

1. `cargo test -p maenifold-core` passes.
2. `pnpm --filter desktop build` and `pnpm --filter desktop test` pass; `vue-tsc` reports zero errors in files in scope.
3. Gate view performs ZERO HTTP calls to `/api/gate/*` (or any gate-prefixed REST path) — verified by network capture in a Playwright run.
4. Gate view uses only `useMcpResources` for reads and `tools/call` for writes.
5. Subscribe on mount + unsubscribe on unmount verified by unit tests on the relevant components.
6. Stage-transition notifications cause the table to refresh without manual reload — verified by a Playwright test that runs `gate-pass` via `tools/call` and asserts the table row updates within a generous timeout.
7. **Zero hardcoded hex/RGB/HSL** and **zero `<style>` blocks** in files in scope (grep verifications, same as T-178.4).
8. Playwright screenshot of the Gate view with a populated task list, attached to PR.
9. `assets/help/resources/gate.md` documents the four URIs and their update conditions.
