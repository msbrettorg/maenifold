# T-62.2 Deprecate no-pipeline public API

## Acceptance Criteria

Mark all no-pipeline public API functions as deprecated to guide consumers toward pipeline-aware alternatives.

### Changes

1. **`parse_task_content()`** in `parser.rs`: Add `#[deprecated(note = "use parse_task_content_with_pipeline; this path has no pipeline awareness")]`

2. **`parse_task_file()`** in `parser.rs`: Add `#[deprecated(note = "use parse_task_file with a pipeline; this path has no pipeline awareness")]`

3. **`done_override_from_content()`** in `types.rs` (line ~117): Add `#[deprecated(note = "use done_override_from_content_with_pipeline")]`. This method internally calls the no-pipeline `parse_task_content`.

4. **Add `#[allow(deprecated)]`** at all internal call sites that still use these functions (sync.rs, status/mod.rs, etc.)

5. **`lib.rs` exports**: Keep exporting the deprecated functions (removing exports is a breaking change), but ensure the deprecation attribute propagates through the re-export.

### Verification

- `cargo test -p maenifold-gate` must pass with zero warnings (all internal call sites have `#[allow(deprecated)]`)
- External consumers get deprecation warnings when using the old API
