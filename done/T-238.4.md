# T-238.4 - Gate backlog dependency cycle is only encoded in titles and not enforced

**Pipeline**: slc

## Problem

The active backlog contains dependency metadata only in task titles, and gate status does not expose or enforce those dependencies. The current board includes a cycle:

- T-236.2 title says it depends on T-237.1.
- T-237.1 title says it depends on T-236.2.

This makes lowest-ID dispatch ambiguous and allows blocked work to appear as `pending`.

## Evidence

- Active thinking session: `session-1777236650835-22077`
- `gate status --root . --json` reports T-236.2 in `research` and T-237.1 in `pending`.
- The dependency information appears only in titles, not in structured gate status fields.

## Expected behavior

- Task dependencies are represented structurally, not only in title prose.
- Gate status exposes whether a task is ready or blocked and why.
- Cycles are detected during `gate sync --rebuild` and reported clearly.

## Spec Notes

This is not a lightweight task. It changes gate task metadata, sync validation, cache/status output, and user-facing JSON semantics. The implementation must go through discovery/spec before code changes so dependency frontmatter shape, cycle diagnostics, and status JSON fields are grounded against `docs/gate-uml-spec.md` and existing gate parsing/cache modules.
