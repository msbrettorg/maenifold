# T-243.8.0 — Settings tab: duo delta review

**Reviewers:** claude-opus-4.7 + gpt-5.5 (architect duo)
**Time-box:** 15 min
**Inputs:** `T-243.8` UAT checklist, CDP enum (`outputs/uat/cdp-tab-enumeration.md`), screenshot `08-settings-default.png`, source `apps/desktop/src/components/Settings*.vue` + `App.vue`, backend `EmbeddingModels` / `GetConfig` / `/api/config/reload`.

---

## Headline

**The Settings tab is a JSON textarea plus an embeddings table.** Everything else a modern user expects from a Settings surface — structured forms, MCP server health, agent test buttons, theme, backup/restore, secret masking — is missing. **And most of it is already half-built and orphaned in the tree.**

`apps/desktop/src/App.vue` only mounts `SettingsView.vue`. `SettingsView.vue` only renders:
1. `JsonEditorVue` over `~/maenifold/maenifold.json`
2. `<SettingsEmbeddings />`

The following components exist on disk but are **not referenced from `App.vue` or `SettingsView.vue`**:

- `SettingsConnection.vue` (+ `SettingsConnectionDaemon`, `SettingsConnectionAgents`, `SettingsConnectionKeys`)
- `SettingsMcpServers.vue` (+ `SettingsMcpServersList`, `SettingsMcpServersDetail`)
- `SettingsPreferences.vue`
- `SettingsSchedules.vue`
- `SettingsMaenifold.vue` (+ `SettingsMaenifoldGraph`, `SettingsMaenifoldMemory`, `SettingsMaenifoldWorkflows`)

That is ~2,200 lines of structured-form UI sitting dark. **This is the single biggest delta.** Either wire them in, or delete them. Carrying them as zombie code is worse than either.

## Section-by-section delta

### A. Section / sidebar layout — **MISSING**

- CDP shows a single scrolling page with two sections (`Configuration`, `Embeddings`). No section sidebar, no anchors, no sticky nav.
- Compare VS Code Settings (search + categorized tree), Claude Desktop (left sidebar), Cursor (left sidebar with sections). Maenifold has none of this.
- `SettingsConnection.vue` and `SettingsMcpServers.vue` already implement multi-pane layouts internally. They just aren't surfaced.

**Gap → file `T-243.8.1`:** wire orphaned section components into `SettingsView.vue` behind a left sidebar (General / Agents / MCP servers / Embeddings / Schedules / Maenifold / Advanced JSON). Or, if the decision is to ship JSON-only, **delete the orphaned components** and document the decision.

### B. General preferences — **MISSING**

- No theme toggle. CDP confirmed app is hardcoded dark (`jse-theme-dark` is hard-imported in `SettingsView.vue:11`).
- No font size, density, language.
- No app version, daemon path, daemon port, maenifold root surfaced as labeled fields. They're inside the JSON blob but not as first-class read-only fields.
- `SettingsPreferences.vue` (222 lines) appears to cover much of this and is orphaned.

**Gap → `T-243.8.2`:** ship `SettingsPreferences` as the General section. Add light-mode CSS bundle (`vanilla-jsoneditor` exposes both themes) and a theme switch persisted to `settings.ui.theme`.

### C. Agents — **MISSING in main Settings**

- No agent list, no per-agent name/command/args/env editor, no test-connection button on the Settings tab.
- `SettingsConnectionAgents.vue` (145 lines) implements an agent form with free-form command input (referenced from `OnboardingStepAgent.test.ts`). It's used by Onboarding, not Settings.
- Backend has everything: `GetConfig` returns the agent map; daemon hot-reload picks up edits.

**Gap → `T-243.8.3`:** mount `SettingsConnectionAgents` (or its parent `SettingsConnection`) in Settings tab. Add a **Test connection** button per agent (`AcpExec` with a no-op `prompt`/`session/new` round-trip).

### D. MCP servers — **MISSING in main Settings; partial elsewhere**

- No structured server list in the Settings tab.
- `SettingsMcpServers.vue` + `List` + `Detail` (≈430 lines combined) implement add / edit / remove. **Status indicator, restart button, env-var masking are absent even from the orphaned components** (verified by scanning the files — they edit config, they don't surface live state).
- `DiscoverMcpTools` exists; not surfaced.

**Gap → `T-243.8.4`:** mount `SettingsMcpServers` in Settings tab and extend with:
- live status pill per server (running / stopped / error) — needs new daemon endpoint or repurpose `DiscoverMcpTools` per-server result as a health proxy.
- restart-server button (new daemon endpoint, narrow scope).
- secret env-var masking — detect keys matching `/_KEY$|_TOKEN$|_SECRET$|PASSWORD/i` and render as `password` input with reveal toggle.
- per-server "View available tools" drawer hitting `DiscoverMcpTools`.

### E. Embeddings — **PRESENT, gaps at the edges**

`SettingsEmbeddings.vue` + `Table` + `ConfirmDialog` are wired. From the source:
- ✅ Table of models with status per row.
- ✅ Activate / Delete actions exist (`EmbeddingModels` has `activate`, `delete`).
- ✅ Active model marked.
- ⚠️ **Download progress** — `EmbeddingModels download` is fire-and-forget at the gateway; the UI needs to confirm whether progress is streamed via SSE or polled. Likely no progress bar today.
- ⚠️ **Regenerate corpus** — `EmbeddingModels regenerate` exists in the gateway. UI needs to expose it with a progress indicator and a destructive-action confirm.
- ❌ **Switch-model warning** — activating a different-dimension model orphans existing embeddings. UI must warn ("Existing notes are still searchable via BM25 until you click Regenerate") before activation.

**Gap → `T-243.8.5`:** confirm download progress wiring; add Regenerate button with progress; add switch-model warning dialog.

### F. Schedules — **ORPHANED**

`SettingsSchedules.vue` (249 lines) exists but isn't routed. The UAT only asks for a count cross-link to T-243.7; there isn't even that today.

**Gap → `T-243.8.6`:** mount `SettingsSchedules` or, at minimum, render an active-schedule count linking to the Schedules tab.

### G. Backup / restore / export config — **MISSING**

- No export, no import, no reset-to-defaults, no version history.
- The Electron IPC `configRead` / `configWrite` already handles file IO; export/import is essentially "Save As" / "Open" dialogs around the same string.
- "Reset to defaults" needs a packaged default `maenifold.json` shipped with the app — verify it exists.

**Gap → `T-243.8.7`:** add Export / Import / Reset buttons to the Configuration footer. Reset must show a destructive-action dialog and a 5-second undo banner.

### H. JSON editor — **PRESENT, decent**

- ✅ Syntax highlighting via `vanilla-jsoneditor`.
- ✅ Edit + save.
- ✅ `JSON.parse` validation before write (`SettingsView.vue:55`).
- ✅ Hot-reload — `api/config_watch.rs` is wired (T-242.32) and the file watcher refreshes editor content when the disk changes (`onConfigChanged` → `load`).
- ⚠️ **Schema validation is absent** — only syntax check. A user can save a structurally invalid config and the daemon discovers it on reload.
- ⚠️ **No diff view** — "Show me what changed since I last saved" is impossible. Today's revert is binary.

**Gap → `T-243.8.8`:** add JSON-schema validation against the daemon's config schema before save (daemon should expose `/api/config/schema`). Add a diff view comparing `editorText` vs last-loaded value (use `vanilla-jsoneditor`'s built-in diff or a small `diff` import).

### I. Hot-reload — **PRESENT but unverified end-to-end in UAT**

- The wiring is in place (`config_watch.rs`, `onConfigChanged` listener).
- UAT checklist needs an explicit cross-tab verification step. Current code only confirms editor → daemon; it doesn't confirm daemon-side state change is observed by other tabs (Agents picker, MCP servers list).

**Gap → `T-243.8.9` (verification, not implementation):** add a UAT step that edits an agent name in Settings, switches to Agents tab, and verifies the new name appears without restart.

### J. Errors — **PARTIAL**

- ✅ Invalid JSON → save rejected with parser error (line 55).
- ❌ Daemon-rejects-config → only a generic error string surfaces. No retry.
- ❌ Permission errors writing config → bubbles up as an opaque IPC error.

**Gap → `T-243.8.10`:** structured error surface — distinguish "JSON syntax", "schema invalid", "daemon rejected reload", "FS permission". Include a retry button for transient failures and a "Show daemon log tail" link for the rejection case.

## Cross-cutting concerns

### Zombie components

The five orphaned `Settings*.vue` trees are the biggest risk and the biggest opportunity. Decision required from product-manager:

1. **Wire them in** (likely 2–4 sub-tasks of integration work, mostly mounting + sidebar).
2. **Delete them** and accept "Settings = JSON editor + embeddings" as the product position.

Carrying them indefinitely wastes context for every future engineer who searches for "MCP server settings" and finds an unreferenced component.

### Secrets

Today, every API key in `maenifold.json` renders in plaintext in the JSON editor. That's defensible for a local-only desktop app but **fails the moment a user screenshares or pair-programs**. Even the JSON-only fallback should:

- detect secret-shaped keys and offer a "Mask secrets" toggle on the editor.
- never log raw config content from the IPC handler.

Verify the latter by grepping the Electron main process for `console.log` around `configRead`/`configWrite`.

### Live MCP server health

The CDP enum and the orphaned `SettingsMcpServers` agree: there is no health surface. A user with a misconfigured MCP server today has to:
1. notice the gateway tool is missing in another tab,
2. open Settings,
3. find the JSON,
4. guess.

This is the single biggest day-to-day usability win on this tab. Even a polled "last successful handshake" timestamp per server would be transformative.

### Theme

Hardcoded dark is a 2026 accessibility regression. Light mode is one CSS bundle and one `data-theme` attribute. Cheap, high-visibility win. Bundle into `T-243.8.2`.
