# T-206.0 — Gate MCP sync/status can fail with EDEADLK after task-file refresh

## Problem

During Sprint 1 backlog grooming, the gate MCP `sync` and `status` tools returned task-level parse errors with:

- `io error: Resource deadlock avoided (os error 11)`

The failures hit freshly edited `todo/T-01.x` files. The CLI fallback succeeded immediately:

- `gate sync --root .`
- `gate status --root .`

This indicates an MCP/runtime locking bug rather than malformed task files.

## Reproduction

1. Edit or create several `todo/T-*.md` task files in one batch.
2. Call gate MCP `sync` with an absolute repo root.
3. Call gate MCP `status` with the same root.
4. Observe task entries reported as `state: error` with `Resource deadlock avoided (os error 11)`.
5. Run the CLI commands above and observe that the same task files parse cleanly.

## Acceptance Criteria

1. Gate MCP `sync` succeeds on freshly edited task files without `Resource deadlock avoided (os error 11)`.
2. Gate MCP `status` reports the same parsed task set as CLI `gate status --root .`.
3. A regression test or equivalent deterministic reproduction covers the MCP locking path.
4. No task-file parsing behavior regresses for existing gate workflows.
