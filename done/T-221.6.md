# T-221.6 - GatewayIntent Integration and Safety

## Problem

`GatewayIntent` must improve usability without turning natural language into unsafe automatic execution. It should resolve, explain, and narrow choices; exact execution remains deterministic.

## Scope

Wire the ACP resolver into the gateway:

- `GatewayIntent` accepts natural language plus optional domain hints.
- `GatewayIntent` is available side by side with the deterministic Unifi-style gateway tools only when enabled and backed by a valid configured ACP/Jockey resolver agent.
- The resolver returns candidates.
- The gateway validates candidates against the deterministic `GatewayCatalog` from T-221.2.
- The gateway may execute only read-safe, single-candidate operations when `autoExecuteReadSafe=true` and candidate confidence is greater than or equal to `autoExecuteConfidenceThreshold`.
- When `autoExecuteReadSafe=false`, all `GatewayIntent` calls return candidates or execution plans and never execute commands.
- Mutating or destructive actions always return an execution plan requiring `GatewayExecute`.
- Ambiguous results return candidates.
- Resolver unavailable returns deterministic fallback instructions.

## Acceptance Criteria

- [ ] `GatewayIntent` calls the ACP resolver only when enabled and configured.
- [ ] `GatewayIntent` is not advertised in `tools/list` when disabled by configuration.
- [ ] `GatewayIntent` is not advertised in `tools/list` when no valid resolver agent is configured.
- [ ] Resolver candidates are validated against the deterministic `GatewayCatalog` before being returned.
- [ ] `GatewayIntent` performs no independent command lookup or safety classification.
- [ ] Candidate validation, safety class, read-safe auto-execute eligibility, and exact-execute plans all use the same registry used by `GatewayExecute`.
- [ ] Unknown resolver-selected domains or commands are rejected.
- [ ] Ambiguous intent returns candidates, not execution.
- [ ] Confidence below `autoExecuteConfidenceThreshold` returns candidates, not execution.
- [ ] `autoExecuteReadSafe=false` returns candidates or plans for all intents, including read-safe intents.
- [ ] `autoExecuteReadSafe=true` may execute only one read-safe candidate whose confidence is greater than or equal to `autoExecuteConfidenceThreshold`.
- [ ] Mutating intent returns an explicit `GatewayExecute` plan, not execution.
- [ ] Resolver unavailable/error/malformed output returns clear instructions for `GatewayIndex` and `GatewayExecute`.
- [ ] Existing heuristic `dispatch_intent` is removed from gateway execution paths.
- [ ] No MCP sampling code path is used.
- [ ] Tests cover read-safe execution policy, mutating candidate policy, ambiguity, resolver error, and deterministic fallback.
- [ ] `cargo build --release -p maenifold-cli` succeeds.

### Phase 1: Schema + Tool Definition

**Modified:** `mcp/schema/gateway_tools.rs`
- `GatewayIntentParams` — intent: String, domain_hints: Option<Vec<String>>
- `gateway_intent_tool()` — tool definition
- `domain_hints` semantics: if present, append as "Domain hints: a, b, c" to the intent string passed to resolver (zero resolver-signature churn)

### Phase 2: Intent Handler

**New:** `mcp/gateway_intent.rs`
- `pub(crate) async fn handle_gateway_intent(state: &GatewayState, params: GatewayIntentParams) -> Result<CallToolResult, ErrorData>`
- Build intent string: append domain_hints if present
- Call `resolve_intent(state.catalog(), state.intent_settings(), &intent, state.workspace_root())`
- Apply safety policy:
  - If auto_execute_read_safe=false → return candidates/plan only
  - If exactly 1 candidate + Read safety + confidence ≥ threshold + !requires_exact_execute → auto-execute via handle_gateway_execute
  - Otherwise → return candidates
- Mutating candidates always return execution plan (never auto-execute)
- Resolver error → structured fallback instructions

### Phase 3: Wiring

**Modified:** `mcp/gateway_handler.rs` (~10 LOC)
- Add `intent_settings: IntentResolverSettings` field to GatewayState
- Add `workspace_root: PathBuf` field to GatewayState
- Add `pub(crate) fn intent_settings(&self) -> &IntentResolverSettings` accessor
- Add `pub(crate) fn workspace_root(&self) -> &Path` accessor
- Add `if tool_name == "GatewayIntent" { ... }` routing branch
- Conditional tool visibility: include `gateway_intent_tool()` in `list_tools()` only when `intent_settings.enabled && intent_settings.agent.is_some()`

**Modified:** `mcp/gateway_startup.rs`
- Pass IntentResolverSettings from AgentsConfig to GatewayState constructor
- Pass workspace root (available from Config or startup context) to GatewayState constructor

**Modified:** `mcp/mod.rs`
- Add `mod gateway_intent;` + `#[cfg(test)] mod gateway_intent_tests;`

### Phase 4: Dead Code Removal

**Modified:** `mcp/gateway_dispatch.rs`
- Remove `dispatch_intent()` function (~lines 83-127)
- Remove `intent_match_score()` helper function
- Remove `tokenize()` / `normalize()` helpers if only used by dispatch_intent
- Remove `dispatch_facade_call()` if only used by tests of the removed heuristic
- Update or remove any test references to removed functions

### Phase 5: Tests

**New:** `mcp/gateway_intent_tests.rs`
- Read-safe auto-execute (single candidate, Read, high confidence)
- Read-safe below threshold (returns candidates)
- Mutating candidate (returns plan, never executes)
- auto_execute_read_safe=false (all intents return candidates)
- Resolver error (structured fallback)
- Ambiguous candidates (multiple results, no auto-execute)
- GatewayIntent not in list_tools() when disabled
