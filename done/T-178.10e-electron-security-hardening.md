# T-178.10e — Electron security hardening: sandbox + CSP

**Pipeline**: sdd
**Pipeline Digest**: tbd

## Objective

Two security posture issues flagged by red-team during Electron 41 upgrade:

### 1. Enable renderer sandbox
`electron/main.ts:65-70` uses `sandbox: false`. Electron defaults to `sandbox: true` since v20. Evaluate whether the app can work with sandbox enabled. If preload IPC is the only bridge, sandbox should be safe to enable.

### 2. Add Content Security Policy
No CSP meta tag in the renderer HTML. With `sandbox: false` + privileged IPC, any XSS becomes a full compromise. Add a strict CSP that blocks inline scripts and limits connections to localhost.

### 3. Lock down vite dev server binding
`vite.config.ts:36-38` has `server.host: true` which binds to all interfaces. Change to `server.host: '127.0.0.1'`.

## Acceptance Criteria
1. `sandbox: true` in BrowserWindow webPreferences (or documented reason why not)
2. CSP meta tag in renderer HTML blocking inline scripts
3. `server.host` set to `'127.0.0.1'` in vite.config.ts
4. App launches and all IPC functions work
5. `npx vue-tsc --noEmit` passes
6. `npm run build` + `npm run package` succeed
