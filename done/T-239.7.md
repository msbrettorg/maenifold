# T-239.7 - Teams chat must not render on Agents tab

**Pipeline**: sdd

## Problem

The Teams chat surface is visible on the Agents tab. That must not happen. Teams Monitor chat, replay, broadcast, or session content must be scoped to the Teams tab only.

User hypothesis: the leak is probably the shared `broadcast` path/event/channel.

## Parent thinking session

- `memory://thinking/sequential/2026/04/27/session-1777297104510-41878`

## Scope

- `apps/desktop/src/components/teams/TeamsTab.vue`
- `apps/desktop/src/components/ChatView.vue`
- `apps/desktop/src/App.vue`
- tab/session/broadcast composables or stores used by Teams and Agents views
- any focused frontend tests that already cover tab isolation

## Requirements

- Teams chat/monitor/replay content is route-local and tab-local.
- Agents tab must not mount, display, subscribe to, or replay Teams chat state.
- Any shared broadcast/event handling must include an explicit destination/session discriminator.
- Switching Teams -> Agents after Teams chat activity must leave no Teams chat content in the Agents accessibility tree or DOM.
- Do not solve this by hiding content with CSS while it remains mounted in Agents.

## Acceptance Criteria

- [ ] Teams tab can display Teams Monitor chat/replay state.
- [ ] Agents tab never displays Teams chat/replay state.
- [ ] Broadcast/session handling is explicitly scoped by destination.
- [ ] Packaged Electron `agent-browser` verification clicks Teams, then Agents, and confirms Teams chat content is absent from Agents.
- [ ] No app-registration copy or phantom Teams settings fields are introduced while fixing the leak.

## Verification

- `cd apps/desktop && npx vue-tsc --noEmit`
- `cd apps/desktop && npm run package`
- Packaged Electron `agent-browser` click-through:
  - open Teams tab
  - trigger or observe Teams chat/replay content
  - open Agents tab
  - verify the Teams chat surface is absent from the Agents snapshot and DOM
