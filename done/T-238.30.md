# T-238.30 — ACP file I/O operations are fabricated

## Problem

`readTextFile` and `writeTextFile` in the ACP host implementation open browser file picker dialogs instead of reading/writing the requested filesystem path. The method names are correct per the ACP protocol spec but the implementation is wrong — it should perform direct filesystem I/O on the path provided in the request, not prompt the user with a dialog.

## Evidence

Red-team finding from sprint 238 wave audit.

## Acceptance criteria

- [ ] `readTextFile` reads the file at the requested path and returns its content.
- [ ] `writeTextFile` writes content to the requested path.
- [ ] No browser file picker dialogs are triggered by these operations.
- [ ] Path validation constrains I/O to allowed directories per the ACP security model.

## Verification

- ACP session calls `readTextFile` with a known path → returns file content without dialog.
- ACP session calls `writeTextFile` → file written at path without dialog.
