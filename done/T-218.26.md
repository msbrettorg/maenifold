# T-218.26 — Gate MCP Cross-Process Locking

## Problem

The Gate MCP write mutex serializes in-process mutators, but it does not protect concurrent reads during sync/write, CLI writes from another process, crash halfway through file move/write, or stale `.gate/gate.db` visibility during rebuild.

## Acceptance Criteria

- [ ] Concurrent `status` during `sync --rebuild` never returns SQLite `database is locked` or malformed JSON
- [ ] Concurrent MCP `pass` and CLI `fail/pass` on the same task cannot create contradictory final state
- [ ] Final-stage `pass` move to `done/` is atomic or recoverable
- [ ] Crash injected between append record and move can be recovered by `sync --rebuild`
- [ ] Tests cover MCP plus CLI cross-process behavior, not only in-process mutex behavior
- [ ] Gate docs state locking model and recovery guarantees
