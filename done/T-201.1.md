# T-201.1 — useOnboarding composable + Vitest tests

## Intent

Create the `useOnboarding` composable that manages first-run detection, wizard step navigation state, and onboarding completion persistence. This is the state machine foundation all wizard steps depend on.

## Architecture

### First-run detection

Two-signal approach (constitutional: no silent defaults):

1. **localStorage flag**: `maenifold-onboarding-v1` with versioned schema
2. **Real state check**: query config store for `hasAgents === false` — if the user has no agents configured, onboarding is warranted regardless of the flag

```typescript
interface OnboardingState {
  completed: boolean;
  completedAt?: string;
  version: number;
}

const CURRENT_VERSION = 1;
const ONBOARDING_KEY = 'maenifold-onboarding-v1';
```

Use `readStorageValue` / `writeStorageValue` from `lib/local-storage.ts` (existing pattern).

### Step state machine

```typescript
const STEPS = ['welcome', 'daemon', 'agent', 'model', 'done'] as const;
type StepId = typeof STEPS[number];

const step = ref(0);
const highWaterStep = ref(0);
const currentStepId = computed(() => STEPS[step.value]);
const canGoBack = computed(() => step.value > 0);
const canGoForward = computed(() => step.value < highWaterStep.value);
```

- `advance()`: increments step, updates highWaterStep
- `goToStep(n)`: navigates to `n` only if `n <= highWaterStep`
- `goBack()`: decrements step if `canGoBack`

### Completion

`markComplete()`: writes localStorage flag with timestamp and version, sets `isFirstRun = false`.

### Composable return

```typescript
return {
  isFirstRun, step, highWaterStep, currentStepId,
  canGoBack, canGoForward, STEPS,
  checkFirstRun, advance, goToStep, goBack, markComplete,
};
```

## Acceptance Criteria

1. `checkFirstRun()` returns `true` when no localStorage flag exists
2. `checkFirstRun()` returns `false` when flag exists with current version
3. `checkFirstRun()` returns `true` when flag version < CURRENT_VERSION (force re-onboard)
4. `advance()` increments step and updates highWaterStep
5. `goToStep()` allows navigation only to visited steps (≤ highWaterStep)
6. `goToStep()` rejects negative values and values > highWaterStep
7. `goBack()` decrements step; no-op at step 0
8. `markComplete()` writes versioned flag to localStorage
9. After `markComplete()`, `checkFirstRun()` returns `false`
10. `npx vue-tsc --noEmit` passes
11. All Vitest tests pass

## Test Plan (Vitest)

Tests use real localStorage (via `jsdom` or similar) — no mocks.

1. `checkFirstRun returns true when no flag exists`
2. `checkFirstRun returns false when flag exists with current version`
3. `checkFirstRun returns true when flag version is outdated`
4. `advance increments step and highWaterStep`
5. `goToStep allows visited steps only`
6. `goToStep rejects out-of-range values`
7. `goBack decrements step`
8. `goBack is no-op at step 0`
9. `markComplete persists flag and clears isFirstRun`
10. `round-trip: checkFirstRun → markComplete → checkFirstRun returns false`
