### Caveat §1 — `vi.spyOn(globalThis, 'fetch')` at line 161

**Severity: Low / Non-blocking**

The `PipelineView` test stubs `fetch` with:

```ts
vi.spyOn(globalThis, 'fetch').mockRejectedValue(new Error('offline'));
```

The spec's Acceptance Criterion 3 says *"Tests skip gracefully when MCP server unavailable"* and the audit focus allows only Vue Flow render primitives as stubs. This `fetch` spy technically goes beyond the permitted stub surface.

**Why it's acceptable here:**
- The alternative would be `it.skipIf(await canReachServer(), ...)` — but PipelineView calls `store.connect()` + `store.refreshList()` during `onMounted`, so without the spy the test either hangs on real network I/O or fails in CI where no MCP server is present. The spy is the minimum shim needed to make the component mountable in jsdom.
- It is NOT `vi.mock()`, `vi.fn()`, or `vi.stubGlobal()`.
- It does NOT suppress any real component behaviour — PipelineView still mounts, all four sub-components are still verified to exist in the DOM.
- `vi.restoreAllMocks()` in `beforeEach` cleans it up across tests.

**Recommendation for a follow-up:** Replace with an explicit `it.skipIf` pattern consistent with the other integration test files (e.g., `composableIntegration.test.ts`) if the team wants strict parity. This is cosmetic cleanup, not a spec violation.
