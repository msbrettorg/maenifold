# T-203.7 — Gate MCP server returns "Session not found" on first call after idle

## Problem

When calling `gate sync` (or any gate MCP tool) via the MCP server after the session has been idle, the first call fails with:

```
MCP server 'gate': Error: Streamable HTTP error: Error POSTing to endpoint: Not Found: Session not found
```

The CLI fallback (`gate sync --root . --rebuild`) works fine. The MCP server appears to lose its session state after idle periods, requiring the client to re-establish.

## Observed

- 2026-04-20T13:59: `gate-sync` via MCP returned "Session not found"
- Immediate CLI fallback succeeded
- This is not the first time — pattern observed across multiple sprint sessions

## Expected

Gate MCP server should either:
1. Auto-reconnect / re-establish sessions transparently, or
2. Return a clear error that tells the client to reinitialize, not a generic 404

## Acceptance Criteria

1. `gate sync` via MCP succeeds after idle period without manual intervention
2. If session expires, MCP server returns a typed error the client can handle (not raw HTTP 404)
3. `cargo build --release -p maenifold-gate` passes

- Notes: Investigation: gate HTTP server uses NeverSessionManager + stateful_mode(false) — correctly stateless. The 'Session not found' 404 is likely from the client sending a stale Mcp-Session header after idle. Server-side fix would require either: (1) rmcp to ignore session headers in stateless mode, or (2) switching to a proper session manager. This is an rmcp library behavior issue. CLI workaround is reliable. Deferring to when rmcp upstream is updated.
