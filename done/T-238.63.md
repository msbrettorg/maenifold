# T-238.63 — P1 Add message-ID deduplication buffer for Trouter delivery

**Pipeline**: sdd

## Problem

Rust `handler.rs` only does per-conversation cooldown (60s). It does NOT track message IDs. Trouter redelivers messages after `trouter.reconnect` events and re-registration. Without message-ID dedup, the same prompt dispatches twice on every reconnect.

Agency-cowork maintains a 2000-entry `_processed_ids` set in `service.py::_route_message` (L580-599) plus `is_duplicate(message_id)` in the handler.

Additionally, cooldown and dedup are conflated — a legitimate follow-up within 60s is silently dropped. These should be separate concerns.

## Reference

- agency-cowork: `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/service.py` L580-599
- agency-cowork: `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/message_handler.py` L940-943
- Rust target: `crates/maenifold-core/src/teams/handler.rs`

## Required changes

1. Add bounded message-ID dedup set (2000 entries, LRU eviction)
2. Check message ID before any processing — reject duplicates silently
3. Share dedup buffer with catch-up polling (T-238.54)
4. Separate cooldown (rate limit) from dedup (correctness) — different concerns, different thresholds

## Acceptance Criteria

- [ ] Message IDs tracked in bounded set
- [ ] Duplicate messages rejected before dispatch
- [ ] Dedup shared between realtime and catch-up paths
- [ ] Cooldown and dedup are separate mechanisms
