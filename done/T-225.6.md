# T-225.6 — Workflow Session Resource Emitters

## Problem

`workflow://sessions` and `workflow://session/{id}` are subscribed by the frontend (`stores/workflow.ts:113,136`) but never emit `notifications/resources/updated`. The workflow dashboard shows stale data.

## Duo Review R1 Findings

- Wrong path (fixed R2): actual workflow code at `src/workflow/`, not `src/tools/workflow/`
- Need to enumerate specific mutation sites (not hand-wave "any mutating operation")
- sync-to-async bridging pattern needed (notify_resource_updated is async, workflow handlers may be sync)
- Submachine mutations scoped OUT for this task (separate concern)

## Fix

Create an `emit_workflow_resource_updated(session_id)` helper following the Teams runtime pattern (`teams/runtime.rs:165-192`). Call it from the primary workflow mutation sites.

### Emitter Helper

```rust
pub fn emit_workflow_resource_updated(session_id: &str) {
    // Follow teams/runtime.rs:179-192 pattern:
    // Handle::try_current() → spawn, else use NOTIFICATION_RUNTIME
    // Emit notify_resource_updated(WORKFLOW_SESSIONS_URI)
    // Emit notify_resource_updated(&format!("workflow://session/{}", session_id))
}
```

Use the `WORKFLOW_SESSIONS_URI` constant from `mcp/resources/workflow.rs:14`.
