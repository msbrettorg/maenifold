# T-240.8 - Copilot MCP auth fails with resource mismatch after OpenCode OAuth fix

**Pipeline**: sdd

## Problem

After the live maenifold HTTP daemon was rebuilt/restarted and OpenCode OAuth authentication succeeded, Copilot CLI reported the configured maenifold MCP server as failed:

```text
MCP Server: maenifold
Type: http
URL: http://127.0.0.1:8080/mcp
Status: Failed
Error: resource does not match authorization request
Source: /Users/brett/.copilot/mcp-config.json
Tools: Server failed to connect
```

Live server probes at the same time showed the expected MCP OAuth metadata:

```text
GET /mcp -> 401 with WWW-Authenticate: Bearer resource_metadata="http://127.0.0.1:8080/.well-known/oauth-protected-resource/mcp"
GET /.well-known/oauth-protected-resource/mcp -> JSON resource "http://127.0.0.1:8080/mcp"
GET /.well-known/oauth-authorization-server/mcp -> JSON authorization/token/register endpoints
opencode mcp debug maenifold -> authenticated and connection successful
```

This suggests a Copilot-client-specific OAuth resource/cache/config mismatch rather than a daemon-down condition.

## Required Behavior

- Copilot CLI can connect to the maenifold HTTP MCP server at `http://127.0.0.1:8080/mcp`.
- The OAuth authorization request resource, token request resource, and protected-resource metadata `resource` value match exactly.
- Stale or mismatched cached Copilot OAuth credentials can be cleared or refreshed without editing secrets by hand.
- OpenCode authentication remains working.
- Gate domain availability regression remains tracked separately by `T-240.7`.

## Research Findings (2026-04-27)

Researcher read MCP spec, rmcp SDK, and agency-cowork. Key findings:

1. **OAuth is OPTIONAL per MCP spec** — SHOULD not MUST
2. **rmcp SDK has no server-side OAuth middleware** — you roll your own regardless
3. **agency-cowork uses STDIO** — sidesteps HTTP auth entirely
4. **Our bearer token is already static** — OAuth just vends the `localhost.token` file

## Recommended Fix: Option D — Stateless Registration

Make `/register` always return a well-known `client_id` (e.g. `maenifold-local-public`).
Make `/authorize` accept any `maenifold-local-*` client_id without lookup.

This eliminates the persistence bug class entirely — no state to lose on daemon restart.
Stays fully MCP-spec-compliant. ~100 LOC reduction.

Ref: MCP Authorization Spec §Protocol Requirements, §Dynamic Client Registration
