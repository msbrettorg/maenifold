# T-203.8 — McpAppFrame resource fetch wiring

## Problem

McpAppFrame.vue (T-203.3) sends placeholder HTML to AppBridge instead of fetching the real app HTML from the originating MCP server. The `onsandboxready` handler at line 56-71 constructs a static message. This blocks T-203.6 (E2E validation).

## Dependency

This task requires T-207.4 (handler delegation for `resources/read` proxying to upstream MCP servers). Without the gateway proxying `resources/read` calls to the upstream server, the frontend has no way to fetch the `ui://` resource content.

## Acceptance criteria

1. McpAppFrame.vue calls `resources/read` with the `ui://` resourceUri via the MCP client
2. Returned HTML is passed to `ab.sendSandboxResourceReady()`
3. Error handling: if fetch fails, show error message in the component (not placeholder)
4. No placeholder HTML remains in the component

## Key files

- Modify: `apps/desktop/src/components/McpAppFrame.vue`
- Reference: `apps/desktop/src/composables/useMcpClient.ts` (`readResource`)

## BLOCKED

This task is blocked on T-207.4 (handler delegation). The maenifold backend must proxy `resources/read` calls to upstream MCP servers before the frontend can fetch app resources.
