# T-157.2 — Add `env` field to stdio MCP server config

## Problem

`McpServerEntry::Stdio` has no `env` field. When maenifold runs as a launchd service, child processes inherit launchd's minimal PATH (`/usr/bin:/bin:/usr/sbin:/sbin`). Stdio servers that depend on homebrew binaries (e.g., `npx` needs `node` at `/opt/homebrew/bin/node`) fail with `env: node: No such file or directory`.

This is the standard MCP config pattern — Claude, VS Code, and Copilot all support `"env": {}` on stdio entries.

## Fix

1. Add `env: Option<HashMap<String, String>>` to `McpServerEntry::Stdio` in `crates/maenifold-core/src/acp/config.rs`
2. In the stdio discovery spawner (`crates/maenifold-core/src/api/mcp_discovery/stdio.rs`), apply env vars to the `Command` before spawn: `cmd.envs(&env)`
3. Pass env through in `to_acp()` as well so ACP agent sessions also get it

## Schema

```json
{
  "name": "azure-mcp-server",
  "type": "stdio",
  "command": "/opt/homebrew/bin/npx",
  "args": ["-y", "@azure/mcp@latest", "server", "start"],
  "env": {
    "PATH": "/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin"
  }
}
```

## Files

- `crates/maenifold-core/src/acp/config.rs` — add `env` field to Stdio variant + wire into `to_acp()`
- `crates/maenifold-core/src/api/mcp_discovery/stdio.rs` — pass env to Command
- `crates/maenifold-core/src/api/mcp_discovery.rs` — pass env through discover_server

## Acceptance Criteria

1. `env` field on Stdio entries is optional (serde default empty)
2. Discovery spawner applies env vars to child process
3. Existing configs without `env` continue to work
4. `cargo build --release -p maenifold-cli` succeeds
