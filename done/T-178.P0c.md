# T-178.P0c — Pipeline ELK layout compound failure

## Priority: P0

## Symptom
Pipeline composer renders edges as parallel vertical waterfalls disconnected from node ports. Nodes may appear as scattered ⚠ edge-indicator stubs. Both TB and LR directions are broken. The bug reproduces on first render and after every status poll.

## Root Cause (duo-confirmed, 2026-04-19)

Eight compounding bugs identified by Architect Alpha (claude-opus-4.7) and Architect Beta (goldeneye):

### Bug 1 — Hard-coded TB direction (Critical)
`useComposerCanvas.ts:145` calls `layout(nextNodes, nextEdges, 'TB')` unconditionally on first sync, ignoring user preference.

### Bug 2 — Live-view watcher stomps layout (Critical)
`useComposerCanvas.ts:215-233` deep watcher fires `syncCanvas` on every status poll, re-running Bug 1 and resetting user's LR choice back to TB.

### Bug 3 — All-or-nothing cache invalidation (High)
`useComposerCanvas.ts:137-139` `hasCachedPositions` requires ALL nodes cached. One new node invalidates entire cache, triggering full re-layout.

### Bug 4 — No ELK port constraints (Critical)
`useLayout.ts:29-39` never sets `elk.portConstraints: FIXED_SIDE`, never declares `ports[]` on ELK nodes, never references `nodeId.portId` on edges. ELK routes to bounding-box edges, not port positions.

### Bug 5 — Hard-coded Left/Right handles (Critical)
`PipelineNodeCardPorts.vue:7-8` hard-codes `Position.Left` (target) and `Position.Right` (source). No Top/Bottom handles exist. In TB layout, edges terminate dozens of px from visible handles.

### Bug 6 — Combined direction/port mismatch (Critical)
Bugs 4+5 together: TB layout stacks nodes vertically but edges must exit Right and enter Left, creating horseshoe routing with parallel vertical lanes — the "waterfall" pattern.

### Bug 7 — Silent ELK worker failure (Critical)
`useLayout.ts:65` `elk.layout(graph)` has no try/catch. Web Worker URL resolution failure in iframe sandbox causes unhandled rejection → layout function never completes → canvas stuck with default grid positions. Indistinguishable from broken output.

### Bug 8 — Drag clears all edge routes (Medium)
`useComposerCanvas.ts:235-246` `onNodeDragStop` clears `elkPoints` on ALL edges, not just moved nodes. Forces global fallback to smoothstep.

### Bonus — Hostile edge-indicator policy
`pipeline-composer-edge-utils.ts:37-42` flags EVERY tool-targeting edge without field mapping as ⚠. In tool-heavy pipelines, the entire canvas fills with warning indicators. Should be reserved for genuine problems.

## Fix Requirements

### 1. Port model alignment
- `PipelineNodeCardPorts.vue` must register 4 handles: Top, Bottom, Left, Right (with stable IDs: `in-top`, `out-bottom`, `in-left`, `out-right`)
- Active handles selected by layout direction: TB uses Top(target)/Bottom(source), LR uses Left(target)/Right(source)
- Inactive handles hidden via CSS (`display: none` or `opacity: 0; pointer-events: none`)

### 2. ELK port constraints
- `useLayout.ts` must set `'elk.portConstraints': 'FIXED_SIDE'` per node
- Each ELK node must include `ports: [{id: 'in-top', properties: {'port.side': 'NORTH'}}, ...]` matching active direction
- Edge `sources`/`targets` must reference `[nodeId.portId]` not bare nodeId

### 3. Single source of truth for direction
- Replace hard-coded `'TB'` in `useComposerCanvas.ts:145` with a reactive `layoutDirection` ref (from Pinia or composable, defaulting to user preference, persisted per pipeline)
- Toolbar LR/TB buttons mutate this ref
- Both `syncCanvas` and `handleAutoLayout` read from it

### 4. Watcher stabilization
- `useComposerCanvas.ts:215-233` watcher must NOT re-layout on status-only changes
- Debounce to structural changes only (node add/remove/edge change)
- When re-layout IS needed, use persisted direction

### 5. Incremental cache policy
- Accept partial cache: existing nodes keep positions as `elk.position` constraints
- Only newly-added nodes get positioned by ELK
- Never invalidate entire cache for a single new node

### 6. Error handling
- Wrap `elk.layout()` in try/catch
- Log structured error
- Surface toast via sonner
- Fall back to deterministic grid layout (not silent garbage)

### 7. Edge indicator fix
- Remove blanket `targetNode.data.type === 'tool'` → `warning` rule
- Reserve ⚠ for actionable problems only (e.g., required arg missing from mapped fields)

### 8. Drag handler scoping
- `onNodeDragStop` only clears `elkPoints` for edges incident to moved node(s)

## Acceptance Criteria
1. A 20-node pipeline (like ftk-analysis) renders with edges connecting to visible port handles in both TB and LR
2. Switching TB↔LR updates handle positions and re-routes edges correctly
3. Status poll updates do NOT reset layout direction or re-layout the canvas
4. Adding one node to an existing pipeline preserves all other node positions
5. ELK worker failure produces a visible toast and deterministic fallback layout
6. Manual node drag only affects edges connected to the dragged node
7. ⚠ indicators only appear on edges with genuine mapping problems
8. Zero `@vue-flow/core` console warnings about missing handles
9. `npx vue-tsc --noEmit` passes
10. Works in both Electron standalone and cowork iframe
