# T-177.0 — README rewrite — lead with why, not what

## Intent

The README is the product's first impression for every human and agent that encounters the repo. Currently it buries the hook ("For anyone who spends more time gathering context and re-doing analysis than doing the actual work") on line 19 behind a logo, badges, and a screenshot. The product thesis ("Build the reasoning layer first. Useful work follows.") is line 22. A feature list before a reason-to-care is backwards.

## Evidence

- Line 1-16: logo, badges, screenshot, status notice
- Line 19: the human hook (buried)
- Line 22: the thesis (buried)
- Line 23-96: feature list organized by surface
- Lines 223-227: "What's Next" is 2 vague bullets despite a rich backlog
- MA_MANIFESTO.md and WHAT_WE_DONT_DO.md — the project's soul — are not linked
- No link to docs/research/ papers
- Workflow/role/color/perspective count inconsistency ("70" in one place, "69" in another, "dozens" in a third)

## Scope

Restructure the README:

1. **Open with the hook and thesis.** First 5 lines should answer "why does this exist" and "who is it for." No logo-first. Logo can follow.
2. **Then the product identity.** One paragraph: cognitive control plane, not a chat wrapper. Memory is the core. Pipelines execute. Workflows codify reasoning. Gates track delivery. The graph connects everything.
3. **Then the screenshot.** Now the reader knows what they're looking at.
4. **Link the soul docs.** Add a "Philosophy" section near the top linking MA_MANIFESTO.md and WHAT_WE_DONT_DO.md. These explain WHY decisions are made.
5. **Link the research.** Add a "Research" section linking the 6 papers in docs/research/. These are differentiators.
6. **Fix the asset counts.** One number, consistent everywhere.
7. **Sharpen "What's Next".** Replace 2 vague bullets with the real near-term themes: plugin ecosystem (T-126.x), cross-surface provenance (T-108), self-evolving pipelines.
8. **Add CONTRIBUTING.md link** (T-177.1 creates the file).
