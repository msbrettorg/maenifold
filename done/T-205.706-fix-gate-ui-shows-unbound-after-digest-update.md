# T-205.706 — Fix: Gate UI shows "unbound" after pipeline digest is updated on disk

**Pipeline**: test
**Pipeline Digest**: 16842feaee5604e196f8d0c4ddc8a6566bd538a1ad2d739bc956a9e49f123128

## Bug

The Gate tab in the desktop app shows tasks as "unbound" in the Process column even after the `**Pipeline Digest**` field in the markdown files has been updated to a valid SHA256 and `gate sync --rebuild` has been run from CLI. The UI's last sync time was 7:18 PM — before the digest fix. Clicking "Refresh" in the Gate UI does not resolve the stale state.

The CLI `gate status --json` correctly shows the tasks as `pipeline=lightweight` with proper binding. The desktop app's gate view is reading stale data.

**Severity: P1** — The Gate tab is the primary task management interface. Showing all 600+ tasks as "unbound" makes the view useless for triage.

## Reproduction

1. Update `**Pipeline Digest**` in task markdown files
2. Run `gate sync --root . --rebuild` from CLI
3. Open Gate tab in desktop app — tasks still show "unbound"
4. Click Refresh — still "unbound"

## Found During

UAT sprint 205 interactive CDP testing. User spotted it in screenshot.

## Acceptance

- Gate UI refreshes its read model when Refresh is clicked
- Tasks with valid digest show their pipeline name (e.g., "lightweight"), not "unbound"
- The UI's gate sync should invoke a full rebuild, not just incremental
