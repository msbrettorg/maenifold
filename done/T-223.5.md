# T-223.5 - Gate progress column should restore compact status dots

## Problem

The Gate task table progress column has regressed from the old compact progress grammar into verbose word badges. Instead of a small dot per stage, the column is now rendering stage words in pills plus a separate state label underneath. In the screenshot, this produces noisy progress chips such as `Problem`, `Evidence`, `Acceptance criteria`, `Source`, and `Pending`, which is both visually heavy and semantically wrong for the Gate list.

The desired behavior is the earlier compact pattern: a series of dots, green for done, yellow for the active/in-progress stage, gray for inactive stages, with only a small label under the active dot naming that stage. No wordy badge row should remain in the progress column.

## Evidence

- User screenshot report from this session: `Screenshot 2026-04-25 at 11.36.16 AM.png`.
- `apps/desktop/src/components/GateTaskProgress.vue:4-5` imports `Badge`, and `:100-120` renders one `Badge` per segment plus a separate `progressLabel`.
- `done/T-202.36.md:31-33` requires no redundant display and explicitly calls for status beads / dots rather than pill badges.
- `docs/UAT-PLAN.md:1288-1290` defines the design-system expectation as `Status dots` — `6px dots (not pill badges)`.
- `done/T-205.712-fix-gate-ui-stage-progress-parses-headings-as-stages.md` is recent evidence that the Gate progress surface must reflect actual gate stages, not task markdown headings.
- `memory://thinking/sequential/2026/04/03/session-1775229524299-45944` explicitly records prior intent to implement “real progress dots” for Gate UI.

## Acceptance Criteria

- [ ] The Gate progress column no longer displays word badges/chips for each stage.
- [ ] The progress column renders one compact dot per actual gate pipeline stage, not one badge per markdown section heading.
- [ ] Completed stages render green dots.
- [ ] The active/in-progress stage renders a yellow dot.
- [ ] Inactive/not-yet-reached stages render gray dots.
- [ ] Only the active stage shows small text beneath its dot naming that stage.
- [ ] The progress column does not show a second redundant text label that duplicates the active state.
- [ ] The implementation reuses the existing design-system status-dot pattern / primitives / tokens already used in the app and does not introduce a new hand-rolled badge/control pattern.
- [ ] Packaged Electron verification confirms Gate task rows show dot progress with a single active-stage label and no word-badge row.
- [ ] `cd apps/desktop && npm run build` succeeds.
