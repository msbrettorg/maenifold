# Gate Pipeline Scaffold

This scaffold provides the starting structure for a gated pipeline.
The sample files in this scaffold use the default SDD flow (`swe → red → blue → done`), but the directory layout is reusable for any Gate pipeline.

## Setup

1. Copy this scaffold to your project root
2. Write your task files (use stable task IDs such as `T-1.1-description.md`)
3. Place pending specs in `todo/`
4. Run `gate_Sync` through `GatewayExecute` to initialize the cache

## File Structure

```text
project/
├── .gate/
│   └── gate.db # Cache (auto-generated by gate_Sync)
├── todo/           # Pending task specs
│   └── T-1.1-*.md
└── done/           # Completed task specs (moved by the final gate_Pass)
    └── T-1.2-*.md
```

## Gateway Commands

- `GatewayExecute domain="maenifold.gate" command="gate_Status" parameters={root: "/path/to/project"}` — View pipeline status
- `GatewayExecute domain="maenifold.gate" command="gate_Append" parameters={root: "/path/to/project", taskId: "T-1.1", agent: "swe", notes: "Implemented scoped changes"}` — Record SDD SWE completion
- `GatewayExecute domain="maenifold.gate" command="gate_Pass" parameters={root: "/path/to/project", taskId: "T-1.1", agent: "red", notes: "Reviewed and approved"}` — Advance the current stage
- `GatewayExecute domain="maenifold.gate" command="gate_Fail" parameters={root: "/path/to/project", taskId: "T-1.1", agent: "blue", notes: "Scoped test failed"}` — Follow the active state's fail edge
- `GatewayExecute domain="maenifold.gate" command="gate_Sync" parameters={root: "/path/to/project", rebuild: true}` — Rebuild `.gate/gate.db` from files and ensure `.gate/` is gitignored
