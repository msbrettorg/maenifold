## Intent

Normalize border usage to Fluent 2 token-driven semantics. Borders are allowed and expected; this task replaces legacy/raw declarations with token utilities, removes redundant cosmetic borders, and preserves only valid token-driven structure.

## Scope

### 1) Inventory

Inventory all declarations in `apps/desktop/src/` (excluding `apps/desktop/src/components/ui/**`) matching:
- `border:`
- `border-color:`
- `border-style:`
- `border-top:`
- `border-right:`
- `border-bottom:`
- `border-left:`

### 2) Classify every declaration

For each border declaration found, classify as:
- **Replace**: convert to token-driven Tailwind utility
- **Remove**: delete if purely cosmetic/redundant under current elevation/shadow model
- **Keep as-is**: only if already token-driven and Fluent 2-compliant

### 3) Classification table (authoritative conversion rules)

| Declaration pattern / intent | Classification | Required result | Token chain |
|---|---|---|---|
| Structural pane/field/list boundaries | Replace | `border border-subtle` | `borderSubtle` (`#383838`) |
| Card/tile separators on dark surfaces | Replace | `border border-card` | `borderCard` (`rgba(255,255,255,0.08)`) |
| One-sided separators (`border-top`, `border-bottom`, etc.) | Replace | Side-specific Tailwind utility tied to `border-subtle` or `border-card` | `borderSubtle` / `borderCard` |
| Hardcoded color border declarations (`#...`, named colors, rgb/rgba literals) | Replace | Tokenized Tailwind border utility only | `borderSubtle` / `borderCard` |
| Decorative borders duplicating elevation intent | Remove | No border utility retained | N/A |
| Already tokenized Tailwind border utilities (`border-subtle`, `border-card`) | Keep as-is | No change | Already compliant |
| Focus/active ring styling routed through border color | Replace | Brand-based focus/ring utility path | `brand` (`#0078D4`) |

## Acceptance Criteria

1. `rg "border(?:-(top|right|bottom|left|color|style))?\\s*:\\s*[^v]" apps/desktop/src/ --glob '!components/ui/**'` returns 0 matches.
2. All remaining border visuals resolve through `borderSubtle` or `borderCard` token chains.
3. Focus rings use the brand token chain (`brand`).
4. Visual result preserves subtle separators (visible, not heavy) across core desktop surfaces.
