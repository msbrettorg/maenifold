# T-202.15 — UAT plan: mandate design system primitives and fill gaps

## Problem

The UAT plan (`docs/UAT-PLAN.md`) has three issues identified by the duo audit:

1. **No design system mandate.** Test cases verify behavior but don't enforce that components use shadcn-vue primitives and Tailwind design tokens. Hand-rolled `<button>`, `<details>/<summary>`, native `confirm()`, and bespoke CSS all pass UAT today despite violating DESIGN.md. The UAT needs cross-cutting assertions that components use the design system, not hand-roll.

2. **Missing Settings > Models section.** The K-section index lists Agents, MCP Servers, Maenifold, Preferences — but no Models sub-section. Zero test cases for model download/install/activate/delete flows.

3. **UAT vs DESIGN.md contradictions.** TC-628 says "no `1px solid` hard borders" and TC-631 says "no drop shadows (ambient glow only)" — these were from the old Obsidian Engine design. DESIGN.md §5 explicitly says "borders ARE allowed and expected" and §4 says "Real drop shadows, NOT ambient glow." The onboarding wizard may have a design exception, but the cross-cutting assertions (Section M) need aligning with the current DESIGN.md.

## Fix

### 1. Add cross-cutting design system assertions (Section M update)

Add test cases that enforce:
- All interactive controls use shadcn-vue primitives (`Button`, `Dialog`, `Card`, `Tabs`, `Select`, `Badge`, `Tooltip`, `Accordion`, `ScrollArea`)
- No native `confirm()`, `alert()`, or `prompt()` — use shadcn `AlertDialog`
- No hand-rolled `<details>/<summary>` — use shadcn `Accordion`
- No hand-rolled `<button>` with bespoke CSS — use shadcn `Button` with variants
- All colors reference design tokens (`bg-bg-app`, `text-text-primary`, `bg-brand`, etc.) — no hardcoded hex
- All radii use token scale: `4px`, `8px`, `12px` — no arbitrary values
- Font stack = Segoe UI Variable system stack — no Inter, Space Grotesk
- Shadows use `shadow-fluent-8/16/64` tokens — no ambient glow

### 2. Add K.10 Settings Models section

New test cases for:
- Model card display (name, dimensions, size, license, status badge)
- Download button on uninstalled models
- Activate button on installed-but-not-active models
- Active badge on current model
- Delete button on installed non-active models
- Dimension-change re-embedding warning
- Loading state during model operations
- Error state with retry

### 3. Align Section M with current DESIGN.md

- TC-628: Update from "no 1px solid borders" to "1px borders expected per DESIGN.md §5; use `border-border-subtle` and `border-border-card` tokens"
- TC-631: Update from "no drop shadows" to "real drop shadows using `shadow-fluent-8/16/64` tokens per DESIGN.md §4"
- TC-629: Update primary button spec to match DESIGN.md — `bg-brand` (#0078D4), `hover:bg-brand-hover` (#106EBE), `text-primary-foreground`, `rounded-[8px]`

## Acceptance criteria

1. Section M includes design system primitive enforcement test cases
2. Section K.10 exists with ≥6 model management test cases
3. TC-628, TC-629, TC-631 aligned with current DESIGN.md (not Obsidian Engine)
4. No remaining references to deprecated design rules (ambient glow, no-borders, Space Grotesk)
