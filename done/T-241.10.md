# T-241.10 — Onboarding Model step Next button UX could mislead testers

**Pipeline**: tdd

## Background

Discovered during T-241.1 CDP blue-team verification. The Model step (Step 4 of 5/6) has a primary button whose label depends on state:

- `selectedModel === null` → "Download →" (button DISABLED)
- `selectedModel.installed && !isActive` → "Next →" (button ENABLED)
- etc.

There's also a sibling "Download later →" button (Skip path).

A naive CDP test (and possibly some users) might click the disabled "Download →" or "Next →" button without selecting a model first, see no advancement, and conclude the wizard is broken.

## Proposed UX improvements (pick one or several)

1. **Default-select** the first available installed model when the step renders. If none installed, default to the smallest/recommended downloadable model.
2. **Inline hint** under the disabled button: "Select a model above first" (when `selectedModel === null`).
3. **Auto-advance** if there's already an active embedding model on first render of this step (skip the Model step entirely for returning users with a configured model — this overlaps with T-241.1's returning-user skip but at sub-step granularity).

## Acceptance Criteria

- [ ] Fresh-user CDP test can advance through the Model step without manual model click (option 1 or 3) OR with a clear visible cue that one is required (option 2).
- [ ] Returning users with active embedding model do NOT see the Model step at all (option 3).
- [ ] No regression of T-241.1's overall fix.

## Notes

T-241.1 is closed because the user-reported issue (Step 1 → Step 2 doesn't advance) IS fixed. This task is a polish item.
