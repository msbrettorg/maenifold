# T-06.4 — Gate progress dots must render the full stage sequence

## Problem

The Gate table progress display is still wrong after the earlier compact-dot fixes. In the latest screenshot from this session, many rows collapse to a single dot plus `Pending` text instead of rendering the full stage sequence for the task's actual pipeline.

The required visual contract is explicit:

1. **Gray** for not-done / not-yet-reached stages
2. **Yellow** for the active stage
3. **Green** for completed stages
4. **Display all dots, not one**

This is a follow-on regression after `T-223.5` and `T-06.2`. The display is no longer merely duplicating or mislabeling stages; it is failing to show the full pipeline-stage grammar at all.

## Evidence

- User screenshot intake in this session: `Screenshot 2026-04-25 at 4.43.33 PM.png`
- `done/T-223.5.md` established the intended compact-dot design.

- `done/T-202.36.md:31-33` and `docs/UAT-PLAN.md:1288-1290` require status dots / beads and no redundant display.

## Root Cause Analysis (revised per duo review)

The issue has two layers:

### Layer 1: Hardcoded stage taxonomy drops valid stages

`apps/desktop/src/lib/gate-display.ts:29-44` — `gateStageFamily()` only recognizes a hardcoded subset of stage names. `normalizeTaskStages()` in `useGateMcp.ts:104-108` AND `GateView.vue` both filter stages through `isPipelineStage()`, removing unrecognized stages.

**Currently missing from the taxonomy:**
- `"remediate"` — SLC pipeline (note: `"verify"` is already mapped to `'blue-team'`)
- All confession stages: `swe-confess`, `red-team-confess`, `blue-team-confess`, `pm-confess`, `red-team-audit`
- All MDD stages: `opus-plan`, `goldeneye-plan-review`, `gpt-5.4-test-writing`, etc.

### Layer 2: Frontend should not be filtering backend-provided stages at all

The backend (`cache_task_row.rs`) now correctly serializes stages from the pipeline definition via `definition.ordered_stage_ids()`. The frontend should **trust** these stages rather than filtering through a hardcoded taxonomy that can never stay in sync with all pipelines.

### Correct Fix

**Remove `isPipelineStage()` filtering from both paths:**
1. `useGateMcp.ts:104-108` — `normalizeTaskStages()` should pass stages through unchanged
2. `GateView.vue` — any duplicate `isPipelineStage` filtering should also be removed

**Keep `gateStageFamily()` for color/styling only** — unknown stages render as neutral dots (gray), not hidden. Add `"remediate"` to the taxonomy for proper color mapping, but do not gate stage visibility on family recognition.

### Additional cause of single-dot rendering

`error_status_row()` in the backend emits `"stages": []` for error rows. These legitimately collapse to a single dot. This is acceptable behavior for error states but should not affect normal tasks.
