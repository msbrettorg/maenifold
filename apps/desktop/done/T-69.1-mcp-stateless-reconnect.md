# T-69.1 — MCP Client Stateless Server Compatibility

**Requirement:** FR-40, FR-41
**Pipeline:** tdd
**Component:** `src/composables/useMcpClient.ts`

## Problem

`useMcpClient.connect()` requires the server to return an `Mcp-Session-Id` header on `initialize`. If the header is missing, connect hard-fails with *"Server did not return Mcp-Session-Id header"*.

The maenifold MCP server now runs in stateless mode (`stateful_mode: false`) per T-68.13 in maenifold-rs. In stateless mode, no `Mcp-Session-Id` is ever returned. This means:

1. **Initial connect fails** — `connect()` throws on missing header
2. **Reconnect fails** — `reconnectSession()` calls `connect()`, same failure
3. **All tool calls fail** — `ensureConnectedSession()` checks `sessionId.value` which is never set

The MCP spec (2025-03-26) explicitly supports stateless servers. The client must handle both modes.

## Acceptance Criteria

1. `connect()` succeeds when the server returns NO `Mcp-Session-Id` header (stateless mode)
2. In stateless mode, `connected` is `true` and `sessionId` is `null` after successful connect
3. `buildHeaders()` sends `Mcp-Protocol-Version: 2025-03-26` when no session ID is present
4. `ensureConnectedSession()` passes when `connected` is `true` even if `sessionId` is null
5. `callTool()` and `listTools()` work in stateless mode (no session ID sent)
6. Reconnect on 404 works in stateless mode (re-initialize without requiring session ID)
7. `disconnect()` skips DELETE when no session ID exists (stateless servers don't track sessions)
8. Existing stateful behavior is preserved — when server DOES return `Mcp-Session-Id`, it's used as before
