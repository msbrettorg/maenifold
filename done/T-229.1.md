## Summary

Add Bearer token authentication to the MCP HTTP transport endpoint (`/mcp`). Currently, REST mutation routes are protected by `require_bearer_token` middleware (`api/auth.rs:56-80`) but the MCP HTTP transport (`mcp/http.rs:18-28`) has no auth. This sub-task closes that gap before config mutation MCP tools are added.

## Scope

### Backend
- Add `require_bearer_token` middleware to `/mcp` endpoint in `crates/maenifold-core/src/mcp/http.rs`
- stdio transport remains unauthed (local trusted process)

### Frontend
- Current MCP transport uses bare `globalThis.fetch` via `getHttpFetch()` in `apps/desktop/src/lib/http.ts`
- Update `getHttpFetch()` to return a fetch wrapper that injects `Authorization: Bearer <token>` header
- Token available via `window.electronAPI.getAuthToken()` (same as `authenticatedFetch` in `daemon-url.ts`)

## Acceptance criteria

- [ ] MCP HTTP requests without valid Bearer token get 401
- [ ] MCP HTTP requests with valid Bearer token succeed (all existing MCP functionality preserved)
- [ ] stdio MCP transport continues to work without auth
- [ ] Frontend MCP transport injects Bearer token automatically
- [ ] `vue-tsc --noEmit` passes
- [ ] `cargo build --release -p maenifold-cli` succeeds

## Files

- `crates/maenifold-core/src/mcp/http.rs`
- `apps/desktop/src/lib/http.ts`
