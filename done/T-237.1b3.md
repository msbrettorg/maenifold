## Goal

Remove old standalone [[gate-service]] tool names from desktop tool-palette/catalog surfaces after the Gate data layer routes through [[GatewayExecute]] domain `maenifold.gate`. This child keeps T-237.1b within its 12-file cap and continues parent [[sequential-thinking]] session `session-1777236650835-22077`.

## File Scope

Stay within 12 files and 600 LOC:

- `apps/desktop/src/lib/tool-palette-catalog.ts`
- `apps/desktop/src/lib/__tests__/tool-palette-catalog.test.ts` or the existing nearest catalog test file

## Acceptance Criteria

- `tool-palette-catalog.ts` no longer advertises old standalone gate tool names as current surfaces.
- The catalog lists or routes only `gate_Status`, `gate_Pass`, `gate_Fail`, `gate_Append`, `gate_Sync`, `gate_History`, and `gate_TaskBody` for native gate operations.
- Catalog text does not instruct users or agents to call a separate gate endpoint.
- Tests or nearest existing catalog coverage prove old `sync` / `gate-sync` / `status` / `gate-status` names are not presented as current gate tools.

## Verification Commands

- `cd apps/desktop && npm run build`
- `cd apps/desktop && npm run test -- tool-palette`

## Non-Goals

- Do not change Gate data transport; T-237.1b owns that.
- Do not change Gate visual detail components; T-237.1b2 owns that.
