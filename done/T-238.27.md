# T-238.27 — Generalize broken-pipe safe stdout to all gate CLI commands

## Problem

T-238.5 fixed `gate status` broken-pipe panics, but other gate CLI commands still use `println!` for stdout and will panic if piped to `head` or a consumer that closes early.

## Evidence

Red-team audit of T-238.5 identified pre-existing `println!` call sites:

- `crates/maenifold-gate/src/cli.rs` line 126 (`gate` with no subcommand)
- `crates/maenifold-gate/src/cli_parser.rs` line 222 (clap error output)
- `crates/maenifold-gate/src/history_command.rs` lines 14-27 (`gate history`)

## Acceptance criteria

- [ ] All gate CLI stdout paths use the `write_line` helper (or equivalent) that returns Ok on BrokenPipe.
- [ ] No `println!` remains in gate CLI command output paths.
- [ ] `gate history --root . | head -1` exits without panic.
- [ ] Existing cross_process regression tests still pass.

## Verification

- `rg 'println!' crates/maenifold-gate/src/ --glob '!*test*'`
- `cargo test -p maenifold-gate -- cross_process`
- `cargo build --release -p maenifold-gate`
