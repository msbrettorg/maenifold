# T-218.31 — Teams Monitor Canonical Runtime State

## Problem

Teams Monitor `enable`/`disable` only mutates config. `teams://status` returns hard-coded zeros. Three UI components (TeamsTab, TeamsSettings, AppTabBar) parse three different status shapes. This task introduces the canonical runtime state model, unifies the frontend, and wires resource notifications — without requiring a live Trouter connection.

**Scope narrowing**: Live Trouter lifecycle wiring (start/stop WebSocket) requires auth from T-218.30 and is deferred to a follow-up task (T-218.44).

## What Exists Today

| Surface | Current behavior |
|---------|-----------------|
| `tools/teams_monitor.rs` enable/disable | Mutates `maenifold.json` only |
| `teams/trouter.rs` TrouterClient | Exists, orphaned, never spawned |
| `mcp/resources/teams.rs` teams://status | Returns `{enabled, connectionState: "disabled"/"not_connected", matchCount: 0, lastNotification: null}` |
| TeamsTab.vue | Reads `status`, `connected`, `detail`/`message`/`error` — phantom fields |
| TeamsSettings.vue | Reads `connectionState` from tool call — matches resource partially |
| AppTabBar.vue | Reads `unreadCount`/`unread_count`/`matchCount` — only matchCount exists |

## Acceptance Criteria

### Backend
- [ ] Introduce `TeamsRuntimeState` (`Arc<RwLock<...>>`) with canonical fields: `connectionState: disabled | connecting | connected | reconnecting | error`, `lastMessageAt`, `lastMatchAt`, `matchCount`, `activeDispatches: u32`, `lastError: Option<String>`
- [ ] `teams://status` reads from `TeamsRuntimeState`, not config
- [ ] `TeamsMonitor enable` transitions state to `connecting` (or `error` with "authentication required" if no token source available)
- [ ] `TeamsMonitor disable` transitions state to `disabled`
- [ ] Status changes emit `notifications/resources/updated` for `teams://status` (via existing `notify_resource_updated` in `subscription.rs`)
- [ ] Coalesce notifications: emit on `connectionState` transitions and counter changes; metric-only updates at ≤1 Hz

### Frontend
- [ ] Add shared composable/type for canonical Teams status shape
- [ ] TeamsTab.vue, TeamsSettings.vue, and AppTabBar.vue all parse the same canonical shape
- [ ] No phantom field reads — all fields match `teams://status` output
- [ ] Badge count derived from `matchCount` in canonical shape

### Build
- [ ] `cargo build --release -p maenifold-core` succeeds
- [ ] `cd apps/desktop && npx vue-tsc --noEmit` succeeds

## Key Files
- `crates/maenifold-core/src/tools/teams_monitor.rs` (enable/disable/status)
- `crates/maenifold-core/src/mcp/resources/teams.rs` (teams://status resource)

- Restart/restore behavior
