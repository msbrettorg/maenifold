# T-205.708 — Fix: Agent responses render code without fenced code blocks

**Pipeline**: test
**Pipeline Digest**: 16842feaee5604e196f8d0c4ddc8a6566bd538a1ad2d739bc956a9e49f123128

## Bug

The markdown renderer supports code blocks, mermaid, SVG, and safe HTML. However, when the Copilot agent returns code (e.g. `print("Hello, World!")`), it renders as flat monospace without syntax highlighting, container, or copy button.

The renderer is correct — the problem is upstream. Either:
1. The agent is returning plain text without markdown fences
2. The ACP response content type is `text` instead of `markdown`
3. The content is being stripped of fences before reaching the renderer

**Severity: P2** — Renderer works; agent/transport is losing the markdown formatting.

## Found During

UAT T-205.137. Two separate prompts asking for fenced Python code both rendered identically as flat monospace.

## Acceptance

- Agent code responses arrive at the renderer with triple-backtick fences intact
- Renderer applies syntax highlighting, container, and copy button
