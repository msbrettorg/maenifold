# T-218.47 — Teams Auth State in Status Resource

## Problem

`teams://status` does not report authentication state. Users and agents cannot determine if Teams is authenticated, pending auth, expired, or unauthenticated.

## Decomposed from T-218.30

This is sub-task 3 of 3. Depends on T-218.46 (auth lifecycle wiring).

## Implementation

Extend `TeamsRuntimeState` and `teams://status` resource response:

- Add `authState` field: `unauthenticated | pending | authenticated | expired | error`
- Add `expiresAt` field: ISO 8601 timestamp of token expiry (null when unauthenticated)
- Add `lastAuthError` field: sanitized error string (no tokens, no filesystem paths)
- Auth state transitions emit resource notifications

## Acceptance Criteria

- [ ] `teams://status` includes `authState` with enum values
- [ ] `teams://status` includes `expiresAt` when authenticated
- [ ] `teams://status` includes `lastAuthError` when in error state
- [ ] Error messages are sanitized (no tokens, no paths)
- [ ] Auth state changes emit notifications/resources/updated for teams://status
- [ ] `cargo build --release -p maenifold-cli` succeeds

## Files Touched

- `crates/maenifold-core/src/teams/runtime.rs` — add auth state fields to TeamsRuntimeState
- `crates/maenifold-core/src/mcp/resources/teams.rs` — include auth fields in status_value()
