# T-221.9 - End-to-end Compatibility and Tool-count Verification

## Problem

The epic only succeeds if real clients see the reduced tools-only surface and can still accomplish Gate, Maenifold, and upstream gateway operations.

## Scope

Verify:

- Maenifold MCP tools/list count
- `GetHelp` standalone exposure
- `GatewayIndex` discovery
- `GatewayExecute` exact read and mutate flows
- `GatewayIntent` resolver flow
- Resolver-disabled deterministic flow
- `ReadMcpResource` for catalog resources
- Gate and Maenifold first-party routing
- Upstream gateway routing

Client focus:

- GitHub Copilot CLI tools-only path is mandatory.
- Codex/OpenAI-compatible tools path is best-effort and must record available/unavailable status.
- opencode tools path is best-effort and must record available/unavailable status.
- Claude tools path is best-effort and must record available/unavailable status.

Compatibility verification must use existing MCP/rmcp/CLI invocation paths. Best-effort client evidence may be manual or observational when no stable automation API exists. Do not add browser automation, client SDK, simulator, or Playwright-style dependencies for best-effort clients unless a later PM-approved spec explicitly justifies the addition.

## Acceptance Criteria

- [ ] tools/list for Maenifold-owned MCP surface is at or below the T-221.0 public tool target.
- [ ] tools/list contains exactly the 5 baseline tools when intent is disabled: `GatewayIndex`, `GatewayExecute`, `GatewayBatch`, `ReadMcpResource`, and `GetHelp`.
- [ ] tools/list contains no more than 6 tools when intent is enabled, adding only `GatewayIntent` to the 5 baseline tools.
- [ ] Existing `GetHelp` remains directly callable as a standalone tool, is not hidden behind `GatewayExecute`, and is not routed under `maenifold.system`.
- [ ] Copilot CLI can use `GatewayIndex`, `GatewayExecute`, `GatewayBatch`, `ReadMcpResource`, `GetHelp`, and `GatewayIntent` when intent is enabled.
- [ ] Resolver-disabled mode can complete representative tasks using only `GatewayIndex` + `GatewayExecute`.
- [ ] Resolver-disabled mode does not advertise `GatewayIntent`.
- [ ] Resolver-enabled mode uses `gpt-5.4-mini` unless explicitly overridden.
- [ ] Selected reasoning level is recorded from T-221.7 evidence.
- [ ] Selected reasoning level is verified as the shipped `MaenifoldSettings` default after T-221.7 applies it.
- [ ] `GatewayBatch` submit and status operations work for deterministic exact-command batches.
- [ ] Gate read operation works through gateway.
- [ ] Gate mutation returns exact execution requirement and does not auto-pass/fail.
- [ ] Maenifold memory search/read works through gateway.
- [ ] Maenifold memory write/edit/delete requires exact command execution and validates parameters.
- [ ] Upstream server command works through gateway without direct tool passthrough.
- [ ] Copilot CLI compatibility is verified as mandatory evidence.
- [ ] Codex/OpenAI, opencode, and Claude compatibility statuses are documented as available, unavailable, or blocked with reason.
- [ ] Compatibility harness uses existing MCP/rmcp/CLI invocation paths.
- [ ] Best-effort client verification does not add browser automation, client SDK, simulator, or Playwright-style dependencies unless separately PM-approved.
- [ ] `cargo build --release -p maenifold-cli` succeeds.
