## Problem

The loaded maenifold skill security model says maenifold has "no network listener" and "no authentication". The live process is `/usr/local/bin/maenifold --http --port 8080`, listening on `127.0.0.1:8080`, and `/mcp` returns `401 Unauthorized` with `missing or invalid bearer token`.

The documentation is materially stale for the current runtime and can mislead agents diagnosing MCP failures.

## Scope Notes

- Focus this task on **agent-facing security-model documentation drift**, not on changing the HTTP auth implementation itself.
- Preserve the actual runtime split:
  - stdio MCP remains local/no-auth
  - HTTP MCP on `127.0.0.1:8080/mcp` requires the bearer token
  - the desktop UI authenticates over the HTTP path using the same local token source
- Do not weaken or redesign auth as part of this task. This is a documentation-alignment task unless implementation review uncovers a tighter repo-owned doc-generation/source-of-truth improvement that stays within the documented-runtime scope.
