# T-43.11: Tool-only prompt turns

**Requirement**: Prompt-turn audit gap  
**Priority**: P1  
**Files**: `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/components/ChatView.vue`

## Acceptance Criteria

1. In the `tool_call` case of `handleSessionUpdate`, if the last message is NOT an assistant message, create a stub assistant message first:
   ```ts
   if (!lastMsg || lastMsg.role !== 'assistant') {
     messages.value.push({
       id: crypto.randomUUID(),
       role: 'assistant',
       content: '',
       timestamp: Date.now(),
       toolCalls: [],
     });
   }
   ```
   Then attach the tool call to it.

2. In `ChatView.vue`, ensure assistant messages with empty `content` but non-empty `toolCalls` still render (show the tool calls, not a blank bubble).

3. Verify `toolCallList` (the global computed from `toolCalls.value`) is either used as a rendering fallback or removed if dead code.


## SWE Remediation
- What I changed:
  - `vendor/acp-ui/src/stores/session.ts`: updated `handleSessionUpdate` so `tool_call` always creates a stub assistant message when a tool call arrives before assistant text, then attaches the tool call to that message; removed unused `toolCallList` computed/export as dead code.
  - `vendor/acp-ui/src/components/ChatView.vue`: made tool-call rendering use an explicit helper for per-message tool calls and marked assistant tool-only messages with a dedicated class so empty-content assistant turns still render their tool calls.
- Test results:
  - PASS — `cd vendor/acp-ui && npx vue-tsc --noEmit`
- Notes:
  - Kept the global `toolCalls` map for update tracking, but removed the unused computed list rather than using it as a rendering fallback because it was dead code and not message-scoped.
