# T-74.1 — Pipeline nodes immediately transition to abandoned

## Priority: P0

## Problem
Pipeline session `pipeline-1774977976761` had nodes that immediately transitioned to `abandoned` status after creation/dispatch. No work was executed.

## Acceptance Criteria
- [ ] Root cause identified and documented
- [ ] Fix applied — nodes must remain `pending` until dispatched, then `active` until completed/failed
- [ ] Regression test added
- [ ] All existing pipeline tests pass

## Researcher Notes

## Root Cause Analysis

**Validation/runtime mismatch in pipeline executor.**

1. `types.rs:54-60` — workflow nodes allow `acpClient` to be absent (Option)
2. `dispatch.rs:118-149` — dispatch marks nodes `Active` BEFORE execution is scheduled
3. `executor.rs:212-227` — executor checks `node.acp_client()`, finds `None`, immediately marks `abandoned`
4. No work executes

The pipeline `pipeline-1774977976761` likely had workflow nodes created without `acpClient`, which passed validation but were immediately abandoned at runtime.

**Fix plan:**
- Require `acpClient` for workflow/prompt/sequentialThinking nodes at validation time
- Don't transition nodes to `active` until executability is confirmed
- Surface missing-agent as a validation error, not a silent runtime abandon
