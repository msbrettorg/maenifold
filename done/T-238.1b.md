## Goal

Document the reproducible bootstrap path for [[Copilot-CLI]] sessions to expose [[maenifold]] [[MCP]] over the single maenifold daemon without CLI fallback. Native [[gate]] access must be documented as Gateway domains served through maenifold, not as a separate server. This continues parent [[sequential-thinking]] session `session-1777236650835-22077`.

## File Scope

Stay within these repo-owned bootstrap and MCP configuration surfaces:

- `docs/BOOTSTRAP.md`
- `assets/integrations/skills/maenifold/references/BOOTSTRAP.md`
- `assets/integrations/copilot/plugin-maenifold/.mcp.json`
- `assets/integrations/copilot/plugin-maenifold/README.md`
- `assets/usage/tools/addmcpserver.md`
- `docs/ARCHITECTURE.md`

Do not edit `~/.copilot/mcp-config.json`; document the required user-level configuration only.
Gate skill and standalone Gate crate docs remain owned by `T-237.1d` unless this task
only needs to reference them as stale surfaces.

## Acceptance Criteria

- Docs state that maenifold MCP is expected at `http://127.0.0.1:8080/mcp`.
- Docs state that Gate is not a separate MCP server; Gate tools are native Gateway domains served by maenifold on `http://127.0.0.1:8080/mcp`.
- Docs avoid promising final `maenifold.gate` command names until `T-237.1a2` lands; if tool names are mentioned, distinguish current partial `gate` (`status`, `sync`, `history`, `task_body`) from target `maenifold.gate`.
- Docs explain that server config and the running maenifold daemon are required.
- Docs identify the user-level Copilot MCP config path as `~/.copilot/mcp-config.json` and show the maenifold HTTP server entry shape without mutating that external file.
- Docs link to or include the maenifold daemon start path used by this repo, without adding standalone Gate daemon instructions.
- Docs explain how to verify `copilot mcp list` includes the maenifold server.
- Docs warn that plugin `.mcp.json` is insufficient if `copilot mcp list` does not show plugin servers.
- Docs remove or explicitly mark stale plugin/config examples that declare `gate` at `http://127.0.0.1:8081/mcp` as invalid.
- Scoped docs do not present direct filesystem access, `gate` CLI commands, `gate --mcp`, `gate --http`, port `8081`, `/usr/local/bin/gate`, `com.ma-collective.gate`, or hidden CLI fallback as equivalent to MCP tools.
