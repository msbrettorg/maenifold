# T-239.0 - Gate MCP surface unavailable in Copilot CLI session

**Pipeline**: lightweight

## Problem

This session is required to dogfood [[gate]] through [[MCP]] before using CLI fallback. The Copilot CLI tool surface available to this session does not expose `gate_Status`, `gate_Sync`, `gate_Append`, `gate_Pass`, or `gate_Fail` as invokable MCP tools, so the PM cannot operate gate through MCP from this client.

This is a PM environment/meta task. It records the dogfooding failure and does not block the Teams Monitor implementation chain T-239.1 through T-239.5.

## Attempted operation

- Operation needed: read and synchronize the active gate board before executing Sprint 239 Teams Monitor work.
- Expected MCP behavior: invoke `gate_Status` / `gate_Sync` or equivalent native `maenifold.gate` MCP commands from the client tool surface.
- Observed client state: no gate MCP invokable tool is present in the available Copilot CLI tool registry for this session.
- Current working path: use maenifold HTTP MCP `GatewayExecute` against domain `maenifold.gate`.
- Standalone `gate` CLI fallback is banned and must not be recreated.

## Ralph pickup

The integrated maenifold MCP surface works when called through HTTP MCP on `http://127.0.0.1:8080/mcp` with the local token from `~/maenifold/auth/localhost.token`.

Use:

- `GatewayIndex` with `domain: "maenifold.gate"` to inspect commands.
- `GatewayExecute` with:
  - `domain: "maenifold.gate"`
  - `command: "gate_Status" | "gate_Sync" | "gate_Append" | "gate_Pass" | "gate_Fail" | "gate_History" | "gate_TaskBody"`
  - `parameters` matching each command schema.

Do not use `gate`, do not build `target/release/gate`, and do not start a Gate service on port 8081. The remaining issue for this task is native Copilot CLI tool exposure/documentation for the integrated maenifold gateway, not restoring the standalone binary.
