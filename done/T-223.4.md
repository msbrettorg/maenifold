# T-223.4 — Gate Summary Chips Replace Duplicate Filter Row

## Problem

Gate view has three overlapping location filter surfaces: (1) top summary chips (passive spans), (2) lower `Tabs` row (Todo/Done/All), and (3) `GateViewFilters.vue` location `Select` dropdown. Only one should exist.

## Design Decision

The top summary chips become the sole interactive location filter. Both the lower Tabs row AND the GateViewFilters location Select are removed. The canonical filter state is `useGateTaskFiltering().selectedLocation`.

## Acceptance Criteria

- [ ] Lower `Tabs` row (Todo/Done/All) in `GateView.vue` removed
- [ ] Location `Select` in `GateViewFilters.vue` removed (keep other filter controls if any)
- [ ] Top summary chips in `GateViewToolbar.vue` become clickable `<button>` elements
- [ ] Clicking `todo` chip sets `selectedLocation` to `'todo'`
- [ ] Clicking `done` chip sets `selectedLocation` to `'done'`
- [ ] Clicking `total` chip sets `selectedLocation` to `'all'`
- [ ] Active chip has `aria-pressed="true"` and visually distinct styling (e.g., ring or inverse variant)
- [ ] Re-clicking the active chip is a no-op (does not toggle)
- [ ] `shown` chip remains non-interactive, preserves current auto-hide behavior when shown equals total
- [ ] Vertical space from removed rows is reclaimed (no dead gap)
- [ ] `cd apps/desktop && npx vue-tsc --noEmit && npm run build` succeeds

## State Model

- `GateViewToolbar` receives `selectedLocation` prop and emits `update:selectedLocation`
- Filter state lives in `useGateTaskFiltering()` composable (not Pinia)
- `shown` is derived from `visibleTasks.length`

## Files Likely Touched

- `apps/desktop/src/components/GateView.vue` — remove Tabs row, wire toolbar props
- `apps/desktop/src/components/GateViewToolbar.vue` — make chips interactive buttons
- `apps/desktop/src/components/GateViewFilters.vue` — remove location Select
