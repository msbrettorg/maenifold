# T-214.3 — Executor session dispatch

## Problem

The pipeline executor dispatches prompt nodes by creating new ACP sessions. Session-as-Node requires resuming existing sessions when `session_ref` is present.

## Solution

**Spike T-214.1 finding:** Session resume infrastructure EXISTS in `cold_start.rs` lines 158-205 but `execute_runtime()` hardcodes `resume_session_id = None` at `crates/maenifold-jockey/src/acp/session/execute.rs` line 65. The fix is parameter threading — no new ACP protocol implementation required.

### Changes Required

1. **`AgentSessionConfig`** (in `runner_prompt.rs`): Add `resume_session_id: Option<String>` field
2. **`execute_runtime()`** (in `execute.rs`): Plumb `resume_session_id` from config instead of hardcoding `None`
3. **`WorkerMsg::Execute`**: Thread the parameter through the worker message
4. **`cold_start()`** (in `cold_start.rs`): Already accepts `resume_session_id` — will now receive real values
5. **Pipeline executor** (in `executor_run_exec.rs`): When `session_ref` is present on a prompt node, set `AgentSessionConfig.resume_session_id = Some(session_ref.session_id)`
6. **Capability check**: Verify `supports_load_session` before attempting resume. Fail hard with clear error if not supported. No silent fallback.

## Key Files

- `crates/maenifold-jockey/src/acp/session/execute.rs:65` — hardcoded `None` (THE FIX)

- Missing capability → hard failure with descriptive error
- Prompt node without `session_ref` → unchanged behavior
- `cargo build --release -p maenifold-core` succeeds
