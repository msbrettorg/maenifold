# T-43.9: Prompt timeout coverage

**Requirement**: Prompt-turn audit gap  
**Priority**: P1  
**Files**: `vendor/acp-ui/src/lib/acp-bridge.ts`

## Acceptance Criteria

1. Update T-43.5's timeout fix (or this spec) to also cover `session/prompt`. The `session/prompt` method is inherently long-lived — the agent may run for minutes across multiple tool call cycles before returning a `stopReason`.

2. In the `getTimeoutForMethod()` function (from T-43.5), add `session/prompt` with a generous timeout (e.g., 30 minutes or `Infinity`).

3. Alternatively, remove the blanket timeout entirely and use AbortController-based cancellation instead, since `session/cancel` already exists as the proper cancellation mechanism.

## SWE Remediation

- What I changed:
  - `vendor/acp-ui/src/lib/acp-bridge.ts`: added `getTimeoutForMethod()` and updated `sendRequest()` to use per-method timeouts instead of a blanket 60-second timeout.
  - `vendor/acp-ui/src/lib/acp-bridge.ts`: configured `session/prompt` to use a 30-minute timeout, matching the long-lived nature of prompt turns and preserving existing longer timeouts for other ACP methods.

- Test results:
  - PASS — `cd vendor/acp-ui && npx vue-tsc --noEmit`

- Notes about decisions made:
  - I implemented the acceptance criteria using the per-method timeout approach described in T-43.5 rather than removing timeouts entirely.
  - `session/prompt` now shares the same 30-minute timeout window as `terminal/wait_for_exit`, which covers multi-minute prompt/tool-call cycles without changing cancellation behavior.
