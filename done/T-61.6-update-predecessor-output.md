# T-61.6 — Predecessor Context from NodeState.output

**Requirement**: FR-47
**Test Cases**: TC-202
**Component**: `crates/maenifold-core/src/workflow/pipeline/update.rs`
**Depends on**: T-61.4 (NodeState.output must exist)

## Context

`predecessor_context_content()` at update.rs:256-297 gathers upstream node conclusions by reading `last` frontmatter from each upstream workflow session file. This approach has two problems:

1. It only works for workflow nodes (prompt and thinking nodes won't have workflow session files with `last` frontmatter)
2. It reads from session files on disk rather than the in-memory `NodeState.output` field (which T-61.4 adds)

The red-team identified this as FAIL-6: predecessor context must read from `NodeState.output` first, falling back to session `last` for workflow nodes only.

## Acceptance Criteria

1. Modify `predecessor_context_content()` to read from `NodeState.output` as the PRIMARY source:
   - For each completed predecessor node, check `node_state.output` first
   - If `output` is `Some(text)`, use that text as the predecessor's contribution
   - If `output` is `None`, fall back to the existing `last` frontmatter read from the workflow session file (this covers workflow nodes that completed before the output field existed)

2. The function signature may need to accept `&HashMap<String, NodeState>` (the node_states map) in addition to its current parameters, so it can read `.output`.

3. The output format MUST remain:
   ```
   ## Predecessor Context

   ### From {source_node_id}

   {output_text}

   ### From {other_source_node_id}

   {other_output_text}
   ```

4. If a predecessor is completed but has no output AND no session `last` frontmatter, skip it silently (don't error).

5. `inject_predecessor_context()` at update.rs:194-231 SHOULD still write to the session body for backwards compatibility, BUT the executor (T-61.7) will also prepend context to the prompt directly.

6. All existing update tests MUST continue to pass.

7. The code MUST compile: `cargo build -p maenifold-core`

## SWE Remediation

- **What I changed**
  - `crates/maenifold-core/src/workflow/pipeline/update.rs`
    - Updated `predecessor_context_content()` to use `NodeState.output` as the primary predecessor context source.
    - Added `predecessor_context_source()` helper to fall back to workflow session `last` frontmatter only when the upstream node is a workflow node and `output` is absent/empty.
    - Preserved the existing rendered section format and silent-skip behavior when neither in-memory output nor workflow `last` content exists.
    - Updated predecessor-context tests to cover output-first behavior and adjusted existing expectations so newly completed nodes contribute their in-memory output instead of stale workflow-session `last` content.
    - Added `#[serial(config)]` to affected update tests to avoid shared-config cross-test interference in this module.

- **Test results**
  - **PASS** — `cargo build -p maenifold-core 2>&1`
  - **FAIL (pre-existing unrelated test in filter set)** — `cargo test -p maenifold-core --lib update -- --nocapture 2>&1`
    - Update-module tests passed, but the command also matched `workflow::pipeline::handler::tests::pipeline_pause_and_pipeline_resume_updates_status`, which failed with `left: Some("stuck")`, `right: Some("paused")`.
  - **FAIL (same unrelated regression)** — `cargo test -p maenifold-core --lib pipeline -- --nocapture 2>&1`
    - Single failing test: `workflow::pipeline::handler::tests::pipeline_pause_and_pipeline_resume_updates_status`

- **Notes / decisions**
  - Treated empty/whitespace-only `NodeState.output` the same as missing output so legacy workflow-session fallback still works cleanly.
  - Kept fallback reads limited to workflow nodes only, per spec, so prompt/sequential-thinking predecessors without session `last` metadata are skipped without error.
