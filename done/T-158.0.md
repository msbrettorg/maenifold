# T-158.0 — ACP relay bug fixes (F-2, F-3, session/load)

## Per ACP Spec

- `session/load` (§Session Setup): Agents that support `loadSession` capability allow Clients to resume previous conversations. The Agent MUST replay the entire conversation via `session/update` notifications, then respond to the original request.
- Our relay advertises `loadSession: false` but Jockey supports `resume_session_id`. Wiring gap.

## Fixes

### 1. `loadSession: true` + `session/load` handler
- Line 290: change `"loadSession": false` → `"loadSession": true`
- Add `session/load` handler that extracts `params.sessionId` and passes it as `resume_session_id` to Jockey worker
- Add dispatch branch in the method router

### 2. Prewarm false success (red-team F-2)
- Prewarm failure sends empty tuple instead of error. Relay stores empty session_id and returns success.
- Check `session_id.is_empty()` after prewarm await, return `rpc_error` to client.

### 3. Delta channel capacity (red-team F-3)
- Line 359: `mpsc::channel(64)` → use `DELTA_CHANNEL_CAPACITY` (512) constant from Jockey.

## Files
- `crates/maenifold-core/src/api/acp_relay.rs`
