3. **`getApiBase()` production change is correct and necessary**: ✅
   - **Why necessary**: Node/undici (used by jsdom's `fetch`) does not resolve relative URLs — `fetch('/api/memory/read')` throws `TypeError: Failed to parse URL from /api/memory/read`. The old implicit empty-string base would have made all integration test `fetch` calls fail with a URL parse error, not a network error.
   - **Why correct**: Returns `window.location.origin` for `http:`/`https:` (same-origin in browser, absolute URL in Node) and falls back to `http://127.0.0.1:8080` for exotic protocols (e.g. `tauri:`). This matches existing runtime behavior — Tauri WebView was already reaching the local dev server via that origin; the change makes the URL construction explicit rather than relying on relative-URL resolution that only works inside a browser host.
   - **Not cargo-cult**: The change is the minimum fix for a real interoperability gap between browser fetch and Node fetch semantics. It is exported as `getApiBase` for testability, consistent with the integration test import at `memoryApiIntegration.test.ts:4`.
