## Summary

**The entire Scriptable UI feature is broken.** Every `callTool()` from the frontend hits the gateway and gets `-32602: Tool 'X' is routed under domain 'Y'. Use GatewayExecute`. This affects every UI screen — memory, graph, pipeline, workflow, config, embeddings, schedules. Nothing works when gateway mode is active.

The root cause: `callTool()` in `mcpClientOps.ts` sends bare tool names via MCP `tools/call`. The backend's `call_tool()` (mod.rs:217-225) intercepts all tool names except `GetHelp` and `ReadMcpResource` when gateway is active, routing them through `gateway.handle_tool_call()`, which returns the domain-routing error.

Agents use `GatewayExecute` with `{domain, command, parameters}`. The UI must do the same. This is the entire point of "AI is the new UI" — one interface for all consumers.

## Fix

Update `callTool()` in `mcpClientOps.ts` to transparently route through `GatewayExecute`:

1. **On connect:** call `GatewayIndex` (no params) to get the full domain→command catalog. Build a `Map<string, string>` of `toolName → domain`.

2. **On callTool(name, args):** look up `domain` from the map. If found, send:
   ```
   callTool('GatewayExecute', {
     domain: '<domain>',
     command: '<name>',
     parameters: { ...args }
   })
   ```
   If NOT found (tool not in gateway — e.g., `GetHelp`, `ReadMcpResource`), send bare `callTool(name, args)` as today.

3. **On reconnect:** rebuild the domain map (GatewayIndex may change after config reload).

This is a single-point fix. Every consumer (`usePipelineMcp`, `useMemoryApi`, `useMemoryPromotion`, `useEmbeddingsActions`, `useSchedulesSettings`, `config.ts`, `useGateMcp`, `useToolPaletteFields`, `McpAppFrame.vue`) gets gateway routing for free.
