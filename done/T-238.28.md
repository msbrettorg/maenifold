# T-238.28 — MCP client passthrough allowlist blocks config/discovery tools

## Problem

The desktop MCP client wrapper has a passthrough allowlist that blocks `ReloadConfig`, `AddAgent`, `UpdateAgent`, `DeleteAgent`, `AddMcpServer`, `UpdateMcpServer`, `DeleteMcpServer`, `DiscoverMcpTools`, and `UpdateSettings` — all real direct tools exposed by the daemon. Meanwhile it allowlists `GatewayIntent` which is config-gated and may not be present.

This means the Config and Discovery UI panels are 100% dead — they call tools the wrapper silently drops.

## Evidence

Red-team finding from sprint 238 wave audit.

## Acceptance criteria

- [ ] All tools returned by `tools/list` from the daemon are callable through the desktop MCP client wrapper.
- [ ] No hallucinated tool names are in the allowlist.
- [ ] Config and Discovery UI panels function end-to-end.

## Verification

- CDP: open Config tab, add/update/delete agent and MCP server entries, verify changes persist.
- CDP: open Discovery tab, trigger tool discovery, verify results display.
