# T-220.4 - Normalize ACP Cancellation Results

## Problem

Cancelled ACP prompt turns can surface as JSON-RPC errors instead of returning the ACP-required `stopReason: cancelled`.

## Evidence

- `crates/maenifold-core/src/api/acp_relay.rs:202-213` tracks cancellation but sends `rpc_error(...)` when the worker returns `Err`.
- `crates/maenifold-jockey/src/acp/worker/mod.rs:153-168` sends cancellation without guaranteeing prompt-result normalization.
- Source: `docs/codebase-audit-2026-04-25.md#p1-3`.
- Parent sequential thinking session: `session-1777125506368-62098`.

## Acceptance Criteria

- [ ] When a pending prompt is marked cancelled, the original `session/prompt` response returns `stopReason: cancelled`.
- [ ] Worker abort or transport errors after cancellation do not leak as user-visible prompt failures.
- [ ] Non-cancellation worker errors still return normal JSON-RPC errors.
- [ ] Tests cover cancelled success, cancelled worker error, and non-cancelled worker error paths.
- [ ] `cargo build --release -p maenifold-cli` succeeds.
