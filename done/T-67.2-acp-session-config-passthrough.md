# T-67.2: Flow Session Config Through Pipeline → Agent

## Requirement
FR-50 — Pipeline node configuration (model, thought_level, allowed_tools, max_turns) must flow through to ACP sessions.

## Problem
Two gaps:

1. **`NewSessionResponse` fields discarded**: `handle_new_session()` extracts only `session_id`, dropping `modes` (available agent modes), `models` (available models from `unstable_session_model`), and `config_options`.

2. **Pipeline node config hardcoded to None**: `agent_session.rs:22` hardcodes `model: None, thought_level: None, allowed_tools: None, max_turns: None` regardless of what the pipeline node specifies. The `PipelineNode::Prompt` type HAS `model` and `thought_level` fields — they just never reach `SessionOpts`.

## Acceptance Criteria
1. `handle_new_session()` must return a `SessionInfo` struct containing `session_id`, `modes`, `models`, and `config_options`
2. `AgentHandle::new_session()` must return `SessionInfo` (not just `String`)
3. `open_agent_session()` must accept `SessionOpts` as a parameter (not hardcode None)
4. `executor_nodes.rs` must pass the node's `model` and `thought_level` into `open_agent_session()`
5. `run_prompt_node` and `run_think_node` must forward these fields
6. The `prompt` CLI subcommand should accept optional `--model` flag

## Files to modify
- `crates/maenifold-core/src/acp/native.rs` — `handle_new_session` returns richer type
- `crates/maenifold-core/src/workflow/agent_session.rs` — accept `SessionOpts` param
- `crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs` — pass node config through
- `crates/maenifold-core/src/cli/handlers.rs` — optional `--model` on `prompt`

## SWE Remediation

- What changed
  - `crates/maenifold-core/src/acp/native.rs`
    - Added public `SessionInfo` to preserve ACP `new_session` metadata.
    - Changed `handle_new_session()` and `AgentHandle::new_session()` to return `SessionInfo`.
    - Updated internal command plumbing and `AcpxDriver::create_session()` to consume `session_id` from `SessionInfo`.
  - `crates/maenifold-core/src/workflow/agent_session.rs`
    - Changed `open_agent_session()` to accept `SessionOpts` from callers instead of hardcoding all session config fields to `None`.
  - `crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs`
    - Forwarded prompt-node and sequential-thinking-node `model`, `thought_level`, `allowed_tools`, and `max_turns` into ACP session creation.
  - `crates/maenifold-core/src/workflow/runner.rs`
    - Updated workflow-owned ACP sessions and workflow-triggered think sessions to pass explicit default `SessionOpts`.
  - `crates/maenifold-core/src/workflow/think_runner.rs`
    - Threaded `SessionOpts` through think-session execution so pipeline sequential-thinking nodes can reach ACP session creation unchanged.
  - `crates/maenifold-core/src/cli/handlers.rs`
    - Added optional `--model` parsing for `maenifold prompt`.
    - Updated prompt-session creation to pass the selected model into ACP session startup.
  - `crates/maenifold-core/src/cli.rs`
    - Updated help text for the prompt command to document `[--model <model>]`.

- Test results
  - PASS — `cargo test -p maenifold-core --lib -- --nocapture 2>&1 | tail -10`
  - PASS — `cargo build -p maenifold-core 2>&1 | tail -10`
  - PASS — `cargo run -p maenifold-cli -- prompt OpenCode "hello" --model gpt-4.1 2>&1 | tail -10`

- Notes
  - `SessionInfo` stores advertised ACP mode/model/config lists as concrete vectors (`available_modes`, `available_models`, `config_options`) so callers keep the response metadata without needing raw ACP response structs.
  - Non-pipeline workflow/think paths still use explicit default `SessionOpts` so behavior remains unchanged outside the new passthrough paths.

- **AC-4** `executor_nodes.rs` passes node `model` and `thought_level` into `open_agent_session()`: ✅ `crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs` — both `PipelineNode::Prompt` and `PipelineNode::SequentialThinking` arms destructure `model`, `thought_level`, `allowed_tools`, `max_turns` and build a full `SessionOpts` with these values.
- **AC-5** `run_prompt_node` and `run_think_node` forward these fields: ✅ `executor_nodes.rs` — `run_prompt_node` receives and passes `session_opts: SessionOpts` to `open_agent_session`; `run_think_with_pool` in `think_runner.rs` accepts `session_opts: SessionOpts` and threads it through `drive_think_session` → `open_agent_session`.
- **AC-6** `prompt` CLI subcommand accepts optional `--model` flag: ✅ `crates/maenifold-core/src/cli/handlers.rs` — `run_prompt_command` parses both `--model <value>` and `--model=<value>` forms; passes the value into `SessionOpts { model: model.clone(), .. }` on session creation. **Observations (non-blocking):**
- `AcpxDriver::create_session()` in `native.rs` still hardcodes `None` for all `SessionOpts` fields. This is intentional — the acpx driver is a standalone path not part of the pipeline, and the spec does not require its config passthrough.
- `runner.rs` workflow and think paths outside the pipeline still use default `SessionOpts { model: None, .. }`. This is explicitly called out in the SWE notes as intended behaviour.
