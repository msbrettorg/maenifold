# T-69.7 — Wire AgentConfig.config_options to session/set_config_option

**Requirement**: FR-52
**Component**: crates/maenifold-core/src/acp/native/session.rs, crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs

## Problem

`AgentConfig.config_options` is accepted in the pipeline schema and preserved in wire format, but the `Map<String, Value>` is logged with a warning and **silently discarded** in `executor_nodes.rs`. Users who pass custom agent-specific configuration options get no error, no effect — silent data loss.

The ACP SDK provides `set_config_option(conn, sid, config_id, value)` for each key-value pair. These must be forwarded.

## Acceptance Criteria

1. `SessionOpts` gains a `config_options: Option<serde_json::Map<String, serde_json::Value>>` field
2. `merged_session_opts` populates `config_options` from `agent_config.config_options`
3. `handle_new_session` iterates `config_options` and calls `set_config_option` for each entry
4. Built-in keys (`thought_level`, `allowed_tools`, `max_turns`) set via `SessionOpts` take precedence over duplicate keys in `config_options`
5. The warning log about config_options being unused is removed
6. Existing session tests pass

## Implementation Notes

- Add `config_options` to `SessionOpts` in `types.rs`
- In `executor_nodes.rs`, remove the warning and populate the field
- In `session.rs`, after the existing `set_option` calls for thought_level/allowed_tools/max_turns, iterate remaining config_options and call `set_option` for each
- Skip keys already handled by built-in fields to avoid double-setting
- Values should be serialized as JSON strings for the ACP wire format
