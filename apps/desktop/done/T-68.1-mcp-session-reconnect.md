# T-68.1 — MCP Session Auto-Reconnect

**Requirement:** FR-40, FR-41
**Component:** `src/composables/useMcpClient.ts`, `src/composables/usePipelineMcp.ts`

## Problem

The MCP client connects to the maenifold MCP server via Streamable HTTP. On `initialize`, the server returns an `Mcp-Session-Id` header which must be sent on all subsequent requests. When the server restarts or the session expires (via `LocalSessionManager` cleanup), the server returns HTTP 404 for the stale session ID. The client has zero recovery — polling silently fails forever, pending requests hang until timeout, and `connected` stays `true`.

## Acceptance Criteria

### 1. Session expiry detection and auto-reconnect in `useMcpClient.ts`

- When `jsonRpc()` receives HTTP 404, treat it as session-expired (not a permanent error)
- Automatically re-run the `initialize` → `notifications/initialized` handshake to get a new `Mcp-Session-Id`
- Retry the original request with the new session ID
- Gate reconnection with a mutex/lock so concurrent 404s trigger only ONE reconnect attempt (others wait for it)
- Cap retry at 1 reconnection attempt per failed request — if reconnect itself fails, propagate the error
- Expose reactive state: `connected` (boolean), `reconnecting` (boolean), `error` (string | null)
- Set `connected = false` and `reconnecting = true` during reconnection; restore on success

### 2. Polling resilience in `usePipelineMcp.ts`

- When `startPolling()` catches an error from a poll cycle, check if the MCP client is reconnecting
- If reconnecting: skip the current poll cycle (do not log warn spam), resume on next interval after reconnection succeeds
- If not reconnecting and error persists for 3 consecutive cycles: stop polling and set an error state
- After successful reconnection, polling resumes automatically on the next interval tick

### 3. What NOT to do

- Do NOT add a periodic heartbeat/ping — the MCP Streamable HTTP spec does not define one
- Do NOT add exponential backoff on the polling interval — keep it simple, 3s fixed interval
- Do NOT change the polling interval or add jitter
- Do NOT modify the Rust backend (`src-tauri/`)
- Do NOT touch ACP/agent connection code — this is exclusively about the MCP HTTP transport
