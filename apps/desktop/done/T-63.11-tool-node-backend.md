# T-63.11 — Backend: Tool Node Type

**Requirement**: FR-4
**Test Cases**: TC-11, TC-12
**Repo**: maenifold-rs
**Component**: crates/maenifold-core/src/workflow/pipeline/types.rs, executor.rs, dispatch.rs, view.rs, handler.rs

## Context

Users need to invoke maenifold tools directly from pipeline nodes (e.g., `adopt`, `readmemory`, `buildcontext`, `searchmemories`). This requires a new `Tool` node type that calls MCP `tools/call` with a specified tool name and arguments.

## Acceptance Criteria

1. Add `PipelineNode::Tool` variant to the enum in types.rs:
   - `id: String` (required)
   - `tool_name: String` (required) — the MCP tool name to invoke
   - `tool_args: Option<serde_json::Value>` — JSON object of tool arguments
   - `agent: String` (required) — which agent/server to invoke the tool on
2. Wire format: `{ "type": "tool", "id": "...", "toolName": "...", "toolArgs": {...}, "agent": "..." }`
3. Add `PipelineNodeKind::Tool` to the kind enum
4. Executor: when dispatching a Tool node, invoke `tools/call` on the specified agent with `tool_name` and `tool_args`. Capture the result text as `node.output`.
5. Handler validation: `tool_name` is non-empty, `agent` exists (if validation from T-63.8 is available)
6. View: include all Tool fields in view response
7. Dispatch: include `type: "tool"` and `toolName`/`toolArgs` in dispatch response
8. ALL existing pipeline tests pass: `cargo test -p maenifold-core -- pipeline`
9. Add tests:
   - Deserialize Tool node from JSON → correct fields
   - Serialize Tool node → correct wire format
   - Handler rejects Tool node with empty `tool_name`
