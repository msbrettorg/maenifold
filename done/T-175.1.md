# T-175.1 — Pipelines: fix edge routing spaghetti

**Pipeline**: sdd
**State**: pending

## Context

`PipelineView` renders a Vue Flow graph with ELK orthogonal routing (with smoothstep fallback). When a single source node fans out to ≥4 siblings (real example: `Verify Hub Connectivity` → 7+ tool nodes in an `ftk-analysis-*` pipeline), edges stack on the same horizontal lane and overlap into an unreadable bus. Each overlap fires the orange `⚠️` edge-indicator badge, so the canvas reads as "broken pipeline" when it is actually working.

Repo: `/Users/brett/src/ma-collective/maenifold-rs`
Renderer: Vue Flow 1.x with `@vue-flow/core` smoothstep + ELK absolute routing.

## Acceptance Criteria

- Fan-out of N≥4 sibling targets from one source produces N visually distinguishable edges — no stacked horizontal segments along a single y-coordinate.
- The orange `⚠️` overlap badge no longer appears on the `ftk-analysis-1776364990723` pipeline (use `Pipeline {sessionId, view: true}` MCP call to load it).
- ELK routing options (`spacing.edgeNode`, `spacing.edgeEdge`, `layered.spacing.edgeNodeBetweenLayers`, `layered.crossingMinimization.semiInteractive`) are tuned, OR the per-edge `edgePath()` adds source-port lane offsets (e.g. fan-out spread by source-handle index).
- Smoothstep fallback path (when ELK has no points) also spreads multi-edge fan-outs — currently every edge from same source uses identical `getSmoothStepPath` args.
- LR and TB layouts both clean — verify with the `Layout LR` / `Layout TB` toolbar buttons.
- No regression on small pipelines (single-source single-target; 2-target fan-out — already render fine).
- Build passes: `cd apps/desktop && pnpm build`.
