# T-218.41 — Desktop Design Token Contrast Audit

## Problem

Multiple desktop surfaces show [[contrast]] failures and ad-hoc color styling that do not match `apps/desktop/DESIGN.md`. The Gate Progress column is one visible example, but the risk is systemic [[design-token-drift]]: if components use raw colors, arbitrary Tailwind values, component-local styling, or semantic colors as decoration, the [[desktop-ui]] will keep drifting away from the [[Fluent 2]] dark design system.

This task must audit the desktop UI for contrast and color-token drift, then remediate the findings through the design system rather than local one-off fixes.

## Evidence

- User screenshot: Gate Progress column badges are low-contrast blue-on-dark.
- `apps/desktop/DESIGN.md` requires:
  - Tailwind utility classes mapped to `@theme` tokens.
  - No component-local color hacks.
  - No component hex literals.
  - No component-local border declarations.
  - Semantic color only for state or intent, not decoration.
- `npm run lint:design` currently passes only its configured scope; this does not prove the full packaged UI is visually compliant.

## Scope

Audit all currently reachable packaged desktop surfaces under the Gate, Knowledge, MCP Apps, Teams, Schedules, Sessions, and Pipeline views. Remediation is limited to files and shared primitives that render those surfaces. Do not expand into unused experiments or unrelated components unless they are imported by those views.

Special attention:

- Gate tab tables, chips, progress/status badges, selected rows, and detail panes.
- Knowledge tab note/sidebar/content surfaces.
- MCP Apps, Teams, Schedules, Sessions, and Pipeline views where status chips, badges, cards, or table rows encode state.
- Shared badge/chip/table/status components that could fix multiple surfaces at once.
- `apps/desktop/src/assets/tailwind.css` token coverage where a missing token or inconsistent token name is causing repeated component-level hacks.

## Sequencing

`T-218.40` lands first. Its Gate Progress column fix becomes the canonical local pattern this broader audit propagates; deviations require justification in the inventory.

## Acceptance Criteria

- [ ] Before remediation, produce an audit inventory at `outputs/audits/T-218.41-token-contrast-inventory.md` with one row per finding: UI surface, file path, component/shared primitive, current class or token usage, violated `apps/desktop/DESIGN.md` rule, measured foreground/background, contrast ratio, proposed replacement token or shared primitive, and whether the issue is contrast, token drift, or both.
- [ ] Every audited non-disabled text, icon, badge, chip, and stateful UI boundary meets WCAG 2.1 AA in the default dark theme: 4.5:1 for normal text and 3:1 for large text and non-text UI components/boundaries. The only exception is intentionally inactive/disabled state that uses `textDisabled`, matching the `apps/desktop/DESIGN.md` inactive-component carve-out.
- [ ] Contrast ratios are measured against rendered packaged Electron DOM computed styles, including default state plus hover/focus and selected-row/active states where applicable. Token-value-only reasoning is not sufficient.
- [ ] Replace component-level color hacks with semantic Tailwind token utilities backed by `apps/desktop/src/assets/tailwind.css`.
- [ ] Verify every `apps/desktop/DESIGN.md` token used by audited surfaces has a corresponding `@theme` utility in `apps/desktop/src/assets/tailwind.css`, including `bgApp`, `bgSidebar`, `bgSurface`, `bgSurfaceHover`, `bgElevated`, `bgOverlay`, `borderSubtle`, `borderCard`, `textPrimary`, `textSecondary`, `textTertiary`, `textDisabled`, `brand`, `brandHover`, `brandLight`, `success`, `warning`, `danger`, `thinking`, `shadow8`, `shadow16`, `shadow64`, `r4`, `r8`, and `r12`.
- [ ] Add missing design tokens to `@theme` only when the existing token set cannot express the intended semantic state, using canonical names that map back to `apps/desktop/DESIGN.md`.
- [ ] Do not introduce raw hex literals, arbitrary one-off color values, `var()` usage in components, `color-mix()` in components, `<style>` blocks, companion CSS, or `audit-ok`.
- [ ] Do not introduce hardcoded Tailwind palette color classes such as `bg-blue-*`, `text-blue-*`, `border-blue-*`, `bg-gray-*`, `text-gray-*`, or similar palette shortcuts in audited surfaces unless they already resolve to the design-system token layer.
- [ ] Preserve semantic color meaning from `apps/desktop/DESIGN.md`: `brand` for focus/primary/selected, `success` for completed/healthy, `warning` for attention/in-progress, `danger` for failure/destructive, `thinking` for processing, `textSecondary` / `textTertiary` for neutral metadata, and `borderSubtle` / `borderCard` for neutral structure.
- [ ] When multiple views share badge/chip/status/table styling, remediate through existing [[shadcn-vue]] primitives or shared desktop UI wrappers rather than per-view bespoke controls or duplicated class recipes.
- [ ] Any raw HTML control (`<button>`, `<input>`, `<select>`, `<table>`, `<progress>`) discovered in an audited surface is replaced with the [[shadcn-vue]] equivalent. If no shadcn-vue primitive exists, escalate before substituting a hand-rolled component.
- [ ] Extend `lint:design` and/or `audit:components` to catch at least one drift class observed in the inventory, such as hardcoded Tailwind palette classes on badges/status chips or raw color attributes on shared badge variants. If a drift class cannot be statically detected, file and link a separate gate task from the inventory before this task passes blue-team.
- [ ] `npm run lint:design` passes.
- [ ] `npm run audit:components` passes.
- [ ] Packaged Electron CDP verification with `agent-browser` captures, at minimum, Gate status/progress badges and selected row, Knowledge sidebar/content surfaces, Sessions or Pipeline status table/chips, and one MCP Apps/Teams/Schedules stateful surface. Captures must cover default, hover/focus where applicable, and selected-row/active-state rendering in the packaged app.
- [ ] CDP evidence screenshots are saved under `outputs/screenshots/sprint-218/T-218.41/` and referenced from the inventory.
