## Problem

90 components have `<style>` blocks because tokens aren't exposed via Tailwind `@theme`. Components CANNOT be pure Tailwind until this is fixed. Blocks ALL of T-03.2 through T-03.16.

## Missing from @theme

- `--color-status-*` (pending, active, completed, abandoned, stuck, ready, error) — 34 files
- `--color-node-*` (prompt, workflow, thinking, tool) — 12 files
- `color-mix()` variants at 6%, 8%, 10%, 15%, 20%, 32% opacity — 51 files

## Solution

1. Add ALL `--color-status-*` to `@theme`
2. Add ALL `--color-node-*` to `@theme`
3. Pre-compute ALL `color-mix()` variants as `@theme` tokens
4. Audit every `var(--*)` in components — each needs a Tailwind utility
5. Update `audit:components` to reject ANY `<style>` block (zero tolerance)

## Acceptance Criteria

- Every CSS custom property used in any .vue file has a Tailwind utility via `@theme`
- `grep -r 'color-mix' --include='*.vue' src/components/` returns zero (only in tailwind.css)
- `npm run audit:components` enforces zero `<style>` blocks
- `npx vue-tsc --noEmit && npm run build` passes
