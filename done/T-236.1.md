## Regression

Two confirmed instances of direct tool calls reaching the backend instead of routing through `GatewayExecute`:

```
MCP error -32602: Tool 'GetConfig' is routed under domain 'maenifold.system'.
Use GatewayExecute with domain='maenifold.system', command='GetConfig'.

MCP error -32602: Tool 'Pipeline' is routed under domain 'maenifold.workflow'.
Use GatewayExecute with domain='maenifold.workflow', command='Pipeline'.

MCP error -32602: Tool 'ListMemories' is routed under domain 'maenifold.memory'.
Use GatewayExecute with domain='maenifold.memory', command='ListMemories'.
```

These were previously fixed by T-235.1. They have returned. The fix was incomplete — one or more call sites bypass the gateway routing path.

## Requirement

**The frontend must never call a domain-routed tool directly.** Every tool call must go through the routing layer in `mcpClientOps.ts`. If the tool appears in the `GatewayIndex` domain map, it is dispatched via `GatewayExecute` with the correct `domain` and `command`. No exceptions.

Only the explicit passthrough set (`GetHelp`, `ReadMcpResource`, `GatewayExecute`, `GatewayIndex`) bypasses this routing.

## Failure scope

- `apps/desktop/src/composables/mcpClientOps.ts` — routing logic from T-235.1 has a gap
- Likely: a call site that uses `callTool` directly without going through the routing wrapper, or the domain map not being populated before the call
