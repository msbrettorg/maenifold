## Problem

The gate MCP resource `gate://status` returns `"title": "T-05.66"` (just the taskId) instead of the actual YAML frontmatter title `"Pipeline tab: can't delete pipelines, cancel draft, or continue"`. The gate CLI `gate status --json` returns the correct title.

This causes the Gate tab's task table to show taskId in both the "Task ID" and "Task" columns.

## Reproduction

```bash
# CLI — correct:
gate status --root . --json | jq '.[] | select(.taskId == "T-05.66") | .title'
# → "Pipeline tab: can't delete pipelines, cancel draft, or continue"

# MCP resource — wrong:
curl -s http://localhost:8080/mcp ... gate://status | jq ... T-05.66 .title
# → "T-05.66"
```

## Root cause

The gate MCP resource handler in `crates/maenifold-core/src/mcp/resources/gate_status.rs` (or equivalent) is likely reading the title from the filename or DB cache instead of parsing the YAML frontmatter. The `.gate/gate.db` cache may have stale titles from before the frontmatter was added.

## Fix

1. Run `gate sync --rebuild` to repopulate the DB cache with correct titles
2. If that fixes it, the bug is that sync wasn't called after task creation
3. If not, the resource handler has a different title extraction path from the CLI

## Acceptance Criteria

- `gate://status` returns full YAML frontmatter title for all tasks
- Gate tab shows actual task titles, not taskIds
- Verified in packaged Electron app
