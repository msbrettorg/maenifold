## Problem

`maenifold tool AcpExec '{"agent":"Codex",...}'` returns:
```
Error invoking AcpExec: [codex-cli] Agent command not found. Check maenifold.json.
```

The Codex agent IS configured in `~/maenifold/maenifold.json`:
```json
"Codex": {
  "command": "/Users/brett/.npm-global/lib/node_modules/@zed-industries/codex-acp/.../bin/codex-acp"
}
```

The binary exists and runs correctly when invoked directly. The maenifold daemon was restarted. The error comes from `crates/maenifold-jockey/src/acp/adapter.rs` which maps several upstream errors to this message.

## Root cause hypothesis

The adapter error classification in `adapter.rs:187-191` catches "binary not found", "adapter unavailable", or "not found in maenifold.json". The actual upstream error needs to be surfaced — the current code masks it. The daemon may be spawning the process but it exits immediately, or the agent lookup is case-sensitive when it shouldn't be.

## Files

- `crates/maenifold-jockey/src/acp/adapter.rs` — error classification + agent lookup
- `crates/maenifold-jockey/src/acp/session/execute_stream.rs` — stream error handling

## Acceptance Criteria

1. `maenifold tool AcpExec '{"agent":"Codex","autoGrantPermissions":true,"prompt":"hello"}'` succeeds
2. Error messages include the actual upstream error, not a generic "not found"
3. Agent lookup is case-insensitive (already should be per line 22)
