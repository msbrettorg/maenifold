# T-238.33 — ACP file I/O TOCTOU race requires platform-level mitigation

## Problem

T-238.30 red-team identified a TOCTOU race in ACP `readTextFile`/`writeTextFile` where an attacker who can mutate ancestor directories under `memory/` can race between path validation and file I/O. The post-open revalidation is path-based and non-atomic.

Node.js does not expose `openat(2)`-style directory-fd-relative traversal, so a fully race-free solution requires either native addon or architectural change (e.g., brokered writes through a memory API instead of direct filesystem I/O).

## Accepted residual risk

Same-user local attacker with write access to `memory/` subdirectories. Documented in code comments. Mitigated by:
- O_NOFOLLOW on final component
- Post-open stat/realpath revalidation (imperfect but raises the bar)
- Write restricted to memory/ with extension policy

## Acceptance criteria

- [ ] Research platform-level options: native addon with openat, Rust helper via napi, or brokered write API
- [ ] Implement race-free write path or document why the residual risk is acceptable long-term
- [ ] Red-team re-audit confirms the race is eliminated or formally accepted
