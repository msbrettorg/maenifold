# T-238.31 — Backend accepts but ignores parameters across multiple tools

## Problem

Multiple backend tools accept parameters in their schemas that are silently ignored in the implementation. This violates "mechanism not policy" — users/agents believe they're configuring behavior that does nothing.

Known phantom parameters:

- `idempotencyKey` on GatewayExecute/GatewayBatch — accepted, never checked
- `analysis_type` on SequentialThinking — accepted, never used
- `branchFromThought` on SequentialThinking — accepted, branching not implemented
- Consolidation thresholds in gateway settings — accepted, never applied
- Schedule fields — accepted, scheduler not wired

## Evidence

Red-team finding from sprint 238 wave audit.

## Acceptance criteria

- [ ] Every parameter in a tool schema either has a working implementation or is removed from the schema.
- [ ] No parameter is silently accepted and ignored.
- [ ] If a feature is not yet implemented, the parameter must not be advertised in the schema.

## Verification

- Audit each listed parameter against its implementation path.
- For each: either verify it affects behavior, or remove from schema.
