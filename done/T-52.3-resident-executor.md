# T-52.3 — Resident Pipeline Executor (Subprocess Supervisor)

**Requirement**: FR-40 (Pipeline Active Executor)
**Component**: `crates/maenifold-core/src/workflow/pipeline/handler.rs`, `crates/maenifold-core/src/workflow/pipeline/supervisor.rs`

## Context

Today `Pipeline { run: true }` is a schema placeholder with no backend. The architecture calls for a **resident-executor/supervisor** pattern: the Pipeline MCP tool spawns `maenifold-acp pipeline <session-id> <prompt>` as a supervised child process. Maenifold tracks the PID, monitors health, and handles restart on crash.

This is the [[agent-runtime]] primitive surfacing through the Pipeline tool — the system owns session lifecycle end-to-end. The bash script is the stateless worker; maenifold is the durable supervisor.

From `memory://build/specs/agent-runtime-primitive-reframing`:
> *"A persistent resident-executor or supervisor with scoped, disposable worker sessions per workflow-run, pipeline-node, or reasoning scope."*

## Acceptance Criteria

### Supervisor Module

1. Create `crates/maenifold-core/src/workflow/pipeline/supervisor.rs`
2. Implement `PipelineSupervisor`:
   - `active_runs: HashMap<String, RunHandle>` — maps session_id → running process
   - `RunHandle { pid: u32, child: tokio::process::Child, started_at: DateTime }`
3. Process-global singleton (same pattern as watcher):
   ```rust
   static SUPERVISOR: Lazy<Mutex<PipelineSupervisor>> = ...
   ```

### Run Operation

4. `Pipeline { sessionId, run: true, prompt }` handler:
   - Validates pipeline exists and is not already running (check supervisor + node states)
   - Spawns `maenifold-acp pipeline <session-id> <prompt>` via `tokio::process::Command`
   - `.current_dir(context.root())` for correct working directory
   - `.kill_on_drop(true)` safety net
   - Registers `RunHandle` in supervisor
   - Returns immediately with `{ status: "started", pid: N }`
   - Does NOT block on completion — fire and observe

### Health Monitoring

5. Supervisor spawns a background task per run that:
   - `child.wait()` for process exit
   - On exit code 0: log success, remove from active_runs
   - On non-zero exit: check pipeline state in graph
     - If all nodes terminal → log completion, remove
     - If nodes still pending/active → increment attempt counter, restart process (up to 3 attempts)
     - On max retries exhausted → log failure, set pipeline status to `stuck`, remove
   - On crash (signal): same as non-zero exit

### Pause / Resume / Cancel

6. `Pipeline { sessionId, pause: true }`:
   - Send SIGSTOP to the process (via `kill -STOP pid`)
   - Update pipeline frontmatter to `status: paused`
7. `Pipeline { sessionId, resume: true }`:
   - Send SIGCONT to the process (via `kill -CONT pid`)
   - Update pipeline frontmatter to `status: active`
   - If process is dead (crashed while paused): restart it
8. `Pipeline { sessionId, cancel: true }`:
   - Send SIGTERM to the process
   - Wait up to 5s, then SIGKILL if still alive
   - Update pipeline frontmatter to `status: cancelled`
   - Remove from active_runs

### Status Query

9. `Pipeline { sessionId, view: true }` already works — enhance with:
   - `running: bool` — is there an active supervisor process?
   - `pid: Option<u32>` — current process ID
   - `attempts: u32` — restart count

### Crash Recovery on Startup

10. On maenifold startup (when supervisor initializes):
    - Scan pipeline sessions with `status: active` in frontmatter
    - Check if any have non-terminal nodes
    - These are orphaned runs from a previous crash
    - Log them as `stuck` — do NOT auto-restart (user must explicitly `run` again)

## Design Constraints

- The supervisor is process-internal state (not persisted). On maenifold restart, all RunHandles are gone — that's fine because the script is stateless and the graph has the truth.
- The `maenifold-acp` script calls back into maenifold via `maenifold --tool Pipeline` CLI — this is a child process calling a DIFFERENT maenifold instance (the CLI spawns its own). No circular dependency.
- SIGSTOP/SIGCONT for pause/resume is Unix-only. On non-Unix: return error "pause not supported on this platform".

## Scoped Tests

```bash
cargo test -p maenifold-core --lib pipeline_supervisor -- --nocapture
```

Write tests using mock processes (e.g., `sleep 10` as a stand-in):
- Run spawns process, registers in supervisor, returns pid

- Cancel sends signal, removes from supervisor
- Status shows running/pid when active
- Process exit cleans up supervisor state
