# T-238.49 — P0 Add Trouter re-registration loop to prevent silent message loss

**Pipeline**: sdd

## Problem

The Trouter registration TTL is 3600s (1 hour). Without proactive renewal, messages are silently dropped between TTL expiry and the next server-initiated `trouter.reconnect` event (up to 20+ minutes). The agency-cowork reference re-registers at 45-minute intervals.

## Reference

- agency-cowork: `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/trouter_client.py` L396-411 `_reregistration_loop()`
- Rust target: `crates/maenifold-core/src/teams/trouter.rs`

## Required changes

Port the re-registration loop from the Python reference:
- Add a `tokio::time::interval(Duration::from_secs(45 * 60))` loop in `listen()` or as a parallel task
- Call `register()` on each tick to refresh the registration before TTL expires
- Log re-registration success/failure

## Acceptance Criteria

- [ ] `TrouterClient::register()` exposed as public method callable by the token-refresh loop (T-238.50)
- [ ] Re-registration failure logs an error but does not crash the connection
