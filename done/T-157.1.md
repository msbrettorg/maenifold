# T-157.1 — Fix flaky stdio MCP discovery timeout

## Problem

`DEFAULT_DISCOVERY_TIMEOUT` in `crates/maenifold-core/src/api/mcp_discovery.rs:12` is hardcoded to 10 seconds. Stdio servers that do network I/O on startup (e.g., `npx -y @azure/mcp@latest` checks the npm registry) flake under slow network conditions. This caused azure-mcp-server to silently fail on 2026-04-14.

## Fix

1. Change `DEFAULT_DISCOVERY_TIMEOUT` from 10s to 60s
2. Add optional `timeout` field (seconds) to `McpServerEntry::Stdio` in `crates/maenifold-core/src/acp/config.rs`
3. `discover_all_mcp_tools` reads per-server timeout, falls back to 60s default

## Schema Change

```json
{
  "name": "azure-mcp-server",
  "type": "stdio",
  "command": "/opt/homebrew/bin/npx",
  "args": ["-y", "@azure/mcp@latest", "server", "start"],
  "timeout": 30
}
```

## Files

- `crates/maenifold-core/src/api/mcp_discovery.rs` — change constant, pass per-server timeout
- `crates/maenifold-core/src/acp/config.rs` — add `timeout: Option<u64>` to `McpServerEntry::Stdio`

## Acceptance Criteria

1. Default discovery timeout is 60s
2. Per-server `timeout` field in maenifold.json overrides the default
3. Existing configs without `timeout` field continue to work (serde default)
4. `cargo build --release -p maenifold-cli` succeeds
