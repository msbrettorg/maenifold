# T-69.4 — Graft Guard: Check Active Nodes Not Frontmatter Status

**Requirement**: FR-45
**Component**: crates/maenifold-core/src/workflow/pipeline/handler_surgery_graft.rs

## Problem

The graft precondition guard checks `frontmatter.status == "active"` to reject graft operations. But a pipeline can have `status: "active"` with zero actually-active nodes (e.g., all nodes completed or abandoned, but the pipeline hasn't been explicitly marked completed/cancelled). This prevents grafting onto pipelines that have no running work — a core use case for extending partially-completed pipelines.

Smoke test failures: ST-4 TC-4.7 (graft onto abandoned pipeline), TC-4.8 (graft with pending downstream nodes). ST-2 also independently confirmed the same guard bug blocks delete on completed pipelines.

## Acceptance Criteria

1. Graft is allowed when no nodes are in `Active` status, regardless of frontmatter status
2. Graft is rejected when any node IS in `Active` status
3. Graft onto a pipeline with all nodes Completed succeeds
4. Graft onto a pipeline with some nodes Abandoned (none Active) succeeds
5. Graft onto a pipeline with Active nodes is rejected with clear error
6. Existing graft tests pass
7. Add test: graft onto completed pipeline
8. Add test: graft onto pipeline with abandoned nodes

## Implementation Notes

- The guard in `handler_surgery_graft.rs` (~line 35-59) needs to check actual node states, not frontmatter status
- Replace `running_frontmatter` check with: count nodes with `status == Active`
- If `active_count > 0`, reject. Otherwise allow.
- The same pattern may affect delete guard in `handler_crud.rs` — verify and fix if so
