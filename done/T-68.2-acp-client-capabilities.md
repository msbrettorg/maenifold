# T-68.2: Declare Client Capabilities in ACP Handshake

## Requirement
FR-50 — Native ACP client must advertise its capabilities so agents can use them.

## Problem
`native.rs` sends `InitializeRequest` with default (empty) `ClientCapabilities`:
- `fs.read_text_file = false`, `fs.write_text_file = false`
- `terminal = false`

This tells agents we can't do anything. Agents that want to read files, write files, or run terminal commands won't even try. The pipeline-ui advertises full capabilities.

## Acceptance Criteria
1. `InitializeRequest` must declare `ClientCapabilities` with `fs.read_text_file = true` and `fs.write_text_file = true`
2. `HeadlessClient` must implement `read_text_file` — read from cwd-relative path and return content
3. `HeadlessClient` must implement `write_text_file` — write to cwd-relative path (with safety: no writes outside cwd)
4. `terminal = false` is correct for headless — keep it false
5. Document which capabilities are advertised in code comments

## Files to modify
- `crates/maenifold-core/src/acp/native.rs` — ClientCapabilities, Client trait methods

## Reference
- `../pipeline-ui/src/composables/useSessionBootstrap.ts` → `clientCapabilities` object
- `agent-client-protocol` types: `ClientCapabilities`, `FileSystemCapabilities`
