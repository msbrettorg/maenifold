## Compliant Patterns Verified

The following patterns were checked and found **compliant**:

1. **`var()` in `:style` bindings** — `App.vue:234–239` and `Sonner.vue:37–40` use `:style` dynamic bindings to configure third-party Sonner toast CSS custom properties. DESIGN.md §10 explicitly permits dynamic `:style` bindings.

2. **`var()` in Tailwind arbitrary values** — Multiple `ui/` components use `bg-[var(--color-bg-elevated)]`, `text-[var(--foreground)]`, etc. These are Tailwind utility classes referencing `@theme` tokens — the approved pattern.

3. **Shadow literals in Tailwind arbitrary values** — `shadow-[0_8px_16px_rgba(0,0,0,0.28),...]` in tooltip, dialog, dropdown, and context menu components. These match `shadow16` / `shadow64` token values and are expressed as Tailwind utilities.

4. **No companion `.css` files** imported by components.
5. **No `audit-ok` waivers** anywhere in `src/`.
6. **No `@keyframes` in components.**
7. **No `:deep()` selectors in production components.**

## Recommendations

### Remediation Required: 1 task, small scope

**Scope:** 2 files, 4 code locations, ~10 class substitutions.

**Task breakdown:**

1. **ChatToolCallDetails.vue** — Add diff-highlighting semantic tokens to `tailwind.css` `@theme` block:
   - `--color-diff-header` (sky/info tone — consider mapping to `brand` or a new `info` token)
   - `--color-diff-add` (map to `success` token `#0E9C57`)
   - `--color-diff-remove` (map to `danger` token `#D13438`)
   - Replace `text-sky-600 dark:text-sky-400` → `text-diff-header`
   - Replace `text-emerald-600 dark:text-emerald-400` → `text-diff-add` (or `text-success`)
   - Replace `text-red-600 dark:text-red-400` → `text-diff-remove` (or `text-danger`)

2. **SettingsMaenifold.vue** — Replace emerald palette → success semantic tokens:
   - `border-emerald-500/40` → `border-success/40`
   - `bg-emerald-500/10` → `bg-success/10`
   - `text-emerald-600 dark:text-emerald-300` → `text-success`

3. **AppTabBar.vue** — Replace `console.error` with structured logger (lower priority).

**Estimated effort:** ~30 minutes SWE time, including token additions to `tailwind.css`.

**Risk:** Low. Changes are cosmetic token substitutions with no behavioral impact. The emerald→success swap may produce a slightly different green shade (`#0E9C57` vs `#10b981`); visual review recommended.

## Methodology

1. Read `apps/desktop/DESIGN.md` for normative token definitions and component rules.
2. Ran `npm run lint:design` (passed) and `npm run audit:components` (passed) — existing CI-grade linting.
3. Searched all `.vue` files under `apps/desktop/src/` using ripgrep for:
   - Hardcoded palette classes: `(bg|text|border)-{color}-{number}` across 24 Tailwind color families
   - Hex color literals: `#[0-9a-fA-F]{3,8}`
   - Inline style color values: `style=` with `color:`/`background:`/`background-color:`/`border-color:`
   - Dynamic style color bindings: `:style=` with color properties
   - `<style>` blocks in any `.vue` file
   - `color-mix()` in components
   - `var(--` references (to distinguish approved Tailwind arbitrary values from banned raw CSS)
   - `audit-ok` escape hatch comments
   - `console.log/warn/error` statements
4. Cross-referenced each finding against DESIGN.md §2 (Tokens), §7 (Color Roles), and §10 (Component Conventions).
5. Excluded `__tests__/evidence/` as non-production test fixtures.
