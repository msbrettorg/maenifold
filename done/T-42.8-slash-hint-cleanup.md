# T-42.8: Slash Command Hint & Cleanup

**Requirement**: FR-42.8, FR-42.10 (listener leak subset)  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/components/ChatView.vue`, `vendor/acp-ui/src/components/CommandPalette.vue`, `vendor/acp-ui/src/components/ModePicker.vue`, `vendor/acp-ui/src/components/ModelPicker.vue`

## Acceptance Criteria

1. **Fix `handleCommandSelect` dead code** in `ChatView.vue` (~L88-94):
   The `if (command.hint) / else` branches are identical. Replace with:
   ```ts
   function handleCommandSelect(command: SlashCommand) {
     inputText.value = `/${command.name} `;
     activeCommandHint.value = command.hint ?? null;
   }
   ```
   Add `const activeCommandHint = ref<string | null>(null);`
   Use it as dynamic textarea placeholder:
   ```html
   :placeholder="activeCommandHint ?? 'Type your message...'"
   ```
   Clear when input no longer starts with `/`.

2. **Add hint rendering in CommandPalette.vue**: After the description span, add:
   ```html
   <span v-if="cmd.hint" class="command-hint">{{ cmd.hint }}</span>
   ```
   CSS for `.command-hint` already exists in the file (L143).

3. **Fix event listener leaks**: In `ModePicker.vue`, `ModelPicker.vue`, and the new `ConfigOptionPicker.vue`, wrap the `window.addEventListener('click', handleClickOutside)` in a proper lifecycle:
   ```ts
   import { onMounted, onUnmounted } from 'vue';
   onMounted(() => window.addEventListener('click', handleClickOutside));
   onUnmounted(() => window.removeEventListener('click', handleClickOutside));
   ```
   Remove the bare `if (typeof window !== 'undefined')` block.

## Spec References

- https://agentclientprotocol.com/protocol/slash-commands
- Audit findings: REQ-6 (hint never rendered), REQ-10 (listener leak)

## SWE Remediation

- **What changed**
  - `vendor/acp-ui/src/components/ChatView.vue`: removed the dead duplicate branches in `handleCommandSelect`, added `activeCommandHint`, cleared the hint when input no longer starts with `/`, and wired the textarea placeholder to the active command hint.
  - `vendor/acp-ui/src/components/CommandPalette.vue`: rendered `cmd.hint` inline after the command description using the existing `.command-hint` styling.
  - `vendor/acp-ui/src/components/ModePicker.vue`: moved the outside-click listener registration into `onMounted`/`onUnmounted` to avoid leaking listeners.
  - `vendor/acp-ui/src/components/ModelPicker.vue`: moved the outside-click listener registration into `onMounted`/`onUnmounted` to avoid leaking listeners.

### Criterion 2 — Add hint rendering in `CommandPalette.vue`

✅ Verified at `CommandPalette.vue` L89:
```html
<span v-if="cmd.hint" class="command-hint">{{ cmd.hint }}</span>
```
Placed after the description span inside `.command-row`, exactly as specified.

**Observation (spec assumption, not SWE fault):** The spec states "CSS for `.command-hint` already exists in the file (L143)." That reference points to the compound selected-state rule (`.command-item.selected .command-hint` at L144), which only applies white text when the item is highlighted. There is no standalone base `.command-hint { color: ...; font-size: ...; }` rule for the unselected state — the hint will render but inherit parent text styling, making it visually indistinct from the description. The SWE implemented exactly what was specified; the missing base CSS rule is a gap in the spec's claim, not the implementation.

### Criterion 3 — Fix event listener leaks in `ModePicker.vue`, `ModelPicker.vue`, and `ConfigOptionPicker.vue`

✅ Listener leak fixed in all three files:

- **`ModePicker.vue`** L54–64: `window.addEventListener` moved into `onMounted`; `window.removeEventListener` moved into `onUnmounted`. Leak eliminated. ✅
- **`ModelPicker.vue`** L52–62: Same pattern applied. Leak eliminated. ✅
- **`ConfigOptionPicker.vue`** L119–125: Uses `onMounted`/`onBeforeUnmount` (functionally equivalent to `onUnmounted` for cleanup) with no `typeof window` guard. Already correct; no regression. ✅

**Minor deviation in `ModePicker` and `ModelPicker`:** The spec prescribes:
```ts
onMounted(() => window.addEventListener('click', handleClickOutside));
onUnmounted(() => window.removeEventListener('click', handleClickOutside));
```
and explicitly says "Remove the bare `if (typeof window !== 'undefined')` block." The SWE moved the guard *inside* the lifecycle hooks rather than removing it entirely:
```ts
onMounted(() => {
  if (typeof window !== 'undefined') {
    window.addEventListener('click', handleClickOutside);
  }
});
```
The "bare" top-level block is gone; the guard survives inside lifecycle hooks. This is a spec deviation on a redundant check (`onMounted` never fires in SSR, so the guard is dead code in practice). Harmless, but technically non-compliant with the spec's removal instruction. The SWE's remediation notes also do not mention `ConfigOptionPicker.vue` despite it being in the spec scope — however, the file is already in the correct state, so this is a documentation gap only.
