# T-178.0 — Desktop MCP client — resources/read, subscribe, unsubscribe + notification handling

## Intent

The desktop app at `apps/desktop/src/composables/useMcpClient.ts` currently supports the MCP `tools/call` and `tools/list` surface but does NOT speak any of the `resources/*` methods, nor does it process `notifications/resources/updated`. Sprint 178 pivots the dashboards onto MCP resources as the canonical state-streaming surface. Without a desktop-side resource client, none of the dashboard work in [[T-178.4]] / [[T-178.5*]] can actually consume the new resources.

This task adds the missing primitive. It is purely client-side plumbing — no server changes, no UI changes. It unblocks every downstream dashboard migration.

Reference: https://modelcontextprotocol.io/specification/2025-06-18/server/resources

## Scope

1. **New composable**: `apps/desktop/src/composables/useMcpResources.ts`
   - Sits on top of (or alongside) `useMcpClient`. Reuses the same session, transport, and JSON-RPC machinery — does NOT open a second MCP session.
   - Public API:
     ```ts
     readResource(uri: string): Promise<{ uri: string; mimeType?: string; text?: string; blob?: string }>
     subscribeResource(uri: string, handler: (uri: string) => void): Promise<() => void>  // returns unsubscribe fn
     unsubscribeResource(uri: string): Promise<void>
     listResources(): Promise<ResourceDescriptor[]>
     listResourceTemplates(): Promise<ResourceTemplateDescriptor[]>
     ```
2. **JSON-RPC method support** in the underlying client:
   - `resources/list`
   - `resources/templates/list`
   - `resources/read { uri }`
   - `resources/subscribe { uri }`
   - `resources/unsubscribe { uri }`
3. **Notification handler** for `notifications/resources/updated { uri }`:
   - Parse server-sent notification frames (the streamable-HTTP transport delivers these as SSE-style `text/event-stream` events on the open POST stream).
   - Dispatch to per-URI handler registry. Multiple subscribers per URI are supported (handlers are deduplicated by reference).
   - Notifications for unsubscribed URIs are dropped silently (debug log only).
4. **Session-aware subscription cleanup**:
   - On MCP disconnect / `resetState()`, clear the local subscription registry. Do NOT attempt server-side unsubscribe — the session is gone.
   - On reconnect, the registry starts empty. Components are responsible for re-subscribing (they own the lifetime). Document this contract clearly in the composable's JSDoc.
5. **Error handling**:
   - `readResource` on unknown URI surfaces the JSON-RPC error code/message verbatim to the caller.
   - `subscribeResource` on a server that doesn't advertise `resources.subscribe` (per `initialize` response capabilities) throws a typed error: `McpCapabilityUnsupportedError`. Components can catch and degrade to polling.
6. **Tests** in `apps/desktop/src/composables/__tests__/useMcpResources.test.ts`:
   - Mock MCP client returns a fixture for `resources/read`.
   - Subscribe → simulate inbound `notifications/resources/updated` → handler invoked exactly once with the URI.
   - Two subscribers on the same URI → both handlers invoked.
   - Unsubscribe → handler not invoked on subsequent notifications.
   - Disconnect → registry cleared, subsequent simulated notifications hit no handlers.

## Files in scope

- `apps/desktop/src/composables/useMcpClient.ts` (extend with resources methods + notification dispatch hook)
- `apps/desktop/src/composables/useMcpTransport.ts` (or wherever frame parsing lives — extend to surface notification frames, not just response frames)
- `apps/desktop/src/composables/useMcpResources.ts` (NEW)
- `apps/desktop/src/composables/__tests__/useMcpResources.test.ts` (NEW)

## Acceptance criteria

1. `pnpm --filter desktop test` passes; new tests cover the cases above.
2. `pnpm --filter desktop build` succeeds; `vue-tsc` reports zero errors in new files.
3. `useMcpResources` shares the existing `useMcpClient` session — verified by a test that asserts only one `initialize` call across both composables.
4. Notification frames for `notifications/resources/updated` are parsed and dispatched to registered handlers within the same tick they arrive.
5. Disconnect drops local subscription state; documented behavior on reconnect (re-subscribe is the consumer's responsibility) appears in the composable's JSDoc.
6. Calling `subscribeResource` against a mocked server that omits `resources.subscribe` capability throws `McpCapabilityUnsupportedError`.
