## Summary

New Rust module providing an async client for Azure OpenAI Images API. Supports both `/images/generations` (text-to-image) and `/images/edits` (image editing for continuity mode). Handles rate limiting with 429 retry logic and saves decoded images to the wallpaper cache directory.

## Implementation

### 0. Add `multipart` feature to reqwest

In workspace `Cargo.toml`, update reqwest features:
```toml
reqwest = { version = "0.13", features = ["json", "multipart"] }
```

### 1. Create `crates/maenifold-core/src/wallpaper/image_client.rs`

Async client using `reqwest`:

```rust
pub struct ImageClient {
    endpoint: String,
    api_key: String,
    image_model: String,
    max_retries: u32,
    http: reqwest::Client,
}
```

**Methods:**

- `ImageClient::new(endpoint, api_key, image_model, max_retries)` — constructor
- `ImageClient::from_config(settings: &WallpaperSettings) -> anyhow::Result<Self>` — reads env vars by name from `settings.azure.endpoint_env_var` and `settings.azure.api_key_env_var` using `std::env::var()`. Returns clear error with the env var name if not set. Uses `settings.azure.image_model` for the model deployment name.
- `generate(&self, prompt: &str, size: &str, quality: &str) -> anyhow::Result<Vec<u8>>` — POST to `{endpoint}/openai/deployments/{image_model}/images/generations?api-version=2025-04-01-preview`. Headers: `api-key: {api_key}`, `Content-Type: application/json`. Body: `{ "prompt": ..., "size": ..., "quality": ..., "n": 1 }`. Do NOT include `response_format` — GPT-image series always returns `b64_json`. Parse response JSON, extract `data[0].b64_json`, decode base64 to bytes.
- `edit(&self, prompt: &str, previous_image: &[u8], size: &str, quality: &str, input_fidelity: &str) -> anyhow::Result<Vec<u8>>` — POST multipart to `{endpoint}/openai/deployments/{image_model}/images/edits?api-version=2025-04-01-preview`. Headers: `api-key: {api_key}`. Multipart form: `image` (PNG bytes), `prompt`, `size`, `quality`, `input_fidelity`. Parse same response format.
- Internal: retry logic takes a request-building closure (not a pre-built request, since multipart bodies can't be reused). Retry up to `max_retries` on HTTP 429, respecting `Retry-After` header for backoff delay.

**Error handling:**
- For non-2xx responses, parse the response body as JSON and extract `error.code` and `error.message` from Azure's error format
- Include the Azure error in the `anyhow::Error` context
- Check for `data[0].b64_json` in successful responses; return clear error if missing

### 2. Create `crates/maenifold-core/src/wallpaper/cache.rs`

File cache management using `std::fs` (sync I/O — cache operations are fast, no need for async):

- `cache_dir(memory_path: &Path) -> PathBuf` — returns `{memory_path}/.cache/wallpaper/`. Callers pass `&Config::current().memory_path`.
- `save_image(cache_dir: &Path, mode: &str, label: &str, data: &[u8]) -> anyhow::Result<PathBuf>` — creates dirs if needed, saves as `{mode}_{label}_{timestamp}.png`, returns path
- `latest_image(cache_dir: &Path, mode: &str) -> Option<PathBuf>` — returns most recent image for the mode (by filename timestamp)
- `list_images(cache_dir: &Path, mode: &str) -> Vec<PathBuf>` — list all images for mode, sorted by timestamp
- `clear_cache(cache_dir: &Path, mode: Option<&str>) -> anyhow::Result<()>` — remove images, optionally filtered by mode

### 3. Create `crates/maenifold-core/src/wallpaper/mod.rs`

Module declaration:

