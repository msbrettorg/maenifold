# T-79.2: SRE Agent Shim Configuration

## Requirement
FR-SRE-1 — Azure SRE Agent must be usable as a pipeline prompt node.

## Problem
The ACP shim needs to know where the SRE Agent lives, which `srectl` binary to call, and how to authenticate. These come from environment variables inherited from the parent process (maenifold's `AgentPool` uses `sh -c` which passes env).

## Acceptance Criteria
1. `config.rs` loads and validates these env vars:
   - `SRE_AGENT_ENDPOINT` (required) — e.g. `https://ftk-sre-agent--7dbe29ed.a5db6d97.eastus2.azuresre.ai`
   - `SRE_AGENT_NAME` (optional, default: `meta_agent`) — subagent to route prompts to
   - `SRECTL_PATH` (optional, default: discover from `PATH`) — path to `srectl` binary
   - `SRECTL_TIMEOUT_SECONDS` (optional, default: `300`) — per-prompt timeout
2. `SreAgentConfig` struct with a `load() -> Result<Self>` method
3. Validation: endpoint must start with `https://`, srectl must be executable
4. Clear error messages on misconfiguration (printed to stderr)
5. Unit tests for config loading with env vars set/unset

## Files to modify
