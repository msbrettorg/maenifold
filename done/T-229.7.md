## Summary

Register `config://` as a subscribable resource family and emit notifications from config mutation handlers. Also register config resources so they pass the `resource_exists()` check in `resources/mod.rs` — merely adding to `SUBSCRIBABLE_PREFIXES` is insufficient because `handle_subscribe()` calls `resource_exists()` first.

## Scope

- Register concrete `config://settings`, `config://agents`, `config://mcp-servers` resources in the resource listing (so `resource_exists()` succeeds)
- Add `config://` to `SUBSCRIBABLE_PREFIXES` in `subscription.rs`
- Wire `notify_resource_updated()` calls into config mutation MCP tool handlers:
  - `UpdateSettings` → `config://settings`
  - `AddAgent`/`UpdateAgent`/`DeleteAgent` → `config://agents`
  - `AddMcpServer`/`UpdateMcpServer`/`DeleteMcpServer` → `config://mcp-servers`
  - `ReloadConfig` → all three URIs
- Notifications carry URI only (not payload) — client calls `GetConfig` for new state

## Acceptance criteria

- [ ] `config://settings` is subscribable (subscription accepted, not rejected by `resource_exists()`)
- [ ] `config://agents` is subscribable
- [ ] `config://mcp-servers` is subscribable
- [ ] Notifications emitted after each mutation tool call
- [ ] `cargo build --release -p maenifold-cli` succeeds

## Files

- `crates/maenifold-core/src/mcp/resources/mod.rs` (register config resources, adjust `resource_exists()`)
- `crates/maenifold-core/src/mcp/resources/subscription.rs` (add to SUBSCRIBABLE_PREFIXES)
- `crates/maenifold-core/src/mcp/config_tools.rs` (add notification calls)
