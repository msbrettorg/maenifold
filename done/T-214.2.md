# T-214.2 — SessionRef type + wire format

## Problem

Pipeline prompt nodes currently have no way to reference an existing ACP session. Session-as-Node requires a `SessionRef` field on prompt nodes that tells the executor which agent session to resume.

## Solution

1. **Create `SessionRef` struct** in `types_node.rs` (or adjacent types file):
   ```rust
   #[derive(Debug, Clone, Serialize, Deserialize)]
   pub struct SessionRef {
       pub agent: String,
       pub session_id: String,
   }
   ```

2. **Extend `PipelinePromptNode`** (in the prompt node types) with:
   ```rust
   #[serde(default, skip_serializing_if = "Option::is_none")]
   pub session_ref: Option<SessionRef>,
   ```

3. **Update wire format** in `types_wire.rs` — the `TryFrom` implementations must handle `session_ref` in serialization/deserialization.

4. **Invariant**: When `session_ref` is present, `prompt.agent == session_ref.agent`. Validate this in the `TryFrom` or validation layer.

## Key Files

- `crates/maenifold-core/src/workflow/pipeline/types_node.rs` — `PipelinePromptNode`
- `crates/maenifold-core/src/workflow/pipeline/types_wire.rs` — wire format TryFrom impls

## Acceptance Criteria

- `SessionRef` type exists with `agent` and `session_id` fields
- `PipelinePromptNode` has `session_ref: Option<SessionRef>`
- Existing pipeline JSON without `session_ref` deserializes cleanly (backwards compatible)
- Pipeline JSON with `session_ref` round-trips through serde
- Agent consistency invariant validated (agent == session_ref.agent)
- `cargo build --release -p maenifold-core` succeeds
