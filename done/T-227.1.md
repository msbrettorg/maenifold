## Summary

When enabled, the Home tab (`HomeDashboard.vue`) runs a background wallpaper slideshow with three modes of visual self-expression. Images rotate on a timer and regenerate when the knowledge graph evolves.

**Three modes:**

| Mode | Source | What it captures |
|------|--------|-----------------|
| **Endophasia** | Recent activity feed → image model | The inner monologue — what's actually happening right now |
| **Zeitgeist** | Louvain communities → image model | The spirit of the time — what concepts are clustering together |
| **Self-actualization** | Communities → reasoning model (with graph tools) → image model | The self-portrait — maenifold understanding and depicting itself |

## Behavior

1. **Feature toggle** — `settings.easterEggs.wallpaper.enabled` in `maenifold.json`. Defaults to `false`. Exposed in Settings UI under a new "Easter Eggs" section.

2. **Mode selection** — `settings.easterEggs.wallpaper.mode`:
   - `"endophasia"` (default) — feeds raw `RecentActivity` output to the image model. The inner monologue.
   - `"zeitgeist"` — feeds Louvain community data to the image model. One image per community, slideshow cycles through them.
   - `"self-actualization"` — feeds communities to a reasoning model with maenifold graph tools, gets a grounded image prompt back, then sends that to the image model.

3. **Slideshow rotation** — Timer cycles through available images at the configured interval (`rotateMinutes`, default 5). Crossfade transition. Wraps around after the last one.

### Mode 1: Endophasia — the inner monologue

The raw recent activity feed goes straight to the image model. No filtering, no reshaping. What's been happening in the knowledge graph right now, rendered as imagery.

**Trigger:** On a timer (same `rotateMinutes`). Each rotation calls `RecentActivity` (filter=all, includeContent=true, limit=10) and sends the output verbatim to the image model with the user's preface.

**Prompt:** `{preface}\n\n{recent activity output}`

**Image count:** One image per rotation. Previous image replaced. The wallpaper is always "right now."

### Mode 2: Zeitgeist — the spirit of the time

Each Louvain community gets its own image. The slideshow cycles through them.

**Trigger:** After each Louvain recompute (community drift past `nmiThreshold`). Generates one image per community, one at a time with 15s gaps (rate limit awareness).

**Prompt per community:** `{preface}\n\n{community line}` — e.g., `**[[maenifold-rs]]** [[gate]] [[maenifold]] [[pipeline]] ...`

**Image count:** Top N communities (`communityCount`, default 10). One image saved per anchor concept. Slideshow cycles through all of them.

### Mode 3: Self-actualization — the self-portrait

Each community goes through a reasoning model with maenifold graph tools before reaching the image model. Maenifold reads its own knowledge to understand what each community means, then describes what it sees.

**Trigger:** Same as zeitgeist — on Louvain recompute.

**Reasoning step:** For each community, dispatch an ACP prompt session (same pattern as the Teams monitor `TeamsDispatchRequest → AcpExec`) to the reasoning model (`azure.smallModel`, default `gpt-5.4-mini`) with maenifold tools enabled (`BuildContext`, `ReadMemory`, `SearchMemories`, `FindSimilarConcepts`). The session prompt:
```
{user preface}

{community line}

Use your tools to read the knowledge graph and understand what these concepts mean — what they represent, how they relate, what work they embody. Then write a concise image generation prompt describing a single visual scene that captures the essence of this community. No text in the image. Output only the prompt, nothing else.
```
The reasoning model traverses the graph, reads memory files, builds context around the anchor and its members, then synthesizes a grounded image prompt from actual knowledge — not just concept names.

**Implementation:** Follow the Teams monitor dispatch pattern — `TeamsDispatchRequest::to_acp_payload()` → `AcpExec`. The wallpaper equivalent builds a `WallpaperDispatchRequest` with the community data and routes it through the same ACP relay infrastructure. The agent session gets `allowedTools` scoped to `["BuildContext", "ReadMemory", "SearchMemories", "FindSimilarConcepts"]` — read-only graph access, no writes.

**Image step:** The reasoning model's output goes to the image model exactly as-is. No preface, no community data appended.

**Cost:** Two API calls per community (reasoning + image) plus local graph tool calls. Uses `azure.smallModel` by default for the reasoning step.

**Preview:** In Settings UI, the "Generate now" button in self-actualization mode shows the intermediate reasoning prompt before generating the image. Two-step preview: first show the generated prompt (approve/edit), then generate the image.

### Why three modes

- **Endophasia** — fast, cheap, always fresh. One image per rotation, always reflecting the current moment. Best default for "I want something alive on my home screen."
- **Zeitgeist** — broader, structural. Shows the conceptual landscape, not the moment-to-moment activity. Multiple images cycling through the top communities.
- **Self-actualization** — deepest, most expensive, most surprising. Maenifold introspects on its own knowledge graph, understands what each community actually represents, then describes and renders its self-portrait.

### Common behavior (all modes)

- **Image generation:** Azure OpenAI Images API. Uses `/images/generations` for fresh images, `/images/edits` when continuity is enabled.
- **Decode and save:** `b64_json` → `{memory_root}/.cache/wallpaper/{mode}_{label}_{timestamp}.png`
- **Rate limiting:** 429 retry with `Retry-After` header, max `maxRetries` attempts per image. 15s gap between calls for multi-image modes.
- **Display:** CSS `background-image` on HomeDashboard container. Low opacity overlay for readability. Crossfade transition.
- **Fallback:** No wallpaper yet or generation fails → show existing default background. Partial availability: slideshow cycles whatever's available.

### Continuity mode (modifier for all modes)

When `continuity` is enabled, each new image **evolves from the previous one** instead of generating from scratch. The previous wallpaper is uploaded to the edit endpoint (`/images/edits`) as the source image, and the new data (recent activity, community, or reasoning output) becomes the edit prompt.

**How it works:**

1. First generation in a session always uses `/images/generations` (no previous image to iterate on).
2. Subsequent generations use `/images/edits` — upload the previous PNG as `image[]`, send the new data as the edit prompt.
3. The `inputFidelity` setting controls how much visual DNA carries over:
   - Low fidelity → more reinterpretation, each frame diverges significantly
   - High fidelity → more preservation, each frame is a subtle evolution
4. The edit prompt includes a continuity directive: `"Update this image to reflect the latest state: {data}"` — the model adjusts reflections, composition, and elements to match the new data while preserving the visual thread.

**Effect by mode:**

| Mode | Without continuity | With continuity |
|------|-------------------|----------------|
| **Endophasia** | Each rotation is a fresh rendering of current activity | Each rotation evolves the previous image — the wallpaper drifts like a living painting |
| **Zeitgeist** | Each community gets an independent image | Each community's image evolves across Louvain recomputes — visual history of how a cluster changed |
| **Self-actualization** | Each community gets a fresh self-portrait | The self-portrait evolves — maenifold's sense of self developing over time |

**Reset:** A "Reset wallpaper" button in Settings clears the cache and forces the next generation to start fresh from `/images/generations`.

## Settings — `maenifold.json`

New section under `settings`:

```json
{
  "settings": {
    "easterEggs": {
      "wallpaper": {
        "enabled": false,
        "mode": "endophasia",
        "prompt": "Generate an image of what's top of mind.",
        "azure": {
          "endpointEnvVar": "AZURE_OPENAI_ENDPOINT",
          "apiKeyEnvVar": "AZURE_OPENAI_API_KEY",
          "imageModel": "gpt-image-2",
          "smallModel": "gpt-5.4-mini",
          "reasoningModel": "gpt-5.4"
        },
        "size": "1536x1024",
        "quality": "low",
        "continuity": false,
        "inputFidelity": "medium",
        "maxRetries": 3,
        "communityCount": 10,
        "rotateMinutes": 5
      }
    }
  }
}
```

### Field descriptions

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | bool | Master toggle. Default `false`. |
| `mode` | string | `"endophasia"`, `"zeitgeist"`, or `"self-actualization"`. Default: `"endophasia"`. |
| `prompt` | string | User-editable preface. Prepended to the data source before sending to the image model (endophasia/zeitgeist) or the reasoning model (self-actualization). |
| `azure.endpointEnvVar` | string | **Name of the env var** holding the Azure OpenAI endpoint URL. Default: `AZURE_OPENAI_ENDPOINT`. |
| `azure.apiKeyEnvVar` | string | **Name of the env var** holding the API key. Default: `AZURE_OPENAI_API_KEY`. |
| `azure.imageModel` | string | Deployment name for image generation. Default: `gpt-image-2`. |
| `azure.smallModel` | string | Deployment name for the self-actualization reasoning step. Default: `gpt-5.4-mini`. |
| `azure.reasoningModel` | string | Deployment name for deeper reasoning (override for smallModel). Default: `gpt-5.4`. |
| `size` | string | Image dimensions. Default: `1536x1024`. |
| `quality` | string | `low`, `medium`, `high`. Default: `low`. |
| `continuity` | bool | When true, each new image evolves from the previous one via the edit endpoint instead of generating from scratch. Default: `false`. |
| `inputFidelity` | string | `low`, `medium`, `high`. Controls how much visual DNA carries over in continuity mode. Low = more reinterpretation, high = subtle evolution. Only used when `continuity` is true. Default: `"medium"`. |
| `maxRetries` | int | Max 429/timeout retries per image. Default: `3`. |
| `communityCount` | int | How many top communities to generate images for (zeitgeist/self-actualization only). Default: `10`. Range: 1-20. |
| `rotateMinutes` | int | Minutes between slideshow rotations. Default: `5`. Range: 1-60. |

### Why env var names, not values

We store the **name** of the env var (e.g., `"AZURE_OPENAI_API_KEY"`), not the actual key. This means:
- No secrets in `maenifold.json` (which is checked into repos, synced across machines)
- The key comes from the user's shell environment (`.zprofile`, `.zshrc`, `.bashrc`, secrets manager, etc.)
- `envPassthrough` in `maenifold.json` already forwards `AZURE_OPENAI_API_KEY` and `OPENAI_API_KEY` to child processes
- If a user has a different env var name for their key, they just change the setting

## Settings UI

New section in `SettingsView.vue` → "Easter Eggs" (or add to an existing experimental section):

1. **Toggle** — "Wallpaper" on/off switch
2. **Mode** — Radio or dropdown: Endophasia / Zeitgeist / Self-actualization. Brief description under each.
3. **Prompt** — Textarea showing the current preface. Editable. Reset button to restore default.
4. **Azure config** — Three text fields for env var names: endpoint, API key, image model. Show whether each env var is currently set (green dot / red dot) by checking `process.env[name]` — show presence, never show the value.
5. **Slideshow** — Slider or number input for `rotateMinutes` (1-60). Number input for `communityCount` (1-20, zeitgeist/self-actualization only).
6. **Continuity** — Checkbox: "Evolve from previous image". When checked, shows a fidelity slider (low/medium/high). "Reset wallpaper" button to clear cache and start fresh.
7. **Preview** — "Generate now" button. In endophasia mode: generates immediately from current recent activity. In zeitgeist: generates for the current community. In self-actualization: shows the intermediate reasoning prompt first (approve/edit), then generates the image.

## API surface (backend)

The wallpaper generation should happen in the **daemon** (Rust backend), not the frontend:

1. New MCP tool or resource: `wallpaper://latest` returns the path to the current wallpaper PNG.
2. After Louvain recompute, if enabled, daemon calls Azure API, saves the image, notifies the frontend via an MCP notification or resource-changed event.
3. Frontend polls `wallpaper://latest` on mount and on notification.

Alternatively, if the daemon doesn't have HTTP client capabilities for Azure, the frontend can call the API directly from the Electron main process (Node.js has `fetch`). The communities data is already available via `maenifold-BuildContext` or the community detection output.
