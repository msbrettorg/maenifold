# T-54.1 — Parser Rework Tolerance

**Requirement**: FR-41 (File-Authoritative Pipeline Gate Cache)
**Sprint**: 54
**Component**: `crates/maenifold-gate/src/parser.rs`

## Problem

The parser (`parser.rs`, 443 LOC) assumes each stage heading appears exactly once with the exact canonical name. Real-world files in `done/` contain rework cycles — multiple SWE attempts after red-team rejections, re-audits, non-canonical heading variants, out-of-order sections, and intermediate sections without verdicts.

102/102 files in `done/` currently produce parse errors.

## Acceptance Criteria

### 1. Recognize rework heading variants

The following headings MUST be recognized as their canonical stage:

| Pattern | Canonical Stage |
|---|---|
| `## SWE Remediation` | SWE |
| `## SWE Remediation (Attempt N)` | SWE |
| `## SWE Remediation (Red-team fixes)` | SWE |
| `## SWE Remediation Update` | SWE |
| `## Red-team Audit` | Red |
| `## Red-team Audit (Attempt N)` | Red |
| `## Red-team Audit (Re-audit)` | Red |
| `## Red-team Audit (Re-audit — *)` | Red |
| `## Red-team Audit — Round N` | Red |
| `## Blue-team Verification` | Blue |
| `## Blue-team Verification (Attempt N)` | Blue |

Rule: match on the canonical prefix (`## SWE Remediation`, `## Red-team Audit`, `## Blue-team Verification`). Everything after is a variant suffix — ignore it for stage determination.

### 2. Handle multiple sections of the same stage

When multiple sections exist for the same stage (rework cycles), the parser MUST:
- Collect ALL sections for that stage
- Use the LAST section's verdict for status derivation
- NOT error on "duplicate" headings

### 3. Handle implicit verdicts on intermediate sections

A section with no `**Verdict**: X` line:
- If followed by another section of the SAME stage → treat as implicit REJECT (rework happened)
- If it's the LAST section of that stage AND the file is in `done/` → treat as implicit PASS
- If it's the LAST section of that stage AND the file is in `todo/` → report as warning (not error)

### 4. Handle out-of-order headings

When a heading appears out of the expected order (e.g., SWE after Red), treat it as a rework cycle. The parser MUST NOT error. It should treat each occurrence as another attempt for that stage and apply the "last section wins" rule from AC-2.

### 5. Zero-warning target for done/ files

After these changes, `gate status --root .` MUST produce zero warnings for files that are legitimate completed work (in `done/` with at least some audit trail). Files that are genuinely in `done/` with zero stage sections (pre-pipeline legacy) are handled by T-54.2.

## Test Cases

1. File with `## SWE Remediation` + `## SWE Remediation (Attempt 2)` → parses as single SWE stage, takes Attempt 2's verdict
2. File with `## Red-team Audit` (no verdict) + `## Red-team Audit (Re-audit)` with `**Verdict**: PASS` → status = blue
3. File with out-of-order `## SWE Remediation` after `## Red-team Audit` → no error, SWE has 2 attempts
4. File with `## Red-team Audit — Round 2` → recognized as red stage
5. File in `done/` with all sections but missing verdict on last blue → implicit PASS, no warning
6. File in `todo/` with missing verdict on last red → warning (not error)

## Constraints

- Do NOT change the verdict format (`**Verdict**: PASS|REJECT|FAIL`)
- Do NOT change the advance command's output format
- Preserve all existing passing tests (25 tests)
- `parser.rs` is currently 443 LOC — keep under 500 LOC after changes
