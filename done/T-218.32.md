# T-218.32 — Teams Session Origin Metadata

## Problem

The Teams tab identifies Teams-originated sessions heuristically by checking if `agentName`, `title`, or `cwd` contains the string "teams" (see `TeamsTab.vue:36-44`). This creates:
- **False positives**: Any session with "teams" in its title/cwd appears in the Teams tab
- **False negatives**: Teams-dispatched sessions without "teams" in the title don't appear

## Dependency

- **T-218.44** (Trouter lifecycle) must ship first — it creates the dispatch path that produces Teams sessions. Without T-218.44, there is no server-side Teams dispatch, so no metadata to attach.

## Design (R4 — Radical Simplification)

R1-R3 duo reviews identified an intractable session ID join problem: `app_session_id` (CONN_MAP routing key) ≠ ACP-listed `session_id` (server-assigned). No registry-based approach can bridge this without deep ACP lifecycle changes. 

**New approach: Title-based identification.** When dispatching from Teams, set a structured title prefix. The session title is already visible in listings. No registry, no sidecar, no join problem.

### Backend: Structured title on Teams dispatch

In `teams/supervisor.rs`, when building the AcpExec payload via `TeamsDispatchRequest::to_acp_payload()`, set the `title` field to:

```
[Teams] {senderName}: {matchedKeyword}
```

Example: `[Teams] Brett: help with deployment`

The `[Teams]` prefix is a machine-readable marker that won't collide with user-typed titles.

### Frontend: Prefix-based identification with heuristic fallback

```typescript
function isTeamsSession(session: SavedSession | null): session is SavedSession {
  if (!session) return false;
  // Primary: structured title from dispatch
  if (session.title?.startsWith('[Teams]')) return true;
  // Fallback: heuristic for legacy sessions dispatched before this change
  const terms = [session.agentName, session.title, session.cwd]
    .filter((v): v is string => Boolean(v))
    .map(v => v.toLowerCase());
  return terms.some(v => v.includes('teams'));
}
```

### What this does NOT do

- No structured metadata field on ListedSession/SavedSession (deferred — needs ACP session metadata support)
- No in-memory registry (unnecessary with title-based approach)
- No sidecar file (eliminated in R3)
