# T-203.4 — ChatContentBlocks integration

## Problem

`ChatContentBlocks.vue` renders tool call results as text/code blocks. When a tool result comes from a tool with `_meta.ui.resourceUri`, it should render an inline interactive app instead.

## Fix

1. In `ChatContentBlocks.vue` (or `ChatToolCallDetails.vue` — whichever renders tool results):
   - Check if the tool call's tool had `_meta.ui.resourceUri` in capabilities
   - If yes, fetch the `ui://` resource via `useMcpResources` and render `<McpAppFrame>`
   - If no, render existing text/code block as before
2. Resource prefetch: when a tool with `_meta.ui` is about to be called (or on tool listing), optionally preload the resource so rendering is instant.
3. Fallback: if resource fetch fails, fall through to text rendering of the tool result (graceful degradation).

## Files likely modified

- `apps/desktop/src/components/ChatContentBlocks.vue`
- `apps/desktop/src/components/ChatToolCallDetails.vue`
- `apps/desktop/src/composables/useMcpResources.ts` (if resource fetch needs ui:// scheme support)

## Acceptance criteria

1. Tool with `_meta.ui` renders as inline iframe app
2. Tool without `_meta.ui` renders unchanged
3. Resource fetch failure gracefully falls back to text
4. No layout shift — loading state shown while resource loads
5. Typecheck passes
