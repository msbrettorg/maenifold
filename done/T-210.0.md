# T-210.0 — Teams Monitor

## Vision

Monitor Microsoft Teams for keyword mentions. When triggered, dispatch an ACP agent session that renders in a dedicated Teams tab in the desktop app. No Python. No PTY bridge. No terminal emulator. No custom components. Use what we've built.

## Architecture

```
Teams Trouter WebSocket (Rust, tokio-tungstenite)
    ↓ push notification
Message handler (keyword match, sender filter)
    ↓ match
AcpExec session (existing infrastructure)
    ↓ session created
UI renders session in Teams tab (existing ChatView/ChatMessageList)
```

### What already exists

- ACP session management (`AcpExec`, `acp_exec.rs`)
- Chat rendering (`ChatView`, `ChatMessageItem`, `ChatContentBlocks`)
- Session list (`SessionList`, session store)
- MCP tool/resource infrastructure
- Agent configuration (`maenifold.json` agents)
- Notification system (toast, tab badges)

### What we build

1. **Trouter WebSocket client** — Rust, in `maenifold-core`. Long-lived tokio task. Connects to Teams Trouter service, authenticates via Azure AD/MSAL token, receives push notifications. Reference: `agency-cowork/skills/teams/scripts/monitor/trouter_client.py`

2. **Message handler** — Rust. Keyword matching, sender filtering, cooldown. On match → create ACP session via existing `AcpExec`. Reference: `agency-cowork/skills/teams/scripts/monitor/message_handler.py`

3. **MCP tools** — `TeamsMonitor { action: "enable" | "disable" | "status" | "configure" }`. Config stored in `maenifold.json` settings.

4. **MCP resources** — `teams://status` (connection state, unread count), `teams://config` (keyword, scope, identity)

5. **Teams tab** — Vue. Another tab in `AppTabBar`. Renders the Teams-triggered ACP sessions using the SAME `ChatMessageList` and `ChatContentBlocks` we already have. No new chat components. Settings section for keyword/scope/identity using existing shadcn form components.

## KISS constraints

- **ZERO custom components.** Reuse ChatView/ChatMessageList/SessionList. The Teams tab is a filtered view of sessions tagged as Teams-originated.
- **ZERO Python.** Trouter client is Rust.
- **ZERO PTY bridge.** ACP handles agent communication.
- **ZERO terminal rendering.** Agent responses render as structured content blocks in the existing chat UI.
- **Aesthetic standard:** Opus 4.7 reviews all UI work. The tab should feel native — same quality as Agents/Pipelines/Gate tabs. Use Stitch reference screens.

## Auth flow

Teams Trouter requires a Bearer JWT. Use Azure MSAL:
1. User authenticates via device code flow or browser redirect (same pattern as WorkIQ)
2. Token stored in keychain/credential store
3. Trouter client refreshes token automatically
4. If token expires and can't refresh → disconnect, show reconnect prompt in UI
