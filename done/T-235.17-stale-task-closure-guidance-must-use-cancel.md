# T-235.17 - Pending stale-task closure guidance must use `gate cancel`

**Pipeline**: lightweight
**Pipeline Digest**: tbd

## Priority

**P1 - PM process / gate semantics**

## Problem

While closing `T-235.16` as stale, the PM followed the current repo guidance in
`ralph/prompt.md`:

```text
Close stale tasks (move to done with a `gate fail` + close-stale rationale, or merge into a still-active task).
```

The live gate CLI rejected that action:

```text
illegal transition: state 'pending' does not allow outcome 'fail'
```

`gate cancel` already exists and is the correct stale/superseded closure verb for
pending tasks. We already shipped that surface in `T-202.7`, but the PM/operator
guidance still teaches `gate fail` for this case. That mismatch causes PMs to
hit an avoidable gate error while grooming stale backlog items.

## Scope Notes

- Fix repo-owned guidance only; do not change gate lifecycle semantics or add a
  new transition.
- Ground the fix against the already-shipped cancel contract:
  - `gate cancel --help`
  - `done/T-202.7.md`
  - `docs/gate-cancel-taxonomy.md`
  - `docs/gate-uml-spec.md`
- Required file scope:
  - `ralph/prompt.md`
  - `AGENTS.md`
  - `ralph/README.md`
  - `CONTRIBUTING.md`
  - `assets/integrations/copilot/plugin-product-team/agents/product-manager.agent.md`
- Also review surface-summary docs that may omit `cancel` from the live gate
  command list (`docs/ARCHITECTURE.md`, `readme.md`) and update them if they are
  touched or if they would otherwise remain contradictory after the PM docs are
  fixed.
- Keep the distinction explicit:
  - `gate fail` follows the active state's fail edge for a real stage failure
  - `gate cancel` is an administrative close for stale, superseded, duplicate,
    blocked-upstream, false-positive, or otherwise abandoned work, including
    tasks still in `pending`
- Do not touch historical session logs, archived iteration transcripts, or gate
  lifecycle code.

## Acceptance Criteria

- [ ] `ralph/prompt.md` no longer tells the PM to close stale pending tasks with

- [ ] The required PM/operator docs (`ralph/prompt.md`, `AGENTS.md`,

      prompt) no longer claim or imply that `gate pass` / `gate fail` are the
      only task-closing verbs.
- [ ] The updated guidance explicitly states:
      - `gate fail` follows a legal fail edge for real stage failure
      - `gate cancel` is the correct administrative close for stale/superseded

- [ ] Any touched gate surface summaries or command lists that enumerate
      mutating commands include `cancel` and remain consistent with the live CLI
      and gateway domain.
- [ ] The fix is grounded against `gate cancel --help`, `done/T-202.7.md`,
      `docs/gate-cancel-taxonomy.md`, and `docs/gate-uml-spec.md`.
- [ ] No gate state-machine change is introduced; this is a docs/process
      alignment fix only.
