# T-42.10: Transport & Bridge Compliance

**Requirement**: FR-42.10  
**Priority**: P2  
**Files**: `crates/maenifold-core/src/acp/relay.rs`, `vendor/acp-ui/src/lib/acp-bridge.ts`, `vendor/acp-ui/src/stores/session.ts`

## Acceptance Criteria

1. **Fix WebSocket relay non-JSON-RPC frames** in `relay.rs`:
   Replace `stderr_msg` format from `{"type":"stderr","data":"..."}` to a valid JSON-RPC notification:
   ```json
   {"jsonrpc":"2.0","method":"_relay/stderr","params":{"data":"..."}}
   ```
   Replace `error_msg` format from `{"type":"error","payload":{...}}` to:
   ```json
   {"jsonrpc":"2.0","method":"_relay/error","params":{...}}
   ```

2. **Add `unstable_setSessionConfigOption` to AcpClientBridge** (`acp-bridge.ts`):
   ```ts
   async unstable_setSessionConfigOption(params: {
     sessionId: string;
     configId: string;
     value: string;
   }): Promise<{ configOptions: any[] }> {
     return await this.sendRequest('session/set_config_option', params);
   }
   ```

3. **Non-text content warning** in `session.ts`: In all three `handleSessionUpdate` cases (`user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`), add an else branch when `update.content.type !== 'text'`:
   ```ts
   } else {
     console.warn('[ACP] Received non-text content block:', update.content.type, update.content);
   }
   ```

### AC2 – `unstable_setSessionConfigOption` (`acp-bridge.ts`): ⚠️ SPEC DEVIATION

**Finding:** Return type is `Promise<any>` instead of the spec-required `Promise<{ configOptions: any[] }>`.

Spec:
```ts
async unstable_setSessionConfigOption(params: {
  sessionId: string;
  configId: string;
  value: string;
}): Promise<{ configOptions: any[] }> {
```

Implementation (`acp-bridge.ts` lines 289–295):
```ts
async unstable_setSessionConfigOption(params: {
  sessionId: string;
  configId: string;
  value: string;
}): Promise<any> {
```

The `Promise<any>` return type abandons the structural contract specified (`{ configOptions: any[] }`). Any caller relying on the type signature for compile-time safety will get no protection. This is a direct spec deviation, not merely cosmetic — the spec explicitly defined the return shape.

### AC3 – Non-text content warning (`session.ts`): ❌ FAIL — TWO defects

**Defect 3a — Wrong warning string:**

Spec:
```ts
console.warn('[ACP] Received non-text content block:', update.content.type, update.content);
```

Implementation (session.ts lines 208, 227, 247):
```ts
console.warn('[ACP] Non-text content block received:', update.content.type);
```

The message string is `'[ACP] Non-text content block received:'` versus the spec's `'[ACP] Received non-text content block:'`. The SWE acknowledged this in the remediation notes.

**Defect 3b — Missing third argument `update.content` (NOT acknowledged by SWE):**

The spec call passes three arguments to `console.warn`:
1. The string label
2. `update.content.type` (the content type discriminant)
3. `update.content` (the **full content object** — critical for debugging unknown content types)

The implementation passes only two arguments, omitting `update.content` entirely. This defeats the purpose of the NFR-9 fix: when a non-text block arrives, a developer cannot inspect the actual payload from the log because the content object is never logged. The "silent drop" problem is only half-fixed — the type is surfaced but the data is still lost.

**Defect 3c — Warning absent from new-message creation path:**

Each of the three chunk cases has two code paths:
1. **Append path** (when a same-role message already exists): the warning `else` branch IS present.
2. **Create path** (when a new message must be pushed): the ternary `update.content.type === 'text' ? update.content.text : ''` silently produces an empty string for non-text content with **no warning at all**.

Since NFR-9 is about eliminating silent content drops, the create path remains a silent drop for all three cases. The spec says to add the warning in "all three `handleSessionUpdate` cases"; the create-path code paths are within those same cases and continue to swallow non-text content without logging.
