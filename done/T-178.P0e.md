# T-178.P0e — Sequential thinking trace display issues

## Priority: P0

## Symptom
In the Pipeline view, sequential thinking nodes appear to show only the last thought. Full thought history is not visible to the user.

## Root Cause (duo-confirmed, 2026-04-19)

The backend DOES return full trace data. The frontend DOES iterate all thoughts. Four independent bugs create the appearance of truncation:

### Bug 1 — TS↔Rust schema drift (Medium)
`apps/desktop/src/lib/pipeline-types.ts:263-267` declares `thinking_trace[].status` field. Backend `crates/maenifold-core/src/workflow/pipeline/view_cognitive.rs:128-136` emits `{thought_number, total_thoughts, text, is_revision, revises_thought, branch_id, agent}` — no `status` field. Frontend calls `statusClass(thought.status)` and `formatStatus(thought.status)` against `undefined` → status pills render empty.

### Bug 2 — Collapse heuristic hides thoughts 4+ (High)
`ThinkingTraceView.vue:132` uses `:open="index < 3"` — only the first 3 `<details>` are expanded. Thoughts 4+ render as collapsed single-line summaries. With small viewport, this is easily mistaken for "missing thoughts."

### Bug 3 — H2 section splitting truncates thought bodies (High)
`crates/maenifold-core/src/markdown/wikilinks.rs` `extract_h2_sections` splits on every `## ` heading. If a thought body contains an internal `## Subheading` (which agents often produce), the body is truncated at that H2 — the continuation becomes a separate section that fails the thought regex and is dropped.

### Bug 4 — Strict THOUGHT_HEADING_RE drops old sessions (Medium)
`view_cognitive.rs:15-20` requires `[agent]` brackets and `^...$` anchors. Older sessions without the bracketed agent name parse as zero thoughts.

### By design (not a bug):
`PipelineNodeCard.vue:161` shows only "Thought N of M" pill on the canvas card. Full trace is intentionally only in `SemanticZoomOverlay` → `ThinkingTraceView`. If the user expects thoughts on the card, that's a feature request, not a bug.

## Fix Requirements

### 1. Fix schema drift
Either:
- (a) Add `status` field to Rust output in `view_cognitive.rs` (derive from thought metadata), OR
- (b) Remove `status` from `pipeline-types.ts` and remove `statusClass()`/`formatStatus()` calls from `ThinkingTraceView.vue`
Option (b) is simpler and preferred unless status has actual semantic value.

### 2. Remove or improve collapse heuristic
Replace `:open="index < 3"` with `:open="true"` (all expanded by default), or provide a "Expand all / Collapse all" toggle button.

### 3. Fix H2 section splitting
In `extract_h2_sections` (or its caller `parse_thinking_trace`), use `THOUGHT_HEADING_RE` as the split anchor instead of bare `## `. Only split on lines that match the thought heading pattern, treating internal `## Subheading` as body content.

### 4. Relax THOUGHT_HEADING_RE for back-compat
Make the `[agent]` bracket portion optional in the regex so older sessions still parse.

## Acceptance Criteria
1. A 10-thought sequential thinking session displays all 10 thoughts with full body text in SemanticZoomOverlay
2. Thoughts containing internal `## Subheading` lines are NOT truncated
3. Older sessions without `[agent]` brackets still parse and display
4. No undefined status pills or empty badges in the trace view
5. User can expand/collapse individual thoughts
6. `cargo build --release -p maenifold-core` succeeds
7. `npx vue-tsc --noEmit` passes
8. Works in both Electron standalone and cowork iframe
