# T-178.1 — Visualize tool — add structured graph output mode

## Intent

`Visualize` already walks the weighted concept graph via recursive CTE and produces typed `(from, to, count)` triples — then immediately flattens them into a Mermaid string. Every consumer that wants to *use* that subgraph (dashboards, agents, future tools) currently has to re-parse Mermaid. Add a structured output mode so callers can request the raw walk result as JSON. Mermaid stays the default; new mode is opt-in.

This is the precondition for [[T-178.4]] (Mind dashboard switching to MCP) — the dashboard's "watching a mind think" flourish requires the weighted local subgraph as data, not a diagram.

## Scope

1. Add `format` field to `VisualizeParams` in `crates/maenifold-core/src/mcp/schema/graph_params.rs`. Enum `VisualizeFormat { Mermaid, Graph }`. Default = `Mermaid`.
2. Refactor `crates/maenifold-core/src/graph/analyzer.rs::visualize`:
   - Extract a private `walk_local_subgraph(conn, concept, depth, max_nodes) -> Result<LocalSubgraph>` returning `LocalSubgraph { center: String, nodes: Vec<{name, depth}>, edges: Vec<{source, target, weight}> }`.
   - `visualize` calls the walker, then dispatches to either `render_mermaid(&LocalSubgraph) -> String` (existing behavior, byte-identical output) or serializes the struct to JSON for `Graph` mode.
3. Update `assets/help/Visualize.md` to document the new `format` field and show both example outputs.
4. Update `crates/maenifold-core/src/mcp/schema/graph_tools.rs` only if the derived schema needs adjustment (the macro should pick up the new field automatically — verify).
5. Tests in `graph/analyzer.rs` (or sibling `analyzer_tests.rs`):
   - Existing Mermaid test must still pass byte-for-byte.
   - New test asserting `format=graph` returns `nodes` (with `depth` per node) and `edges` (with weight) and the center concept.
   - Test asserting `format=graph` with no neighbors returns `{center, nodes:[{name:center, depth:0}], edges:[]}` instead of the Mermaid "[No connections found]" placeholder.

## Acceptance criteria

1. `cargo test -p maenifold-core` passes.
2. Existing Mermaid output is byte-identical to pre-change for the same inputs (regression test enforces this).
3. `Visualize { conceptName: "X", depth: 2, maxNodes: 30, format: "graph" }` returns JSON of shape `{ center: "X", nodes: [{name, depth}], edges: [{source, target, weight}] }`. `weight` is numeric (f64), preserving co-occurrence count semantics.
4. Help doc shows both Mermaid and graph-mode example outputs.
5. No new dependencies added.
6. Wire values for the new `format` enum are lowercase strings: `"mermaid" | "graph"`. Serde rename is explicit (`#[serde(rename_all = "lowercase")]` on `VisualizeFormat`).
7. `tools/list` JSON-RPC output for `Visualize` includes the `format` field in `inputSchema` with an enum constraint listing exactly `["mermaid", "graph"]`. Verified by a JSON-shape assertion in the existing tools-list test (or a new sibling assertion if none exists).
