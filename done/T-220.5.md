# T-220.5 — Authenticate Localhost Admin Config Mutations

## Problem

Desktop settings mutate agent and MCP configuration through unauthenticated localhost REST routes. Any local process or browser tab can call these endpoints. CORS allows `null`, `file://`, and arbitrary localhost origins on mutation routes.

## Chosen Auth Mechanism: Loopback Bearer Token

On daemon startup, generate a random 32-byte token, write it to `{data_dir}/auth/localhost.token` with `0600` permissions. The desktop app reads this token via Electron main process and provides it to the renderer via preload contextBridge. Mutation requests include `Authorization: Bearer <token>`. The daemon validates the token on privileged routes.

### Why this approach
- Simple: ~100 LOC middleware + file + preload
- Secure: file permissions prevent other users; token rotation on restart
- Compatible: doesn't break the REST API shape, just gates access
- Electron-native: preload bridge is the standard Electron security pattern

## Protected Route List (mutations only)

These routes require the bearer token:
1. `POST /api/config/reload`
2. `POST /api/config/agents`
3. `PUT /api/config/agents/{name}`
4. `DELETE /api/config/agents/{name}`
5. `POST /api/config/mcp-servers`
6. `PUT /api/config/mcp-servers/{name}`
7. `DELETE /api/config/mcp-servers/{name}`
8. `POST /api/config/settings`

## Read-Only Routes (no auth required)

These remain publicly accessible on localhost:
- `GET /api/config` — read-only config view
- `GET /api/config/path` — config file location
- `GET /api/config/watch` — config change SSE stream
- `GET /api/discovery/*` — tool/agent discovery
- `/mcp` — MCP transport (has its own permission flow)
- All memory/graph/search read endpoints

## CORS Changes

Both CORS mount points must be updated:
- `crates/maenifold-core/src/mcp/web.rs:23` (web server)
- `crates/maenifold-core/src/mcp/http.rs:127` (HTTP MCP server)
- `crates/maenifold-core/src/mcp/http.rs:186` (`#[cfg(test)]` mount — keep consistent)

New policy — **CORS stays on all routes; bearer token is the security gate:**
- **All routes**: Keep current `localhost_cors()` (required for Electron renderer — `file://` origin in production, `http://localhost:vite-port` in dev are always cross-origin to the daemon)
- **Mutation routes**: Additionally require valid `Authorization: Bearer <token>` header — return 401 without it
- **Read-only routes + /mcp**: No auth required, CORS allows access as today

Rationale: CORS only constrains browsers, not local processes. Bearer token is the actual security gate. Removing CORS from mutations would block the Electron renderer's preflight, making mutations impossible.

## Failure UX

When a mutation request returns HTTP 401:
- Desktop settings components show an inline error banner: "Authorization failed. The daemon may have restarted — please reload the app."
- A "Reload" button triggers IPC to main process to re-read the token file from disk, then retries

## Token Lifecycle

1. **Generation**: Daemon startup → generate 32 random bytes → hex encode → atomic write to `{maenifold_root}/auth/localhost.token` with mode 0600 (create `auth/` dir with `create_dir_all` first; write to `.tmp` then rename for atomicity)
2. **Discovery**: Electron main process reads token file path from config
3. **Injection**: Preload exposes `window.electronAPI.getAuthToken()` via IPC — main reads file from disk on EVERY IPC call (no caching, so daemon restart rotation is picked up automatically)
4. **Rotation**: New token on every daemon restart. No stale cache — IPC reads fresh from disk each time
5. **CLI clients**: Can read the same token file if they need mutation access (none do currently)

### Platform note
`0600` is Unix-specific. On Windows, standard DACL restriction is a known limitation — document as such. Desktop target is macOS/Linux primarily.

### Threat model
The bearer token protects against:
- ✅ Arbitrary browser tabs / web pages calling localhost mutations
- ✅ Other OS users (file permissions)
- ✅ Unauthenticated localhost callers
- ❌ Same-user local malware (can read the token file — accepted for single-user desktop app)
