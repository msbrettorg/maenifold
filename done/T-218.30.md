# T-218.30 — Teams Auth Lifecycle

## Problem

Teams auth can initiate device-code flow, but the composed lifecycle is incomplete: no proven complete/poll action, secure token persistence, restart restore, refresh, revocation, or authenticated status surface.

## Acceptance Criteria

- [ ] Add explicit Teams auth lifecycle actions: `authenticate_start`, `authenticate_complete` or polling continuation, `refresh`, and `sign_out`
- [ ] Store access/refresh token material only in OS credential storage/keychain, never `maenifold.json`
- [ ] `teams://status` reports `authState: unauthenticated | pending | authenticated | expired | error`
- [ ] `teams://status` includes `expiresAt` and sanitized `lastAuthError`
- [ ] On app restart, Teams Monitor restores token from secure storage and refreshes before connecting
- [ ] Sign-out removes stored credentials and disables active Trouter use
- [ ] Verification covers app restart and expired-token refresh
