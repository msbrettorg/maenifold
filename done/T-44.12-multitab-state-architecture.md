# T-44.12: Multi-Tab State Architecture

**Requirement**: FR-44
**RTM**: RTM-306, RTM-307, RTM-308, RTM-350
**Priority**: P0 — replaces deprecated patch specs T-44.8, T-44.9, T-44.10, T-44.11
**Deprecates**: T-44.8 (auto-scroll), T-44.9 (tab isolation), T-44.11 (tool_call unseen output)

## Context

Sprint 34 added multi-tab by wrapping the OG single-session state in a `Map<string, TabState>` inside a `shallowRef`. This created three classes of bugs:

1. **Stale reactivity** — 17+ mutation sites lack `triggerRef(tabs)`, causing permission dialogs, auth prompts, terminal snapshots, startup state, and optimistic UI writes to silently fail to propagate.
2. **Missed scroll/unseen detection** — scroll watches `messageIds + messageCount`, missing streaming chunks, tool_call_update, and thought expansion (all in-place mutations within existing messages).
3. **Component state bleed** — unkeyed `ChatView` reuses local refs (`expandedThoughts`, `expandedToolCalls`, `pendingAttachments`, `activeCommandHint`) across tab switches.

These are not individual bugs — they are symptoms of an architectural mismatch. The OG was a single-session app. Patching individual sites will never converge because every new feature that mutates `TabState` will need a manual `triggerRef` call that developers will forget.

## Design Principle

**Let Vue's reactivity system do the work.** The store should be structured so that mutations naturally trigger reactivity without manual intervention.

## The Fix

`shallowRef<Map>` → `ref<Map>`. Delete all `triggerRef` calls. Add `:key` to ChatView. Pinia's setup stores with `ref()` are deeply reactive by default — Vue will track all nested TabState property mutations automatically. The `shallowRef` "optimization" was premature for 2-5 tabs and caused every bug.

## Acceptance Criteria

1. **`shallowRef` → `ref`**: Change `const tabs = shallowRef<Map<string, TabState>>(new Map())` to `const tabs = ref<Map<string, TabState>>(new Map())` in `session.ts`.
2. **Delete all `triggerRef`**: Remove every `triggerRef(tabs)` call in `session.ts`. Remove `triggerRef` from the import. Zero should remain.
3. **Delete `shallowRef` import**: Remove `shallowRef` from the vue import if no other uses exist.
4. **Key ChatView by tab**: `App.vue` SHALL render `<ChatView :key="activeTabId" />` so Vue destroys and recreates the component on tab switch.
5. **Restore deep scroll watch**: In ChatView.vue, replace the `messageIds + messageCount` signature watch with a deep watch on messages (or watch message content length) so streaming chunks, tool_call_update, and thought expansion all trigger auto-scroll.
6. **Backward compatible**: All existing multi-tab functionality (create, resume, switch, close, sidebar) SHALL continue to work.

## Anti-Goals

- Do NOT add `triggerRef` calls. That's what we're removing.
- Do NOT store transient DOM state (textarea ref, scroll container ref) in the store.

## Implementation Notes

- Target files: `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/components/ChatView.vue`, `vendor/acp-ui/src/App.vue`
- The `tabList` computed and `TabStrip` rendering should naturally recompute from the new reactive structure
- Consider `defineModel` or `provide/inject` for passing per-tab state to ChatView if `:key` approach causes prop drilling
- Test with 3+ tabs: create, switch rapidly, stream on background tab, verify no bleed

## SWE Remediation

### What I changed
- `vendor/acp-ui/src/stores/session.ts`
  - Replaced `shallowRef<Map<string, TabState>>` with `ref<Map<string, TabState>>` for `tabs`.
  - Removed `shallowRef` and `triggerRef` from the Vue import.
  - Deleted every `triggerRef(tabs)` call so tab state now relies on Vue's deep reactivity.
- `vendor/acp-ui/src/App.vue`
  - Keyed `ChatView` by the active tab id so the component is recreated on tab switches and local UI state does not bleed between tabs.
  - Used `sessionStore.activeTabId ?? 'no-active-tab'` for the key to satisfy Vue/TypeScript's `PropertyKey` requirement while preserving active-tab keying behavior.
- `vendor/acp-ui/src/components/ChatView.vue`
  - Replaced the `messageIds + messageCount` watcher with a deep `watch(messages, ...)`.
  - Added an `isNearBottom()` helper and only auto-scroll when the user is already near the bottom, so streaming/in-place message mutations now participate in auto-scroll without forcing jumps when reading older content.
