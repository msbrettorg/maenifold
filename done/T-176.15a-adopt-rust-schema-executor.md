## Intent

Split from the parent adopt task to deliver backend schema and executor support for first-class per-node adopt configuration before UI layering.

## Scope

1. Extend pipeline node schema to support:
   - `adopt: { role?, color?, perspective? }`
   - `requires_role?: <role-name>`
   for node types that dispatch LLM reasoning.
2. Preserve backward compatibility for existing pipeline definitions without adopt fields.
3. Update executor dispatch flow to apply adoption into the agent session before prompt dispatch.
4. Ensure serialization/deserialization and validation behavior covers adopt object shape.

## Acceptance Criteria

1. Pipeline schema accepts optional per-node adopt object with role/color/perspective and optional `requires_role`.
2. Executor applies adoption prior to node prompt dispatch.
3. Existing pipelines without adopt fields continue to run unchanged.
4. Pipeline JSON round-trips retain adopt configuration and `requires_role`.
5. `requires_role` is exposed on the executor adopt API and preserved through schema serialization/deserialization.

## Files In Scope

- `crates/maenifold-core/**` (pipeline schema/model definitions)
- executor/runtime crates that dispatch agent sessions for pipeline nodes
