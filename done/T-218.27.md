# T-218.27 — Stdio MCP Server-to-Client Requests

## Problem

Some MCP servers may send server-to-client requests even when the gateway advertises no client capabilities. The stdio read loop can ignore messages with unexpected IDs, which may leave upstream waiting for a response and cause deadlock or timeout.

## Acceptance Criteria

- [ ] Define gateway behavior for unexpected upstream requests: valid JSON-RPC method-not-found response or typed incompatibility error
- [ ] Fake upstream server sending `roots/list`, `sampling/createMessage`, or unknown request does not hang the gateway
- [ ] Behavior is logged with server name and method
- [ ] No client capabilities are advertised unless actually implemented
- [ ] Tests cover notification-only messages and request-with-id messages separately
- [ ] Tests cover unexpected request during initialize and during tool call
