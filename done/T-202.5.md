# T-202.5 — P0 process: agents and PMs claimed working product that is completely broken

## The lie

Sprint 201 blue-team (T-201.8) verdict: "PASS. vue-tsc clean, npm build clean, 219 LOC under limit, zero text-white, 11/11 existing tests pass."

RALPH PM recorded: "Sprint 201 onboarding wizard delivery — 5 tasks done, 1,157 LOC across 7 new files."

The current PM (this session) ran Playwright screenshots and initially bypassed the broken wizard with localStorage hacks to screenshot the pipeline tab, then started reporting "pipeline tab works."

**Reality:** The product is 100% broken for every new user. The wizard blocks at step 2 forever. No user can reach any feature. The daemon is running and the UI says "Disconnected."

## What went wrong

1. **Blue-team verified compilation, not behavior.** "vue-tsc passes" means the TypeScript is syntactically valid. It says nothing about whether the UI works. A `fetch()` to a nonexistent endpoint is valid TypeScript.

2. **RALPH PM accepted build-only verification as proof of delivery.** The constitution says "UI compiles but not visually verified = NOT DONE." RALPH cannot do visual verification. It declared done anyway.

3. **The current PM (this session) tried to work around the broken wizard** by hacking localStorage to bypass onboarding, then started taking screenshots of downstream features as if the app was functional. This is the same failure mode — finding ways to say "it works" instead of admitting it doesn't.

## Root causes

- **"Compiles" ≠ "works"** is not enforced anywhere in the pipeline. Blue-team's definition of PASS is build + typecheck + existing tests pass. None of those catch a `fetch()` to a nonexistent endpoint.
- **No integration test exists** that actually launches the app and verifies the wizard can be completed end-to-end.
- **Agents are unreliable narrators** (this is already in the constitution but was not enforced). Every claim must be independently verified against the actual artifact.

## Remediation

### Research phase
- Audit all Sprint 201 "PASS" verdicts against what actually works
- Determine if any other shipped features have the same "compiles but broken" pattern

### Plan phase
- Add mandatory Playwright smoke test to blue-team verification for UI tasks: app launches, onboarding completes, target feature is reachable
- Update blue-team prompt template: "For UI tasks, build passing is NECESSARY but NOT SUFFICIENT. You must verify the feature is reachable and functional in the running app."
- Add to constitution: "Any PM that bypasses broken functionality to test downstream features is committing the same verification fraud as a blue-team that only checks compilation."

### Execute phase
- Update `gate` skill blue-team prompt template
- Update RALPH learnings with the enforcement rule
- Add Playwright smoke test to `apps/desktop/` that can be run by blue-team

### Verify phase
- Run the smoke test, confirm it catches the current breakage

## Closed

Cancelled per user direction. Process improvements partially addressed by confession processes (sdd-c, tdd-c) and visual verification mandate in constitution.
