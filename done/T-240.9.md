# T-240.9 — P0 OAuth client registry not persisted

**Pipeline**: sdd

## Problem

The MCP OAuth dynamic client registration (DCR) stores registered clients in an in-memory `Lazy<Mutex<OAuthState>>` (`oauth/mod.rs:24-25`). Every daemon restart wipes all registered `client_id`s. OpenCode persists its `client_id` to `~/.local/share/opencode/mcp-auth.json` and never re-registers, causing `client_id is not registered` errors after any restart.

## Audit findings (from OAuth code audit)

The entire OAuth surface is 941 LOC of hand-rolled code with zero references to the MCP SDK or spec:
- `oauth/{mod,authorize,token,register,metadata}.rs` = 578 LOC production
- `mcp/http_oauth_{helpers,tests}.rs` = 363 LOC tests
- None of this code cites the MCP auth spec or uses `oxide-auth` or any OAuth library
- The OAuth flow contributes zero real security beyond what the loopback + bearer token already provide
- `api/auth.rs` (121 LOC bearer middleware) is the only real security boundary — keep

## Options (PM to decide)

### Option A: Minimum fix — persist client registry (~30 LOC)
- Write `OAUTH_STATE.clients` to `auth/clients.json` on every `register_client`
- Load on startup
- Fixes OpenCode immediately
- Keeps the 941 LOC of unreferenced hand-rolled OAuth code

### Option B: Delete OAuth entirely — clients use bearer token directly (-941 LOC)
- Drop all `oauth/` files
- Remove OAuth routes from `http.rs`
- Clients configure `Authorization: Bearer <token>` directly from `auth/localhost.token`
- Claude Desktop, Cursor, Codex CLI all support per-server `headers.Authorization`
- OpenCode supports `--header` flag
- Constitution says: best code is no code

### Option C: Replace with `oxide-auth` + `oxide-auth-axum` (~150 LOC)
- Delete hand-rolled OAuth
- Add proper OAuth library
- Cited, tested, maintained by the community
