## Summary

Implement the endophasia wallpaper mode: on a timer, call `RecentActivity` (filter=all, includeContent=true, limit=10), prepend the user's prompt, send to Azure image model, save the result as the current wallpaper.

## Implementation

### 1. Create `crates/maenifold-core/src/wallpaper/endophasia.rs`

**Function:**

```rust
pub async fn generate_endophasia_wallpaper(
    config: &Config,
) -> anyhow::Result<PathBuf>
```

Steps:
1. Read wallpaper settings: `let wallpaper = &config.settings.easter_eggs.wallpaper;`
2. Call extracted RecentActivity functions directly (NOT via MCP dispatch):
   ```rust
   let rows = tools::collect_recent_activity_records(config, None, Some("all"), 10)?;
   let report = tools::format_recent_activity_report(rows, true);
   ```
3. Prepend `wallpaper.prompt` + `\n\n` + report
4. Create `ImageClient::from_config(wallpaper)?`
5. Call `client.generate(&prompt, &wallpaper.size, &wallpaper.quality).await?`
6. Save via `cache::save_image(&cache::cache_dir(&config.memory_path), "endophasia", "recent", &image_data)?`
7. Return the saved path

**Note:** `collect_recent_activity_records` and `format_recent_activity_report` are already extracted in `tools/recent_activity.rs` and `tools/recent_activity_format.rs`. Import and call them directly — do NOT go through MCP tool dispatch.

### 2. Create `crates/maenifold-core/src/wallpaper/service.rs`

**Wallpaper service** — background task on a timer:

```rust
pub async fn wallpaper_service(
    config: Arc<parking_lot::RwLock<Config>>,
    shutdown: CancellationToken,
)
```

Uses `tokio_util::sync::CancellationToken` (matches codebase convention from `teams/supervisor.rs` and `tray.rs`).

Loop pattern:
```rust
loop {
    tokio::select! {
        _ = shutdown.cancelled() => break,
        _ = tokio::time::sleep(interval) => {
            let cfg = config.read().clone();
            let wallpaper = &cfg.settings.easter_eggs.wallpaper;
            if !wallpaper.enabled {
                interval = Duration::from_secs(60); // check again later
                continue;
            }
            match wallpaper.mode.as_str() {
                "endophasia" => {
                    if let Err(e) = endophasia::generate_endophasia_wallpaper(&cfg).await {
                        // Log error, back off, don't tight-loop
                    }
                }
                _ => {} // future modes
            }
            interval = Duration::from_secs(wallpaper.rotate_minutes as u64 * 60);
        }
    }
}
```

**Credential handling:** If `ImageClient::from_config()` fails (missing env vars), log the error, set error state on `WallpaperServiceState`, and back off for 60s. Do NOT tight-loop retries on missing credentials.

### 3. Global service state via static

`WallpaperServiceState` must be accessible from both the async service AND the synchronous MCP tool handler (`fn(&ToolContext, &Value) -> Result<String>`). Since `ToolContext` cannot be extended with wallpaper state, use a process-global static (following the `endophasia::channel` pattern):

```rust
// In wallpaper/mod.rs or wallpaper/service.rs
use once_cell::sync::Lazy;
use parking_lot::RwLock;

pub struct WallpaperServiceState {
    pub last_generated: Option<chrono::DateTime<chrono::Utc>>,
    pub error: Option<String>,
}

static SERVICE_STATE: Lazy<RwLock<WallpaperServiceState>> =
    Lazy::new(|| RwLock::new(WallpaperServiceState { last_generated: None, error: None }));

pub fn service_state() -> &'static RwLock<WallpaperServiceState> { &SERVICE_STATE }
```

The service writes to `SERVICE_STATE` after each generation attempt. The `WallpaperStatus` MCP tool reads from `SERVICE_STATE`.

### 4. Create MCP tool `WallpaperStatus`

New tool in `crates/maenifold-core/src/tools/wallpaper_status.rs`:

Handler signature matches registry pattern:
```rust
pub fn wallpaper_status(context: &ToolContext, _payload: &Value) -> Result<String>
```

Response shape:
```json
{
  "enabled": true,
  "mode": "endophasia",
  "configured": true,
  "images": ["/absolute/path/to/endophasia_recent_1714147200.png"],
  "lastGenerated": "2026-04-26T15:00:00Z",
  "error": null
}
```

- `images`: calls `cache::list_images()` for the current mode, returns absolute paths (frontend converts to data URLs via preload IPC in T-232.4)
- `configured`: true if Azure env vars are set, false otherwise
- `lastGenerated`: from `WallpaperServiceState` or derived from most recent filename timestamp
- `error`: last error message from the service, or null

Register in `registry.rs` with `ToolDescriptor { name: "WallpaperStatus", aliases: &["wallpaperstatus"], invoke: tools::wallpaper_status }`.

### 5. Spawn from `mcp/http.rs`

**NOT `tray.rs`** — `tray.rs` is synchronous (winit event loop) and doesn't have the async runtime or shared config. The correct site is `crates/maenifold-core/src/mcp/http.rs::serve_http_listener_with_shutdown`, where:
- The Tokio runtime is running
- `config_mutation.runtime_config()` provides the shared `Arc<parking_lot::RwLock<Config>>` that reflects live frontend settings changes
- `shutdown_token` (CancellationToken) is available

Add after `config_mutation` creation:
```rust
let wallpaper_config = config_mutation.runtime_config();
let wallpaper_shutdown = shutdown_token.child_token();
tokio::spawn(async move {
    wallpaper::service::wallpaper_service(wallpaper_config, wallpaper_shutdown).await;
});
```
