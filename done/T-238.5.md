# T-238.5 - gate status panics on downstream broken pipe

**Pipeline**: tdd

## Problem

`gate status --root . --json` panicked when its stdout consumer exited early because a shell pipeline was wired incorrectly. CLI tools should handle downstream broken pipes without a Rust panic message.

## Evidence

- Active thinking session: `session-1777236650835-22077`
- Attempted command:
  - `gate status --root . --json | python3 - <<'PY' ...`
- Exact observed error:
  - `json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`
  - `thread 'main' (...) panicked at library/std/src/io/stdio.rs:1165:9: failed printing to stdout: Broken pipe (os error 32)`

## Expected behavior

- If stdout closes early, `gate` exits cleanly without a panic backtrace/panic banner.
- JSON status remains valid when the consumer is correctly connected.
- Shell misuse should not produce a product panic.

## File Scope

Keep the fix focused on CLI output handling:

- `crates/maenifold-gate/src/main.rs`
- `crates/maenifold-gate/src/status_command.rs`
- `crates/maenifold-gate/src/json_output.rs`
- focused CLI regression test file if an existing real-process CLI test target already exists

## Acceptance constraints

- Do not swallow non-broken-pipe I/O errors.
- Do not add broad panic suppression that hides unrelated panics.
- Do not change status JSON shape.
- Do not use mocks, stubs, or fake CLI processes.

## Acceptance criteria

- [ ] `gate status --root . --json | head -1` exits without a panic banner.
- [ ] The command returns either success or a conventional broken-pipe exit without Rust panic output.
- [ ] The behavior is covered by a focused CLI regression test if the test harness can exercise pipe closure without mocks.

## Verification

- Run `gate status --root . --json | head -1`.
- Confirm stderr does not contain `panicked`, `Broken pipe`, or a Rust backtrace banner.
- `cargo test -p maenifold-gate broken_pipe` if a focused real-process test is added.
- `cargo build --release -p maenifold-gate`.
