# T-203.2 — Parse `_meta.ui` from tool descriptions

## Problem

When the MCP client lists tools from connected servers, tool descriptions may include `_meta.ui.resourceUri` (a `ui://` URI pointing to the app's HTML resource). Our current tool capability model (`stores/agent-capabilities.ts`) does not parse or store this metadata.

## Fix

1. Extend the tool capability type to include optional `_meta.ui` fields:
   - `resourceUri: string` — the `ui://` URI
   - `csp?: string` — Content Security Policy directives
   - `permissions?: string[]` — requested iframe permissions (camera, mic, etc.)
2. Parse `_meta.ui` from tool listing responses in `agent-capabilities.ts` or `agent-capabilities-helpers.ts`.
3. When a tool call result arrives, check if the originating tool had `_meta.ui.resourceUri`. If so, flag the result for iframe rendering.

## Files likely modified

- `apps/desktop/src/stores/agent-capabilities.ts`
- `apps/desktop/src/stores/agent-capabilities-helpers.ts`
- `apps/desktop/src/lib/types.ts`

## Acceptance criteria

1. Tool capabilities include parsed `_meta.ui` when present
2. `_meta.ui` absent → no change to existing behavior
3. Typecheck passes (`npx vue-tsc --noEmit`)
