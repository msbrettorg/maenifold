# T-31.1: Create maenifold-app Crate with Tauri Runtime

**Requirement**: FR-41 (Native Desktop App via Tauri)

## Objective

Create a new workspace crate `crates/maenifold-app` that owns the Tauri v2 runtime. This crate provides a `pub fn run_app(port: u16)` function that opens a native Tauri webview window with the ACP UI frontend embedded.

## Acceptance Criteria

1. `crates/maenifold-app/Cargo.toml` exists as a workspace member with Tauri v2 deps (`tauri`, `tauri-plugin-opener`, `tauri-plugin-fs`, `tauri-plugin-store`, `tauri-plugin-dialog`)
2. `crates/maenifold-app/build.rs` calls `tauri_build::build()`
3. `crates/maenifold-app/tauri.conf.json` exists with:
   - `productName`: `maenifold`
   - `identifier`: `com.ma-collective.maenifold`
   - `frontendDist`: pointing at `../../vendor/acp-ui/dist`
   - No `beforeBuildCommand` / `beforeDevCommand` (we build frontend separately)
4. `crates/maenifold-app/src/lib.rs` exports `pub fn run_app(port: u16) -> i32` that:
   - Creates a `tauri::Builder` with required plugins
   - Calls `tauri::generate_context!()` to embed frontend assets
   - Runs via `app.run()` or `app.run_return()`
5. The Tauri IPC commands from `vendor/acp-ui/src-tauri/src/lib.rs` are ported into this crate (the `get_config`, `spawn_agent`, `send_to_agent`, etc. commands)
6. `Cargo.toml` (workspace root) adds `crates/maenifold-app` to members
7. Frontend must be pre-built: `cd vendor/acp-ui && npm install && npm run build` before `cargo build`
8. `cargo build -p maenifold-app` succeeds

## Files to Examine

- `vendor/acp-ui/src-tauri/Cargo.toml` — deps to replicate
- `vendor/acp-ui/src-tauri/src/lib.rs` — Tauri builder + IPC commands to port

- `vendor/acp-ui/src-tauri/capabilities/` — Tauri capability files to copy/adapt

### Non-blocking findings

**F1 — Vendor submodule pointer advanced (low severity)**
`git diff vendor/acp-ui` shows the outer repo's recorded submodule pin changed from `dc4882e` → `3d68fc6-dirty`. The submodule working tree additionally has `package-lock.json` modified (version bump from npm install) and an untracked `bun.lock`. No Rust or TypeScript source files inside `vendor/acp-ui` were modified. The npm artifacts are an expected side-effect of the required `npm install` prerequisite (AC7); the commit-pointer advance was not mentioned in the SWE notes and should be acknowledged. The outer repo should either commit the new pointer intentionally or reset the submodule to the previously-pinned commit.

**F2 — SWE notes contain a false claim (informational)**
The remediation notes state: *"removed `vendor/acp-ui/src-tauri` from the workspace `exclude` list"*. Inspection of the full git history for `Cargo.toml` shows no `exclude` section was ever present in any commit. This is a documentation inaccuracy only; the actual code change (adding `crates/maenifold-app` to `members`) is correct.

**F3 — `port` parameter unused (informational)**
`run_app(_port: u16)` silently drops the port. The spec only requires the signature accept `port: u16`, not that it be used. SWE acknowledged this. No action required for this task.
