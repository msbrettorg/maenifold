# T-45.1b: Backward Compatibility Verification

**Requirement**: FR-45.1
**RTM**: RTM-313
**Priority**: P0 — Regression gate

## Context

The pipeline engine adds new types, a new MCP tool, and new session status values. Existing serial workflow sessions (`queue: [A, B, C]`) must continue to work unchanged. This spec verifies backward compatibility.

## Scope

Verify that all existing workflow functionality is preserved after pipeline additions. No code changes expected — this is a verification-only spec.

## Acceptance Criteria

1. **Serial workflows work**: `workflow(workflowId="ftk-query")` creates and executes a session with sequential steps. The queue mechanism (`currentWorkflow`, `currentStep`) advances correctly.
2. **Existing session frontmatter**: Sessions created before pipeline changes can still be read, continued, and completed.
3. **Workflow tool unchanged**: The Workflow MCP tool's public API and behavior are identical to pre-pipeline behavior. No parameters removed, no defaults changed.
4. **Submachine lifecycle**: Workflow submachines (sequential thinking sessions linked via `activeSubmachineSessionId`) continue to register, resume, and clear correctly.
5. **Queue append**: `workflow(sessionId=X, append=...)` continues to add workflows to the session queue.

## Verification Approach

Run existing workflow tests. If they pass, backward compatibility is confirmed. The SWE agent should run:

```bash
cargo test -p maenifold-core --lib workflow -- --nocapture
cargo test -p maenifold-core --test workflow -- --nocapture
```

If any tests fail, investigate and fix — the failure is a regression introduced by pipeline changes.
