## Summary

`make audit` fails because `launchd.rs` (412 LOC) and `systemd.rs` (328 LOC) exceed the 300 LOC hard limit. Split both files to bring them under the limit. Deduplicate shared helpers.

## Current state

| File | LOC | Over by |
|------|-----|---------|
| `crates/maenifold-core/src/schedule/launchd.rs` | 412 | 112 |
| `crates/maenifold-core/src/schedule/systemd.rs` | 328 | 28 |

## Plan

### launchd.rs (412 → ~200 + ~135 + ~77)

1. **Extract tests** (lines 336-412, ~77 LOC) to `launchd_tests.rs`. Include via `#[cfg(test)] #[path = "launchd_tests.rs"] mod launchd_tests;` at the bottom of `launchd.rs`.

2. **Extract cron-to-plist helpers** (lines 150-275, ~126 LOC) to `launchd_cron.rs`:
   - `cron_to_start_calendar_interval_xml`
   - `expand_field`
   - `parse_number`
   - `render_calendar_dict`
   - Make them `pub(super)` so `launchd.rs` can call `cron_to_start_calendar_interval_xml`.

3. Register both new modules in `launchd.rs` (not in `schedule/mod.rs` — they're internal to `launchd`).

### systemd.rs (328 → ~200 + ~128)

1. **Extract cron translation helpers** (lines 135-258, ~124 LOC) to `systemd_cron.rs`:
   - `cron_to_oncalendar`
   - `translate_numeric_field`
   - `translate_weekday_field`
   - `translate_field`
   - `parse_number`
   Make them `pub(super)` so `systemd.rs` can call `cron_to_oncalendar`.

2. Keep the inline tests (only 20 LOC) in `systemd.rs` — not worth a separate file.

3. Register `systemd_cron` module in `systemd.rs`.

### Dedup validate_schedule_id

Both `launchd.rs` (line 284) and `systemd.rs` (line 259) have identical `validate_schedule_id`. Move it to `schedule/mod.rs` as `pub(crate) fn validate_schedule_id` and have both files import it.

### Module registration

Add to `schedule/mod.rs` — nothing. The new files are sub-modules of `launchd.rs` and `systemd.rs`, not of the `schedule` module.
