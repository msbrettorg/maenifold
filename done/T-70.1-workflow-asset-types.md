# T-70.1 — Workflow Asset Types

**Requirement**: Workflow Authoring — Stitch Screen 1
**Component**: `src/lib/workflow-asset-types.ts`

## Context

The app has `workflow-types.ts` (workflow execution/session types) and `pipeline-types.ts` (WorkflowNode for DAG). Neither models the workflow *definition* JSON returned by `ReadMcpResource` at `asset://workflows/{id}`. The authoring page needs types for the full schema: steps with metadata, toolHints, stop_conditions, triggers, sequentialThinkingEnabled, etc.

ListAssets returns: `{ id, name, emoji, description, multiAgent }`.
ReadMcpResource returns the full definition with steps, triggers, metadata.

## Acceptance Criteria

1. New file `src/lib/workflow-asset-types.ts` (< 120 LOC)
2. `WorkflowAssetSummary` interface matching ListAssets response: `{ id, name, emoji, description, multiAgent }`
3. `WorkflowAssetDefinition` interface matching full ReadMcpResource response: id, name, emoji, description, triggers, sequentialThinkingEnabled, multiAgent, steps
4. `WorkflowStepDefinition` interface: id, name, description, requiresSequentialThinking, metadata
5. `WorkflowStepMetadata` interface: toolHints (Record<string, ToolHint>), reasoning_effort ('low'|'medium'|'high'), stop_conditions (string[]), next_actions (string[]), escape_hatches (string[])
6. `ToolHint` interface: reason, priority ('mandatory'|'recommended'|'optional'), estimated_thoughts?
7. `WorkflowCategory` type union: 'reasoning' | 'scientific' | 'multi-agent' | 'devops' | 'memory' | 'custom'
8. Helper function `categorizeWorkflow(wf: WorkflowAssetSummary): WorkflowCategory` that derives category from name/description heuristics
9. `npx vue-tsc --noEmit` passes
