## Summary

Create a `DiscoverMcpTools` MCP tool and migrate the frontend from REST `GET /api/discovery/mcp-tools`.

## Backend

- New handler-intercepted MCP tool (same pattern as config mutation tools)
- Returns same shape as REST endpoint: `Vec<McpServerDiscoveryResult>` with per-server `{ server, type, status, error, tools[] }`
- Needs `ConfigMutationState` (for `ConfigManager::get_config()` to enumerate non-gateway MCP servers) plus `GatewayState`/`StdioPool` (for `all_gateway_tools()`)
- Add to `call_tool()` exception list and `list_tools()` gateway-mode allowlist
- Register schema in `mcp/schema/` + `mod.rs`

## Frontend

- Replace `fetch(\`\${DAEMON_BASE_URL}/api/discovery/mcp-tools\`)` with `DiscoverMcpTools` MCP tool call
- `appUi` extraction and stale-cache fallback remain frontend-local (no change to that logic)
- `deriveServerHealth()` remains frontend-local

## Acceptance criteria

- [ ] `DiscoverMcpTools` callable via MCP `tools/call`
- [ ] Returns same data as REST endpoint (server health, tool list)
- [ ] Frontend tool discovery works via MCP
- [ ] `appUi` and stale-cache behavior preserved
- [ ] No `fetch` calls to `/api/discovery/mcp-tools` remain
- [ ] `cargo build --release -p maenifold-cli` succeeds
- [ ] `vue-tsc --noEmit` passes
