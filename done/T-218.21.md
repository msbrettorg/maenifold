# T-218.21 — StdioPool Single-Flight Restart and Health

## Problem

When an upstream stdio MCP server dies, concurrent gateway calls can race into restart and spawn multiple replacement child processes. Startup failures are logged and omitted, but clients do not get structured gateway health explaining degraded upstream servers.

## Acceptance Criteria

- [ ] Per-server restart is single-flight: concurrent calls to the same dead server produce at most one replacement child process
- [ ] Restart backoff prevents tight loops after repeated spawn/init failures
- [ ] Gateway health includes per-server configured/enabled, running/degraded, last start error, last restart time, tool count, and resource count when available
- [ ] Health output redacts env values and secrets
- [ ] Tests simulate N concurrent calls against a dead fake server and assert one restart attempt
- [ ] Operational errors still preserve JSON-RPC error semantics
