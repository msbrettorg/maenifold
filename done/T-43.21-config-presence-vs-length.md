# T-43.21: configOptions presence vs length

**Requirement**: Config-options audit gap  
**Priority**: P1  
**Files**: `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/components/ChatView.vue`

## Acceptance Criteria

1. The spec says: if an agent provides `configOptions`, clients that support config options SHOULD use `configOptions` exclusively and ignore `modes`.

2. Current code keys off `configOptions.length`, not presence. If the agent returns `configOptions: []` with `modes: { ... }`, the client falls back to legacy modes. This is wrong.

3. Fix: check `'configOptions' in sessionResponse && sessionResponse.configOptions !== null` instead of `sessionResponse.configOptions?.length`.

4. In `ChatView.vue`, use `sessionResponse.configOptions !== undefined && sessionResponse.configOptions !== null` to decide whether to show ConfigOptionPicker vs legacy pickers. An empty array means "no options available" — it does NOT mean "use legacy modes."

5. Apply this fix in both `createSession` and `resumeSession` paths.

## SWE Remediation

- **What I changed**
  - `vendor/acp-ui/src/stores/session.ts`: added `hasConfigOptions` store state to track config-options support by field presence, not array length; updated both `createSession` and `resumeSession` to use `'configOptions' in sessionResponse && sessionResponse.configOptions !== null` before deciding whether to fall back to legacy modes/models; reset the flag on session teardown and keep it true when config-option updates arrive.
  - `vendor/acp-ui/src/components/ChatView.vue`: switched legacy picker visibility to use `hasConfigOptions` instead of `configOptions.length`, so an empty `configOptions` array suppresses the legacy mode/model pickers.

- **Test results**
  - PASS — `cd /Users/brett/src/ma-collective/maenifold-rs/vendor/acp-ui && npx vue-tsc --noEmit`

- **Notes**
  - I used a dedicated presence flag in the store because the existing `configOptions` state only stores the parsed array, which cannot distinguish “field absent” from “field present but empty.”
