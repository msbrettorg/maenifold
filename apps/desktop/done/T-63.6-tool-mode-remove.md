# T-63.6 — Remove or Implement tool_mode

**Requirement**: FR-8
**Test Cases**: TC-19
**Repo**: maenifold-rs
**Component**: crates/maenifold-core/src/workflow/pipeline/types.rs, executor.rs

## Context

`tool_mode` field exists in the schema but executor names it `_tool_mode` and ignores it — dead code. It either needs to work or be removed.

## Acceptance Criteria

**Decision: REMOVE tool_mode entirely.** Rationale: tool invocation is better modeled as a dedicated Tool node type (T-63.11) rather than a mode flag on every node.

1. Remove `tool_mode` from `PipelineNodeWire` struct
2. Remove `tool_mode` / `_tool_mode` from executor dispatch functions
3. Remove any `tool_mode` references in view.rs and dispatch.rs
4. Wire format backwards compat: if incoming JSON has `"toolMode"`, silently ignore it (don't error). Use `#[serde(default)]` or deny_unknown_fields exception.
5. Update frontend `pipeline-types.ts`: remove `toolMode` from PromptNode and SequentialThinkingNode interfaces
6. ALL existing pipeline tests pass: `cargo test -p maenifold-core -- pipeline`
7. Add a test: deserialize JSON with `"toolMode": "allowed"` → succeeds (field ignored, no error)
