## Problem

T-221.12 spec received FAIL from both duo architects (Opus 4.7 + GPT 5.5). Seven findings require spec revision before SWE dispatch.

## Findings to address

### 1. Missing scope: SettingsMcpServers.vue
MCP server CRUD (`POST/PUT/DELETE /api/config/mcp-servers`) is not in the scope table. Add `AddMcpServer`, `UpdateMcpServer`, `DeleteMcpServer` tools.

### 2. GatewayIndex ≠ tool discovery
`GatewayIndex` is a routing catalog, not a discovery surface. Missing: per-server health/status, `appUi` metadata (Inline MCP Apps), stale-cache fallback. Either extend GatewayIndex with a `verbose` mode or design a separate `DiscoveryStatus` tool. Phase 1 is the highest-risk phase — consider moving to Phase 5.

### 3. GetConfig response shape mismatch
REST returns `agents` as `Record<string, AgentConfig>`, MCP returns agents as array. Sensitive env values redacted differently. Need normalizers or a backend raw mode.

### 4. Config mutation tools under-specified
Need explicit tool designs for: `ReloadConfig`, `UpdateSettings` (partial-update semantics to avoid clobbering redacted secrets), `AddAgent`, `UpdateAgent`, `DeleteAgent`, `AddMcpServer`, `UpdateMcpServer`, `DeleteMcpServer`.

### 5. config:// resources don't exist
Backend subscription infrastructure exists but no `config://` resource family is registered. Need: resource registration, read handlers, watcher, subscribe allowlist update, notification emission. Define URI scheme and whether notifications carry payload or just URI.

### 6. MCP auth gap for writes
Current REST writes use `authenticatedFetch`. MCP transport doesn't attach auth headers. Define security model before adding write tools.

### 7. README overclaims
- Gate row lists `gate-pass`/`gate-fail` — verify UI actually calls these
- Settings row lists `UpdateSettings` which doesn't exist yet
- "audit logs and rate limits apply uniformly" — verify middleware exists
- Word as target architecture until migration complete
