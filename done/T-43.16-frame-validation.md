# T-43.16: ACP frame validation (inbound + outbound)

**Requirement**: Transports audit gap  
**Priority**: P1  
**Files**: `crates/maenifold-core/src/acp/relay.rs`, `crates/maenifold-app/src/agent.rs`

## Acceptance Criteria

1. **Outbound validation (client → agent stdin)**: Before writing to agent stdin, verify the message is valid JSON (parseable) and contains no embedded newlines. If it contains embedded newlines, compact it (re-serialize). If not valid JSON, reject with an error.

2. **Inbound validation (agent stdout → client)**: Before forwarding agent stdout lines to the WebSocket (relay.rs) or Tauri IPC (agent.rs), verify each line is valid JSON. If a line is not valid JSON, log a warning and skip it — do not forward non-JSON-RPC data to the client.

3. **Embedded newline prevention**: Add a debug assertion or defensive strip on outbound messages: `debug_assert!(!msg.contains('\n'))` or re-serialize to compact JSON before writing.

## SWE Remediation
- **What changed**
  - `crates/maenifold-core/src/acp/relay.rs`: added outbound ACP frame validation/compaction before stdin writes, added inbound stdout JSON validation with warning-and-skip behavior for invalid frames, and added focused relay unit coverage for the new transport checks.
  - `crates/maenifold-app/src/agent.rs`: added the same outbound compaction/validation for Tauri-to-agent stdin writes plus inbound stdout filtering so only valid JSON frames are emitted to the app client.
- **Test results**
  - PASS — `cargo test -p maenifold-core --lib relay_ -- --nocapture`
- **Notes**
  - Outbound frames are normalized by parsing and re-serializing JSON, which removes transport newlines while preserving escaped `\\n` content inside JSON strings.
  - Invalid inbound stdout frames are logged with `eprintln!` and dropped so transport clients only receive valid JSON payloads.
  - I did not run a separate `maenifold-app` build/test because the SWE prompt limited verification to the scoped commands above; the app-side change mirrors the validated relay logic.

## Red-team Audit

  - `relay.rs`: ✅ `validate_outbound_frame(&payload)` is called inside the WebSocket `Message::Text` branch before any stdin write (lines ~75–84). If invalid JSON, an error message is sent to the WebSocket client and the iteration `continue`s without touching stdin.

- **AC2 (inbound validation — agent stdout → client)**:
  - `relay.rs`: ✅ `normalize_inbound_frame(&line, "stdout")` is called for every stdout line (loop ~line 100). Returns `None` for non-JSON, which causes the line to be silently skipped via `if let Some(line) = ... { socket.send(...) }`. Invalid lines produce an `eprintln!` warning.
  - `agent.rs`: ✅ `normalize_inbound_frame(&message, &agent_id_clone, "stdout")` is called in the stdout-reading thread (lines ~152–159) with a `let Some(...) else { continue; }` guard. Only valid JSON frames reach `app_handle_clone.emit("agent-message", ...)`.

- **AC3 (debug assertion / embedded newline prevention)**:
  - `relay.rs` `validate_outbound_frame`: ✅ `debug_assert!(!compact.contains('\n'))` after re-serialization (relay.rs within the function body).
  - `agent.rs` `validate_outbound_frame`: ✅ Same `debug_assert!(!compact.contains('\n'))` inside the function; additionally a second `debug_assert!(!message.contains('\n'))` is present in `send_message` after the call (line ~203), providing belt-and-suspenders coverage in debug builds.

- **Unit tests**: ✅ `relay.rs` test module covers: `relay_compacts_outbound_json_frames_before_writing`, `relay_rejects_invalid_outbound_json_frames`, `relay_skips_invalid_inbound_stdout_frames`, `relay_compacts_valid_inbound_stdout_frames`. `agent.rs` test module covers the parallel set: `agent_compacts_outbound_json_frames_before_writing`, `agent_rejects_invalid_outbound_json_frames`, `agent_skips_invalid_inbound_stdout_frames`.
