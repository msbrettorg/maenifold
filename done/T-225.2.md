# T-225.2 — Migrate useGateTaskDetail to Gate MCP Tools

## Problem

`apps/desktop/src/composables/useGateTaskDetail.ts` reads task body and history via the maenifold MCP resource path (`gate://task/{id}`, `gate://history/{id}`). These resources are served by hand-rolled code in `crates/maenifold-core/src/mcp/resources/gate_task.rs` and `gate_history.rs` that parses markdown directly instead of using the gate tool.

## Fix

Switch `useGateTaskDetail.ts` to use `useGateMcp().readTaskBody()` and `readTaskHistory()` — these call the real gate MCP tools which use pipeline definitions.

After migration, delete `apps/desktop/src/lib/gate-resources.ts` (no remaining consumers) and remove dead `isPipelineStage` from `gate-display.ts`.

## Subscription Strategy

The current composable uses `resources.subscribeResource()` for live-refresh of task body and history. Gate MCP tools are request-response only — there is no equivalent subscription channel.

**Decision: Drop resource subscriptions entirely.** Task detail refresh relies on explicit reloads (user navigates to a task) and the existing gate status polling cycle. Per-poll-interval latency on detail panes is acceptable since task files change infrequently and only during gate operations.

Remove all subscription-related code: `stopTaskBodySubscription`, `stopTaskHistorySubscription`, and the `subscribeResource()` calls.

## Key Files

- `apps/desktop/src/composables/useGateTaskDetail.ts` — switch from `resources.readResource()` + `resources.subscribeResource()` to `useGateMcp().readTaskBody()` and `readTaskHistory()`. Remove subscription logic. Update `UseGateTaskDetailOptions` to remove `resources: McpResources` and add `gateMcp: ReturnType<typeof useGateMcp>` (or instantiate `useGateMcp()` internally). Remove `stopTaskDetailWatchers` export (callers updated below).
- `apps/desktop/src/components/GateView.vue` — stop constructing/passing `useMcpResources()` if it becomes unused. Remove `detail.stopTaskDetailWatchers()` call. Pass `gateMcp` instance if the composable requires it via options.
- `apps/desktop/src/lib/gate-resources.ts` — delete (sole consumer is `useGateTaskDetail.ts`)
- `apps/desktop/src/lib/gate-display.ts` — remove dead `isPipelineStage` export (zero consumers confirmed)

**Note:** Backend `gate_task.rs` / `gate_history.rs` resource handlers remain — their removal is T-225.3.

## Acceptance Criteria

- [ ] `useGateTaskDetail` reads task body and history via `useGateMcp()` tools, not `gate://` resources

- [ ] `UseGateTaskDetailOptions` no longer requires `resources: McpResources`

- [ ] No remaining imports of `gate-resources` anywhere in desktop src
