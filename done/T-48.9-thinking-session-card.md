# T-48.9 — Component: `ThinkingSessionCard`

**Requirement:** FR-48
**Component:** `vendor/acp-ui/src/components/`

## Summary

Vue component that renders a sequential thinking session as an expandable thought chain.

## Acceptance Criteria

1. Create `vendor/acp-ui/src/components/ThinkingSessionCard.vue`
2. Props: `node: ThinkingSession` from `workflow-types.ts`
3. Renders:
   - **Header**: 🧠 icon, session ID (truncated), thought count badge (e.g., "5 thoughts"), status badge
   - **Thought chain**: vertical timeline of thoughts, each showing:
     - Thought number pill (e.g., "0/5")
     - Content rendered as markdown (compact, max 3 lines collapsed)
     - `[[WikiLinks]]` rendered as styled pills
     - Timestamp (relative)
   - **Conclusion**: if present, rendered in a distinct card section with subtle border
4. Collapsed by default — shows header + thought count only
5. Expand/collapse animation (smooth height transition)
6. Dark theme matching WorkflowNodeCard
7. Connector line on the left side (vertical timeline aesthetic)

## Design

- Card width: ~280px (slightly narrower than workflow cards)
- Background: `#1a1c24` (slightly darker than workflow cards)
- Border-left: 3px purple/violet (distinguishes thinking from workflow)
- Thought pills: small rounded badges, monospace numbers
- Timeline connector: 2px line connecting thought pills vertically
- WikiLink pills: `#2d3748` background, `#90cdf4` text, rounded corners

### Advisory Findings

**[Medium] Thought content is permanently clamped at 3 lines — no per-thought expansion**

`.thought-content` unconditionally applies `-webkit-line-clamp: 3` (lines 439–441). The spec says *"compact, max 3 lines **collapsed**"*, implying a collapsed state that could be expanded. However the spec never defines a per-thought expand interaction. The result is that thoughts longer than 3 lines are permanently truncated. The browser renders a native `…` at the clip point, so there is a visual affordance, but no mechanism exists to read the full content. If maenifold thinking sessions produce long reasoning chains this silently discards information. Recommend either (a) clarifying the spec as intentional always-compact, or (b) adding a per-thought expand toggle in a follow-up ticket.

**[Low] `v-html` rendered from unsanitized `marked.parse()` output**

`renderMarkdown()` first substitutes `[[WikiLinks]]` using `escapeHtml()` (correct), then passes the result through `marked.parse()` which renders raw HTML by default. The output is injected via `v-html` (lines 207, 221). A thought entry containing e.g. `<img src=x onerror="…">` would execute in the renderer process. In the current local-only desktop context the exploitability is low (data originates from the local maenifold graph, not untrusted user input), but it is a latent XSS sink. Recommend adding `marked.use({ hooks: { postprocess: sanitize } })` or a DOMPurify pass before `v-html` assignment as a hardening measure.
