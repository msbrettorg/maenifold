# T-68.4: ACP Session List and Load Support

## Requirement
FR-50 — Native ACP client should support listing and loading existing sessions.

## Problem
`native.rs` always creates new sessions via `new_session`. There is no `load_session` or `list_sessions` path. `AgentCapabilities.load_session` from init response is discarded. For long-running workflows and pipeline restarts, all prior context is lost.

## Acceptance Criteria
1. `AgentHandle` must expose `list_sessions()` returning `Vec<SessionInfo>` (paginated)
2. `AgentHandle` must expose `load_session(session_id)` for agents that advertise `load_session = true`
3. `open_agent_session()` should accept an optional `existing_session_id` to load instead of create
4. Pipeline restart logic should attempt `load_session` before creating new for nodes with existing session IDs
5. Guard: only call `list_sessions` when agent advertises `session_capabilities.list`
6. Guard: only call `load_session` when agent advertises `capabilities.load_session = true`

## Files to modify
- `crates/maenifold-core/src/acp/native.rs` — add list_sessions, load_session commands
- `crates/maenifold-core/src/workflow/agent_session.rs` — optional existing session load
- `crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs` — load on restart
