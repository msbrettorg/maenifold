# T-43.18: session_info_update must target by sessionId

**Requirement**: Session-list audit gap  
**Priority**: P1  
**Files**: `vendor/acp-ui/src/stores/session.ts`

## Acceptance Criteria

1. The `session_info_update` handler currently only updates `currentSession.value`. It ignores the notification's `sessionId` field. Once `session/list` is implemented (T-43.2), non-active sessions discovered via listing will go stale.

2. Update the handler to use the notification's `sessionId` to find the correct session in `savedSessions` and update it, regardless of whether it's the active session.

3. If the notification targets the active session, also update `currentSession.value`.

## SWE Remediation

- **What changed**
  - `vendor/acp-ui/src/stores/session.ts`: updated the `session_info_update` notification handler to target sessions by `sessionId`, update the matching entry in `savedSessions`, keep `currentSession.value` in sync only when the notification targets the active session, and persist saved-session changes after title/lastUpdated updates.
  - `todo/T-43.18-session-info-target.md`: appended this remediation summary.

- **Test results**
  - PASS — `cd vendor/acp-ui && npx vue-tsc --noEmit`

- **Notes**
  - The handler now ignores `session_info_update` payloads that do not include a string `sessionId`, which keeps updates scoped to explicit ACP session targets.

## Red-team Audit

**Verdict: PASS**

All acceptance criteria verified against `vendor/acp-ui/src/stores/session.ts` lines 377–411:

- **[AC1] Handler previously ignored `sessionId`**: ✅ Old behaviour confirmed absent. The handler is now gated at line 378 — `if ('sessionId' in update && typeof update.sessionId === 'string')` — so the entire block only executes when a valid string `sessionId` is present. Payloads without it are silently ignored, exactly as the SWE claims.

- **[AC2] Find and update correct session in `savedSessions` regardless of active session**: ✅ Line 385 does `savedSessions.value.find(s => s.sessionId === update.sessionId)`. Lines 387–396 update `saved.title` and `saved.lastUpdated` when `saved` is truthy, independently of whether it is the active session. This handles non-active sessions correctly.

- **[AC3] Also update `currentSession.value` when notification targets the active session**: ✅ Lines 398–405 check `currentSession.value?.sessionId === update.sessionId` and mirror the same `title` and `lastUpdated` mutations onto `currentSession.value`. The two branches are independent, so a session that is both in `savedSessions` and is the current session gets both updates.

- **[Bonus — persistence]**: ✅ `shouldPersistSessions` flag (line 384) is set to `true` on any mutation to `saved` (lines 390, 394), and `saveSessionsToStore()` is called at line 408 when the flag is set. Persistence is not triggered for current-session-only updates (i.e., when the session is active but not yet in `savedSessions`), which is the correct behaviour — `currentSession` is sourced from `savedSessions` in practice.
