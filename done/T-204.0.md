# T-204.0 — Epic: Adopt Handy speech-to-text companion

## Problem

maenifold desktop has no voice input capability. Users must type everything. Speech-to-text is table-stakes for an AI desktop app.

## Approach

**Adopt [Handy](https://github.com/cjpais/Handy)** as an external companion process. Handy is a free, open-source, cross-platform desktop speech-to-text app (Tauri 2.x, Rust + React, MIT license). It runs entirely local — Whisper models (GPU) or Parakeet V3 (CPU). User installs Handy separately, configures their hotkey in Handy's settings, and Handy pastes transcribed text into whatever input has focus.

**Working reference implementation** exists at `/Users/brett/src/agency-cowork` (Electron + React). The integration is ~150 LOC. We port the pattern to our Vue stack.

**maenifold's only jobs:** detection, launch/foreground, and running indicator. We do NOT own recording, transcription, clipboard, hotkeys, or audio.

## Architecture

```
User installs Handy separately (brew/winget/manual)
    ↓
maenifold Electron main process
    ↓ IPC: voice:check
Detects Handy binary via which/where + known install paths
    ↓ IPC: voice:launch
Launches Handy detached (or brings to foreground if running)
    ↓
VoiceInputButton.vue shows running indicator (6px green bead)
    ↓
User presses Handy's hotkey → speaks → Handy pastes via clipboard
```

## Trust boundary

Handy is a **user-installed third-party binary**. We launch whatever `which handy` resolves to. No signature/hash verification in v1 (Handy's Homebrew cask and winget package are not maintained by Handy developers). IPC surface is intentionally narrow: `voice:check` (read-only) and `voice:launch` (spawn detached, no args in v1).

## Design compliance (DESIGN.md)

- Mic button: 32×32 ghost button, lucide `Mic` icon, 4px radius
- Status: 6px circle bottom-right, `#0E9C57` when running
- Tooltip (sentence case): "Launch Handy to dictate" / "Open Handy — use its hotkey to record"
- Settings: new "Voice input" section in SettingsPreferences.vue

## Platform coverage

| Platform | Status | Notes |
|----------|--------|-------|
| macOS | Supported | `brew install --cask handy`. Needs mic + accessibility permissions. |
| Windows | Supported | `winget install cjpais.Handy`. Multiple install paths. |
| Linux X11 | Best effort | Needs `xdotool`. |
| Linux Wayland | Best effort | Needs `wtype`/`dotool`. Known issues with focus/overlay. |

## Scope redlines (out for 204)

- ❌ Embed whisper-rs, transcribe-rs, cpal, vad-rs, or any ML/audio library
- ❌ Capture microphone audio in renderer or main process
- ❌ Intercept or read the system clipboard
- ❌ Bundle Handy binary inside the maenifold installer
- ❌ Use Handy CLI flags (--toggle-transcription, --cancel) in v1
- ❌ Register global hotkeys in maenifold (Handy owns hotkeys)
- ❌ Change maenifold.json schema or any Rust/ACP surface
- ❌ Streaming/realtime transcript UI, waveform, custom overlay
- ❌ Linux parity guarantees
