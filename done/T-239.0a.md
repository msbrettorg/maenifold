# T-239.0a - Gate CLI missing from Copilot PATH during required fallback

**Pipeline**: lightweight

## Problem

After recording that the gate MCP surface was unavailable in this Copilot CLI session, the old CLI fallback also failed because `gate` is not present in `PATH`.

That fallback is no longer valid. Standalone `gate` is banned and deprecated. Gate functionality is now available through maenifold's integrated `maenifold.gate` Gateway domain.

This is a PM environment/meta task. It records the fallback failure and does not block the Teams Monitor implementation chain T-239.1 through T-239.5.

## Attempted operation

```text
gate sync --root . --rebuild && gate status --root . --json
```

## Exact error

```text
bash: gate: command not found
```

## Expected behavior

The Copilot CLI session should have:

- native maenifold gateway tools exposed; or
- a documented maenifold HTTP MCP GatewayExecute fallback.

It must not rely on a repository-local or installed standalone `gate` binary.

## Ralph pickup

The repository has already been changed so the standalone binary does not come back:

- root `Cargo.toml` excludes `crates/maenifold-gate` from workspace members.
- `crates/maenifold-gate/Cargo.toml` no longer declares `[[bin]] name = "gate"`.
- `crates/maenifold-gate/src/main.rs` is deleted.
- `rebuild.sh` no longer builds `maenifold-gate`.
- `maenifold-gate-core` remains and must remain: it backs the integrated `maenifold.gate` tool domain.

Current verification state:

- `cargo build --release -p maenifold-cli` passes.
- `find target -type f -perm -111 -name gate -print -quit` prints nothing.
- Desktop Electron no longer starts `com.ma-collective.gate` on port 8081.
