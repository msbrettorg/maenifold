# T-204.8 — Regenerate embeddings action fails with "no such module: vec0"

**Pipeline**: sdd
**Pipeline Digest**: pending

## Problem

The `EmbeddingModels` tool's `regenerate` action fails with:
```
Error invoking EmbeddingModels: Failed to clear embeddings: no such module: vec0
```

The UI button works (dialog appears, confirms), but the backend errors silently. No error is shown to the user.

## Root Cause

The `handle_regenerate()` function in `embedding_models.rs` tries to clear a `vec0_embeddings` table, but:
1. The vec0 SQLite extension may not be loaded in the tool's DB connection
2. The actual vector tables live in `memory.db` (`vec_memory_files`, `vec_concepts`), not in `maenifold.db`

The regenerate action needs to trigger the maenifold sync/indexing pipeline to re-embed all files, not directly manipulate vec0 tables.

## Acceptance Criteria

1. `EmbeddingModels { action: "regenerate" }` completes successfully
2. Vector counts in `memory.db` change after regeneration
3. UI shows success toast or progress indicator during regeneration
4. UI shows error toast if regeneration fails

## Evidence

- CDP test: Button clicked → dialog confirmed → backend returned error
- MCP call: `curl -X POST http://localhost:8080/mcp` with regenerate action → `isError: true`
- Vector tables are in `memory.db`, not `maenifold.db`
