# T-207.3 — ToolRoutingRegistry

## Requirement

Create a `ToolRoutingRegistry` that maps tool names to their owning server, built from StdioPool discovery + native tool registry.

## Interface

```rust
pub struct ToolRoutingRegistry { /* ... */ }

impl ToolRoutingRegistry {
    /// Build from native tools + gateway pool tools.
    /// Returns Err on tool name collision (same name from two servers, or gateway shadowing native).
    /// Checks ALL invocable names, including any aliases in the native registry.
    pub fn build(native_tools: &[Tool], pool: &StdioPool) -> Result<Self>;

    /// Look up which server owns a tool. None = native tool.
    pub fn lookup(&self, tool_name: &str) -> Option<&str>;

    /// All gateway tools (for inclusion in tools/list response).
    /// Returns cloned Tool definitions — no schema mutation.
    pub fn gateway_tools(&self) -> Vec<Tool>;
}
```

## Collision Detection

Must check against:
1. Native maenifold tool names from `ToolRegistry`
2. Native tool aliases (if any exist in the registry)
3. Other gateway server tool names

Collision = hard error with message: `"Tool name collision: '{tool}' is provided by both '{server_a}' and '{server_b}'"`.

The rmcp `Tool` struct's `inputSchema` MUST be passed through without mutation — no deduplication or `$ref` rewriting.
