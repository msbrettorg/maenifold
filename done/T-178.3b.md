# T-178.3b — graph:// URI — concept template (graph://concept/{name})

## Intent

Per-concept local subgraph reads, exposed as a templated MCP resource. Lets dashboards and agents fetch "what does this concept connect to" directly from the resource layer (instead of round-tripping through `tools/call Visualize`) and lets them subscribe to per-concept change notifications. Builds on the Visualize graph-mode walker from [[T-178.1]] and the URI / subscribe primitives from [[T-178.2]].

## Scope

1. Define and register one templated resource in `crates/maenifold-core/src/mcp/resources.rs`:

   | URI template | Read returns | Updated when |
   |---|---|---|
   | `graph://concept/{name}` | `{ center, nodes: [{name, depth}], edges: [{source, target, weight}], generated_at }` (shape matches T-178.1 graph-mode output) | Any write/edit changes the concept's edge set |

2. Register the template in `resources/templates/list` per spec — do NOT enumerate every concept in `resources/list`. The template entry includes `uriTemplate: "graph://concept/{name}"`, name, description, and `mimeType: "application/json"`.

3. Read implementation: parse `{name}`, URL-decode, canonicalize (see rule 4), then call `walk_local_subgraph` from [[T-178.1]] with `depth=2, max_nodes=40`. Defaults are `const`s in `resources.rs` and documented in the help doc.

4. **URI encoding & canonicalization rules** — frozen contract:
   - Concept names in URIs are **percent-encoded UTF-8**. Spaces become `%20`, not `+`.
   - On read, percent-decode → trim → apply the same canonicalization the write path uses (the existing `[[WikiLink]]` normalizer; do not invent a new one). Document explicitly in `assets/help/resources/graph.md` which characters are preserved and which are folded.
   - Round-trip rule: for any concept `C` known to the graph, `read(graph://concept/{percent_encode(C)})` returns a payload with `center == C` (the canonical form, not necessarily the input string).
   - Unknown concept (post-canonicalization, no matching node in the graph) → spec-compliant `resources/read` error (`-32002` or whatever rmcp surfaces for not-found) with message `"unknown concept: <canonical>"`.

5. **Concept-diff tracking** for emitters:
   - On every memory write/edit that changes the WikiLink set of a file, compute `(added_concepts, removed_concepts)` against the previous indexed state of that file.
   - For each concept `X` whose edges changed (i.e., `X` was added or removed from the file, OR a co-occurring concept was added/removed), fire `notify_resource_updated(format!("graph://concept/{}", percent_encode(X)))`.
   - Also fire `notify_resource_updated("graph://corpus/snapshot")` (coalesced — leverages the throttle from T-178.3c if landed; otherwise a local coalescer here, refactor when 3c lands).
   - The diff lives in the existing write/edit pipeline; this task adds a hook, not a new indexer pass.

6. Tests:
   - `resources/templates/list` includes the `graph://concept/{name}` template entry.
   - Read on a known concept (with neighbors) returns the documented shape, and `center` matches the canonical form.
   - Read on a concept name containing a space, an apostrophe, and a non-ASCII character round-trips correctly when properly percent-encoded.
   - Read on an unknown concept returns a spec-compliant error.
   - Write a memory file that adds `[[X]]` and `[[Y]]` co-occurring → notifications fire on `graph://concept/X` and `graph://concept/Y` (and on `corpus/snapshot`).
   - Edit the same file to remove `[[Y]]` → notification fires on `graph://concept/Y` (so subscribers see it dropped) and on `graph://concept/X` (its neighbor set changed).

## Files in scope

- `crates/maenifold-core/src/mcp/resources.rs` (template registration, read dispatch, URI parsing)
- Memory write/edit pipeline — minimal touches to add the concept-diff hook
- `assets/help/resources/graph.md` (append a section documenting the template, URI encoding, canonicalization, update conditions)

## Acceptance criteria

1. `cargo test -p maenifold-core` passes.
2. `resources/templates/list` includes the `graph://concept/{name}` entry.
3. Reading a known concept returns the documented JSON shape with `center == canonical(input_name)`.
4. URI percent-encoding rules are documented in `assets/help/resources/graph.md` and verified by tests including spaces, punctuation, and non-ASCII characters.
5. Unknown concept reads return a spec-compliant not-found error.
6. Concept-diff emitters fire only on the affected concepts, not on every concept in the file.

## Out of scope

- Activity stream + throttling primitive (T-178.3c).
- Dashboard consumption (T-178.4).
