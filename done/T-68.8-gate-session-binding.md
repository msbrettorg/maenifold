# T-68.3 — Gate Session Binding

**Requirement**: FR-68
**Status**: pending

## Summary

Make `gate_sync` mandatory as the first MCP call in any session. When called, it binds the session to that project root. All subsequent tool calls use the bound root — no `root` parameter needed. If any tool is called before `gate_sync`, return a clear initialization error.

## Acceptance Criteria

1. `GateHandler` gains a `bound_root: Option<PathBuf>` field (session-scoped state)
2. `gate_sync` sets `bound_root` to the synced root on success
3. All other tools (`gate_pass`, `gate_reject`, `gate_append`, `gate_status`) check for bound root:
   - If `root` param provided → use it (explicit override)
   - If `root` param omitted AND session bound → use bound root
   - If `root` param omitted AND no binding → return error: `"No gate bound to this session. Run gate_sync with a root path first to initialize."`
4. Same semantics in stdio mode (single session, same binding)
5. `GateHandler` uses interior mutability (`std::sync::Mutex` or `tokio::sync::Mutex`) for the bound root since `ServerHandler` methods take `&self`
6. `gate_list_gates` does NOT require session binding (works immediately)
7. Session binding persists for the lifetime of the MCP session
8. All existing 95 tests pass
9. Both feature configurations build clean

## Files

- `src/mcp/mod.rs` — add `bound_root: Mutex<Option<PathBuf>>` to `GateHandler`
- `src/mcp/tools.rs` — update dispatch to accept optional bound root, apply fallback logic, return init error when unbound

## Architecture

The rmcp `StreamableHttpService` creates a fresh `GateHandler` per HTTP session via the factory closure. This gives us natural session isolation — each handler instance has its own `bound_root`. No shared state between sessions.

For stdio, there's one handler instance for the connection lifetime — same semantics.

### RT-68.8-A — MEDIUM: Bound root stored as raw un-canonicalized client string

In prepare_args for gate_sync, synced_root is PathBuf::from(raw_client_string). If the client
sends "." or "../relative" the bound_root stores that literal value. When injected into subprocess
calls as --root, the path resolves relative to the MCP server CWD, not the caller CWD.
The registry auto_register does canonicalize via normalize_root, so registry entries and
bound_root can diverge for the same project when non-absolute paths are used.

Fix: canonicalize root in prepare_args before storing as synced_root, or document and enforce
absolute paths in gate_sync schema.

### RT-68.8-B — LOW: Dual unbound-session error paths require synchronized maintenance

SESSION_INIT_ERROR is checked in two places: early guard in mod.rs call_tool() via
requires_bound_root(), and fallback in tools.rs inject_bound_root(). If a new bound-only tool
is added to one gate but not the other, the defense-in-depth silently degrades. Currently
correct but fragile as the tool list grows.

Fix: add a code comment explaining the dual-guard contract, or collapse to a single check.

### Informational
- gate_sync always requires explicit root — correct, binding call must always receive its root.
- prepare_args for gate_sync does take+re-insert of root key to validate presence and preserve
  it for the dispatch body. Correct but non-obvious; a comment would improve maintainability.

### RT-68.8-A Fix: Canonicalize Bound Root

prepare_args for gate_sync (tools.rs lines 207-215):

  let root = required_string(args, "root")?;
  args.insert("root".into(), Value::String(root.clone()));
  Ok(Some(std::fs::canonicalize(&root).unwrap_or_else(|_| PathBuf::from(&root))))

Canonicalization before synced_root: fs::canonicalize is called and returned as Some(...) -> assigned to synced_root in DispatchResult -> stored as bound_root in mod.rs on dispatch success. The canonicalized value reaches session state before any subsequent tool call. Correct.

Fallback to raw path on error: unwrap_or_else(|_| PathBuf::from(&root)) — if canonicalize fails (path does not yet exist, permissions), falls back to PathBuf::from(&root). Matches the spec requirement. Correct.

Subprocess isolation: The re-inserted raw root string is passed to the gate subprocess unchanged. Only the session binding stores the canonicalized form. This preserves correct CWD-relative resolution for the subprocess while fixing the divergence between bound_root and registry entries for inputs like '.'.
