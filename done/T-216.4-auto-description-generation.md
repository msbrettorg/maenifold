# T-216.4 — Auto-Description Generation

**Pipeline**: sdd
**Priority**: P1

## Scope

Implement `generate_server_description()` in `gateway_consolidation.rs` (~50 LOC addition).

## What to Build

Given a server name and its list of `Tool` definitions, produce a concise description for the facade tool that helps the LLM decide whether to use this server.

### Algorithm

1. Collect all tool names and descriptions from the server
2. Extract unique domain keywords (nouns/verb phrases) from descriptions
3. Deduplicate and group by frequency
4. Build a summary sentence: "{server_name} — {capability summary}. Set learn=true to discover available commands."

### Examples

Input: azure-mcp-server with tools like `subscription_list`, `compute_vm_list`, `cosmos_list`, `monitor_metrics_query`...

Output: "Azure MCP Server — manage Azure infrastructure including subscriptions, compute VMs, Cosmos DB, monitoring, storage, networking, and more. Set learn=true to discover available commands."

Input: discovery-workbench with tools like `submit_job`, `get_job_logs`, `list_nodepools`, `upload_input_files`...

Output: "Discovery Workbench — submit and manage computational jobs on the Discovery Supercomputer including job submission, log retrieval, nodepool management, and file operations. Set learn=true to discover available commands."

### Quality bar

- ≤200 characters for the summary (excluding the learn hint)
- Must mention the top 3-5 capability domains
- Must end with the learn=true hint
- No tool implementation details (no "calls POST /api/v2/...")
- Deterministic — same tools always produce same description

## Acceptance Criteria

- [ ] Descriptions are readable and informative
- [ ] Top capabilities are mentioned
- [ ] learn=true hint is always present
- [ ] Deterministic output
- [ ] ≤300 LOC total file size maintained
