# T-238.41 - SequentialThinking start validation error is not discoverable

**Pipeline**: lightweight

## Parent thinking session

- `memory://thinking/sequential/2026/04/27/session-1777297104510-41878`

## Problem

During PM grounding for the `T-239.2` red-team re-audit result, `maenifold.thinking/SequentialThinking` was invoked without an existing session id and with `thoughtNumber: 1`.

Observed error:

```text
SESSION_MISSING: Session session-1777298556037-14313 missing. Start with thoughtNumber=0.
```

Expected MCP behavior: the command schema or validation message should make session-start requirements explicit before invocation. If the command auto-generates a session id, it should not report a synthetic missing session without explaining the required start shape.

## Acceptance Criteria

- `SequentialThinking` schema/help documents that new sessions must start with `thoughtNumber: 0`.
- The validation error includes the exact minimal retry payload shape.
- Existing sessions and new sessions have clearly distinct required parameters.
