# T-65.4: Structured ACP Output Standard

## Requirement
All ACP agent response parsing must use structured XML output tags. No more magic string detection (`DONE`), no unstructured text parsing. This is the standard for all node types — workflow, sequentialThinking, prompt — and all future types.

## Design

### Format: XML

XML over JSON because:
- LLMs produce valid XML ~95% on first try, ~99.9% on retry with error feedback
- Content fields can contain markdown, code, [[WikiLinks]] without escaping
- Regex extraction works as fallback if parser fails
- Every major model trains heavily on XML (Claude thinking, tool calls, system prompts)

### The `<output>` Contract

Every ACP prompt includes the expected output shape. The agent wraps its structured response in `<output>` tags. Free-form thinking/reasoning can appear outside the tags — only the `<output>` block is parsed.

### SequentialThinking Output Shape

```
<output>
  <response>Your thinking content with [[WikiLinks]]</response>
  <done>false</done>
  <needs_more>false</needs_more>
  <revision_of></revision_of>
  <conclusion></conclusion>
</output>
```

Fields:
- `response` (required): The thought content. Must contain [[WikiLinks]].
- `done` (required): `true` when the agent has completed its analysis and is ready to conclude.
- `needs_more` (optional, default false): `true` if the agent needs more thoughts than initially estimated.
- `revision_of` (optional): Thought number to revise. Empty if not a revision.
- `conclusion` (required when done=true): Final synthesis/confession. Ignored when done=false.

Maps to SequentialThinking tool payload:
- `response` → `response`
- `done=true` → `nextThoughtNeeded: false` + `conclusion`
- `done=false` → `nextThoughtNeeded: true`
- `needs_more=true` → `needsMoreThoughts: true`
- `revision_of=N` → `isRevision: true, revisesThought: N`

### Workflow Output Shape

```
<output>
  <response>Step completion content with [[WikiLinks]]</response>
  <done>false</done>
  <conclusion></conclusion>
</output>
```

Fields:
- `response` (required): The step's work output. Must contain [[WikiLinks]].
- `done` (required): `true` when the agent considers the workflow step complete.
- `conclusion` (required when done=true): Final workflow conclusion.

Maps to Workflow tool payload:
- `response` → `response`
- `done=true` → `status: "completed"` + `conclusion`

### Prompt Output Shape

```
<output>
  <response>The agent's response with [[WikiLinks]]</response>
</output>
```

Fields:
- `response` (required): The prompt response. Must contain [[WikiLinks]].

Prompt nodes are one-shot — no loop, no done signal. The entire response is the output.

### Prompt Template (included in every ACP prompt)

```
{actual_prompt_content}

Wrap your response in <output> tags using this exact structure:
{shape_for_node_type}

Your thinking and reasoning can appear outside the tags. Only the <output> block is parsed.
```

### Error Recovery Loop

```
1. Send prompt with output shape to ACP agent
2. Parse <output> block from response.text
3. If parse succeeds → extract fields → build tool payload → call MCP tool
4. If parse fails → re-prompt agent:
   "Your response could not be parsed. Error: {error_message}
    Expected format:
    {shape_for_node_type}
    
    Please rewrite your response with the correct <output> tags."
5. Parse retry response
6. Repeat up to 3 retries
7. If all 3 retries fail → fall back to raw text as response, mark done, log warning
8. Hard cap at totalThoughts + 3 remains as safety net
```

Max 3 retries. If all fail, use raw text and force completion. Never loop indefinitely on parse errors.

### What Goes to Memory

**Only successfully parsed responses are persisted.** Retries are ephemeral ACP exchanges that never touch `memory://`.

- The runner holds the agent's response in memory during the retry loop
- The MCP tool (SequentialThinking, Workflow, etc.) is NOT called until a valid parse succeeds
- Thought numbers do not increment on retries — it's the same thought being re-attempted
- The session file only ever contains clean, successfully parsed thoughts
- No parse error noise, no garbled XML, no retry annotations in the thinking trace

Flow example:
```
Prompt agent for thought 3
  → bad parse (no <output> tags)
  → retry prompt with error feedback
  → bad parse (missing <done> field)
  → retry prompt with error feedback  
  → good parse
  → NOW call SequentialThinking tool with thought 3 content
  → thought 3 persisted to memory://thinking/sequential/...
```

On force-completion fallback (all 3 retries failed):
- Raw agent text is used as the response content
- `done=true` is forced
- The raw text is persisted as the final thought + conclusion
- A warning is logged but NOT written to the session file

### Parser Requirements

Implement in `crates/maenifold-core/src/workflow/`:
- `output_parser.rs` — Generic `<output>` XML tag extractor
  - Extract content between `<output>` and `</output>`
  - Extract individual fields by tag name
  - Return `Result<ParsedOutput, ParseError>` with error message suitable for agent feedback
  - Handle nested content (markdown with `<code>` blocks) — use first/last `<output>` tags only
- `output_types.rs` — Per-node-type structured output types
  - `ThinkingOutput { response, done, needs_more, revision_of, conclusion }`
  - `WorkflowOutput { response, done, conclusion }`
  - `PromptOutput { response }`

### Files to Change

#### Rust (`crates/maenifold-core/src/workflow/`)
- **New:** `output_parser.rs` — XML tag parser with error messages
- **New:** `output_types.rs` — Typed output structs per node type
- **Edit:** `think_runner.rs` — Replace `DONE` detection with `<output>` parsing + retry loop
- **Edit:** `runner.rs` — Workflow runner: add `<output>` parsing + retry loop
- **Edit:** `runner_helpers.rs` — Remove `tag_response()`, add prompt template builder

#### Bash (`maenifold-acp`)
- **Edit:** `run_think()` — Same `<output>` parsing with retry
- **Edit:** `run_workflow()` — Same `<output>` parsing with retry

### What to Delete

- `tag_response()` in `runner_helpers.rs` — no more `[[step]]` fallback tagging
- `DONE` string detection in `think_runner.rs` — replaced by `<done>true</done>`
- `DONE` string detection in `maenifold-acp` `run_think()` — same
- Step number parsing (`sed -n 's/Step .../p'`) in `maenifold-acp` `run_workflow()` — replaced by `<done>` field

### No Backward Compatibility

No fallback to old `DONE` detection. No fallback to unstructured text parsing. The old path is deleted entirely. If an agent can't produce `<output>` tags, it gets one retry, then force-completion with raw text.

## Acceptance Criteria

- All ACP prompts include the expected `<output>` shape for their node type
- Agent responses are parsed for `<output>` blocks, not magic strings
- Parse failures trigger up to 3 retries with error feedback
- SequentialThinking runner uses `needs_more`, `revision_of` from parsed output
- Workflow runner uses `done` from parsed output instead of step counting
- `maenifold-acp` bash script updated with same parsing standard
- Hard cap safety net remains at `totalThoughts + 3`
- All existing tests updated or replaced
- All tests pass
- Release builds succeed
