# T-178.5d — Agent dashboard — desktop MCP resources migration

## Intent

Migrate the desktop Agent surface (agent selector, agent probe preview, chat view's agent context) onto MCP `agent://` resources via the [[T-178.0]] client. Same migration pattern as [[T-178.5a]] / [[T-178.5b]] / [[T-178.5c]].

## Scope

### 1. Define + register `agent://` resources in `crates/maenifold-core/src/mcp/resources.rs`

| URI | Read returns | Updated when |
|---|---|---|
| `agent://catalog` | `{ agents: [{ id, name, description, capabilities, ... }], generated_at }` | Agent config changes (`maenifold.json` reload) |
| `agent://sessions/active` | `{ sessions: [AgentSessionSummary], generated_at }` | Agent session created, ended, or status change |
| `agent://session/{id}` (template) | `{ id, agentId, status, turnCount, lastActivityAt, ... }` | Per-session lifecycle event |

Apply the throttle wrapper from [[T-178.3c]] to `agent://sessions/active`. Per-session URIs are unthrottled.

### 2. Wire emitters

- Agent session create / connect / disconnect / end → `agent://session/{id}` + `agent://sessions/active`.
- Agent config reload → `agent://catalog`.

### 3. Migrate desktop components

- `apps/desktop/src/components/AgentSelector.vue`
- `apps/desktop/src/components/AgentProbePreview.vue`
- `apps/desktop/src/components/AgentProbePreviewCapabilities.vue`
- `apps/desktop/src/components/AgentProbePreviewStatus.vue`
- `apps/desktop/src/components/ChatView.vue` (only the agent-status surface — chat message machinery stays on its existing path)
- Any other component currently calling `tools/call ListSessions` or polling agent status

Pinia store `apps/desktop/src/stores/agent.ts` (extend or create) with slices `catalog`, `activeSessions`, `selectedSession`. Subscribe-on-mount / unsubscribe-on-unmount.

Writes (creating an ACP session, sending prompts) stay on `tools/call AcpExec` — unchanged.

### 4. Fluent 2 styling — HARD REQUIREMENT

Same rules as the rest of T-178.5*:
- All tokens from `apps/desktop/DESIGN.md`.
- shadcn-vue primitives only.
- Status colors: `--success` (idle/ready), `--warning` (active/working), `--danger` (errored/disconnected), `--muted` (ended).
- ZERO hardcoded hex/RGB/HSL. ZERO `<style>` blocks in any `.vue` file in scope.
- Body font: Segoe UI Variable.

### 5. Help docs

`assets/help/resources/agent.md` (NEW) documents URIs.

## Files in scope

- `crates/maenifold-core/src/mcp/resources.rs` (agent URI registration + read dispatch)
- Agent session-lifecycle and config-reload call sites (minimal `notify_resource_updated` additions)
- `apps/desktop/src/stores/agent.ts` (extend or create)
- `apps/desktop/src/components/AgentSelector.vue`
- `apps/desktop/src/components/AgentProbePreview*.vue`
- Agent-status surface in `apps/desktop/src/components/ChatView.vue` (narrow scope — agent status only)
- `apps/desktop/src/components/__tests__/Agent*.test.ts` (extend or add)
- `assets/help/resources/agent.md` (NEW)

## Acceptance criteria

1. `cargo test -p maenifold-core` passes.
2. `pnpm --filter desktop build` and `pnpm --filter desktop test` pass; zero `vue-tsc` errors.
3. Agent surface performs ZERO `/api/agent/*` HTTP calls and ZERO polling `tools/call ListSessions` loops — the live state arrives via subscriptions.
4. Reads via `useMcpResources`; ACP-side writes via `tools/call AcpExec`.
5. Agent session lifecycle event → AgentSelector / AgentProbePreview UI updates without manual reload (Playwright assertion).
6. ZERO hardcoded hex/RGB/HSL and ZERO `<style>` blocks in files in scope (grep verification).
7. Playwright screenshot of AgentSelector with multiple catalog entries and at least one active session, attached to PR.
8. `assets/help/resources/agent.md` documents URIs and update conditions.

## Out of scope

- Removing legacy agent REST / polling endpoints.
- Chat message rendering (out of this slice).
- Agent authoring UX (`maenifold.json` editing).
- Gate / Workflow / Pipeline dashboards.
