# T-214.14 — Resume session ID single-use

## Problem

`AgentSession::prompt` re-passes `resume_session_id` on every call, not just the first. If the connection pool evicts (cwd change, health failure), the next prompt re-issues `session/load` — double-loading a session whose state has already advanced.

## Solution

After the first successful prompt, clear `self.resume_session_id` to `None` so subsequent prompts don't re-trigger session/load.

## Source

Red-team finding from T-214.3 dual audit (opus-4.7).

## Key Files

- `crates/maenifold-core/src/workflow/agent_session.rs`

## Acceptance Criteria

- `resume_session_id` cleared after first successful prompt
- Subsequent prompts use the established connection without re-loading
