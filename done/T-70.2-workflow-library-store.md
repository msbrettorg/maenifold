# T-70.2 — Workflow Library Pinia Store

**Requirement**: Workflow Authoring — Stitch Screen 1 (Left Panel)
**Component**: `src/stores/workflow-library.ts`
**Depends**: T-70.1

## Context

The pipeline store has a `workflows: string[]` array and `refreshWorkflows()` that calls `mcp.listWorkflows()`. This only stores IDs. The workflow browser panel needs rich metadata (name, emoji, description, multiAgent, step count) and the ability to load full definitions. A dedicated Pinia store separates concerns.

## Skills Required

SWE agent MUST load these skills: `pinia`, `maenifold-workflow-authoring`.

## Acceptance Criteria

1. New file `src/stores/workflow-library.ts` (< 200 LOC)
2. Store `useWorkflowLibraryStore` with state:
   - `summaries: WorkflowAssetSummary[]` — all workflow metadata from ListAssets
   - `currentDefinition: WorkflowAssetDefinition | null` — currently selected full definition
   - `currentId: string | null` — selected workflow ID
   - `loading: boolean`
   - `error: string | null`
   - `searchQuery: string`
   - `categoryFilter: WorkflowCategory | 'all'`
3. Getters:
   - `filteredWorkflows` — filters by searchQuery (name/description match) and categoryFilter
   - `currentStepCount` — number of steps in current definition
   - `categories` — unique categories derived from all summaries
4. Actions:
   - `fetchSummaries()` — calls `usePipelineMcp().listWorkflows()` then enriches with ListAssets data, populates summaries
   - `selectWorkflow(id: string)` — sets currentId, calls ReadMcpResource to load full definition
   - `clearSelection()` — resets currentId and currentDefinition
5. Uses `usePipelineMcp` for MCP calls (existing pattern)
6. `npx vue-tsc --noEmit` passes
