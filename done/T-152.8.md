## Problem

Red-team F-1 found that `CONFIG_ROOT` is a `OnceLock` — first caller wins, all subsequent pipeline nodes silently use the wrong root. But the deeper issue: pipeline nodes have no way to specify a working directory for their ACP agent session.

The `cwd` determines:
- Where the agent reads/writes files (ACP `fs/read`, `fs/write`)
- Which `maenifold.json` is loaded for agent resolution
- The agent's terminal working directory

Pipeline nodes executing in different repos or directories need different cwds.

## Fix

Add `cwd` as an optional field on pipeline node definitions (all ACP node types: prompt, sequentialThinking, workflow). The pipeline executor passes it through to the ACP session open. Defaults to the pipeline session's root directory if not specified.

## Schema Change

```json
{
  "id": "analyze-anomalies",
  "type": "sequentialThinking",
  "agent": "copilot",
  "cwd": "/Users/brett/src/trey",
  "topic": "Analyze anomalies",
  "totalThoughts": 3
}
```

## Acceptance Criteria

1. `PipelineNode` types (Prompt, SequentialThinking, Workflow) accept optional `cwd` field
2. Pipeline executor passes `cwd` to ACP session open / agent connection
3. Default `cwd` is the maenifold root (current behavior) when not specified
4. `CONFIG_ROOT` OnceLock is replaced with per-invocation config resolution keyed by cwd (ties into T-152.2 fix)
