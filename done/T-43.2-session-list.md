# T-43.2: Session List Implementation

**Requirement**: FR-42 audit findings — Session List  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/lib/acp-bridge.ts`, `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/components/SessionList.vue`

## Acceptance Criteria

1. Add `listSessions` method to `AcpClientBridge`:
   ```ts
   async listSessions(params?: { cwd?: string; cursor?: string }): Promise<{
     sessions: Array<{ sessionId: string; cwd: string; title?: string; updatedAt?: string }>;
     nextCursor?: string;
   }> {
     return await this.sendRequest('session/list', params ?? {});
   }
   ```

2. In the session store, after `initialize` completes:
   - Check `initResponse.agentCapabilities?.sessionCapabilities?.list`
   - Store as `supportsSessionList` boolean ref
   - If supported, call `listSessions()` with cursor-based pagination (loop until `nextCursor` is absent)
   - Merge agent-provided sessions into `savedSessions`, keyed by `sessionId`

3. Update `SessionList.vue` to show sessions from both local store AND agent-provided list. Agent-provided sessions that don't exist locally should appear with an indicator (e.g., "from agent").

4. Treat cursors as opaque tokens — never parse, modify, or persist them.

5. Add `cwd` filter support — when listing, pass the current working directory.

## Red-team Audit

**Verdict: PASS**

All acceptance criteria verified:

- **Criterion 1 — `listSessions` method**: ✅ Implemented at `vendor/acp-ui/src/lib/acp-bridge.ts:604–609`. Signature matches spec exactly (`params?: { cwd?: string; cursor?: string }`, return type, `sendRequest('session/list', params ?? {})`).

- **Criterion 2a — `supportsSessionList` boolean ref**: ✅ Declared at `session.ts:174` (`const supportsSessionList = ref(false)`). Set from `initResponse.agentCapabilities?.sessionCapabilities?.list` at `session.ts:360`.
  - **Caveat**: The capability check uses `!== undefined` rather than a truthiness check (`Boolean(...)`). If `sessionCapabilities.list` is ever explicitly `false`, the store would incorrectly treat the agent as supporting session listing. In practice the ACP protocol convention is that capabilities are either truthy-objects or absent, so this is low-risk. Not a blocking issue.

- **Criterion 2b — cursor-based pagination loop**: ✅ `mergeSessionsFromAgent` at `session.ts:238–283` uses a `do/while (cursor !== undefined)` loop that drives the full paginated fetch before merging.

- **Criterion 2c — merge into `savedSessions` keyed by `sessionId`**: ✅ `sessionsById` map at `session.ts:261` is keyed by `sessionId`; each agent session is upserted, then the map is flattened back into `savedSessions`.

- **Criterion 3 — SessionList.vue shows both local and agent-provided sessions with "from agent" indicator**: ✅ Agent sessions are merged into `savedSessions` (with synthetic `agent:<name>:<id>` ids). `SessionList.vue` renders `resumableSessions` and the `isAgentSession()` helper (`session.id.startsWith('agent:')`) gates the `from agent` badge.
  - **Caveat**: Agent sessions only surface in `resumableSessions` when `supportsLoadSession === true`. The spec says "show sessions from both local store AND agent-provided list" without restricting to resumable. However, displaying sessions that can't be loaded would be misleading UX, so this is a defensible design decision, not a spec violation.

- **Criterion 4 — Cursors as opaque tokens**: ✅ The cursor `string | undefined` variable at `session.ts:244` is passed through verbatim, never parsed, transformed, or written to persistent storage.

- **Criterion 5 — `cwd` filter support**: ✅ `mergeSessionsFromAgent` receives `cwd` as a parameter and passes it as the first argument to `listSessions` at `session.ts:248–251`. All three call sites (lines 697, 752, 926, 1009) supply the correct cwd.

- **Bonus: `session_info_update` ACP compliance fix**: ✅ Handler at `session.ts:535–568` uses `notification.sessionId` (not any legacy field) to look up and update both `savedSessions` and `currentSession`.
