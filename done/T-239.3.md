## Required behavior

- Keyword matching uses the configured trigger keyword.
- Listen scope:
  - `wildcard` listens to all conversations.
  - `self` listens only to `48:notes`.
  - `custom` listens to persisted monitored conversation IDs.
- Self-loop prevention skips messages whose sender MRI equals the detected self MRI.
- Detected identity MRI is used as the `from` identity on outbound replies where Teams requires it.
- Dispatch timeout is passed into the ACP dispatch path.
- Reply behavior:
  - source conversation replies to the triggering conversation.
  - self-chat replies to `48:notes`.
- Reply prefix is prepended to outbound monitor responses.
- Add the outbound Teams reply/chatsvc client needed to post responses; do not present reply controls as implemented unless a real reply transport exists.
- `trouter.rs` consumes configured gateway, registrar URL, app ID, heartbeat interval, token refresh interval, and `chatsvcRegion` rather than hardcoding values that config owns.
- Saving config while the monitor is running safely applies the new runtime configuration and reports the resulting state.

## Acceptance Criteria

- [ ] No visible Teams Monitor setting is UI-only.
- [ ] Handler tests cover wildcard, self-chat, custom conversation filtering, and identity matching.
- [ ] Dispatch timeout is enforced or passed to the dispatch executor with an explicit error if unsupported.
- [ ] Outbound replies use the configured target and prefix.
- [ ] Outbound replies are sent through a real Teams/chatsvc transport with no mocks, stubs, or fake replies.
- [ ] The monitor suppresses self-authored messages to prevent reply loops.
- [ ] Trouter connection uses configured gateway, registrar URL, app ID, heartbeat, token refresh, and region fields.
- [ ] Runtime config changes do not leave the supervisor in an unknown state.
