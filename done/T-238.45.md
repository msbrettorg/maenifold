# T-238.45 - P0 Gate create command missing from MCP Gateway surface

**Pipeline**: sdd

## Goal

Add a native `maenifold.gate` Gateway command for creating Gate task files so agents and UI clients can create backlog items through MCP instead of writing files directly.

## Problem

`GatewayIndex` for `maenifold.gate` exposes:

- `gate_Status`
- `gate_Append`
- `gate_Pass`
- `gate_Fail`
- `gate_Sync`
- `gate_History`
- `gate_TaskBody`

It does not expose a create command.

This breaks the product rule that MCP is the common interface for AI and UI alike. When the PM needs to log a new bug or missing-tooling item, the only available path is filesystem fallback plus `gate_Sync`.

## Required behavior

Expose a task creation command through the integrated Gateway surface, for example `gate_Create`, that accepts:

- `root`
- `taskId`
- `title`
- `pipeline`
- `priority`
- `sprint`
- task body / sections

The command must create a valid markdown task under `todo/`, reject duplicate IDs, validate the pipeline, and return the same canonical task status shape as other Gate commands.

## Acceptance Criteria

- [ ] `GatewayIndex` lists the create command for `maenifold.gate`.
- [ ] `GatewayExecute` can create a valid task markdown file under `todo/`.
- [ ] Duplicate task IDs are rejected with an actionable error.
- [ ] Invalid pipeline IDs are rejected with an actionable error.
- [ ] Created tasks are immediately visible via `gate_Status` without manual filesystem work.
- [ ] UI/AI clients no longer need direct file writes to create Gate items.
- [ ] Skill/docs are updated to describe the create command.

## Verification

- Focused Gate/Gateway tests for successful create, duplicate ID rejection, invalid pipeline rejection, and `gate_Status` visibility.
- `cargo build --release -p maenifold-cli`
- `cargo build --release -p maenifold-gate`
