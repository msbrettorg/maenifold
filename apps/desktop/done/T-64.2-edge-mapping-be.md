# T-64.2 — Add edge mapping + resolve in executor (BE)

**Requirement**: FR-15

## Acceptance Criteria

- `PipelineEdge` has `mapping: Option<HashMap<String, String>>` field in types.rs
- Serde: `skip_serializing_if = "Option::is_none"`, defaults to None on deser
- In `build_node_execution_request()` for Tool variant:
  - Collects all incoming edges with mappings where source node is completed
  - For each mapping entry: resolves dot-path against source node's `state.output` JSON
  - Merges resolved values into tool_args (mapped values override static)
  - Unresolved paths → `serde_json::Value::Null` (no retry, no fallback)
- ACP nodes unchanged — predecessor context concatenation already works
- New test: tool node with mapped edge receives resolved args
- New test: tool node without mapping uses static args (backward compat)
- All existing pipeline tests pass
- `cargo test -p maenifold-core -- pipeline` green

## Design Decisions

- Keys = target parameter names (tool_args field names)
- Values = dot-path into source output (e.g., `results[0].title` or `data.content`)
- Resolution at dispatch time (when building NodeExecutionRequest)
- No type coercion, no auto-mapping, no template language
- Errors are information: null on unresolved path, let tool fail naturally

See: `memory://build/architecture/pipeline-t64-architectural-intent-analysis` Section 4.

FINDING M1 (Medium) — Empty path leaks entire source output: parse_dot_path("") returns Some([]) and resolve_dot_path propagates the full source JSON as the mapped value, rather than Null. Violates 'errors are information' principle. Exploit: mapping entry {"sink": ""} silently pipes entire predecessor output into the target tool. No test covers this edge case.

FINDING L1 (Low) — Non-object static_args silently dropped: when static_args is Some(non-Object) and applied_mapping is true, the merged_args starts as an empty Map and the original value is lost with no error. Out-of-spec usage, but silent data loss is worse than a hard error.

FINDING I1 (Info) — Trailing dot after bracket swallowed: 'results[0].' parses identically to 'results[0]' due to allow_empty_dot flag logic. Unexpected but harmless.

FINDING I2 (Info) — Bracket notation enables string-key object access: data["key"] works on objects (not just arrays). Undocumented but safe.

FINDING I3 (Info) — Multi-edge same-key collision is deterministic by edge array order but undocumented; last edge wins.

All AC satisfied. Fork propagation correct. Serde round-trip correct. Recommend: fix M1 by returning None (→ Null) when path is empty in parse_dot_path.
