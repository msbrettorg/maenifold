# T-56.2 — Strip Supervisor to Essentials

**Requirement**: FR-40 (Pipeline Active Executor)
**RTM**: RTM-160 / TC-160
**Component**: `crates/maenifold-core/src/workflow/pipeline/supervisor.rs`

## Context

`supervisor.rs` is 849 LOC of process management for spawning and monitoring a bash script. With the async executor (T-56.1) handling execution directly, the supervisor's process management is dead code. Its useful functions — orphan detection and stuck-marking — must be preserved.

Depends on: T-56.1 (executor must exist before supervisor can delegate to it).

## Acceptance Criteria

### Remove (dead code after T-56.1)

1. Remove `RunHandle` struct
2. Remove `spawn_supervised()` function
3. Remove `pipeline_command()` function  
4. Remove `spawn_monitor_thread()` function
5. Remove `poll_process_exit()` function and `ProcessState` enum
6. Remove `wait_for_exit()` and `child_has_exited()` functions
7. Remove `send_signal_group()` function
8. Remove `supervisor_spawn_test_process()` test helper
9. Remove the `static SUPERVISOR: Lazy<Mutex<HashMap<String, RunHandle>>>` global
10. Remove `MAX_RESTART_ATTEMPTS` constant

### Keep (still needed)

11. Keep `supervisor_detect_orphans()` — but simplify: instead of checking against in-memory RunHandle map, check against a new `RUNNING_PIPELINES: Lazy<Mutex<HashSet<String>>>` that the executor registers/deregisters with.
12. Keep `mark_pipeline_stuck()` — unchanged.
13. Keep `pipeline_has_non_terminal_nodes()` — unchanged.
14. Keep `supervisor_context()` — unchanged.

### Replace (lifecycle controls)

15. Replace `supervisor_run()` with a function that:
    - Registers session_id in `RUNNING_PIPELINES`  
    - Spawns `executor::execute_pipeline()` via `tokio::spawn`
    - Stores the `JoinHandle` and `CancellationToken` in a new lightweight tracking map
    - Returns Ok(()) instead of a PID
16. Replace `supervisor_cancel()` with: trigger the `CancellationToken`, await the `JoinHandle`, deregister from `RUNNING_PIPELINES`
17. Replace `supervisor_pause()` / `supervisor_resume()` with: set/clear an `AtomicBool` pause flag that the executor checks between dispatch cycles
18. Keep `supervisor_is_running()` — backed by `RUNNING_PIPELINES.contains(session_id)`
19. Replace `supervisor_status()` — return `Option<Instant>` (started_at only, no PID)

### Update handler.rs references

20. `run_pipeline` — call new `supervisor_run()` (no PID in response)
21. `pause_pipeline` — call new `supervisor_pause()` (no SIGSTOP)
22. `resume_pipeline` — call new `supervisor_resume()` (no SIGCONT)
23. `cancel_pipeline` — call new `supervisor_cancel()` (no kill)

### Pause Mechanism ✅

**AtomicBool semantics**: `Ordering::SeqCst` used consistently for all stores and loads — correct and conservative.

**No MutexGuard held across await**: `supervisor_wait_if_paused` (supervisor.rs:210–230) acquires `TRACKED_PIPELINES.lock()`, reads the flag, and drops the guard — all before the `tokio::select!` await point. No `Send`-safety issue.

**Cancel-while-paused handled**: After `supervisor_wait_if_paused` returns, executor.rs:85–87 checks `cancel.is_cancelled()` and breaks immediately. Edge case handled.

---

### Cancel Semantics ✅

In-flight ACPX prompts are aborted: executor.rs:155–156 calls `join_set.abort_all()` then `drop(join_set)` when `cancel.is_cancelled()` after the `tokio::select!` resolves to `None`. `JoinSet::abort_all` sends abort signals to all spawned tasks, stopping in-flight driver calls at their next yield point.

---

### Nested Tokio Runtime (Informational) ℹ️

The SWE flagged this themselves. `SUPERVISOR_RUNTIME.block_on()` (supervisor.rs:173) is called from `supervisor_cancel()`, which is reachable via:

```
MCP call_tool → spawn_blocking → ToolRegistry::try_invoke → pipeline() → cancel_pipeline() → supervisor_cancel() → SUPERVISOR_RUNTIME.block_on()
```

This is safe in **tokio 1.50.0** (confirmed in Cargo.lock). Tokio 1.13.0 relaxed the `block_on` restriction to permit calls from `spawn_blocking` threads (PR #4760: "When called from within a blocking task, block_on is permitted because the blocking task does not hold any tokio work"). The two runtimes are fully independent.

**Risk**: This pattern would silently break if the call path ever moves from `spawn_blocking` to a true async worker thread context. Worth documenting in a code comment.

### Findings

**Finding 1 — Dead code: `paused_for_task` clone is never read (LOW)**

supervisor.rs:66 clones `paused` into `paused_for_task`, which is moved into the spawned task and then only explicitly dropped on line 93. The task never reads it. The executor checks paused state exclusively via `supervisor_wait_if_paused` → `TRACKED_PIPELINES` mutex; the captured Arc serves no purpose. This is harmless but creates maintenance confusion about the intended pause-signalling mechanism.

```rust
let paused_for_task = paused.clone();   // line 66 — never read
// ...
drop(paused_for_task);                  // line 93 — explicit drop, no-op beyond Arc refcount
```

Recommendation: remove `paused_for_task`. The `TRACKED_PIPELINES` map approach is the actual mechanism.
