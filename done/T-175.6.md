# T-175.6 — Replace text-prompt path picker with real folder picker

**Pipeline**: sdd
**State**: pending

## Context

The "Working directory" picker on every tab (Agents sidebar, Gate root selector, etc.) is currently `promptForAbsolutePath()` — a hand-rolled `<dialog>` with a free-text input and a "Use Path" submit button. The user must type the full absolute path. There is no folder browse, no autocomplete, no validation feedback before submit.

This was acceptable when the SPA ran inside the Agency Cowork Electron host (which provided a native dialog through preload IPC). The SPA now ships standalone (`npx serve`-served, embedded via `memory/Dashboards/maenifold-spa.html` iframe). Electron preload bridges are unavailable, so the prompt is the only path entry surface — and users report it as "doesn't work" because typing a multi-segment path is hostile UX.

Affected code: every place that calls `promptForAbsolutePath()`.

Repo: `/Users/brett/src/ma-collective/maenifold-rs`

## Scope

**Files:**
- `apps/desktop/src/composables/useAppSession.ts` — `promptForAbsolutePath()` at line 82-138 and call-site `handleSelectFolder()` at line 212
- `apps/desktop/src/components/AppSidebar.vue` — folder picker button at line 97-103 (only if a UX hint changes)
- (Server-side, if needed) a `/api/files/list-dirs` endpoint to power autocomplete — only if the chosen client API isn't sufficient

**Out of scope:** Gate-specific cwd entry that re-uses the same util (will inherit the fix automatically), the dashboards' own postMessage `select-folder` action (handled by the host), persisting `lastCwd` (already works).

## Acceptance Criteria

- "Use Path" / folder button on the sidebar opens a real directory chooser, not a text prompt.
- Implementation order of preference (use the first one available at runtime):
  1. **`window.showDirectoryPicker()`** (File System Access API — supported in Chromium, including Electron WebView and Chrome). Returns a `FileSystemDirectoryHandle`; resolve absolute path via the handle's `name` plus a server-side reverse-lookup endpoint OR by asking the user to confirm the resolved path.
  2. **Electron preload bridge** — if `window.electronAPI?.showOpenDialog` exists (legacy host), use that. Keep the existing branch.
  3. **Fallback** — keep the current text dialog, but add path autocomplete via a new `GET /api/files/list-dirs?prefix=...` (only built if the previous two are unavailable AND the team accepts the API addition).
- Picked path must be absolute. Reject relative paths with the existing `isAbsolutePath` validator.
- Cancel returns gracefully — no error toast.
- Existing `lastCwd` persistence via `prefsStore` continues to work.
- Picker works equally on the standalone SPA (`npx serve … :8090` + Maenifold dashboard iframe) AND the legacy Electron host (if still present).
- No regression on `handleNewSession` validation (`isAbsolutePath`, "Working directory is required").
- Build passes: `cd apps/desktop && pnpm build`.
