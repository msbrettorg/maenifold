# T-174.4 — Enforce `timeout_seconds` via `tokio::time::timeout` (re-scoped 2026-04-18)

## Why
Original premise (`executor_nodes.rs:178` hardcoding `timeout_seconds: None`) was ALREADY remediated by a prior sprint (likely T-170.x). The forwarding wiring is correct. However, that prior sprint introduced a **silent default policy** that violates this spec's Forbidden clause and the constitution's "Mechanism, Not Policy" tenet. This task is re-scoped to:

1. Strip the silent default constants and make timeout policy strictly caller-supplied.
2. Align the failure-message wording with the spec.
3. Add the missing real-engine timeout test (AC-4 was never landed).

## Scope (re-scoped)
**Crate:** `maenifold-core` only.
**Files (in scope):**
- `crates/maenifold-core/src/workflow/pipeline/executor.rs` — strip `DEFAULT_TOOL_NODE_TIMEOUT_SECS` (60) and `DEFAULT_AGENT_NODE_TIMEOUT_SECS` (300) constants and any logic that substitutes them when the caller passed `None`. Make `extract_timeout` (lines ~223–249) return `Option<u64>` with `None` semantics = no wrapper. Update the timeout wording at line ~362 from `"node timed out after {N}s"` → `"timeout after {N}s"`.
- `crates/maenifold-core/src/workflow/pipeline/executor_timeout_tests.rs` — NEW. Real engine, no mocks. A tool node that sleeps 1s with `timeout_seconds=Some(<1s)` must report `NodeStatus::Abandoned` and `failure_reason` containing `"timeout after"`.

**Out of scope:** `executor_nodes.rs` (already correct — DO NOT MODIFY); cancellation child-kill (T-174.5); retry/backoff (T-174.6).

## Acceptance
- AC-1: `extract_timeout` returns `None` when the caller did not supply `timeout_seconds`. No constant fallback. `DEFAULT_TOOL_NODE_TIMEOUT_SECS` and `DEFAULT_AGENT_NODE_TIMEOUT_SECS` deleted.
- AC-2: Node execution future is wrapped in `tokio::time::timeout(Duration::from_secs(t), fut)` only when `Some(t)`; passes through unwrapped when `None`.
- AC-3: On elapse → `NodeStatus::Abandoned` with `failure_reason` containing `"timeout after {N}s"` (was: `"node timed out after {N}s"`).
- AC-4: NEW `executor_timeout_tests.rs` proves AC-2/AC-3 against the real engine. No mocks. No fake futures. Use an actual tool node that sleeps via `tokio::time::sleep` with `timeout_seconds` < sleep duration.
- AC-5: All existing pipeline tests still pass — `cargo test -p maenifold-core` (blue-team will run; SWE only `cargo build`).
- AC-6: `cargo build -p maenifold-core` succeeds with isolated `CARGO_TARGET_DIR`.
- AC-7: No new dependencies.

## Forbidden
- Silent default timeout. Policy must remain caller-supplied. Re-introducing `DEFAULT_*_TIMEOUT_SECS` is a P0 violation.
- Touching `executor_nodes.rs` — the wiring there is already correct.
- Touching retry / backoff / cancellation logic — T-174.5/6.
- Mocks or fake futures — real tool node with real sleep.

## Caller migration note
Any call site that previously relied on the silent 60s/300s default must now pass `timeout_seconds` explicitly OR accept unbounded execution (the conscious choice — that is the whole point). If a caller in this crate breaks with `None` semantics and unbounded execution would be wrong, surface it as a follow-up task; do not re-add the default.
