# T-239.1 - Teams Monitor signed-in token and identity provider

**Pipeline**: sdd

## Goal

Implement the agency-cowork [[teams-monitor]] auth foundation in Rust: acquire Teams tokens from the signed-in environment, decode the Teams JWT into monitor identity, classify auth errors, and stop requiring user-supplied app-registration fields for token acquisition.

## Source pattern

Mirror the proven behavior from:

- `/Users/brett/src/agency-cowork/skills/teams/scripts/api/auth.py`
- `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/message_handler.py`
- `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/service.py`
- `/Users/brett/src/agency-cowork/tests/regression/test-identity-auto-detect.sh`

Required pattern:

- Teams token resource is `https://ic3.teams.office.com`.
- Token acquisition order:
  1. `TEAMS_CHATSVC_TOKEN` process environment token for monitor/runtime handoff
  2. agency-cowork-compatible disk token cache at `~/.teams-agent/token-cache.json`
  3. Azure CLI `az account get-access-token --resource https://ic3.teams.office.com --query accessToken -o tsv`
  4. agency-cowork-compatible browser-session fallback source: re-read the `~/.teams-agent/token-cache.json` entry populated by a Teams browser session; if AADSTS530084 is hit and no valid browser-session cache entry exists, return a structured `TokenProtectionRequiresBrowserSession` error rather than stubbing token acquisition
- Decode JWT claims:
  - `oid` -> `mri = 8:orgid:<oid>`
  - `tid` -> tenant diagnostic field
  - `upn` or `preferred_username`
  - `name`
  - `exp`
- Detect AADSTS530084 Token Protection and stop retrying Azure CLI for that process lifetime before falling through to the browser-session cache path.
- When Graph identity detection is unavailable because of AADSTS530084, missing Azure CLI, or missing login, JWT-derived identity is authoritative and is sufficient to populate `mri`, `upn`, and `displayName`.
- Detect `chatsvcRegion` with the agency-cowork Graph preferred data location path when Graph is available:
  - `az rest --method GET --url https://graph.microsoft.com/v1.0/me?$select=preferredDataLocation -o json`
  - map `NAM`, `CAN`, `BRA` to `amer`
  - map `EUR`, `FRA`, `CHE`, `DEU`, `GBR`, `NOR`, `ZAF`, `ARE`, `SWE` to `emea`
  - map `APC`, `AUS`, `JPN`, `IND`, `KOR`, `SGP` to `apac`

## File Scope

Stay in `maenifold-core` backend token/identity support files:

- `crates/maenifold-core/src/teams/token_provider.rs`
- `crates/maenifold-core/src/teams/identity.rs`
- `crates/maenifold-core/src/teams/mod.rs`
- `crates/maenifold-core/src/teams/credential_store.rs`
- focused tests under `crates/maenifold-core/src/teams/*tests.rs`
- minimal Cargo dependency changes if required for JWT decoding or agency-cowork-compatible disk cache support

Do not modify the desktop UI in this task.

## Acceptance Criteria

- [ ] A backend token provider can acquire a Teams bearer token without `clientId` or `tenantId` input.
- [ ] JWT decoding derives MRI, object ID, tenant ID, UPN, display name, and expiry.
- [ ] `TEAMS_CHATSVC_TOKEN` is accepted when valid and skipped when expired or malformed.
- [ ] `~/.teams-agent/token-cache.json` is read and written with agency-cowork-compatible resource keys, token fields, expiry fields, and TTL semantics.
- [ ] AADSTS530084 is classified distinctly, blocks repeated Azure CLI attempts for the process lifetime, and routes to the browser-session cache path or a structured `TokenProtectionRequiresBrowserSession` error.
- [ ] JWT-derived identity is authoritative when Graph identity detection is unavailable.
- [ ] Graph preferred-data-location detection maps `chatsvcRegion` with the agency-cowork mapping table when Graph is available.
- [ ] Missing Azure CLI, missing login, malformed token, expired token, and fallback failure produce structured errors safe for UI display.
- [ ] Access tokens are never written to `maenifold.json`, frontend state, docs, or logs; the only disk token cache is the agency-cowork-compatible `~/.teams-agent/token-cache.json`.
- [ ] The provider can return both token material for runtime use and non-secret identity/status metadata for MCP status.
- [ ] Tests do not introduce subprocess mocks, stubs, fake Azure CLI binaries, fake Teams browser sessions, fabricated JWT fixtures, or fake token material. Tests that require live Azure CLI/Teams sign-in are marked ignored and runnable locally. No tests is better than fake tests.
