# T-244.1 — Single markdown rendering path

## User decision (PM, 2026-04-28)

> "Yeah, rendering — that's important. we need one path. Chat tab seems far more robust."

The chat tab's rendering pipeline (`markdown-it` + `useMarkdownIt` + `useMermaid`) is the canonical path. The other path (`marked` in `ThinkingTrace`, `PromptAssembly`, `WorkflowStepDetail`) is **deleted**. Every surface that renders markdown uses the same renderer, with the same plugins, the same WikiLink handler, the same code highlighter, the same mermaid renderer.

## What this fixes

Per the duo delta review (`done/T-243.9.0-delta-review.md`):

- Same `.md` renders differently on Chat vs Thinking vs WorkflowStep today — divergent engines.
- Mermaid only fires on Path A. Path B users see raw fence text.
- Code highlighting works on Path A; on Path B, `marked-highlight` + `highlight.js` are installed but not wired.
- Two different WikiLink CSS classes (`wiki-pill` vs `note-wiki-pill`) — only one of them has a click handler.
- Math is missing on both paths. (Tracked separately as T-244.2.)
- Task lists `- [ ]` work on Path B, break on Path A. Inversion of #2.

Consolidating eliminates all of these in one move.

## Plan

1. Author a single `<MarkdownView>` Vue component that wraps `useMarkdownIt`. It accepts a `content: string` prop and emits the rendered HTML. It applies the existing plugin pack (gfm tables, autolinks, code highlighting via Shiki) plus what's missing (task lists, footnotes — see audit corpus).
2. Replace every `marked` callsite with `<MarkdownView>`:
   - `ThinkingTraceView.vue` / `ThinkingThoughtItem.vue`
   - `PromptAssembly*.vue`
   - `WorkflowStepDetail.vue`
   - any other component that imports `marked`.
3. Remove `marked` and `marked-highlight` from `package.json`. Verify tree-shaking removes them from the bundle.
4. Move the WikiLink click handler from `KnowledgeLeafPane.vue` into the renderer itself, so every surface navigates on click — chat, gate task body, gate history, knowledge, workflow step, thinking trace.
5. Standardize on one CSS class for WikiLink chips (`wiki-pill`). Delete the alternate.
6. Audit: every surface that displays markdown should now be one of:
   - `<MarkdownView :content="..." />` (preferred), or
   - has a documented reason to render raw text instead.

## Acceptance criteria

- [ ] `package.json` no longer includes `marked` or `marked-highlight`.
- [ ] No `import { marked }` anywhere in `apps/desktop/src/`.
- [ ] Every component that displays markdown imports `<MarkdownView>` (or a derived `KnowledgeNoteRenderer` that wraps it).
- [ ] WikiLinks navigate from chat, gate body, gate history, knowledge, workflow step, thinking trace. Click handler is at the renderer level, not duplicated per surface.
- [ ] Mermaid renders in EVERY markdown surface, not only chat.
- [ ] Code blocks syntax-highlight in EVERY markdown surface, with the same language list.
- [ ] Task lists, footnotes, GFM tables, autolinks all work everywhere.
- [ ] Bundle size reported before/after — should drop (one engine vs two).
- [ ] `vue-tsc --noEmit` and `npm run build` pass.

## Out of scope (file separately)

- KaTeX / math rendering (will land via T-244.2).
- Mermaid theme reactivity to app theme toggle (T-244.4).
- New plugins beyond what Path A already has (file as polish if needed).
