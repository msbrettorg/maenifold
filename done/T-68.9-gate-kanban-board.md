# T-68.4 — Gate Kanban Board

**Requirement**: FR-68
**Status**: pending

## Summary

Embedded read-only kanban board SPA served by the gate HTTP daemon. The board speaks MCP to the gate backend — no custom REST, no custom IPC. Supports viewing all registered gates or filtering to a single gate.

## Acceptance Criteria

1. Static HTML/JS/CSS SPA embedded in the gate binary via `rust-embed`
2. Served at `/` by the HTTP server (alongside `/mcp` for the MCP endpoint)
3. Board calls `gate_list_gates` via MCP to populate the gate selector
4. Board calls `gate_status` via MCP with the selected gate's root to get tasks
5. Kanban columns derived from pipeline stages (pending → swe → red → blue → done)
6. Task cards show: task ID, title, status, location (todo/done), attempt count
7. Gate selector: dropdown or tabs — "All Gates" (aggregated) + one entry per registered gate
8. URL-driven filtering: `/` = all, `/?gate=project-name` = filtered
9. Auto-refresh on a reasonable interval (30s) or manual refresh button
10. Read-only — no pass/reject/append from the UI
11. Board is only available in `--http` mode (feature-gated behind `app`)
12. Responsive, works in standard browsers
13. All existing 95 tests pass
14. Both feature configurations build clean

## Dependencies

- T-68.2 (registry — `gate_list_gates` tool)
- `rust-embed` crate (add to Cargo.toml behind `app` feature)

## Files

- `src/board/` — embedded SPA assets (index.html, board.js, board.css)
- `src/mcp/http.rs` — add static file serving at `/` alongside `/mcp`
- `Cargo.toml` — add `rust-embed` behind `app` feature

## Design Constraints

- MCP is the ONLY data source — the board is a pure MCP client
- No server-side rendering — all rendering in JS
- The board creates its own MCP session to fetch data
- Keep it simple: vanilla HTML/CSS/JS, no framework dependencies
