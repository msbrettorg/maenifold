# T-79.4: ACP Agent Trait Implementation

## Requirement
FR-SRE-1 — Azure SRE Agent must be usable as a pipeline prompt node.

## Problem
Maenifold's `AgentPool` spawns ACP agent binaries and communicates via `agent-client-protocol` JSON-RPC over stdio. The shim must implement the `acp::Agent` trait so maenifold treats it as a native ACP agent.

## Acceptance Criteria
1. `agent.rs` implements `acp::Agent` for `SreAgent` struct with these methods:
   - `initialize()` → return `ProtocolVersion::V1`, client info `"maenifold-sre-agent"`, capabilities (no fs, no terminal)
   - `authenticate()` → return `AuthenticateResponse::default()` (auth is config-level via Azure CLI)
   - `new_session(req)` → generate a UUID session_id, store in `SessionStore`, return session_id
   - `prompt(req)` → extract `session_id` and prompt text, call `SrectlClient::prompt()`, emit `SessionNotification::AgentMessageChunk` with the response, return `PromptResponse` with `StopReason::EndTurn`
   - `cancel(req)` → call `SrectlClient::cancel()` for the session's active subprocess
   - `close_session(req)` → remove session from `SessionStore`
2. `session.rs` provides `SessionStore`:
   - `Arc<Mutex<HashMap<String, SessionState>>>` where `SessionState` tracks session_id and active srectl process handle
   - `create(session_id)`, `get(session_id)`, `remove(session_id)`
3. Prompt handling emits a "⏳ Investigating..." chunk immediately before calling srectl, then the full response after completion
4. All ACP errors map to proper JSON-RPC error codes

## Files to modify
