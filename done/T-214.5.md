# T-214.5 — Session uniqueness constraint

## Problem

Two pipeline nodes referencing the same session would race — both trying to send prompts to the same agent session simultaneously. The duo review identified this as a must-fix.

## Solution

Add schema-level validation: no two nodes in a pipeline may share a `sessionRef` (same agent + session_id combination). This is cheaper and safer than runtime locking.

Validate during pipeline definition processing — before any execution begins. Return a clear error identifying the conflicting nodes.

## Key Files

- Pipeline validation code (likely in the pipeline definition parsing/validation layer)

## Acceptance Criteria

- Pipeline with two nodes sharing same `sessionRef` is rejected at creation time
- Error message names both conflicting node IDs
- Pipeline with different `sessionRef` values accepted
- Pipeline with no `sessionRef` nodes accepted (backwards compatible)
- `cargo build --release -p maenifold-core` succeeds
