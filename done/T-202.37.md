# T-202.37 — Download button does nothing

## Problem

On Settings > Embeddings, clicking "Download" on any model changes the button text to "Downloading…" and disables it, but NO actual download occurs. The button stays in "Downloading…" state indefinitely. There is no progress indicator, no error, no timeout. The user sees a spinner forever.

## Observed

CDP test 2026-04-20: Clicked Download for all-MiniLM-L6-v2 (90 MB). Button changed to "Downloading…" (disabled). Waited 45+ seconds. No progress. No completion. No error. No toast. Button still says "Downloading…".

This is the same class of bug as the original T-202.9 — the UI promises functionality the backend doesn't deliver. The button is a lie.

## Root Cause (hypothesis)

The frontend calls `callTool('EmbeddingModels', { action: 'download', modelId: '...' })` but either:
1. The backend `handle_download()` function fails silently
2. The hf-hub download never starts or errors without surfacing
3. The frontend doesn't handle the response/error from the tool call
4. The download action is implemented but returns immediately without actually downloading

## Acceptance Criteria

1. Clicking Download starts a real download from HuggingFace
2. Progress is shown (percentage, bytes, or at minimum a real spinner with timeout)
3. On completion: button changes to "Activate" or "Installed"
4. On error: error toast shown, button returns to "Download" state
5. On timeout (>60s no progress): error state shown
6. CDP interactive test confirms end-to-end: click Download → see progress → model appears as Installed
