# T-200.12 — Unit tests for TaskStatusDeriver::derive()

## Intent

`task_status.rs` (111 LOC) contains the core gate state machine replay logic — `TaskStatusDeriver::derive()` — with zero direct unit tests. This function determines the effective state of every gate task by replaying its history records. A bug here would silently corrupt task state across the entire pipeline. Add targeted unit tests covering the key code paths.

## Scope

File to modify:
- `crates/maenifold-gate/src/task_status.rs` — add `#[cfg(test)]` module

## Test Plan

All tests use in-memory structs (`TaskDocument`, `TaskMetadata`, `TaskStageRecord`, `GateDefinition`). No filesystem access needed.

Use a helper function to build an SDD definition via `GateDefinition::from_json_text()` with states: pending → swe → red-team → blue-team → done.

### Tests to add:

1. **`empty_records_yields_initial_state`** — TaskDocument with no records, location "todo" → state should be "pending", attempts 0

2. **`single_pass_advances_to_next_stage`** — One pass outcome record (stage=pending, outcome=pass) → state "swe"

3. **`full_pass_chain_reaches_done`** — Pass through all stages (pending→swe→red-team→blue-team) → state "done", location "done"

4. **`fail_returns_to_initial`** — Pass from pending→swe, then fail from swe → state "pending"

5. **`append_does_not_change_state`** — Pass to swe, then an append record → state still "swe"

6. **`attempt_increments_on_fail_from_non_initial`** — Pass to swe, fail back to pending → attempts = 1

7. **`done_location_requires_terminal_state`** — State "swe" with location "done" → error

8. **`todo_location_rejects_terminal_state`** — Full pass chain with location "todo" → error (terminal state in todo/)

9. **`reopen_from_terminal_increments_attempts`** — Full pass chain to done (location "done"), then fail from done → state "pending", attempts 1, location "todo"
