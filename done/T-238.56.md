# T-238.56 — P1 Add PID/lock singleton to prevent multiple Teams monitor instances

**Pipeline**: sdd

## Problem

No singleton enforcement. Multiple monitor instances can run simultaneously, causing duplicate message processing and conflicting Trouter registrations.

## Reference

- agency-cowork: `/Users/brett/src/agency-cowork/skills/teams/scripts/monitor/service.py` L122-263 PID file + file lock management
- Rust target: `crates/maenifold-core/src/teams/supervisor.rs`

## Required changes

1. Write PID file on startup (`monitor/monitor.pid`)
2. Acquire file lock (`monitor/monitor.lock`) — fail if already held
3. Check for stale PID on startup (process no longer running → clean up)
4. Release lock and remove PID on clean shutdown

## Acceptance Criteria

- [ ] Only one monitor instance runs at a time
- [ ] Second instance fails with clear error naming the existing PID
- [ ] Stale PID from crashed process is cleaned up
- [ ] `cargo build --release -p maenifold-cli` passes
