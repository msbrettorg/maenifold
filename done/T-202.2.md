# T-202.2 — Fix daemon step: replace hallucinated /health probe with GET /api/config

## P0 — Blocks 100% of users

The onboarding wizard daemon step probes `GET /health` which does not exist. The daemon IS running but the wizard shows "Disconnected" forever. Continue is disabled. No user can get past step 2.

## Verified ground truth

- Binary: `maenifold` (NOT `maenifold-cli`)
- HTTP mode: `maenifold --http` with optional `--port 8080`
- No `serve` subcommand exists
- No `/health` endpoint exists in `crates/maenifold-core/src/api/routes.rs`
- `GET /api/config` returns `AgentsConfig` JSON and is already used by `configStore.loadConfig()` in `stores/config.ts:36`
- `POST /api/config/agents` exists at `routes.rs:669`

## File

`apps/desktop/src/components/OnboardingStepDaemon.vue`

## Changes required

1. **Line 21**: Change `const command = 'maenifold-cli serve'` → `const command = 'maenifold --http'`
2. **Line 29**: Replace `fetch(\`${DAEMON_BASE_URL}/health\`)` with a call through `useConfigStore().loadConfig()`. On success (no error), state = connected. On failure, state = disconnected.
3. **Lines 7-11**: Replace `DaemonStatus { version, tools, agents }` interface with data derived from the real config response: `agents = Object.keys(config.agents).length`, `mcpServers = (config.mcpServers ?? []).length`.
4. **Connected state display** (lines 181-186): Drop `version` line. Show agent count and MCP server count from the real config.
5. **Auto-poll** (line 56): Keep the 5-second poll but use the same `configStore.loadConfig()` path.

## Acceptance criteria

1. With daemon running (`maenifold --http`), wizard daemon step shows "Connected" with real agent/MCP server counts
2. With daemon NOT running, wizard shows "Disconnected" with correct command `maenifold --http`
3. Copy button copies `maenifold --http` to clipboard
4. Continue button enables when connected, advances to Agent step
5. `npx vue-tsc --noEmit` passes
6. Visual verification via Playwright: daemon step reaches "Connected" state with real daemon
