# T-79.3: srectl Subprocess Client

## Requirement
FR-SRE-1 — Azure SRE Agent must be usable as a pipeline prompt node.

## Problem
The ACP shim needs to send prompts to Azure SRE Agent and receive responses. The `srectl` CLI is the only documented programmatic interface. The shim must spawn `srectl` subprocesses, capture output, and handle errors/timeouts.

## Acceptance Criteria
1. `srectl.rs` provides `SrectlClient` struct with methods:
   - `init(endpoint: &str) -> Result<()>` — runs `srectl init --resource-url <endpoint>` in a temp workspace
   - `prompt(agent_name: &str, message: &str, timeout: Duration) -> Result<String>` — runs `srectl agent test --name <agent> --message <message>`, returns stdout as response
   - `cancel()` — kills the running srectl subprocess
2. Subprocess spawning uses `tokio::process::Command` with:
   - stdout captured (piped)
   - stderr captured (for error reporting)
   - `kill_on_drop(true)`
   - Configurable timeout via `tokio::time::timeout`
3. On timeout: kill subprocess, return `AgentError::Timeout`
4. On non-zero exit: return `AgentError::Message` with stderr content
5. `srectl init` is called once at construction time, not per-prompt
6. Working directory is a temp dir (cleaned up on drop)
7. Unit tests with mock srectl binary (shell script that echoes)
