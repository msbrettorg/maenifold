# T-69.3 — Pipeline MCP Schema: Advertise Node Config Fields

**Requirement**: FR-52
**Component**: crates/maenifold-core/src/mcp/schema/pipeline_tools.rs

## Problem

The MCP tool schema for Pipeline (`pipeline_node_schema()`) does not advertise `model`, `thoughtLevel`, `allowedTools`, `maxTurns`, `timeout`, `toolMode`, or `agentConfig` fields. LLMs and tool-calling clients cannot discover these capabilities when introspecting the tool schema. Fields still pass through because `definition` is an open `object`, but discoverability is zero.

## Acceptance Criteria

1. `pipeline_node_schema()` includes `model` (string, optional) for Prompt/SequentialThinking/Tool nodes
2. Schema includes `thoughtLevel` (string, optional)
3. Schema includes `allowedTools` (array of strings, optional)
4. Schema includes `maxTurns` (integer, optional)
5. Schema includes `timeout` (integer, optional) for applicable node types
6. Schema includes `toolMode` (string enum: "disabled", "auto", "normal", optional) for Prompt nodes
7. Schema includes `agentConfig` (object with model/mode/thoughtLevel/configOptions, optional)
8. Schema descriptions are clear and helpful for LLM tool-calling
9. Existing pipeline schema tests pass

## Implementation Notes

- The schema is hand-built JSON in `pipeline_tools.rs`
- Add properties to each node variant's schema object
- Use `description` fields to explain what each option does
- `agentConfig` should be a nested object schema
