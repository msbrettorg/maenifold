**Requirement**: NFR-10 (RTM-381)
**Priority**: P0
**Depends on**: T-50.1, T-50.2, T-50.3, T-50.4

## Context

Final step. After all extractions, `handler.rs` should contain only:
- `pub fn pipeline` (~135 lines) — the entry-point dispatcher
- `parse_max_concurrency` (~15 lines) — used only by the create path
- Inline create logic within `pipeline()` — or optionally extracted to a private `create_pipeline()` fn
- Remaining imports from sibling modules

## Acceptance Criteria

### Cleanup

1. Verify handler.rs contains ONLY:
   - `pub fn pipeline(context: &ToolContext, payload: &Value) -> Result<String>` — the entry-point
   - `parse_max_concurrency` — private helper for create path
   - No other production functions remain
2. handler.rs should be ~160–200 LOC (production code only, excluding test block)
3. All imports point to sibling modules: `use super::session_io::...`, `use super::view::...`, `use super::dispatch::...`, `use super::update::...`

### Remaining Tests

4. handler.rs retains ONLY these tests in its `#[cfg(test)] mod tests` block:
   - `pipeline_tool_registration_includes_pipeline_aliases` (test #1)
   - `pipeline_create_persists_pipeline_and_workflow_sessions` (test #2)
   - `pipeline_create_defaults_max_concurrency_to_eight` (test #3)
   - `pipeline_learn_returns_help_text` (test #4)
