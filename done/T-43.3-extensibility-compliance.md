# T-43.3: Extensibility Compliance — Wire Names, _meta, Capabilities

**Requirement**: FR-42 audit findings — Extensibility  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/lib/acp-bridge.ts`, `vendor/acp-ui/src/stores/session.ts`, `vendor/acp-ui/src/lib/types.ts`

## Acceptance Criteria

1. **Fix `session/set_model` wire name**: In `acp-bridge.ts`, the `unstable_setSessionModel` method sends `'session/set_model'`. This is a non-standard method that MUST use a `_` prefix per the extensibility spec. Change to `'_session/set_model'`.

2. **Fix `session/set_config_option` wire name**: Same issue — change to `'_session/set_config_option'` if this is not a standard spec method. Check the SDK's `AGENT_METHODS` export to determine if it's standard. If the SDK defines it as `session_set_config_option` in its methods enum, it IS standard and should NOT be prefixed. Only prefix methods that are truly custom.

3. **Add `_meta` to all request/response types**: Add `_meta?: Record<string, unknown> | null` to:
   - All outgoing request params (initialize, newSession, loadSession, prompt, setMode, setConfigOption)
   - All incoming response types where we construct objects
   - All notification params

4. **Advertise custom capabilities via `_meta`**: In the `initialize` call's `clientCapabilities`, add `_meta` advertising any custom methods the client supports.

5. **Read agent `_meta` capabilities**: After `initialize`, check `initResponse.agentCapabilities?._meta` for advertised extension support before calling custom methods.

6. **Reserve W3C trace context keys**: Document (via code comment) that `_meta.traceparent`, `_meta.tracestate`, and `_meta.baggage` are reserved for W3C trace context and must not be used for other purposes.

## Spec References

- Audit: EX-2 (_meta partial), EX-3 (W3C), EX-4 (wire name violations), EX-7 (capability advertisement)

## SWE Remediation

### What I changed

- `vendor/acp-ui/src/lib/acp-bridge.ts`
  - Changed the unstable session model wire method from `session/set_model` to `_session/set_model`.
  - Kept `session/set_config_option` unprefixed after checking the SDK `AGENT_METHODS` export, which defines it as a standard wire method.
  - Added `_meta` normalization for outbound requests/notifications so ACP request params consistently include `_meta`.
  - Added `_meta` to locally constructed ACP response objects (`RequestPermissionResponse`, `ReadTextFileResponse`) and preserved `_meta` when translating incoming permission requests into local UI state.
- `vendor/acp-ui/src/stores/session.ts`
  - Added ACP extensibility helpers for request `_meta`, extension capability advertisement, and agent extension capability parsing.
  - Advertised `_session/set_model` support under `clientCapabilities._meta`.
  - Read `initResponse.agentCapabilities?._meta` and gated unstable model handling on the agent advertising `_session/set_model`.
  - Added the required W3C trace-context reservation comment for `_meta.traceparent`, `_meta.tracestate`, and `_meta.baggage`.
  - Added `_meta` to outgoing initialize/newSession/loadSession/authenticate/prompt/cancel/setMode/setModel/setConfigOption requests and preserved `_meta` when mapping tool calls, slash commands, modes, models, and plan entries into local state.
- `vendor/acp-ui/src/lib/types.ts`
  - Added a shared `AcpMetadata` alias and `_meta` support to local ACP-derived UI types used for tool calls, permissions, modes, commands, models, config options, and plan entries.
