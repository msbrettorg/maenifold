# T-242.33 — Knowledge Graph node click broken after recovery

**Pipeline**: tdd

## Problem

Discovered during T-242.31 CDP verification of the recovered Knowledge tab. When clicking a node on the Graph subtab canvas, the Node Inspector remains blank ("No concept selected"). Expected: clicking a node populates the inspector with concept name, file count, community, neighbours, edge weights.

Evidence: `outputs/screenshots/T-242.31/scenario-3-node-selected.png` (showing Inspector still says "No concept selected" after clicking).

## Recovery context

T-242.13.6 (lost commit `94dde2d5d`) added `KnowledgeNodeInspector` + double-click jump. The component was recovered via T-242.29a cherry-pick. Likely cause: the recovered click handler binds to a property/event that's named differently on dev's current `useForceGraph` composable, OR the cytoscape binding for node selection drifted between when the original commit was authored and the current useForceGraph state.

## Investigation steps

1. Read `apps/desktop/src/composables/useForceGraph.ts` — does it expose a `selectedNode` ref or emit a `node:click` event?
2. Read `apps/desktop/src/components/KnowledgeGraphView.vue` and `KnowledgeNodeInspector.vue` — do they consume that ref/event correctly?
3. Look for the specific click handler. The cytoscape API uses `cy.on('tap', 'node', cb)` typically.
4. CDP-test fix: click a node, confirm inspector populates.

- [ ] Double-click on a node jumps to the Memory subtab with that note open (T-242.13.6 acceptance criterion).
