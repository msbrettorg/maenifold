# T-64.7 — Workflow step progress reader + view integration (BE)

**Requirement**: FR-24

## Acceptance Criteria

- For Workflow nodes with completed/active status: view response includes `workflow_steps` array
- Each step element contains: `step_name` (String), `status` (String: pending/active/complete/failed), `output` (Option<String>)
- Step data sourced from workflow session files
- When session file is missing: `workflow_steps` is null
- For in-progress workflows: return steps with current progress (completed steps + active step)
- All existing pipeline tests pass
- `cargo test -p maenifold-core -- pipeline` green

## Design Guidance

**`parse_step_progress()` in runner.rs is private and step data isn't persisted to NodeState.** Two options:
1. Make the parser public and call it from view.rs to parse session files on demand
2. Persist step progress in NodeState during execution

Option 1 is preferred (simpler, no state schema change, follows maenifold's "read from real files" philosophy). The session files are the source of truth.
