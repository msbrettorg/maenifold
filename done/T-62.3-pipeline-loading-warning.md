# T-62.3 Warn when using default SDD pipeline fallback

## Acceptance Criteria

When `load_pipeline_def()` falls back to the embedded SDD pipeline (no `pipeline.json` found), emit a diagnostic so users know they're getting SDD semantics by default.

### Changes

1. **`pipeline.rs` `load_pipeline_def()`** (line ~44): When falling back to the embedded `sdd.json`, print to stderr:
   ```
   note: no pipeline.json found in {root}, using default SDD pipeline
   ```

2. **Consider**: Add a `--pipeline <name>` flag to gate commands that accepts `sdd`, `tdd`, `gsd`, or a path. When specified, load from `assets/pipelines/{name}.json` (embedded) or the given path. This gives TDD/GSD users an explicit way to select their pipeline without creating a `pipeline.json`.

3. **CLI integration**: `parse_pass`, `parse_reject`, `parse_status`, `parse_sync` in `cli.rs` already accept `--pipeline`. Verify that the `--pipeline` flag in `parse_transition_args` passes through to `load_pipeline_def`.

### Verification

- `cargo test -p maenifold-gate` must pass
- Running `gate status .` in a directory without `pipeline.json` shows the note on stderr
- Running `gate status . --pipeline tdd` uses the TDD pipeline without needing a file
