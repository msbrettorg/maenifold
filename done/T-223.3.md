# T-223.3 — Agent env var passthrough drops configured API keys

## Problem

After editing an agent's environment variables in Settings, new sessions still use the stale cached env. The `ADAPTER_CACHE` in `crates/maenifold-jockey/src/acp/adapter.rs` is keyed by `(runtime, root)` and caches `(binary, args, env)`. `clear_adapter_cache()` exists but is **never called**. `update_agent_handler` in `routes_config.rs` refreshes `MaenifoldSettings` but does not invalidate the adapter cache, so cold-starts after a config edit reuse the original (possibly empty) env vector.

## Root Cause

`crates/maenifold-jockey/src/acp/adapter.rs:66-77` — `ADAPTER_CACHE` is a `LazyLock<Mutex<HashMap>>` that caches resolved adapter entries. `clear_adapter_cache()` at line ~116-124 exists but has zero callers. When the user updates `agents.<name>.env` via the Settings UI, the config file is written but the in-memory cache is never flushed.

## Fix

Call `clear_adapter_cache()` in `update_agent_handler` (in `crates/maenifold-core/src/api/routes_config.rs`) after the config persist succeeds, so the next session cold-start reads fresh env values from disk.
