## Problem

vec0 SQLite extension binaries are pre-placed in `~/maenifold/assets/native/<platform>/` but most platform variants are 0-byte placeholders. Only osx-arm64 and linux-arm64 have real binaries. Windows, osx-x64, and linux-x64 are broken.

Bundling platform-specific native binaries creates licensing, size, and staleness problems.

## Solution

Add a vec0 download step to the onboarding wizard (alongside the embedding model step):

1. Detect platform (`process.platform` + `process.arch`)
2. Check if `~/maenifold/assets/native/<platform>/vec0.{dylib,so,dll}` exists and is non-zero
3. If missing, download from `https://github.com/asg017/sqlite-vec/releases/latest`
4. Extract the correct binary to the native assets directory
5. Show progress + error handling in the wizard UI

## Platform mapping

| Platform | Arch | Release asset pattern | Target file |
|---|---|---|---|
| darwin | arm64 | `sqlite-vec-*-loadable-macos-aarch64.tar.gz` | `osx-arm64/vec0.dylib` |
| darwin | x64 | `sqlite-vec-*-loadable-macos-x86_64.tar.gz` | `osx-x64/vec0.dylib` |
| linux | arm64 | `sqlite-vec-*-loadable-linux-aarch64.tar.gz` | `linux-arm64/vec0.so` |
| linux | x64 | `sqlite-vec-*-loadable-linux-x86_64.tar.gz` | `linux-x64/vec0.so` |
| win32 | x64 | `sqlite-vec-*-loadable-windows-x86_64.tar.gz` | `win-x64/vec0.dll` |

## Acceptance Criteria

- Onboarding wizard detects missing/empty vec0 binary
- Downloads correct platform binary from GitHub releases
- Progress indicator during download
- Error toast if download fails
- vec0 binary verified loadable after download
- Zero bundled placeholder binaries in the repo
- Works offline if binary already present
