# T-218.48 — Gateway Startup Diagnostics Completion

## Problem

Per-server degraded startup already exists in `StdioPool::start` (JoinSet-based parallel spawn, `ManagedServer::degraded` on failure). However, diagnostics are incomplete:

1. **Stderr lost on startup failure** — when `StdioSession::start()` returns `Err`, the `StartupState` (including `stderr_sink`) is dropped. Failed servers have no stderr evidence.
2. **Error messages may leak filesystem paths** — raw OS spawn errors can include command paths.
3. **All-failed pool is destroyed** — `gateway_startup.rs` lines 59-67 shut down the pool and discard diagnostics when all gateway tools are empty.
4. **StdioServerHealth lacks explicit outcome enum** — status is inferred from `running` + `last_start_error` fields.

## Parent

Decomposed from T-218.37 (Gateway consolidation startup diagnostics).

## Acceptance Criteria

- [ ] `StdioSession::start()` returns stderr buffer alongside errors (change return type to capture stderr on failure, e.g. include `Option<String>` stderr tail in the error path)
- [ ] `StdioServerHealth` extended with: explicit `status: Started | Failed` enum, `stderr_tail: Vec<String>` (max 10 lines, captured from startup stderr)
- [ ] Error messages in `StdioServerHealth.last_start_error` are sanitized: absolute paths matching `/[~/][\w./-]+` stripped and replaced with `[path]`
- [ ] When ALL upstream gateway servers fail, `gateway_startup.rs` retains the health snapshot (do NOT shut down pool or discard diagnostics). `GatewayStartup` carries diagnostics even in the `Failed` variant.
- [ ] `tools/list` continues returning native maenifold tools when all gateway servers fail — native tools are never hidden by gateway failures
- [ ] `GatewayState` exposes a `startup_diagnostics()` accessor returning the per-server health snapshot for downstream consumers
- [ ] `cargo build --release -p maenifold-cli` succeeds
- [ ] `cargo test -p maenifold-core` passes (existing `stdio_pool_partial_startup_keeps_survivors_usable` test must continue passing)

## Key Files

- `crates/maenifold-core/src/mcp/stdio_session.rs` — stderr capture on startup failure (~30 LOC)
- `crates/maenifold-core/src/mcp/stdio_pool.rs` — propagate stderr through `start_session` (~20 LOC)
- `crates/maenifold-core/src/mcp/stdio_pool_health.rs` — extend `StdioServerHealth` with status enum + stderr tail + sanitization helper (~30 LOC)
- `crates/maenifold-core/src/mcp/gateway_startup.rs` — retain diagnostics on all-failed, carry in `GatewayStartup` (~30 LOC)
- `crates/maenifold-core/src/mcp/gateway_handler.rs` — expose `startup_diagnostics()` on `GatewayState` (~20 LOC)
- Server config: `crate::acp_config` (`AgentsConfig`, `McpServerEntry`)
