# T-64.3 — Add edge mapping to FE types + edge mapping editor (FE)

**Requirement**: FR-17

## Acceptance Criteria

- `PipelineEdge` interface has optional `mapping?: Record<string, string>`
- Edge serialization updated in pipeline store create/graft operations
- Edge deserialization handles mapping from view response
- New component: EdgeMappingEditor.vue
  - When edge selected in design mode: shows target node's input params
  - For tool targets: shows tool's inputSchema fields from store.tools (dropdown of available params)
  - For ACP targets: shows "Predecessor context (prepended)" with optional mapping override
  - Source output field selection: dropdown populated from source node's completed output JSON keys (when available), falls back to text input for dot-path when source has no output
  - Allow mapping source output fields → target input fields
- Integrated into PipelineInspector.vue edge section (design mode)
- `npx vue-tsc --noEmit` passes

## Error/Edge State Design (Gründlichkeit)

- **Tool not in store**: Show "Tool schema unavailable — enter parameter names manually" with text input fallback
- **Source node has no output** (not yet executed): Show text input for dot-path with placeholder "e.g., results[0].title"
- **Source node has completed output**: Parse output JSON, show top-level keys as dropdown options. Nested paths entered as text.
- **Tool inputSchema changes between design and execution**: Not validated at design time. If mapping becomes invalid, tool fails at runtime with real error (maenifold philosophy).
- **store.tools not loaded**: Show loading spinner, retry on tools refresh
