# T-177.1 — CONTRIBUTING.md — contributor onboarding guide

## Intent

MIT licensed, "Issues and pull requests are welcome" — but no CONTRIBUTING.md. A contributor landing on this repo has no map: how to build, how to test, what the architecture is, what the conventions are, where to start. DEVELOPMENT.md exists but is build-commands only.

## Scope

Create `CONTRIBUTING.md` at repo root:

1. **Quick orientation** — what the repo is (one sentence), link to `readme.md`
2. **Architecture map** — crate responsibilities (maenifold-core, maenifold-cli, maenifold-gate, maenifold-jockey, maenifold-pipeline-driver), apps/desktop relationship, MCP-only boundary rule
3. **Build from source** — cargo build, desktop app (`pnpm --dir apps/desktop dev:electron` / `pnpm --dir apps/desktop build`), prerequisites
4. **Testing** — cargo test, MAENIFOLD_FULL_SUITE, testing philosophy (no mocks — link `docs/TESTING_PHILOSOPHY.md`)
5. **Code conventions** — Ma philosophy (link `docs/MA_MANIFESTO.md`, `docs/WHAT_WE_DONT_DO.md`), mechanism not policy, one responsibility per file
6. **Gate workflow** — how SDD works (todo/ → swe → red-team → blue-team → done/), link `docs/gate-uml-spec.md`
7. **Where to start** — good first issues, which areas need help
8. **Documentation** — link to all docs/*.md

## Files touched

- `CONTRIBUTING.md` (new)

## Acceptance criteria

1. New contributor can go from clone to running tests in < 5 minutes following the guide
2. Architecture section names all 5 crates with one-line descriptions (`maenifold-core`, `maenifold-cli`, `maenifold-gate`, `maenifold-jockey`, `maenifold-pipeline-driver`)
3. Links to `docs/MA_MANIFESTO.md`, `docs/WHAT_WE_DONT_DO.md`, `docs/TESTING_PHILOSOPHY.md`, `docs/DEVELOPMENT.md`
4. Gate workflow explained
