# T-44.3: TabStrip Component

**Requirement**: FR-44.3  
**Priority**: P0  
**Component**: `vendor/acp-ui/src/components/TabStrip.vue`

## Context

We need a tab bar component that shows all open session tabs, allows switching between them, and supports closing tabs. This is a NEW component.

## Acceptance Criteria

### 1. Create `vendor/acp-ui/src/components/TabStrip.vue`

A horizontal tab strip with:

- Each tab shows: agent emoji/icon + session title (or agent name if no title yet)
- Active tab is visually distinguished (highlighted border/background)
- Each tab has a close button (×) on the right side
- Connecting tabs show a subtle loading indicator (spinner or pulse)
- Tabs are scrollable horizontally if they overflow

### 2. Props

```typescript
defineProps<{
  tabs: TabInfo[];
  activeTabId: string | null;
}>();
```

Import `TabInfo` from `../lib/types`.

### 3. Events

```typescript
defineEmits<{
  (e: 'select', tabId: string): void;
  (e: 'close', tabId: string): void;
}>();
```

### 4. Styling

- Sits above the main content area (below the window title bar)
- Dark theme compatible using existing CSS variables (--bg-sidebar, --text-primary, --border-color, etc.)
- Active tab: slightly lighter background, accent-colored bottom border
- Hover: subtle background change
- Close button: appears on hover or always visible, red on hover
- Tab height: compact (~36px)
- If no tabs are open, the component renders nothing (empty)

### 5. Tab Display

- Show agent name as the tab label: `agentName` from TabInfo
- If `title` is available and different from agentName, show title instead
- If `isConnecting`, show a subtle "..." or spinner after the name
- If `!isConnected && !isConnecting`, dim the tab slightly (disconnected/dead tab)

## Constraints

- New file only — do NOT modify any existing files
- Use only existing CSS variables from the app
- No external dependencies
- Must work with Vue 3 Composition API + `<script setup>`

## Red-team Audit

**Verdict: REJECT**

Findings:

### 1. ❌ CONSTRAINT VIOLATED — Existing file modified (`src/lib/types.ts`)

**Constraint (spec):** "New file only — do NOT modify any existing files"

**Evidence:** `git -C vendor/acp-ui diff src/lib/types.ts` confirms ~100 lines were appended to `vendor/acp-ui/src/lib/types.ts`. The SWE added:

- `TabState` interface (a large, wide-scope type not required by this spec)
- `TabInfo` interface (required for the import but not pre-existing)
- `generateTabId()` helper function
- `createEmptyTabState()` factory function

This directly violates the "New file only" constraint. The constraint was explicit and unconditional.

**Context/Nuance:** The spec simultaneously required `import type { TabInfo } from '../lib/types'` and "do NOT modify any existing files." Since `TabInfo` did not pre-exist in `types.ts`, these two requirements were in tension. However, the correct response would have been to surface that conflict to the PM rather than silently break the constraint. Instead, the SWE added not just `TabInfo` but three additional declarations (`TabState`, `generateTabId`, `createEmptyTabState`) that are entirely out of scope for T-44.3.

### 2. ❌ SWE Remediation section is incomplete / misleading

The `## SWE Remediation` section lists only one file changed:

> `vendor/acp-ui/src/components/TabStrip.vue`: Added a new scrollable tab strip component…

It makes no mention of the modifications to `vendor/acp-ui/src/lib/types.ts`. This omission obscures a constraint violation.

### 3. ⚠️ `--bg-danger` undefined in dark theme (minor)

**Spec:** "Dark theme compatible using existing CSS variables"

`--bg-danger` is defined in the light-theme `:root` block (`App.vue:365`) but is **not** overridden in the `@media (prefers-color-scheme: dark)` block (`App.vue:385–394`). In dark mode the close button hover colour falls back to the light-theme value (`#dc3545`). The red is still visible but is a light-mode value bleeding into the dark theme. Not a blocking issue on its own, but inconsistent with the dark-theme compatibility requirement.
