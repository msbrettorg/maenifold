# T-68.5: Pipeline Capability-Aware Node Configuration

## Requirement
FR-51 — Pipeline nodes must be configurable based on the capabilities of the selected ACP agent.

## Problem
Pipeline nodes specify `agent`, `model`, and `thought_level` but have no way to know what the agent actually supports. Different agents support different models, modes, thinking levels, and config options. Without capability awareness, node config is guesswork.

## Acceptance Criteria
1. Pipeline `definition` must support a new `agent_config` object on prompt/thinking nodes:
   ```json
   {
     "id": "research",
     "agent": "OpenCode",
     "agent_config": {
       "model": "gpt-4.1",
       "mode": "code",
       "thought_level": "high",
       "config_options": { "key": "value" }
     }
   }
   ```
2. Before dispatching a node, the executor must validate `agent_config` against the agent's capabilities (from T-67.1/T-67.2):
   - `model` must be in `available_models` (or log warning and proceed)
   - `mode` must be in `available_modes` (or log warning and proceed)
   - Unknown `config_options` keys should log warnings
3. Pipeline `view` output must include the agent's available models/modes for each agent used
4. The `Pipeline` MCP tool schema must document `agent_config` in the help text
