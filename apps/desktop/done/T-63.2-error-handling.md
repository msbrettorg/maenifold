# T-63.2 — Error Handling: Surface MCP Errors

**Requirement**: FR-2
**Test Cases**: TC-3, TC-4
**Repo**: pipeline-ui
**Component**: src/components/PipelineRunner.vue, src/components/PipelineInspector.vue, src/stores/pipeline.ts

## Context

ALL MCP errors are silently swallowed. Store actions use `void` + `try/finally` with no `catch`. Users see nothing when operations fail — buttons just stop spinning.

## Acceptance Criteria

1. Add `errorMessage: ref<string | null>(null)` and `clearError()` to the Pinia store
2. Every store action that calls MCP (`runPipeline`, `pausePipeline`, `resumePipeline`, `cancelPipeline`, `deletePipeline`, `restartNode`, `updateNodeStatus`, `graftNodes`, `loadPipeline`, `createPipeline`) must `catch` errors and set `errorMessage`
3. `PipelineRunner.vue`: display error banner (styled with `--bg-error`, `--text-error`, `--border-error`) above runner controls when `store.errorMessage` is non-null. Include dismiss button that calls `store.clearError()`
4. `PipelineInspector.vue`: display error banner above inspector actions for action-specific errors
5. Error messages should include the MCP tool name and a user-readable summary — not raw JSON
6. Errors auto-clear after 10 seconds OR on next successful action
7. Typecheck passes: `npx vue-tsc --noEmit`


## SWE Remediation

Implemented by claude-sonnet-4.6. Modified pipeline.ts (store), PipelineRunner.vue, PipelineInspector.vue. Added errorMessage ref, clearError(), setError(), withError<T>() wrapper. All 10 actions wrapped. Error banners with role=alert + dismiss in Runner and Inspector. Uses design tokens. vue-tsc passes. All files under 300 LOC.

This is safe in practice because `withError` always calls `clearError()` (which does cancel the timer) before invoking any action, making a double-`setError` without an intervening `clearError` unreachable from the public API. Not a spec violation.
