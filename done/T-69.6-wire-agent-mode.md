# T-69.6 — Wire AgentConfig.mode to session/set_mode

**Requirement**: FR-52
**Component**: crates/maenifold-core/src/acp/native/session.rs, crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs

## Problem

`AgentConfig.mode` is accepted in the pipeline node schema and preserved in the wire format, but `session/set_mode` is **never called** anywhere in the codebase. The `mode` field is logged with a warning and silently dropped in `executor_nodes.rs`. Users who set `mode: "extended"` or similar values on pipeline nodes are silently ignored.

The ACP SDK provides `set_session_mode(session_id, mode_id)` which maps to `session/set_mode`. This must be wired.

## Acceptance Criteria

1. `SessionOpts` gains a `mode: Option<String>` field
2. `merged_session_opts` populates `mode` from `agent_config.mode` (node-level mode field does not exist, so no merge needed)
3. `handle_new_session` calls `set_session_mode(conn, sid, mode)` when `opts.mode` is `Some`
4. The warning log about mode being unused is removed
5. Existing session tests pass
6. Add test: verify mode is passed through to ACP session

## Implementation Notes

- Add `mode` to `SessionOpts` in `types.rs`
- In `executor_nodes.rs`, remove the warning log and populate `mode` from `agent_config.mode`
- In `session.rs` `handle_new_session`, add the `set_session_mode` call after model setup
- The ACP SDK method is: `conn.set_session_mode(sid, SessionMode::new(mode_id))`
- Check if `SessionMode` needs to be imported from `agent_client_protocol`
