# T-63.26 — Mermaid Initialize Once

**Requirement**: NFR-2
**Test Cases**: TC-28
**Repo**: pipeline-ui
**Component**: src/components/PipelineRunner.vue

## Context

`PipelineRunner.vue` calls `mermaid.initialize()` on every render cycle. This is wasteful and can cause flickering/reinit bugs.

## Acceptance Criteria

1. Move `mermaid.initialize()` call out of the render/update cycle
2. Initialize once at module level or on first use (lazy singleton pattern):
   ```ts
   let initialized = false
   function ensureMermaidInit() {
     if (!initialized) { mermaid.initialize({ ... }); initialized = true }
   }
   ```
3. Call `ensureMermaidInit()` before each `mermaid.render()` call
4. Mermaid config (theme, etc.) is set once, not overwritten per render
5. Typecheck passes: `npx vue-tsc --noEmit`

## Swe Notes

PASS. Added ensureMermaidInit lazy singleton guard, moved init call to immediately before each mermaid.render(), and kept mermaid.initialize config one-time only.

## Red Notes

AC2: lazy singleton via module-level let mermaidInitialized=false + ensureMermaidInit(). AC3: ensureMermaidInit(mermaid) called immediately before mermaid.render() in watch handler. AC4: initialize config (startOnLoad:false, theme:neutral) set once only. AC5: npx vue-tsc --noEmit exits 0, no type errors.
