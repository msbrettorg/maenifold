## Goal

Create the first cycle-free [[gate-backlog]] library boundary required before maenifold can expose gate as native [[MCP]] tools. The current `maenifold-gate` crate depends on `maenifold-core`, so `maenifold-core` must not depend on `maenifold-gate`. This child extracts only pure data/state modules into `crates/maenifold-gate-core/`; stage-section parsing, I/O/cache/catalog, and command/tool-service layers are split into dependent children. This child continues parent [[sequential-thinking]] session `session-1777236650835-22077`.

## File Scope

Stay within 12 files. The 600 LOC budget applies to net-new logic only; mechanical relocation of existing data/state modules is expected to exceed 600 moved lines and must not change behavior.

- `Cargo.toml`
- `Cargo.lock`
- `crates/maenifold-gate-core/Cargo.toml`
- `crates/maenifold-gate-core/src/lib.rs`
- `crates/maenifold-gate-core/src/error.rs`
- `crates/maenifold-gate-core/src/gate_definition.rs`
- `crates/maenifold-gate-core/src/state_machine.rs`
- `crates/maenifold-gate-core/src/task_id.rs`
- `crates/maenifold-gate-core/src/task_metadata.rs`
- `crates/maenifold-gate-core/src/task_status.rs`
- `crates/maenifold-gate/Cargo.toml`
- `crates/maenifold-gate/src/main.rs`

## Acceptance Criteria

- `maenifold-gate-core` has no dependency on `maenifold-core`.
- `maenifold-core` has no dependency on `maenifold-gate`.
- The retiring `maenifold-gate` crate depends on the new library during transition.
- The retiring `maenifold-gate` crate root consumes the relocated data/state modules from `maenifold-gate-core` instead of continuing to declare local copies.
- Gate definition parsing, state-machine transitions, task ID ordering, task metadata parsing, and task status derivation are preserved.
- No task section parsing, task file I/O, cache DB, command execution, tool-service, native [[GatewayExecute]] registration, or standalone service removal is attempted in this child.
- No native [[GatewayExecute]] registration is attempted in this child; that is `T-237.1a2`.

## Verification Commands

- `cargo metadata --format-version 1 --no-deps`
- `cargo test -p maenifold-gate-core`
- `cargo test -p maenifold-gate-core state_machine`
- `cargo test -p maenifold-gate-core task_status`

## Non-Goals

- Do not change desktop UI.
- Do not remove the standalone binary/tray in this child.
- Do not register native gate MCP tools in this child.
- Do not extract `gate_tool_service.rs` in this child; `T-237.1a1b` owns the CLI-type decoupling.
