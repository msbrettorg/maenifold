# T-218.34 — Schedule OS Install Transactionality

## Problem

Schedule create/update can persist JSON config before OS scheduler installation succeeds. Unsupported platforms or permission failures can leave active-looking schedules that never run.

## Acceptance Criteria

- [ ] Create/update performs OS install before commit, or rolls back store changes if OS install fails
- [ ] Delete removes config when OS uninstall reports "not installed" while surfacing actionable warnings for real permission failures
- [ ] UI shows platform support: macOS launchd, Linux systemd user timers, Windows unsupported unless implemented
- [ ] On unsupported platforms, enabled schedule creation is blocked before persisting
- [ ] Failure-injection test or manual verification proves OS install failure leaves no active-looking persisted schedule
- [ ] Gate notes document the chosen consistency model
