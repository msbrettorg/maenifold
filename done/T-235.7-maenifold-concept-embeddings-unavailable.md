## Problem

During required grounding for the instruction update, `FindSimilarConcepts` returned no similar concepts and advised running `Sync`. Earlier in the same session, maenifold sync reported concept and memory embedding failures because the ONNX Runtime library was not found.

That means required graph reasoning can degrade to keyword-only behavior while agents continue as if grounding succeeded.

## Scope Notes

- Fix the product behavior when semantic grounding is unavailable
- Do not treat this as an environment setup task for the current PM session
- Reuse the explicit `BLOCKED` / degraded-state pattern already present in `repair/semantics.rs` instead of inventing a new signaling style
- Adjacent shared helpers or response-shaping code may be updated if required, but the change stays within the `maenifold-core` semantic search / similarity surface

## Expected result contract

Use the existing `repair/semantics.rs` pattern as the acceptance reference:

1. `FindSimilarConcepts` must return a success transport with a human-visible result body that begins with `BLOCKED:` (or the same `⚠️ BLOCKED:` style) when embeddings are unavailable, followed by actionable remediation text.
2. `SearchMemories` semantic mode must return the same explicit `BLOCKED:` style result when embeddings are unavailable rather than an empty success-shaped result.
3. `SearchMemories` hybrid mode may still return normal text results, but the returned output must include an explicit warning that semantic search was unavailable and the results are text-only.
4. Low-level vector helpers own unavailability detection; the command/search layers named in the file scope own synthesis of the user-visible `BLOCKED` / warning output.

## Acceptance Criteria

- [ ] `FindSimilarConcepts` no longer falls through to success-shaped output when embeddings are unavailable; it returns an explicit actionable `BLOCKED` result instead of misleading users to run `Sync`
- [ ] `SearchMemories` semantic mode returns an explicit actionable `BLOCKED` result when embeddings are unavailable instead of empty results
- [ ] `SearchMemories` hybrid mode remains usable but explicitly states that semantic search is unavailable and the result set is text-only
- [ ] User-facing remediation text tells agents what is actually missing (for example ONNX runtime, vec0 support, or embedding model activation/path) rather than implying sync alone will fix it
- [ ] Future grounding output cannot be treated as fully successful when embeddings are unavailable because the degraded/blocked state is explicit in the returned result
