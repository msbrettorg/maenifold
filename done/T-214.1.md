# T-214.1 — Spike: session/load RPC in executor

## Problem

The Session-as-Node feature requires resuming ACP sessions by passing a known `sessionId` to the pipeline executor. Before implementing, we need to verify whether the current executor code path actually resumes agent sessions, or if an explicit `session/load` RPC is needed.

## Research Questions

1. **Does `open_agent_session()` in `agent_session.rs` accept a sessionId parameter?** If so, what happens — does it call `session/load` or `session/new` with the ID?
2. **What does `AgentSessionConfig.session_id` do?** (defined in `runner_prompt.rs`) — is it plumbed through to the ACP client?
3. **Does `keep_session_alive = true` (in `executor_run_exec.rs`) prevent session teardown?** What happens to the agent's session state between pipeline node executions?
4. **What does the ACP `session/load` RPC require?** Read the protocol spec for session loading/resuming.
5. **Does `ListedSession.status` expose `supports_load_session` correctly?** Check `sessions_query.rs:181`.

## Key Files to Read

- `crates/maenifold-core/src/workflow/agent_session.rs` — `open_agent_session()`
- `crates/maenifold-core/src/workflow/runner_prompt.rs` — `AgentSessionConfig`

**Research Question:** Can we pass a sessionId to the executor and have it resume that ACP session?

**Answer: NO** — Session resume does NOT work today.

### Critical Finding
`execute_runtime()` in `execute.rs` line 65 hardcodes:
```rust
let resume_session_id = None;
```

The session_id field in AgentSessionConfig is used only as a connection pool key (`app_session_id`), not as an ACP session resume target.

### Existing Infrastructure
The jockey ACP client already has working `session/load` code in `cold_start.rs` lines 158-205. It checks `supports_load` capability and calls `conn.load_session()` when `resume_session_id` is Some.

### Implementation Path for T-214.3
1. Add `resume_session_id: Option<String>` to session config (distinct from pool key)
2. Plumb through `execute_runtime()` → `WorkerMsg::Execute` → `cold_start()`
3. Verify agent `supports_load_session` capability before attempting resume
4. Add `sessionRef` field to pipeline node schema

The infrastructure exists — only parameter threading is required.
