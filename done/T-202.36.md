# T-202.36 — Full-app design system audit

## Problem

DESIGN.md exists but is not consistently followed across the app. Multiple screens violate the design system in different ways. This needs a systematic sweep — not one-off fixes.

## Scope

Every screen, every component, every state must be audited against `apps/desktop/DESIGN.md`. This is not optional polish — it's brand consistency. The UI is our first impression.

## Known Violations (from CDP testing 2026-04-20)

- Dark blue text on gray backgrounds in Knowledge explorer (T-202.35)
- Active model card on Embeddings page not visually distinct from others
- "Disconnected" status on Home has no visual treatment (just plain text)
- Graph visualization is bare-bones (T-202.34)

## Audit Checklist (per DESIGN.md)

- [ ] No `1px solid` borders — tonal surface shifts only
- [ ] Sentence case always — never ALL CAPS
- [ ] No debug info in default UI state
- [ ] No redundant display
- [ ] Status beads (6px dots) — not pill badges
- [ ] `4px` radius — not bubbly
- [ ] No drop shadows — ambient glow only
- [ ] Typography: Space Grotesk 500 headlines, Inter 400 body, JetBrains Mono code
- [ ] Text `#e5e2e1`, muted `#707070`
- [ ] Primary buttons: gradient `#adc6ff → #4d8eff`, dark text `#001a42`
- [ ] z-index layers correct

## Approach

1. CDP walkthrough of every screen with agent-browser
2. Screenshot each screen
3. Compare against DESIGN.md spec point by point
4. File individual items for each violation found
5. SWE fixes grouped by component

## Acceptance Criteria

1. Every screen passes DESIGN.md checklist
2. CDP interactive verification confirms visual consistency
3. No contrast violations
4. No stale design patterns (pill badges, drop shadows, bubbly corners)
