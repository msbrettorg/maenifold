# T-53.1 — `fs.rs` — Filesystem Operations

**Requirement**: FR-41 (File-Authoritative Pipeline Gate Cache)
**Component**: `crates/maenifold-gate/src/fs.rs`

## Context

The gate CLI needs filesystem primitives to discover task files in `todo/` and `done/`, read their content, and move files between directories on stage transitions. The `walkdir` crate is already declared as a dependency.

## Acceptance Criteria

1. Implement `discover_tasks(root: &Path) -> Result<Vec<DiscoveredTask>>` that:
   - Walks `{root}/todo/` and `{root}/done/` using `walkdir`
   - Filters for files matching `T-*.md` pattern
   - Returns `DiscoveredTask { path: PathBuf, location: TaskLocation }` for each match
   - Skips non-matching files silently
   - Returns an error if neither `todo/` nor `done/` exist

2. Implement `read_task(path: &Path) -> Result<String>` that:
   - Reads the file content as UTF-8
   - Returns a descriptive error if the file doesn't exist or isn't valid UTF-8

3. Implement `move_task(from: &Path, to_dir: &Path) -> Result<PathBuf>` that:
   - Moves a task file from its current location to `to_dir`, preserving the filename
   - Creates `to_dir` if it doesn't exist
   - Returns the new path
   - Returns an error if the destination file already exists (no silent overwrite)

4. Implement `resolve_task_path(root: &Path, file: &str) -> Result<(PathBuf, TaskLocation)>` that:
   - Searches `{root}/todo/{file}` then `{root}/done/{file}`
   - Returns the first match with its location
   - Returns an error if not found in either directory

5. All functions use `anyhow::Result` for error handling with descriptive context messages.

6. Module must be under 100 LOC.

## Red-team Audit

**Verdict: PASS**

### Check 1 — `discover_tasks`
✅ Walks both `{root}/todo/` and `{root}/done/` via `walkdir::WalkDir`. Skips a base dir that doesn't exist (`continue` on `!base.is_dir()`). Filters with `is_task()` which checks `starts_with("T-")` and `ends_with(".md")`. Returns `DiscoveredTask { path, location }` for each hit.

Error condition (line 19):
```rust
if found.is_empty() && !root.join("todo").is_dir() && !root.join("done").is_dir() { bail!(...) }
```
`found.is_empty()` is logically redundant — when neither dir exists both loops `continue`, so `found` is always empty — but it is **not** wrong. The effective guard is still "bail iff neither dir exists", which matches the spec exactly. Returns `Ok(vec![])` when dirs exist but hold no matching files, which is also correct.

### Check 2 — `read_task`
✅ Calls `fs::read(path)` (byte read) then `String::from_utf8(...)`. Each step attaches a descriptive `.with_context()` message: one for I/O failure (missing file, permission error) and one for invalid UTF-8. Both error paths are exercised implicitly through the build; the spec does not require a dedicated unit test for this function.

### Check 3 — `move_task`
✅ Extracts filename with `.context("task path is missing a filename")`. Calls `fs::create_dir_all(to_dir)`. Guards against silent overwrite with `to.exists()` → `bail!`. Calls `fs::rename` and returns the new path.

Minor observation (not a reject): `to.exists()` followed by `fs::rename` is a TOCTOU window. For a single-user local CLI tool this is acceptable.

### Check 4 — `resolve_task_path`
✅ Iterates `[(todo/file, Todo), (done/file, Done)]` in order, returns the first path whose `is_file()` is true. Bails with a descriptive message when neither matches. The test covers todo hit, done hit, and missing case.

### Check 5 — `anyhow::Result` + `.context()`
✅ Every fallible operation carries a `.with_context(|| ...)` or `.context(...)` call. All four public functions return `anyhow::Result`.
