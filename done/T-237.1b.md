## Goal

Remove the desktop app's separate [[gate-service]] MCP connection and route Gate UI data operations through the main maenifold [[MCP]] connection using [[GatewayExecute]] domain `maenifold.gate`. This child continues parent [[sequential-thinking]] session `session-1777236650835-22077`.

## Acceptance Criteria

- Gate UI no longer uses `DEFAULT_GATE_MCP_BASE_URL` or any separate gate MCP endpoint.
- Required Gate actions call `GatewayExecute` with `domain: "maenifold.gate"`.
- This child creates or updates `apps/desktop/src/composables/__tests__/useGateMcp.test.ts`; it is not assumed to exist before implementation.
- `useGateMcp.test.ts` proves all seven required gate operations call `GatewayExecute` with `domain: "maenifold.gate"` and the accepted `gate_*` command names.
- `useGateMcp.test.ts` proves there is no `DEFAULT_GATE_MCP_BASE_URL`, separate gate endpoint, or legacy fallback-array path in the migrated composable behavior.
- Old tool fallback arrays (`sync`, `gate-sync`, `status`, `gate-status`, `history`, `gate-history`, and `task_body`) are removed.
- `useGateTaskDetail` loads body and history through `gate_TaskBody` and `gate_History`.
- Gateway/domain-map behavior does not regress T-236.2.
- Missing `maenifold.gate` support produces an actionable UI error rather than silent empty state.
