# T-06.1 — MCP gateway crashes on pass-through tools without schema mapping

**Pipeline**: sdd
**Pipeline Digest**: tbd

## Priority

**P0** — App cannot start. `initialize` returns HTTP 500, UI shows "initialize failed: HTTP 500" on every launch.

## Problem

The MCP gateway (`maenifold --http`) aggregates tools from all connected MCP servers (maenifold, gate, workiq, etc.). During `initialize`, it builds the tool list by looking up each registry tool in a hardcoded schema mapping in `crates/maenifold-core/src/mcp/schema/mod.rs`.

When a pass-through server (e.g. workiq) exposes tools the gateway doesn't have explicit mappings for (e.g. `Schedule`), the gateway panics:

```
Missing MCP tool schema mapping for registry tool Schedule
```

This returns HTTP 500 to the UI client, which surfaces as `"initialize failed: HTTP 500"` in the notification tray. The entire app is non-functional.

## Evidence

- Screenshot: `outputs/screenshots/T-06.1-initialize-500.png`
- Reproduction: `curl -v http://127.0.0.1:8080/mcp -X POST -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"test","version":"0.1"}}}'`
- Error source: `crates/maenifold-core/src/mcp/schema/mod.rs`

## Root Cause

The gateway demands an explicit schema mapping for every tool in the registry. Pass-through tools from external MCP servers (workiq, etc.) don't have these mappings. The gateway should either:

1. Auto-generate schemas from the tool's `inputSchema` (the MCP standard already provides this), or
2. Gracefully skip unknown tools with a warning log instead of crashing

## Acceptance Criteria

- [ ] Gateway initializes successfully even when connected MCP servers expose tools without explicit schema mappings
- [ ] Pass-through tools are available to UI clients using their native `inputSchema`
- [ ] No HTTP 500 on `initialize` when external MCP servers are connected
- [ ] Warning log emitted for tools using auto-generated schemas (not silent)

## Files in Scope
