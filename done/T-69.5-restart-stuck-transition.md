# T-69.5 — Restart Max-Attempts: Transition to Stuck

**Requirement**: FR-45
**Component**: crates/maenifold-core/src/workflow/pipeline/update_restart.rs

## Problem

When `restart_pipeline_node` rejects a restart because `attempts >= maxAttempts`, it returns an error but does NOT transition the node to `Stuck` status. The node remains `Abandoned`. This contradicts the intended state machine where max-attempts exhaustion should produce `Stuck`.

Smoke test failures: ST-8 TC-8.6 (max attempts doesn't produce stuck), TC-8.7 (stuck never appears in view).

## Acceptance Criteria

1. When restart is rejected due to max attempts, node status transitions to `Stuck`
2. The node state is persisted with `Stuck` status before the error is returned
3. Pipeline view shows the node as `stuck` after max-attempts exhaustion
4. Pipeline-level status reflects `stuck` when a node is stuck and no active/ready nodes remain
5. Existing restart tests pass
6. Add test: verify node transitions to Stuck on max-attempts exhaustion

## Implementation Notes

- In `update_restart.rs` (~line 52-64), the max-attempts branch returns an error but the state.status assignment to Stuck must happen AND be persisted before the error return
- Check that `persist_pipeline_node_states` is called in the error branch
- The node state should be: `status: Stuck, attempts: maxAttempts, output: None`
