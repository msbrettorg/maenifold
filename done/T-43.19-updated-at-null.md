# T-43.19: updatedAt null means clear, not Date.now()

**Requirement**: Session-list audit gap  
**Priority**: P2  
**Files**: `vendor/acp-ui/src/stores/session.ts`

## Acceptance Criteria

1. In the `session_info_update` handler, `updatedAt: null` means the agent is clearing the timestamp. Current code treats `null` as `Date.now()` which is incorrect.

2. Fix:
   ```ts
   if ('updatedAt' in update && update.updatedAt !== undefined) {
     if (update.updatedAt === null) {
       // Agent is clearing updatedAt
       currentSession.value.lastUpdated = 0; // or undefined
     } else {
       currentSession.value.lastUpdated = new Date(update.updatedAt as string).getTime();
     }
   }
   ```

## SWE Remediation

- **What changed**
  - `vendor/acp-ui/src/stores/session.ts`: Updated `session_info_update` handling so `updatedAt: null` is treated as an explicit clear (`lastUpdated = 0`) instead of falling back to `Date.now()`. This applies consistently to both saved session state and the active `currentSession`.

- **Test results**
  - PASS — `cd /Users/brett/src/ma-collective/maenifold-rs/vendor/acp-ui && npx vue-tsc --noEmit`

- **Notes**
  - Kept the clear behavior as `0` rather than `undefined` so it remains compatible with the existing `SavedSession.lastUpdated: number` type.
