# T-243.6.0 — Workflows tab delta review

Plain-English review of the **Workflows tab**. Three lenses:

1. **What the UAT doc tests** (`T-243.6-workflows-tab-uat.md`)
2. **What's actually built today** (per `outputs/uat/cdp-tab-enumeration.md` §Workflows + `06-workflows-default.png` + source under `apps/desktop/src/components/Workflow*.vue`, `stores/workflow-library*.ts`)
3. **What a normal user expects from a workflow / template product** (Zapier templates, n8n templates, Airflow DAGs, Notion templates)

Workflows are our **methodology library** — abductive reasoning, multi-agent dispatch, six-thinking-hats, etc. The backend `Workflow` MCP command can run any of them. The question is whether the UI lets a human reach that capability or just lets them browse a catalogue.

---

## Snapshot of "what is actually built"

From CDP enumeration + source dive:

- Left rail (`WorkflowBrowser.vue` + `WorkflowBrowserList.vue`): search, 6 category chips (All / Reasoning / Scientific / Multi-agent / DevOps / Memory), scrollable list of ~80 workflows, **New workflow** button, **Import workflow** button (with overwrite/copy conflict resolution).
- Right rail (`WorkflowStepTimeline.vue` + `WorkflowMetadataForm.vue` + `WorkflowStepInspector.vue`): step list with expand/collapse, move-up/move-down, remove, "+ Add new step", **Export**, **Save** (disabled when clean), metadata form (name/emoji/category/description/triggers, sequential-thinking switch, multi-agent switch).
- Step inspector shows per-step detail when a step is clicked.
- Default-select on mount + dirty-aware reselect (T-242.14) confirmed in `WorkflowWorkspace.vue` via `ensureVisibleWorkflowSelected()` and `requestSelectWorkflow()`.

What's **not** in the tab (greppable absence in `Workflow*.vue` / `workflow-library*.ts`):

- No **Run** / **Execute** / **Dispatch** button anywhere.
- No **Delete** affordance.
- No **Duplicate / Clone** affordance (despite the import path having a "copy" branch — that logic is reachable only via filename collision).
- No **Pin / Favorite / Star**.
- No **Execution history** panel (the daemon-side `Workflow` sessions are exposed by the orphaned `WorkflowView.vue`, which is **not mounted** anywhere in `App.vue` — only `WorkflowWorkspace` is).
- No **Schedule from here** cross-link.
- No **"Pipelines that use this workflow"** back-reference.
- No category management — "Auto" is a fallback bucket only.

So today the Workflows tab is a **rich asset editor** (browse + edit + import/export + metadata) with **zero execution surface and zero lifecycle ops beyond create/save**. The methodology library is browseable but not runnable from the UI.

## Lens 2 — Built vs user expectations (Zapier / n8n / Airflow / Notion templates)

What a normal user reaches for in a templates / workflow library:

| User expectation | Found in… | Have it? | Gap impact |
|---|---|---|---|
| **"Try this template"** — one-click run with sane defaults | Zapier, n8n, Notion templates | ❌ | **Critical.** The whole point of a methodology library is dispatch-on-click. Without a Run button the tab is a museum. |
| **Live execution progress** — per-step status, current step highlighted, step output visible | n8n editor, Airflow grid view | ❌ in this tab; the daemon emits it (per `WorkflowStepProgress.vue` + `WorkflowStepTimelineEntry.vue` exist but only render against a session that the tab never opens) | **Critical.** Components are built — they just have nothing to render against because there's no run path. |
| **Cancel a running workflow** | Airflow, n8n | ❌ | High once Run lands. |
| **Execution history** ("show me workflows I've ran before, when, with what result") | Zapier "Task History", n8n executions, Airflow runs | ❌ in tab. Orphaned `WorkflowView.vue` has the data shape (`activeSessions`, `selectedSession.history`) but **isn't mounted**. | **High.** Quick win — wire the orphan into a tab section or a side panel. |
| **Pin / Favorite / "use often"** | Notion templates, Zapier | ❌ | Medium. With 80+ workflows the list is hard to navigate. |
| **Duplicate this template and tweak** | Every template product | ❌ (logic exists in import path; not exposed) | High. Forking-to-customize is the natural authoring workflow. |
| **Delete a workflow** | Every editor | ❌ | Medium. Today users have to delete the JSON on disk. |
| **Schedule this workflow** | Airflow (DAG schedules), Zapier (zaps run on trigger) | ❌ — no link from a workflow to the Schedules tab | Medium. We literally have a Schedules tab; cross-linking is cheap. |
| **"Where is this workflow used?"** (which Pipelines reference it) | Airflow lineage, Zapier "used by" | ❌ | Medium. Helps avoid breaking changes when editing. |
| **Per-step parameter editor** ("with what inputs?") inline in the run dialog | n8n, Zapier | ❌ | High once Run lands — most workflows expect inputs. |
| **Search / category filter / featured templates** | Zapier templates page | ✅ search + chips; ❌ no "Featured" or "Recently added" rows | Mostly there. |
| **Step descriptions render markdown / WikiLinks** | Notion, GitHub READMEs | Unknown — verify in UAT | Likely partial. |
| **Categorize / tag** workflows beyond the 5 fixed chips | Zapier, Notion | ❌ — chips are hardcoded; "Auto" is a fallback bucket | Medium. Custom categories or free-form tags would make a 200-workflow library navigable. |
| **Versioning / diff / revert** | Airflow DAG history, GitHub | ❌ | Low for now; high once teams co-author. |
| **Share / publish a workflow to a community library** | Zapier, n8n | ❌ (Export ✅ as the manual path) | Low. |

The **must-haves** for credibility as a workflow product are: **Run**, **live progress**, **execution history**, **duplicate**, **delete**. Everything else is polish.

## What we'd file as sub-tasks

In priority order:

1. **T-243.6.1 — Run a workflow from the UI.** Run button in the timeline header. Dispatches `Workflow` MCP call, opens a session, and surfaces the session ID. Without this, the tab is a museum. **P0.**
2. **T-243.6.2 — Live execution progress in the timeline.** Wire `WorkflowStepProgress` / `WorkflowStepTimelineEntry` to the active session so the current step highlights and per-step status streams in. Components already exist — just need a session source. **P0.**
3. **T-243.6.3 — Wire (or replace) `WorkflowView.vue` as an Execution History panel** in the Workflows tab. The orphan already lists `activeSessions` and renders `selectedSession.history`. Mount it as a third pane, a tab toggle, or a drawer. **P1, cheap win.**
4. **T-243.6.4 — Duplicate workflow.** Right-click / kebab / "Duplicate" button. Re-uses `nextCopyId` logic already in `WorkflowBrowser.vue`. **P1.**
5. **T-243.6.5 — Delete workflow.** Kebab + confirmation dialog. Calls a backend delete (or `SaveWorkflowAsset` inverse). **P1.**
6. **T-243.6.6 — Cancel a running workflow.** Stop button on the active session. Depends on .1. **P1.**
7. **T-243.6.7 — Run dialog with per-step parameters / context inputs.** Many workflows expect a topic/question. Today there's no place to type one. **P1, follows .1.**
8. **T-243.6.8 — Schedule-from-here cross-link.** "Schedule…" button on the workflow → opens Schedules tab pre-populated. **P2.**
9. **T-243.6.9 — Pipelines using this workflow.** Back-reference list in the metadata pane (read pipeline DAGs, find `WorkflowViewNode` referencing this id). **P2.**
10. **T-243.6.10 — Pin / favorite workflows.** Local persistence; pinned bucket at top of list. **P2.**
11. **T-243.6.11 — Per-step "requires sequential thinking" indicator.** Today only the workflow-level switch exists; surface per-step too. **P2.**
12. **T-243.6.12 — Long-title ellipsis tooltip in browser list.** Add `title=` (or `<Tooltip>`) on truncated names in `WorkflowBrowserList.vue`. Trivial. **P3.**
13. **T-243.6.13 — Verify malformed-asset error surface.** Read a known-bad workflow, confirm graceful fallback. **P3.**
14. **T-243.6.14 — Custom categories / freeform tags.** Stretch once the library grows past 100. **P3.**
15. **T-243.6.15 — Workflow versioning + diff + revert.** Stretch; only meaningful once multiple agents co-author. **P3.**

`T-243.6.1`, `.2`, `.3`, `.4`, `.5` are the bare minimum to call this tab "the Workflows tab" instead of "a workflow asset editor."

## Reviewer notes

**claude-opus-4.7:** the asymmetry is striking. The asset editor is genuinely well built — search, chips, draft management, dirty-aware reselect, conflict-resolved import, exportable JSON, step reorder/inspect. Then the **execution surface is a hole**. The backend `Workflow` MCP command exists, the daemon emits step progress, and `WorkflowView.vue` already renders sessions — and none of it is wired in. .1/.2/.3 close that hole with mostly plumbing, no new components. Do those three before touching anything else.

**gpt-5.5:** agreed. One nuance — `.1` should ship with `.7` (a parameter dialog) close behind, otherwise the first user click lands on a workflow that needs a `topic` and silently dispatches with `null`. I'd file `.7` as a P1 tied to `.1`'s done-criteria, not a separate priority. Also: the orphaned `WorkflowView.vue` is technical debt — either adopt it (.3) or delete it; leaving an unmounted component reading sessions is the kind of thing that breaks during a refactor and nobody notices for a sprint. Last flag: `.5` (delete) needs a confirmation dialog **and** a "this workflow is used by N pipelines" warning if `.9` lands first — order them so delete doesn't ship without the back-reference check.
