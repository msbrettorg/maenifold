# T-240.5 - SequentialThinking completion error requires explicit conclusion guidance

**Pipeline**: lightweight

## Problem

`maenifold.thinking/SequentialThinking` returned a success-shaped MCP response with an embedded failure when the PM completed the active T-238.47 thinking session without a `conclusion` field:

```text
{"success":false,"data":null,"error":{"code":"CONCLUSION_REQUIRED","message":"Conclusion required when completing session."}}
```

The command returned through `GatewayExecute` with MCP `isError=false`, so callers must inspect the nested payload to detect that the domain operation failed.

The live `maenifold.gate` surface still exposes only seven commands and no `gate_Create`, so this task file was created directly as a documented fallback. Missing create support remains covered by `T-238.45`.

Additional evidence from the same orchestration session:

```text
GatewayExecute maenifold.thinking SequentialThinking
parameters={
  initialThoughts: 0,
  thoughtNumber: 1,
  totalThoughts: 3,
  nextThoughtNeeded: true,
  response: "..."
}

{"success":false,"data":null,"error":{"code":"SESSION_MISSING","message":"Session session-1777310801338-35246 missing. Start with thoughtNumber=0."}}
```

This shows the start-session contract is also unclear or easy to misuse: `initialThoughts=0` did not start a session unless paired with `thoughtNumber=0`.

## Required Behavior

- `SequentialThinking` documentation and schema make `conclusion` required whenever `nextThoughtNeeded=false`.
- `SequentialThinking` documentation and schema make the start-session contract explicit, including when `thoughtNumber=0` is required.
- Error handling makes domain failures visible to MCP clients without requiring callers to parse a success-shaped text payload.
- `GatewayExecute` and domain tools preserve enough structured error state for clients to route failures consistently.
- The active thinking session can be completed with a conclusion after the caller supplies one.

## Acceptance Criteria

- [ ] A completion call without `conclusion` produces an MCP-visible error or a clearly structured failure field.
- [ ] Tool help/schema documents the `conclusion` requirement for completing a session.
- [ ] Tool help/schema documents how to start a session and rejects inconsistent `initialThoughts` / `thoughtNumber` combinations with actionable guidance.
- [ ] A completion call with `conclusion` succeeds.
- [ ] A start-session call using the documented shape succeeds.
- [ ] The behavior is covered by a focused test or documented manual verification.
