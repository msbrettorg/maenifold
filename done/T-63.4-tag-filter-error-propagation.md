# T-63.4 — Tag Filtering Error Propagation

## Problem
`search/api.rs` uses `.unwrap_or(false)` on `file_matches_all_tags()` at 4 call sites (lines ~194, 211, 374, 529). `file_matches_all_tags()` returns `Result<bool>` — the `Err` variant (tag resolution failure) is silently dropped, hiding files from results instead of surfacing the error.

## Requirements
1. Replace `.unwrap_or(false)` with `?` at all 4 call sites in `api.rs`:
   - Line ~194: text results tag filtering in `search_memories()`
   - Line ~211: vector results tag filtering in `search_memories()`
   - Line ~374: vector results tag filtering in `semantic_hybrid_search()`
   - Line ~529: text results tag filtering in `semantic_search()`
2. The filter closures need adjustment since `?` doesn't work inside closures — use `.filter_map()` or collect-and-filter pattern
3. Log the specific failing file URI before propagating: `eprintln!("[TAG FILTER] Error filtering {uri}: {error}")`

## Technical Note
The `.unwrap_or(false)` sites are likely inside iterator `.filter()` closures where `?` can't be used directly. Pattern to use:
- Convert to `.filter_map(|item| match file_matches_all_tags(...) { Ok(true) => Some(item), Ok(false) => None, Err(e) => { eprintln!(...); None } })`
- This preserves filter semantics while logging errors instead of silently swallowing them
- Alternative: collect results, partition Ok/Err, log errors, filter Ok values
