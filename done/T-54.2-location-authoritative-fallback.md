# T-54.2 — Location-Authoritative Fallback

**Requirement**: FR-41 (File-Authoritative Pipeline Gate Cache)
**Sprint**: 54
**Component**: `crates/maenifold-gate/src/status.rs`, `crates/maenifold-gate/src/sync.rs`

## Problem

24 files in `done/` parse as `pending` or `red` because they predate the TDD pipeline format. They have no SWE/Red/Blue sections at all (Sprints 46, 52) or incomplete audit trails (Sprints 29, 50, 51). They are legitimately completed work — their presence in `done/` is the proof.

The file-authoritative model says files are truth. For these legacy files, the *location* (done/) is the authoritative signal that the work is done, even if the file lacks the full modern audit trail.

## Acceptance Criteria

### 1. Status derivation: location overrides parsed status for done/ files

When a file is in `done/` and the parser derives a status other than `done`:
- If the parser found ANY stage sections (even incomplete) → override status to `done` with a note that the audit trail is incomplete
- If the parser found ZERO stage sections → override status to `done` (pre-pipeline legacy file)
- This MUST NOT produce a warning or error — it's expected for historical files

### 2. Status output reflects the override

`gate status --root .` and `gate status --root . --json` MUST show these files as `done`, not as their parsed intermediate status.

### 3. Sync respects the override

`gate sync --rebuild .` MUST insert/upsert these files with `status = 'done'` and `location = 'done'` in the cache. The cache must reflect the effective status, not the raw parsed status.

### 4. No override for todo/ files

Files in `todo/` MUST NOT get location-based overrides. If a file in `todo/` parses as `pending`, that's correct. If it parses with an error, that's a legitimate problem to surface.

## Test Cases

1. File in `done/` with zero stage sections → status = `done`, no warning
2. File in `done/` with SWE section only (no red/blue) → status = `done`, no warning
3. File in `done/` with SWE + Red (PASS) but no blue → status = `done`, no warning
4. File in `todo/` with zero stage sections → status = `pending` (no override)
5. `gate sync --rebuild` with mixed legacy and modern files → cache reflects correct status for all
6. `gate status --json` shows all done/ files as status = `done`

## Constraints

- Do NOT change the parser itself — the parser should still report what it actually found. The override happens in the status/sync layer.
- Keep `status.rs` under 150 LOC
- Keep `sync.rs` under 200 LOC
- Preserve all existing passing tests (25 tests)

Added effective_status() override in types.rs, applied in status.rs and sync.rs. 5 new tests.
