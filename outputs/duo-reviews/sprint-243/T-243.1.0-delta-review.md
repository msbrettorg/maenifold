# T-243.1.0 — Duo delta review for Home tab

## What's built today

Grounded in `apps/desktop/src/components/HomeDashboard.vue` and `outputs/uat/cdp-tab-enumeration.md` (Home section) plus `outputs/screenshots/uat-tabs/01-home-default.png`:

- A centered hero greeting: "What can I help you with?" with a brain icon.
- Five quick-action tiles in a single row: Agents, Pipelines, Gate, Workflows, Knowledge. Each tile is a button that switches to that tab.
- A single composer input ("Ask me anything…") with a Send button. Submitting calls `submitPrompt(...)` then switches to the Agents tab. Errors render inline ("Unable to send your prompt…").
- An `onMounted` call that refreshes the pipeline list (invisible side effect — the user sees nothing from this).
- The component **accepts** props for `hasAgents`, `selectedCwd`, `isConnected`, `isConnecting`, and `recentSessions`, but **none of them are rendered in the template**. They are dead inputs today.

That's the entire surface. No recent items, no status indicator, no search, no empty state messaging, no branding text, no settings entry, no help link.

## What a reasonable user expects

Coming from Claude Desktop, Cursor, Zed welcome, or Linear inbox, a first-time visitor would expect roughly the following on a "home" screen of an AI desktop client:

- To see **what they were last doing** — the 3–5 most recent chats / pipelines / notes — so they can resume in one click.
- To see **whether the app is actually connected** — a green/red dot or a "Daemon: running" pill — and a way to start the daemon if it's down.
- To see the **app's name and version** somewhere on the home screen, not just as a window title.
- For the big input box to behave like every other AI client's input box: multi-line, Shift+Enter for newline, paste images, drag-and-drop files, and a visible keyboard hint ("Enter to send").
- To see **which agent / model the prompt will go to** before they hit Send. Right now it silently routes to whatever the Agents tab last had selected.
- A friendly **empty state** the first time they launch — "Welcome. Pick an agent to get started" — instead of a composer that may silently fail because no agent is configured.
- A **search** affordance on home that searches across notes / sessions / tasks, not a per-tab search they have to discover.
- Lightweight discoverability: a "What's new" or "Tips" link, or example prompts under the composer ("Try: research Azure savings plans"), the way Claude Desktop and ChatGPT both do.
- Keyboard navigation: Tab through the tiles, Esc to clear, Cmd+K to focus the composer.

## Delta — gaps to file

### Critical (P0/P1) — features a user would notice missing on first launch

- **No recent activity shown.** The component receives `recentSessions` and ignores it. A user opening the app for the second time has no way to resume from home.
- **No daemon / connection status.** `isConnected` and `isConnecting` are passed in and dropped on the floor. If the backend is down, the composer just fails with a generic error after the user types and hits Send.
- **Composer silently routes to "whatever Agents had selected".** No visible agent name, no model name, no "sending to: Copilot" affordance. The user can't predict where their prompt will land.
- **No empty / first-run state.** On a clean profile with no agents configured, the composer is still shown and active; submission will fail with a one-line red error rather than a helpful "Set up an agent first" CTA.
- **No app name / version anywhere on Home.** Only the window chrome identifies the app.
- **Composer is a single-line `<input type="text">`, not a textarea.** No Shift+Enter newline, no multi-line prompts, no paste-image, no drag-drop. This is the single biggest gap vs. Claude Desktop / Cursor.
- **No way to start the daemon from the UI** if it's stopped. (UAT checklist asks for this and it does not exist.)

### Polish (P2)

- Tile descriptions are 9px — borderline unreadable on a Retina display at default zoom.
- Five equal-width tiles in one row don't reflow gracefully under ~800px width (UAT explicitly tests this).
- "Knowledge" tile uses the same accent color (`text-brand`) as "Agents" — visually merges the row.
- No hover tooltip / aria-description on the Send button beyond the icon.
- Composer error message is generic ("Unable to send your prompt…") regardless of root cause (no agent vs. daemon down vs. transport error).
- No keyboard shortcut hint shown next to the composer (e.g., "↵ Send · ⇧↵ Newline").
- The brain icon is decorative and not labelled for screen readers.

### Stretch (P3)

- No example-prompt chips under the composer to seed first use.
- No "What's new in this version" panel.
- No global Cmd+K palette wired from Home.
- No personalization (greeting by time of day, last-used agent badge, pinned items).
- No drag-and-drop a file onto Home to attach-and-send.

## Recommended additions to T-243.1's checklist

Add these specific test cases the current UAT doc misses:

- [ ] Submit a prompt from Home with **no agent configured**. Expect: clear CTA to configure an agent, not a generic red error.
- [ ] Submit a prompt from Home with the **daemon stopped**. Expect: an explicit status indicator and a "Start daemon" affordance.
- [ ] On a profile **with prior sessions**, verify the most recent N are listed and clickable from Home.
- [ ] Type a multi-line prompt (Shift+Enter). Expect: a newline, not submit. (Will fail today — single-line input.)
- [ ] Paste an image into the composer. Expect: attachment chip. (Will fail today.)
- [ ] Drag a file onto Home. Expect: graceful handling or clear "not supported here" message.
- [ ] Confirm the **agent and model the prompt will route to** is visible before Send.
- [ ] Confirm app name + version is visible on the Home view (not just window chrome).
- [ ] Tab-through keyboard navigation hits every tile and the composer in a logical order.
- [ ] Cmd+K (or equivalent) focuses the Home composer from anywhere.

## Architect-A perspective (claude-opus-4.7 voice — design rigor, spec correctness, ACP/MCP adherence)

The Home tab as built is a navigator, not a dashboard. That is a defensible scope choice, but the component's own prop signature betrays a richer original intent: `hasAgents`, `isConnected`, `isConnecting`, and `recentSessions` are all wired through and then ignored by the template. The spec gap is not "we forgot to design recents" — it is "we designed recents and stopped halfway." A correctness-first reviewer should treat unused props as a contract violation: either the parent shouldn't be computing them or the child should be rendering them. Today both sides pay the cost and the user gets none of the value.

The composer also under-delivers on the protocol surface beneath it. Submitting a prompt synthesizes a session via the Agents path, but the user has no visibility into the agent identity, model, or session ID that will receive their text. From an ACP standpoint that's the equivalent of `session/prompt` with no `sessionId` echoed back to the user — the protocol guarantees correctness, but the UI hides it. The fix is small and additive: render a "→ Copilot · gpt-5" affordance next to the Send button. No backend change required.

Finally, the UAT checklist itself is well-shaped but optimistic. It assumes recents, status, and search **may** be present and conditions checks on "(if present)". Given that none of these are present today, the executor will tick "N/A" through three of the most important sections and produce a deceptively green report. The checklist should be tightened: state explicitly that the **absence** of recents and status is itself a gate item to file, not a free pass.

## Architect-B perspective (gpt-5.5 voice — user experience, parity with established AI clients, polish)

A user landing on this Home screen will, within five seconds, do one of three things: type into the composer, click a tile, or wonder "did this thing remember anything about me?" Today, only the first two work. There is no answer to the third question, and that is the most damaging UX gap, because every modern AI client — Claude Desktop, ChatGPT, Cursor, Zed, Linear — treats home as a memory surface first and a launcher second. We are inverted. Tiles are fine, but tiles without recents read as "you have no history here," which is actively false in our case.

The composer is the second-biggest parity gap. A single-line `<input>` in 2026 reads as a search box, not a prompt box. Every comparable product uses a multi-line textarea with paste, drag-drop, and a visible keyboard hint. Users will type one sentence, hit Enter, get whisked to a different tab, and not understand whether they composed a chat or a search. Worse, when something fails, the message is generic and rendered in the same place no matter the cause — daemon, agent, transport. That is the difference between "this app is opinionated" and "this app is opaque."

The polish items are individually small but cumulatively shape first impression: 9px tile captions, no version string, no daemon dot, identical accent colors on adjacent tiles, no example prompts. None of these are bugs. All of them are signals. A user who sees a Linear-grade home will trust the rest of the app; a user who sees a half-finished launcher will discount everything they find downstream — including the legitimately impressive Pipelines and Knowledge surfaces.

## Synthesis

Both perspectives converge on the same headline: **Home is a launcher pretending to be a dashboard, and the component already has the props to be a dashboard but doesn't use them.** Architect-A frames this as a spec/contract violation (unused props, hidden routing target, optimistic UAT phrasing); Architect-B frames it as a parity/first-impression problem (no recents, single-line input, no status). They differ only in priority weight: A would tighten the checklist and surface the agent identity first; B would build recents and a multi-line composer first. The duo's joint recommendation is to (1) amend T-243.1's checklist to treat absent features as filable gaps rather than N/A, (2) file the seven critical items above as T-243.1.{1..7} this sprint, and (3) open a single sprint-244 epic — "Home becomes a dashboard" — that rebuilds Home around the props that already flow into it.
