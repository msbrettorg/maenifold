# T-45.1: Pipeline Definition Types and Validation

**Requirement**: FR-45.1
**RTM**: RTM-309, RTM-310, RTM-311, RTM-312, RTM-313
**Priority**: P0 — All pipeline code depends on these types

## Context

The pipeline engine needs core type definitions for pipeline definitions, nodes, edges, and node state. These are the foundation for all pipeline operations. This spec creates a new `pipeline` submodule under `workflow/`.

## Scope

Create `crates/maenifold-core/src/workflow/pipeline/` module with:
1. Type definitions (structs + serde)
2. Validation (cycle detection, referential integrity)
3. Module wiring

## Acceptance Criteria

1. **PipelineDefinition struct**: `nodes: Vec<PipelineNode>`, `edges: Vec<PipelineEdge>`. Derives `Serialize`, `Deserialize`, `Clone`, `Debug`.
2. **PipelineNode struct**: `id: String`, `workflow_id: String`, `acp_client: Option<String>`. Derives `Serialize`, `Deserialize`, `Clone`, `Debug`.
3. **PipelineEdge struct**: `source: String`, `target: String`, `edge_type: EdgeType` (defaulting to `Success`). Derives `Serialize`, `Deserialize`, `Clone`, `Debug`.
4. **EdgeType enum**: `Success`, `Always`. Serializes as lowercase (`"success"`, `"always"`). Derives `Serialize`, `Deserialize`, `Clone`, `Debug`, `PartialEq`.
5. **NodeState struct**: `session_id: String`, `status: NodeStatus`, `attempts: u32`. Derives `Serialize`, `Deserialize`, `Clone`, `Debug`.
6. **NodeStatus enum**: `Pending`, `Ready`, `Active`, `Completed`, `Abandoned`, `Stuck`. Serializes as lowercase. Derives `Serialize`, `Deserialize`, `Clone`, `Debug`, `PartialEq`.
7. **Validation function**: `validate_pipeline(definition: &PipelineDefinition) -> Result<()>` that:
   - Rejects empty `nodes` array
   - Rejects duplicate node IDs
   - Rejects edges referencing non-existent node IDs
   - Rejects cycles via topological sort (Kahn's algorithm)
   - Returns `Ok(())` on valid acyclic graph
8. **Module structure**: Create `crates/maenifold-core/src/workflow/pipeline/mod.rs` and `crates/maenifold-core/src/workflow/pipeline/types.rs`. Wire into `workflow/mod.rs`.
9. **Serde rename**: Use `#[serde(rename_all = "camelCase")]` on structs for JSON compatibility. Edge `type` field should use `#[serde(rename = "type")]` since `type` is a Rust keyword — use field name `edge_type` with serde rename.
10. **Backward compatibility**: No changes to existing workflow types or behavior. Existing serial workflow sessions unaffected.

## Implementation Notes

- Follow the existing module pattern in `crates/maenifold-core/src/workflow/` (mod.rs re-exports, separate files for concerns)
- Kahn's algorithm for cycle detection: maintain in-degree counts, process zero-degree nodes, if remaining nodes > 0 then cycle exists
- The `NodeStatus` enum mirrors the session status lifecycle from FR-45.4 plus `Stuck`
- Add `pub mod pipeline;` to `workflow/mod.rs`
