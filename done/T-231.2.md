## Plan

### Extract test helpers to `schedule_consistency_helpers.rs`

Move these helper items (lines 1-167, ~167 LOC) to a new `schedule_consistency_helpers.rs`:

- Constants: `MAX_LOG_BYTES_PER_FILE`, `MAX_TOTAL_LOG_BYTES`, `TRUNCATED`
- `SemanticTask` struct + its `From<&Value>` / extraction logic
- `test_context()` function
- `call_schedule()` function
- `resource_json()` function
- `handle_read_resource()` function
- `store()` function
- `assert_all_surfaces_agree()` function
- `set_enabled_with_store()` function
- `update_fields_with_store()` function
- `write_large_logs()` function
- `assert_logs_within_bounds()` function

### Keep test functions in `schedule_consistency_tests.rs`

Keep the actual `#[test]` functions (~149 LOC) in the original file. Import helpers via `use super::schedule_consistency_helpers::*;`.

### Module wiring

In `schedule.rs`, the existing wiring is:
```rust
#[cfg(test)]
#[path = "schedule_consistency_tests.rs"]
mod schedule_consistency_tests;
```

Add an adjacent module declaration for the helpers:
```rust
#[cfg(test)]
#[path = "schedule_consistency_helpers.rs"]
mod schedule_consistency_helpers;
```

The tests file uses `use super::*;` which brings in `schedule.rs` items. The helpers file needs the same import pattern. The tests file adds `use super::schedule_consistency_helpers::*;` to access the helpers.
