# T-207.6 — Error semantics

## Requirement

Define and implement the complete error handling contract for the gateway, per MCP spec requirements.

## Error Classification

### 1. Upstream JSON-RPC errors
When the stdio server returns a JSON-RPC error response (e.g. `{ "error": { "code": -32602, "message": "Unknown tool" } }`):
- Preserve the error code and message.
- Surface as a JSON-RPC error from the HTTP endpoint.
- Per Server/Tools § Error Handling: protocol errors use JSON-RPC error responses.

### 2. Tool execution errors
When the stdio server returns `CallToolResult` with `isError: true`:
- Return as-is through the HTTP endpoint.
- Per Server/Tools § Error Handling: tool errors use `isError` in the result, not JSON-RPC errors.

### 3. Connection errors (stdin write fail, stdout EOF)
- Mark session as dead.
- Return JSON-RPC error code `-32603` (Internal Error) with message: `"Gateway: {server_name} connection lost: {detail}"`.
- Include stderr tail (last 500 chars) in error `data` field for debugging.

### 4. Timeout
- Per Lifecycle § Timeouts: implementations SHOULD establish per-request timeouts.
- Default: 60s per `tools/call`, configurable via `McpServerEntry::Stdio::timeout`.
- On timeout:
  1. Send `notifications/cancelled` to the upstream server per Lifecycle § Timeouts ("sender SHOULD issue a cancellation notification for that request and stop waiting for a response"). The notification includes the original request `id`.
  2. Mark the session as **poisoned** — stdout may contain a stale late response that would corrupt the next call.
  3. Return JSON-RPC error code `-32001` with message: `"Gateway: {server_name} tool '{tool_name}' timed out after {n}s"`.
- The pool will force a full restart (kill + respawn) on the next call to a poisoned session, ensuring a clean stdio stream.
- `-32001` is a maenifold-defined server error code (in the `-32000` to `-32099` range reserved for implementation-defined server errors per JSON-RPC 2.0 § Error object).

### 5. Server not found / tool not found
- Server name not in pool: JSON-RPC error `-32602` (Invalid params): `"Gateway: unknown server '{name}'"`.
- Tool name not in any registry: JSON-RPC error `-32601` (Method not found): `"Unknown tool: '{name}'"`.

## Observability

- All gateway errors MUST be logged at `warn` or `error` level via tracing.
- Connection errors and timeouts include server name, tool name, and stderr tail.
- Structured fields: `server="{name}" tool="{tool}" err="{message}"`.

## Key Files

- Applies to: `StdioSession` (T-207.1), `StdioPool` (T-207.2), `MaenifoldHandler` delegation (T-207.4)

## Protocol References

- Server/Tools § Error Handling: JSON-RPC errors for protocol failures, isError for tool failures
- Lifecycle § Timeouts: per-request timeout with cancellation
- JSON-RPC 2.0 § Error codes: -32600 to -32699 reserved, -32000 to -32099 server-defined
