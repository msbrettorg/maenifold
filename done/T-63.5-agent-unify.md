# T-63.5 — Unify agent/acpClient Field Naming

**Requirement**: FR-8
**Test Cases**: TC-19, TC-20
**Repo**: maenifold-rs
**Component**: crates/maenifold-core/src/workflow/pipeline/types.rs, executor.rs, dispatch.rs, view.rs, handler.rs

## Context

WorkflowNode uses `acpClient` (optional), PromptNode/SequentialThinkingNode use `agent` (required). Same concept, different names, different optionality. The UI must guess which field to read.

## Acceptance Criteria

1. Rename `acpClient` → `agent` on `WorkflowNode` (make it `String`, required — same as Prompt/ST)
2. In `PipelineNodeWire`, accept BOTH `"acpClient"` and `"agent"` during deserialization for backwards compatibility. Use `#[serde(alias = "acpClient")]` or custom deser.
3. Serialize as `"agent"` in all output (view, dispatch, wire format)
4. Update executor.rs: all references to `acp_client` on Workflow nodes → `agent`
5. Update dispatch.rs: response includes `agent` field for all node types
6. Update view.rs: output includes `agent` for all node types
7. Update handler.rs validation: `agent` is validated for all node types (not just Prompt/ST)
8. ALL existing pipeline tests pass: `cargo test -p maenifold-core -- pipeline`
9. Add a test: deserialize JSON with `"acpClient"` field → resolves to `agent` field correctly
