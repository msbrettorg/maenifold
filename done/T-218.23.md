# T-218.23 — Streamable HTTP Gateway Integration Suite

## Problem

Current gateway tests cover much of the internal logic, but the highest-risk boundary is the real Streamable HTTP MCP service stack: rmcp transport, HTTP headers, stateless mode, CORS, gateway handler, stdio pool, and fake upstream servers together.

## Acceptance Criteria

- [ ] Start a real in-process HTTP MCP listener on an ephemeral port
- [ ] Configure at least two fake stdio MCP servers
- [ ] Drive the endpoint through HTTP JSON-RPC requests with MCP headers
- [ ] Test `initialize`, `tools/list`, native `tools/call`, gateway facade `tools/call`, hidden direct upstream call denial, passthrough small-server call, and `resources/read ui://...`
- [ ] Verify stale/unknown `Mcp-Session-Id` behavior for stateless mode
- [ ] Verify JSON-RPC error codes survive through HTTP transport
- [ ] Verify CORS only permits allowed localhost/file/null origins as intended
- [ ] Test fails if gateway startup silently drops all upstream servers while returning healthy-looking `tools/list`
