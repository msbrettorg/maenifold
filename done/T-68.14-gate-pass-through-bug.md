# T-68.14 — Gate Pass-Through Bug: Empty Sections Skip Pipeline

**Requirement**: FR-68

## Summary

`gate pass` allows tasks to advance through the entire pipeline in a single call when sections have no verdicts. A fresh task with empty `## SWE`, `## Red`, `## Blue` sections gets parsed as status `blue` (instead of `pending`), and a single `gate pass` moves it straight to `done/`.

**Root cause**: The status/stage parser treats an empty section (no verdict) as "completed" and advances to the next stage. It should treat a missing verdict as "blocked" — a section with no verdict means the stage hasn't been executed yet.

**Expected behavior**:
- Fresh task with empty sections → status `pending`
- `gate pass` → advances to `swe` (first stage)
- `gate pass` again → should FAIL because SWE has no verdict
- Only after SWE section gets a verdict (via `gate append`) should `gate pass` advance to `red`

## Acceptance Criteria

- [ ] A task with empty SWE/Red/Blue sections has status `pending`, not `blue`
- [ ] `gate pass` on a pending task advances to `swe` only
- [ ] `gate pass` on a task at `swe` with no SWE verdict returns an error
- [ ] `gate pass` succeeds only when the current stage has a verdict
- [ ] Existing tests still pass (verdict-bearing tasks should work as before)
- [ ] New tests cover: empty sections, missing verdicts, partial verdicts
