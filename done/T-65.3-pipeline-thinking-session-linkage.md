# T-65.3: Pipeline SequentialThinking Session Linkage

## Requirement
Fix two bugs where pipeline-executed sequentialThinking nodes lose their actual thinking session and use wrong naming.

## Bug 1: Sequential session ID discarded

**File:** `crates/maenifold-core/src/workflow/pipeline/executor_nodes.rs:124-140`

The pipeline calls `runner::run_think()` which correctly creates a `session-{ts}-{suffix}` file under `thinking/sequential/`. But `classify_think_result()` (line 180-189) extracts only the conclusion text and discards `ThinkResult.session_id`. The actual thinking trace is orphaned — no link back to the pipeline.

Additionally, `parent_workflow_id` is set to `None` (line 136), so the spawned sequential session has no back-reference to the pipeline.

**Fix:**
- Capture `ThinkResult.session_id` and store it in pipeline node state
- Pass the node's wrapper session ID as `parent_workflow_id` when calling `run_think()`
- Add a field to `NodeState` or `NodeOutcome` to carry the sequential session reference

## Bug 2: Thinking trace reader uses wrong session ID

**File:** `crates/maenifold-core/src/workflow/pipeline/view_cognitive.rs:98-100`

`parse_thinking_trace()` calls `sequential_session_uri(session_id)` using the node's wrapper `sessionId` (which is `workflow-{ts}-{nodeId}` format). This generates a URI under `thinking/sequential/` that doesn't exist — the actual sequential session has a different ID (`session-{ts}-{suffix}`).

**Fix:**
- Use the actual sequential session ID (from Bug 1 fix) instead of the wrapper session ID
- This may require storing the sequential session ID in node state and passing it to the view layer

## Bug 3: Test/production session ID mismatch

**File:** `crates/maenifold-core/src/workflow/pipeline/dispatch_tests_non_workflow.rs:69-86`

Test fixtures use `sequentialThinking-thought-node-{ts}` format for session IDs, but production code generates `workflow-{ts}-{nodeId}`. Tests need to align with the actual production format.

**Fix:**
- Update test fixtures to use `workflow-{ts}-{nodeId}` format

## Acceptance Criteria

- Pipeline-executed sequentialThinking nodes produce a `session-{ts}-{suffix}` file under `thinking/sequential/`
- The sequential session ID is stored in pipeline node state
- `pipeline view` can retrieve and display the full thinking trace for sequentialThinking nodes
- `parent_workflow_id` links the sequential session back to the pipeline
- All existing tests pass after changes
- No orphaned sequential session files
