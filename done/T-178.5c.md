# T-178.5c — Pipeline dashboard — desktop MCP resources migration

## Intent

Migrate the desktop Pipeline surface (`apps/desktop/src/components/PipelineView*.vue`, `PipelineComposer*.vue`, `PipelineRunner.vue`, etc.) onto MCP `pipeline://` resources via the [[T-178.0]] client. Same migration pattern as [[T-178.5a]] / [[T-178.5b]].

## Scope

### 1. Define + register `pipeline://` resources in `crates/maenifold-core/src/mcp/resources.rs`

| URI | Read returns | Updated when |
|---|---|---|
| `pipeline://sessions/active` | `{ sessions: [PipelineSessionSummary], generated_at }` | Session created, node state change, session status change |
| `pipeline://session/{id}` (template) | `{ id, name, nodes: [...], edges: [...], status, ... }` (full pipeline session view) | Any node state change in this session |
| `pipeline://node/{session_id}/{node_id}` (template) | `{ id, type, status, output, errorCount, ... }` (single node detail) | This node's state changes |

Apply the throttle wrapper from [[T-178.3c]] to `pipeline://sessions/active` and to the per-session URI when high-velocity node updates are expected (running pipeline). Per-node URIs are unthrottled (point reads, low cardinality of subscribers per node).

### 2. Wire emitters

- Pipeline node state change (ready → active → completed/abandoned) → `pipeline://node/{sid}/{nid}` + `pipeline://session/{sid}`.
- Pipeline session lifecycle (create, run, cancel, complete) → `pipeline://session/{id}` + `pipeline://sessions/active`.

### 3. Migrate desktop components

Targets (non-exhaustive — enumerate during implementation):
- `apps/desktop/src/components/PipelineView.vue`
- `apps/desktop/src/components/PipelineSidebar.vue`
- `apps/desktop/src/components/PipelineActionBar.vue`
- `apps/desktop/src/components/PipelineRunner.vue`
- `apps/desktop/src/components/PipelineFlyout.vue`
- `apps/desktop/src/components/PipelineNodeCard*.vue`
- `apps/desktop/src/components/PipelineComposer*.vue`

Pinia store `apps/desktop/src/stores/pipeline.ts` (extend or create) with slices `activeSessions`, `selectedSession`, `nodeStateById`. Subscribe-on-mount / unsubscribe-on-unmount.

Writes (`Pipeline { dispatch, restart, cancel, ... }`) stay on `tools/call`.

### 4. Fluent 2 styling — HARD REQUIREMENT

Same rules as [[T-178.4]] / [[T-178.5a]] / [[T-178.5b]]:
- All tokens from `apps/desktop/DESIGN.md`.
- Node status colors: `--success` (completed), `--warning` (active/pending), `--danger` (abandoned/failed), `--muted` (ready/idle).
- shadcn-vue primitives only.
- ZERO hardcoded hex/RGB/HSL. ZERO `<style>` blocks.
- **Special case**: `PipelineView.css` exists today. This task DELETES that file or moves all of its rules into Tailwind utility classes / token-based CSS variables — no raw hex values may survive into `apps/desktop/src/`. If migrating every selector is out of scope, document the residual file as a known follow-up and gate it for a separate cleanup task; do not extend it.

### 5. Help docs

`assets/help/resources/pipeline.md` (NEW) documents URIs.

## Files in scope

- `crates/maenifold-core/src/mcp/resources.rs` (pipeline URI registration + read dispatch)
- Pipeline node-state and session-lifecycle call sites (minimal `notify_resource_updated` additions)
- `apps/desktop/src/stores/pipeline.ts` (extend or create)
- All `apps/desktop/src/components/Pipeline*.vue` files
- `apps/desktop/src/components/PipelineView.css` (delete or token-migrate per rule 4)
- `apps/desktop/src/components/__tests__/Pipeline*.test.ts` (extend or add)
- `assets/help/resources/pipeline.md` (NEW)

## Acceptance criteria

1. `cargo test -p maenifold-core` passes.
2. `pnpm --filter desktop build` and `pnpm --filter desktop test` pass; zero `vue-tsc` errors.
3. Pipeline view performs ZERO `/api/pipeline/*` HTTP calls.
4. Reads via `useMcpResources`; writes via `tools/call`.
5. Node state change → UI updates without manual reload (Playwright assertion).
6. ZERO hardcoded hex/RGB/HSL and ZERO `<style>` blocks in `.vue` files in scope. `PipelineView.css` either deleted or contains only references to design tokens (no raw color literals).
7. Playwright screenshot of Pipeline view with a running session showing node state colors driven by tokens.
8. `assets/help/resources/pipeline.md` documents URIs and update conditions.

## Out of scope

- Removing legacy pipeline REST endpoints.
- Gate / Workflow / Agent dashboards.
- New composer features.
