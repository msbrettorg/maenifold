# T-69.2 — Pipeline View: Emit All Node Config Fields

**Requirement**: FR-52
**Component**: crates/maenifold-core/src/workflow/pipeline/view_nodes.rs

## Problem

`add_pipeline_node_view_fields` in `view_nodes.rs` drops 7 session configuration fields from every agent-bearing node type: `model`, `thoughtLevel`, `allowedTools`, `maxTurns`, `timeout`, `toolMode`, `agentConfig`. Clients reading the pipeline view cannot reconstruct the original pipeline definition, and the UI pipeline composer cannot display per-node configuration.

## Acceptance Criteria

1. Pipeline view output includes `model` when set on Prompt/SequentialThinking/Tool nodes
2. Pipeline view output includes `thoughtLevel` when set
3. Pipeline view output includes `allowedTools` when set
4. Pipeline view output includes `maxTurns` when set
5. Pipeline view output includes `timeout` when set on Workflow/Prompt/SequentialThinking nodes
6. Pipeline view output includes `toolMode` when set on Prompt nodes (omit if "disabled")
7. Pipeline view output includes `agentConfig` when set on Prompt/SequentialThinking/Tool nodes
8. Fields are emitted using camelCase wire names matching `types_wire.rs` serialization
9. Null/None fields are omitted (not emitted as null)
10. Existing view tests pass; add tests for config field emission

## Implementation Notes

- Edit `view_nodes.rs` — the `add_pipeline_node_view_fields` function
- Each node variant's match arm needs to emit the additional fields
- Use `skip_serializing_if` semantics: only emit when `Some` / non-default
- The definition is already loaded; this is purely a serialization gap in the view builder
