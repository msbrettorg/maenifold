## Problem

The native `maenifold.gate` Gateway domain exposes 7 commands (`gate_Status`, `gate_Sync`, `gate_Append`, `gate_Pass`, `gate_Fail`, `gate_History`, `gate_TaskBody`) through MCP — but **none of them are reachable from the CLI**.

```bash
$ maenifold tool gate_Status '{"root":"/Users/brett/src/ma-collective/maenifold-rs"}'
Unknown tool: gate_Status
```

`maenifold tool --help` does not list the gate domain at all. The CLI tool registry is hand-curated and was never updated when gate folded into the Gateway domain. CLI-only users (terminal scripts, CI, ralph runs that don't go through MCP) have no way to advance gate state.

## Required Behavior

CLI invocations of any gate command must round-trip identically to the MCP equivalent:

```bash
maenifold tool gate_Status '{"root":"/path/to/repo"}'
maenifold tool gate_Sync   '{"root":"/path/to/repo","rebuild":true}'
maenifold tool gate_Pass   '{"root":"/path/to/repo","taskId":"T-1.1","agent":"swe","notes":"..."}'
# etc.
```

Either:
- Wire the CLI tool registry to forward gate command names through the same handler MCP uses, **or**
- Make the CLI dispatch unknown tool names through `GatewayExecute` automatically when they look like a known Gateway command (this also fixes T-242.17).

## Acceptance Criteria

- [ ] All 7 gate commands invokable via `maenifold tool gate_*` with identical JSON payloads to the MCP Gateway shape.
- [ ] `maenifold tool` help text lists the gate commands under a `Gate:` heading.
- [ ] `maenifold tool gate_Status '{"root":"…"}'` returns the same JSON structure as `GatewayExecute domain="maenifold.gate" command="gate_Status" parameters={"root":"…"}`.
- [ ] No `Unknown tool: gate_*` error path remains.

Discovered during the sprint 242 CLI/MCP parity audit. Constitutional requirement: **CLI and MCP MUST have 100% parity** (user direction, 2026-04-28).
