# T-221.4 - Configurable ACP Intent Resolver Settings

## Problem

Intent routing cannot depend on MCP sampling. The gateway needs explicit resolver configuration that uses our ACP/Jockey infrastructure and fails clearly when unavailable.

## Scope

Add gateway intent resolver settings to `maenifold.json` via `MaenifoldSettings`.

Required shape:

- `settings.gateway.intentResolver.enabled`
- `settings.gateway.intentResolver.agent`
- `settings.gateway.intentResolver.model`
- `settings.gateway.intentResolver.thoughtLevel`
- `settings.gateway.intentResolver.timeoutSeconds`
- `settings.gateway.intentResolver.maxCandidates`
- `settings.gateway.intentResolver.autoExecuteReadSafe`
- `settings.gateway.intentResolver.autoExecuteConfidenceThreshold`
- `settings.gateway.intentResolver.maxCatalogCharacters`
- `settings.gateway.intentResolver.mcpServers`

Default policy:

- `model`: `gpt-5.4-mini`
- `thoughtLevel`: omitted or `none` until T-221.7 selects a measured default. `"none"` is accepted and normalized to omission (no config option sent to ACP).
- `enabled`: false
- `autoExecuteReadSafe`: false
- `autoExecuteConfidenceThreshold`: 0.9 (must be 0.0–1.0)
- `maxCatalogCharacters`: 24000
- `mcpServers`: empty array
- `timeoutSeconds`: `Option<u64>`, default `None` (no timeout). When set, must be > 0.
- `maxCandidates`: `Option<u32>`, default `None` (resolver decides). When set, must be > 0.

If `enabled` is true, `agent` is required and must name a valid configured Jockey/ACP agent from `maenifold.json`. Unknown, missing, empty, or non-executable resolver agents fail config validation before any intent call is attempted.

No hidden agent fallback is allowed. If intent is disabled or no valid resolver agent is configured, `GatewayIntent` is disabled and omitted from `tools/list`. If a configured resolver later becomes non-executable or cannot support the requested model/thought level at call time, `GatewayIntent` must return a clear configuration error and point to `GatewayIndex` + `GatewayExecute`.

Resolver validation must reuse existing Jockey/`AgentsConfig` resolution and runtime-kind inference. The resolver must not fork an independent agent config loader. Resolver ACP session construction must be resolver-specific enough to prevent implicit inheritance of global or per-agent MCP server lists; only `settings.gateway.intentResolver.mcpServers` may be attached.

## Acceptance Criteria

- [ ] Config structs deserialize and serialize the new gateway intent resolver settings.
- [ ] Default model is exactly `gpt-5.4-mini`.
- [ ] Default `enabled` is false.
- [ ] Setting `enabled=true` requires a valid configured resolver `agent` and fails config validation when the agent is unknown, missing, empty, or non-executable.
- [ ] `GatewayIntent` is omitted from `tools/list` when `enabled=false`.
- [ ] `GatewayIntent` is omitted from `tools/list` when no valid resolver agent is configured.
- [ ] `none`, `low`, `medium`, `high`, and `xhigh` are representable for experiment runs.
- [ ] `none` means no thought-level config option is sent to ACP.
- [ ] `autoExecuteReadSafe` defaults to false.
- [ ] `autoExecuteConfidenceThreshold` defaults to 0.9 and is used only when `autoExecuteReadSafe=true`.
- [ ] `maxCatalogCharacters` defaults to 24000 and is available to the resolver prompt builder.
- [ ] `mcpServers` defaults to an empty array and is the only source of MCP servers attached to resolver ACP sessions.
- [ ] Resolver agent validation reuses existing Jockey/`AgentsConfig` resolution and runtime-kind inference.
- [ ] Resolver ACP sessions attach only `settings.gateway.intentResolver.mcpServers`; global and per-agent MCP server lists are not implicitly inherited.
- [ ] No independent resolver-only agent config loader is introduced.
- [ ] Unsupported configured model or thought level fails explicitly.
- [ ] Missing resolver agent fails explicitly; no silent use of another agent.
- [ ] Existing `maenifold.json` files without gateway settings continue to parse.
- [ ] Unit tests cover defaulting, explicit override, missing/unknown agent, auto-execute threshold, explicit MCP server list, and unsupported thought level.
- [ ] `cargo build --release -p maenifold-cli` succeeds.

### Phase 1: New Config Structs

**New:** `crates/maenifold-core/src/acp/config/gateway_settings.rs`
- `GatewaySettings` — container with `intent_resolver: IntentResolverSettings` (~10 LOC)
- `IntentResolverSettings` — 10 fields from spec with defaults (~35 LOC struct + ~25 LOC Default impl)
- `mcpServers` field reuses existing `McpServerEntry` from `types.rs` — no new server config type
- `thought_level` as `Option<String>` (matches existing codebase convention, no enum needed)
- Default helper fns: `default_model()` → `"gpt-5.4-mini"`, `default_threshold()` → `0.9`, etc.

### Phase 2: Settings Integration

**Modified:** `settings.rs` — add `#[serde(default)] pub gateway: GatewaySettings` field
**Modified:** `acp/config.rs` — add `#[path = "config/gateway_settings.rs"] mod gateway_settings;` and `pub use gateway_settings::*;`

### Phase 3: Validation

**Modified:** `loader.rs`:
- Make `validate_agent_entry()` `pub(crate)` (currently file-private)
- Add `validate_intent_resolver_config(&IntentResolverSettings, &AgentsConfig)` (~30 LOC):
  - If `enabled=true`, `agent` must be Some, non-empty, and non-whitespace
  - Agent must exist in `AgentsConfig.agents` map (post-filtering — if agent was filtered by `validate_agent_entry`, the config error should say "resolver agent is not executable" not just "unknown")
  - `thought_level` if Some("none") → normalized to None (omission). If Some(other) → must be one of: `low`, `medium`, `high`, `xhigh`
  - `auto_execute_confidence_threshold` must be 0.0–1.0
  - `timeout_seconds` if Some → must be > 0
  - `max_candidates` if Some → must be > 0
- Call validation from `AgentsConfig::load()` — hard error via `MaenifoldError::AgentSetup`, NOT silent warn+filter
- **Note:** Unlike regular agents where `validate_agent_entry` warns and filters, resolver validation must FAIL HARD when enabled=true and the agent is invalid.

### Phase 4: Tests

**New:** `acp/config/gateway_settings_tests.rs` (~80-120 LOC) — separate from tests.rs (already 269 LOC):
- Default deserialization (no gateway section → enabled=false, model=gpt-5.4-mini)
- Explicit override of all fields
- **Positive case:** valid enabled=true + valid agent + valid model passes cleanly
- Missing/unknown agent when enabled=true → error
- Non-executable agent when enabled=true → error with clear message
- Auto-execute threshold out of range → error
- Explicit MCP server list roundtrip
- thoughtLevel "none" → normalized to omission
- Unsupported thought level (e.g., "ultra") → error
- timeoutSeconds=0 → error
- Omitted, null, empty, whitespace-only agent when enabled=true → error
- Existing configs without gateway section continue to parse
- Round-trip serialization test for defaults
