# T-202.19 — Embedding model catalog: external manifest

## Problem

The model catalog is a hardcoded `CURATED_MODELS` static array in `crates/maenifold-core/src/tools/embedding_models.rs`. Adding, removing, or updating models requires recompiling the binary. Users can't add their own models without modifying Rust source code.

## Fix

Move the catalog to a JSON manifest file at `~/maenifold/assets/models/catalog.json`. The `list` action reads from this file instead of the static array. Ship a default `catalog.json` as a bundled asset (same pattern as gate process JSONs — copy to runtime dir if missing, never overwrite).

Future: fetch from a remote URL on startup with local cache fallback. But for now, a local JSON file that ships with the binary and can be edited by the user is sufficient.

## Acceptance criteria

1. `catalog.json` exists in assets with the 8 curated models
2. `EmbeddingModels { action: "list" }` reads from the JSON file, not a Rust const
3. Default catalog ships with the binary (bundled asset, copied on first run)
4. User can edit `catalog.json` to add custom models
5. `cargo build --release -p maenifold-core` passes
6. Existing frontend works unchanged (it already calls `list` via MCP)
