# T-225.8 — Frontend Polling Fallback for Non-Subscribable Resources

## Problem

After T-225.7 rejects subscriptions for non-subscribable URIs, the frontend must fall back to polling for resources it currently subscribes to that will now be rejected.

## Fix

Update `useMcpResources.ts` to handle subscription rejection gracefully:
1. On subscribe error, start a polling interval for the resource
2. Configurable per-URI polling intervals

## Polling Configuration

| URI Pattern | Interval | When |
|-------------|----------|------|
| `graph://stats` | 30s | Graph tab active |
| `schedule://logs/{id}` | 10s | Viewing active job |

## Key Files

- `apps/desktop/src/composables/useMcpResources.ts` — subscription handling

## Acceptance Criteria

- [ ] Failed subscription triggers automatic polling fallback
- [ ] Polling intervals are resource-specific, not global
- [ ] Polling stops when component unmounts
- [ ] `cd apps/desktop && npx vue-tsc --noEmit` succeeds
