# T-238.8 — Agents tab probe failure must show actionable capability state

**Pipeline**: tdd
**Pipeline Digest**: pending-sync

## Priority

**P0 — Blocks honest packaged-app UI verification**

## Problem

T-231.7 packaged [[Electron]] [[UI-verification]] documented the Agents tab showing `Copilot — probe failed` with an unexpected capability payload. The failure was incorrectly accepted as a caveat instead of becoming a [[gate-backlog]] item. A raw or unexplained probe failure prevents trustworthy agent status and violates the requirement that real UI errors discovered through [[agent-browser]] CDP verification are filed and failed until fixed.

## Scope

This task is intentionally narrow. It owns only the Agents tab probe/capability-state behavior. It is not the active full packaged-app verification replacement; that belongs to `todo/T-238.9-packaged-app-ui-backend-verification.md`.

Use TDD because this is a concrete behavior contract: the Agents tab probe path must either parse/display a valid capability state or show an actionable degraded state. The implementation stage should identify whether the fault is frontend capability parsing, backend/agent capability shape, [[Agent Client Protocol]] compatibility, launch/configuration state, or missing error-state mapping.

Do not change unrelated UI or backend behavior. Do not use screenshots alone as proof.

## Acceptance Criteria

- [ ] Real packaged [[Electron]] app is launched with `--remote-debugging-port=9222`.
- [ ] [[agent-browser]] connects to CDP and clicks the Agents tab through an accessibility ref.
- [ ] The Copilot probe either succeeds and shows the parsed capability state, or fails into a user-actionable degraded state that explains the next step.
- [ ] The UI no longer presents an unexplained raw `probe failed` state for an available/configured agent.
- [ ] Evidence is captured at `outputs/screenshots/T-238.8/01-agents-probe-actionable-state.png`.
- [ ] The verification report states what was clicked, what probe/capability action occurred, what visible state changed, and whether the result succeeded or failed.
- [ ] If the probe still fails without an actionable state, this task FAILS and records the exact visible error plus the next required gate item.
