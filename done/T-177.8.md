# T-177.8 — Tool naming & alias plan (decision)

**Pipeline**: sdd  
**Owner**: Architect  
**State**: pending  
**Timebox**: 2 days  
**Dependencies**: NONE  
**Blocks**: Any future tool-namespace changes

## Intent

Produce a concrete naming decision for all 29 tools, including backward-compatible aliases, without implementing renames in code.

This is a decision spec, not an open-ended research stream and not an implementation task.

## Decision constraints (fixed for this task)

1. Keep PascalCase MCP tool naming convention.
2. Keep compound tools (`Pipeline`, `Workflow`) and reject decomposition in this phase.
3. Provide compatibility aliases for at least 6 months from rename rollout.

## Deliverables

1. `docs/decisions/tool-naming.md` (short ADR):
   - Problem statement
   - Options considered
   - Final decision
   - Consequences
2. Complete renaming table:
   - All 29 current tool names
   - Proposed final names
   - One-line rationale per rename/keep decision
3. Alias table:
   - Old name → new name
   - Alias ownership location (where alias map lives)
   - Alias deprecation/removal date policy (minimum 6 months)
4. Discoverability improvement recommendation:
   - Optional `mcp__list_tools_by_category` helper, or
   - Doc-only category index

## Required decision statement

The ADR must explicitly state:
- **Decision: keep compound tools (`Pipeline`, `Workflow`)**
- **Decision: reject decomposition in this phase**

Required justification basis:
- MCP tools spec has no hard count cap and supports pagination plus tool-list change notifications.
- Anthropic agent guidance indicates tool selection accuracy degrades when too many tools are visible (roughly 30–50), with tool-search recommended at 10+.
- AWS guidance favors workflow-scoped tools over exposing raw endpoint-level tool fragmentation.

## References

- MCP tool spec: `https://modelcontextprotocol.io/specification/2025-06-18/server/tools`
- Anthropic tool-search guidance: `https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool`
- AWS workflow-scoping guidance (paraphrased; no canonical URL)

## Acceptance Criteria

1. ADR is committed at `docs/decisions/tool-naming.md`.
2. All 29 tools have a final name proposal.
3. Alias mechanism is specified, including where alias mapping lives and when aliases are removed.
4. ADR explicitly records decision to keep compound tools and reject decomposition for now.
5. No code changes are made in this task (plan/decision artifacts only).

## Out Of Scope

- Implementation of tool renames.
- Implementation of alias runtime behavior.
- Decomposition of `Pipeline` or `Workflow`.
