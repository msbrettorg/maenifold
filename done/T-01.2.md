# T-01.2 — Gate MCP transport: split `mcp/mod.rs` and remove local `no-unwrap` violations

## Objective

Bring `crates/maenifold-gate/src/mcp/mod.rs` under the 300 LOC cap and remove the two remaining local `no-unwrap` violations in the same file. The grounded fix is a mechanical split: keep the production MCP transport code in place, extract the embedded test module into dedicated `src/mcp/` test file(s), and thread lock-poison failures through existing error paths instead of hiding them. This task owns `mcp/mod.rs` exclusively so no other Sprint 1 task overlaps it.

## Scope

- `crates/maenifold-gate/src/mcp/mod.rs` — 788 LOC (`max-loc`)
- `crates/maenifold-gate/src/mcp/mod.rs` — `no-unwrap` at lines 79 and 83 in `KnownRoots::current()` / `KnownRoots::register()`
- New dedicated `crates/maenifold-gate/src/mcp/` test file(s) for the extracted `#[cfg(test)]` module body
- `crates/maenifold-gate/src/mcp/http.rs`, `crates/maenifold-gate/src/tray.rs`, and `crates/maenifold-gate/src/tray_lifecycle.rs` are in-bounds only for minimal mechanical updates if the `KnownRoots` API needs explicit error propagation; the `KnownRoots` type itself should stay stable
- `crates/maenifold-gate/src/mcp/dispatch.rs` is explicitly out of scope for this task; preserve the current dirty worktree state there unchanged

## Acceptance Criteria

1. `make audit-crates` reports no `max-loc` violation for `crates/maenifold-gate/src/mcp/mod.rs`
2. `make audit-crates` reports no `no-unwrap` violation for `crates/maenifold-gate/src/mcp/mod.rs`
3. The LOC reduction is achieved by mechanical test extraction from `mcp/mod.rs`; do not redesign `GateMcpHandler`, `GateMcpServer`, dispatch flow, or localhost CORS behavior
4. `KnownRoots` preserves current behavior: `with_initial()` seeds the list, `current()` returns the most recently registered root, and `register()` de-duplicates before appending the newest root
5. Lock-poison failures are handled explicitly with clear surfaced errors through existing result/error paths; no `unwrap`, no `expect`, and no silent reset/fallback behavior
6. `cargo test -p maenifold-gate mcp::` succeeds, or the equivalent targeted filter for the moved `src/mcp/` unit tests succeeds after extraction
7. `cargo build --release -p maenifold-gate` succeeds
8. The test extraction remains a unit-test child module under `crates/maenifold-gate/src/mcp/`; do not widen visibility on private `mcp` items solely to keep the moved tests compiling
9. Every new or modified Rust source file created by the split stays at or below the 300 LOC constitution cap; if one `tests.rs` file would exceed the cap, replace it with `src/mcp/tests/mod.rs` plus multiple child modules under `src/mcp/tests/` instead of relocating the violation

## Implementation Notes

- Preferred split: leave the production code in `mcp/mod.rs`, replace the inline block with `#[cfg(test)] mod tests;`, and move the embedded test body into `crates/maenifold-gate/src/mcp/tests.rs` (or equivalent sibling unit-test module) so the production file falls below the LOC cap
- If a single `crates/maenifold-gate/src/mcp/tests.rs` file would exceed 300 LOC, keep `#[cfg(test)] mod tests;` in `mcp/mod.rs`, replace `tests.rs` with `crates/maenifold-gate/src/mcp/tests/mod.rs`, and split the moved tests across multiple child modules under `crates/maenifold-gate/src/mcp/tests/`
- Preferred unwrap fix: make `KnownRoots::current()` / `KnownRoots::register()` return explicit errors so `GateMcpHandler::new()` and `call_tool()` can surface poisoned lock failures cleanly
- Do not introduce hidden recovery that discards or recreates poisoned state
